# 环境兼容方案：双路径启动设计

日期：2026-07-05
状态：设计稿

## 问题

用户端存在两类截然相反的环境：

1. **小白用户**：没有 Python，使用一键包（embedded Python 3.12），依赖全预装，但 CUDA torch 文件过大无法打包
2. **研究者用户**：有自己的 Python + CUDA 环境（可能 3.10/3.11），期望 GPU 加速

当前 `_detect_user_torch()` 试图从系统 Python 找到 CUDA torch 并注入到 embedded Python 进程，当 Python 大版本不匹配时 ABI 不兼容，导致崩溃或 fallback 后困惑。

## 设计决策：双路径

放弃"跨 Python ABI 注入"策略。启动时不在不同 Python 版本间共享 site-packages。同一进程的 torch 必须由同一个 Python 安装。

```
                   启动
                     │
            ┌────────┴────────┐
            ▼                 ▼
     嵌入式 Python 3.12   用户自己的 Python
     (一键包 Path A)      (源码运行 Path B)
            │                 │
     默认 CPU 模式        用户自己管理 torch
     GPU: 跑 install_cuda   pip install 自行负责
     将 CUDA torch 装进     同一进程同一 ABI
     嵌入式 Python 自身     注入机制不启用
```

## Phase 1 改动范围

### 1. `_detect_user_torch()` 重写

```python
# 旧：遍历 PATH 找其他 python.exe → 版本比对 → 尝试注入
# 新：只检查当前 Python 自身是否有 CUDA torch
```

- 去掉 `subprocess.run` 多 python 探测
- 去掉 Python 版本比对
- 去掉 `sys.path.insert` 跨 Python 注入

### 2. GPU 决策逻辑重构

| 条件 | 行为 |
|------|------|
| `BTRANSLATOR_GPU_MODE` + embedded + 自身有 CUDA torch | GPU 模式 |
| `BTRANSLATOR_GPU_MODE` + embedded + 自身无 CUDA torch | 打印建议 → 自动 CPU |
| 非 embedded（用户 Python） | 不做任何跨 Python 查找 |

### 3. `prepare_environment()` 分支

- Path A（embedded）：保持原行为，跳过所有 pip 操作
- Path B（用户 Python）：正常执行 `check_req_file` + pip/uv 安装

### 4. `launch.bat` GPU 检测段

`BTRANSLATOR_GPU_MODE` 语义从"去找系统 CUDA torch"调整为"本机有 NVIDIA GPU，是否使用取决于当前 Python 本身"。检测逻辑不变。

### 5. 新增 `install_cuda.bat`

一键包中选择性安装 CUDA torch 到嵌入式 Python：

```batch
.\ballontrans_pylibs_win\python.exe -m pip install ^
    torch==2.7.1 torchvision==0.22.1 torchaudio==2.7.1 ^
    --index-url https://download.pytorch.org/whl/cu124
```

### 6. 延迟化 module-level import

- `utils/proj_imgtrans.py` → `from PIL import Image` 移为局部 import
- 其他可能依赖外部包的 module-level import 按同样模式处理

### 7. 虚拟环境兼容

不引入额外逻辑。`launch.bat` 的 Python 发现优先级确定谁跑 launch.py，谁就是 torch 来源。用户自行保证 venv Python 版本与 embedded 一致（3.12）。

## Phase 2（占位）

软件设置内提供环境管理 UI，供有自己环境的用户配置/切换后端。具体内容后续细化。

## 边界行为

| 用户场景 | 能否进 UI | CUDA |
|----------|-----------|------|
| 一键包（无 GPU） | ✅ | ❌ CPU |
| 一键包 + run install_cuda.bat | ✅ | ✅ |
| 源码 + 自己 3.12 + CUDA | ✅ | ✅ |
| 源码 + venv 3.12 + CUDA | ✅ | ✅ |
| 源码 + 3.9（无 CUDA） | ✅ | ❌ CPU |
| 混合 embedded + venv | ✅ | 取决于哪个 python 被启动 |

## 不做的改动

- 不保留跨 Python 版本查找 CUDA torch 的代码路径
- 不改变模块注册器系统
- 不改变 `_ensure_module_fallback()` / `_ensure_model_files_fallback()`
- 不修改 `prepare_environment()` 中的 GPU 版本检测（`detect_gpu_info()`）
