## HelpDialog — 代码块样式渲染

**问题描述：** 帮助文档中的 fenced code block（````` ``` ````）在正文中没有视觉区分度，与普通段落混在一起。

**当前处理（2026-07-14）：**

- 原先尝试 `block.charFormat().fontFixedPitch()` 检测代码块，但该属性在 Qt 的 `setMarkdown()` 渲染后**对绝大多数代码块返回 False**，导致 `_style_code_blocks()` 命中率为 0。
- 诊断脚本 `debug_codeblocks.py` 确认：代码块的 `fontFamilies()` 为 `["Courier New"]`，而普通段落为空列表。因此检测改为 `_block_is_code_block()` 静态方法，用 font families 关键词匹配（courier / monospace / consolas / mono）。
- 样式应用使用 `QTextBlockFormat.setBackground()` + 边距。
- 依赖 Qt 版本中 `fontFamilies()` 的稳定性。

**现状：** 检测机制已修正，但用户反馈视觉效果仍不符预期。可能原因：
- `QTextBlockFormat.setBackground()` 在 QTextBrowser 中只填充文本区域宽度，不铺满整行，不像 Obsidian 那种全宽背景面板。
- 字体差别（Courier New vs Microsoft YaHei）不够明显。
- 缺乏代码块专用的边框/圆角容器。

**后续方向：**
- 考虑用 `QTextFrame` 包裹代码块以实现全宽背景 + 圆角。
- 或在 `setMarkdown()` 之后拦截 HTML 输出，给 `<pre>` 加 inline style。
- 也可以考虑换用第三方 markdown 渲染库。

## HelpDialog — 搜索结果跳转不准确

**问题描述：** 点击搜索结果的链接后，跳转位置与预期不符，可能跳到了文档中相同文字的其他出现位置。

**当前处理（2026-07-14）：**

- 原先尝试 heading 范围限定（`find(heading)` → `find(plain)`），但 `find()` 只做纯文本匹配，如果 heading 文字在代码块或正文中提前出现，就"截胡"了定位。
- 当前简化为全文 `find(plain)`，不做范围限定。

**现状：** 如果匹配文字在文档中出现多次，`find()` 只定位到第一次出现，不一定是用户点击的那个结果。

**后续方向：**
- 在搜索结果中记录精确的行号或块号，点击时导航到特定块。
- 或使用 `QTextCursor` 的块位置接口直接跳转到指定段落。
