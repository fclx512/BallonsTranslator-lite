# 上游兼容策略（长期规范）

> 拍板日期：2026-10-02。上游 = `dmMaze/BallonsTranslator`（本地工作区 `userspace_update` 分支，内容 = 最新 dev）。
> 上游代码改不了，本规范只约束 fork 侧。差异底稿见桌面《富文本特性差异_fork_vs上游_交接.md》与 `.workbuddy/align_upstream_recon_2026-10-02.md`。

## 一、方针（用户拍板，勿再翻案）

1. **对齐只做到「基础排版互通」为止**——档一（数据层容错）与档二（行为对齐）全做；**档三（整族功能移植）不做**。
2. **各自的拓展功能按「没有」兼容**：上游有而 fork 没有的功能（alpha 蒙版、纹理、AI 图、docx、TCY 整形），在 fork 里一律按「该功能未启用」处理——载荷保留不崩、不渲染、不报错。**不为了渲染对等而移植整族功能。**
3. fork 独有的功能（标签体系、项目级样式、删除线、自定义描边色）**保留**，接受上游打开时丢失；不因为"上游不认识"就砍掉。
4. **对上游做长期监测**：上游改了契约要能被发现，而不是等用户互开工程时才炸。

一句话理由：fork 无法与上游同步开发节奏，因此不追功能对等，只守"基础排版不出问题 + 变化可感知"。

## 二、兼容底线（什么算"不出问题"）

fork 打开上游工程时，以下必须成立：

- 页面/块全部加载成功，不抛异常、不静默丢块。
- 基础排版属性（坐标、字体族、字号、颜色、粗斜体、对齐、竖排、行距字距、描边、阴影、渐变）渲染与上游一致。
- 富文本 HTML（`rich_text`）双向可读。
- 未知/不支持的效果载荷**原样保留、回写不丢**（`utils/text_effects.py::UnknownEffect` 透传机制）。
- fork 保存后再被上游打开：不产生新的数据损坏（已有的 `base_styles`/`tags` 丢失属已知接受项）。

## 三、例外清单（明确不做，按"未启用"处理）

| 项 | 上游有 / fork 无 | fork 侧处置 |
|---|---|---|
| alpha 蒙版（`text_alpha_mask`） | 上游独有块级字段 | 缺失即视为未启用；载荷进 `deprecated_attributes` 后回写保留（现状即如此），不实现笔刷与渲染 |
| 纹理（TexturePaint as paint）、AI 生成图（ImageEffect） | 上游独有 | 数据类保留（已逐字移植），渲染/面板跳过；缺栅格资产持久层不再补 |
| 栅格资产管线（工程 `assets/` 目录） | 上游独有 | 不做工程侧集成 |
| docx 通道（`dump_doc`/`load_doc`） | 上游独有 | 不做 |
| TCY run 级整形 / native stroke 对齐 / `_PlainColumnLayout` | 上游渲染增强 | 不做，保留 fork 自有实现 |
| 合成粗体（SyntheticBoldEffect） | 上游独有 | 走 UnknownEffect 透传（历史拍板，重申） |

## 五、长期监测机制

脚本：`scripts/check_upstream_drift.py`（纯 AST，不 import 两侧代码，因此不受依赖缺失影响）。

巡检面：`TextBlock`/`FontFormat` 的字段与默认值、效果类型注册表、`ProjImgTrans.to_dict` 的工程写入键。
基线：`scripts/upstream_drift_baseline.json`（唯一权威，记录已拍板接受的差异）。

用法：

```text
python scripts/check_upstream_drift.py                # 与基线比对，有漂移退出码 1
python scripts/check_upstream_drift.py --update-baseline   # 重算基线（确认差异可接受后再做）
python scripts/check_upstream_drift.py --print        # 打印当前两侧契约面
```

约定：

1. **上游不存在时自动跳过并退出 0**——不是每台机器都有上游 clone，不得因此挂掉检查。路径用 `--upstream` 或环境变量 `BT_UPSTREAM_ROOT` 指定，默认取本机 `D:\ruanjian\BallonsTranslator\ballontranslator`。
2. 已挂进 `scripts/verify.py`（在展示台检查之后），**只提醒不阻断**：漂移打印 `⚠` 与明细，不计入失败。
3. **节奏**：每次同步上游（fetch/切换工作区）后跑一次；发现漂移 → 判断是"fork 需要补容错"还是"新增的已接受差异" → 前者进第四节清单，后者 `--update-baseline` 并在此文档说明。
4. 基线里的每条差异都应是**有意为之**；不要在不知情的情况下刷新基线（那等于把监测关掉）。

## 六、新增落盘字段的守则

1. fork 新增持久化键：默认"仅非默认值落盘"，避免上游每块告警（`tests/test_upstream_writer_compat.py` 的契约）。
2. 读取上游数据时"宽进"：不认识的键/值一律保留或降级，**不抛异常、不静默丢弃**（第 5 项就是这个毛病的修法）。
3. 新增不落盘的功能开关走 `utils/config.py` 的 pcfg，不进工程 JSON——工程 JSON 是互通面，尽量少动。
4. 任何"上游工程里的键缺失"分支，语义统一为"该功能未启用"，不得把缺失当错误处理。
