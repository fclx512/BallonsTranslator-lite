## 一、通用观察点

每场景顺手核对四件事，异常即记录：①**一致性**——画布文字与右侧译文框文字始终相同；②**保存状态**——角标与直觉一致（改了→未保存；撤回到保存点→已保存）；③**编号徽标**——画布块角标编号与右侧列表顺序一致；④**控制台**——从 `launch.bat` 启动时终端无异常堆栈。另留意「按了没反应」的空撤销格：记录出现前做过哪些操作，这正是本清单要暴露的信息。

## 三、已知限制与刻意不做（防复活）

- 撤销不跨页、切页清空两栈是**页屏障语义**的一环（正确性层）：栈外管线写入（检测/OCR/整页翻译）会使该页更早历史整体作废，不存在半新半旧还原。用户发起的跨页编辑由决策 3/4 在 UX 层解决。
- 整页管线运行后历史被清空、不可撤销；选区运行可撤销——两者行为不同是当前设计（S20 vs S1）。
- 原文面板「非相邻且含删除」的编辑降级为不可撤销，已在 `ui/canvas.py::note_source_edit` 注释声明，未改。
- 键入会话空闲 1.5 秒自动闭合切步、预览/会话悬开期 Ctrl+Z 不落命令（取消手势恢复原值）均为**预期行为**，非缺陷。
- 绘制栈重做无越界保护，计数漂移可致保存状态误报「未保存」（S4）；Qt `setUndoLimit` 仅空栈生效（决策 1）。
- 批量重渲保栈路径产生的僵尸命令静默失效，允许「按了没反应」，不报错。
- 撤销历史面板暂只挂文本栈：窄栏仅在文本模式可见，绘制栈入口由用户拍板搁置。
- 已退役（勿加回）：item/panel 文档栈的逐路径事后切换、C 排水口、D 步数记账、E joint 链（决策 8），以及 `on_global_replace_finished` 中对当前页的无效标脏调用（决策 7）。

## 五、相关决策记录（2026-09-04）

1. **最大撤销步数（✅ 2026-09-05 落地）**：Qt `QUndoStack.setUndoLimit` 实现；字段 `utils/config.py::ProgramConfig` 的 `undo_steps_limit`（默认 0 = 无限，范围 0–500，UI 直接显示数字 0 表示无限、不用特殊文本——不会有人专门禁用撤销，0 无歧义），入口 ConfigPanel → 界面 → Canvas；文本/绘制两栈同时生效。**⚠️ Qt 限制（实现绕开）**：`setUndoLimit` 仅在空栈上生效，非空栈上调用只打警告并被忽略（Qt 文档化行为，Qt4 起如此；早期探针恰在空栈设置，误得出「缩容惰性」结论，后经非空栈复测纠正）——`ui/canvas.py::apply_undo_limit` 以空栈守卫落地：启动时栈空立即生效，会话中途改设置由下次清栈（切页/整页管线，各 `clear_*` 处再应用）生效。固化进 `tests/test_undo_limit.py` 的前置实测结论：保存点被截断时 Qt cleanIndex 落 -1、`isClean()` 恒 False（不假报「已保存」，**无需**自造判定）；保存点幸存时 cleanIndex 正确平移、可撤回。配套修正：`ui/canvas.py::push_draw_command` 截断时同步平移绘制栈手工计数器（`num_pushed_drawstep`/`saved_drawundo_step`），保存点被截落 -1 哨兵保持「未保存」。
2. **撤销历史面板（✅ 2026-09-05 一期落地：仅文本栈）**：形态由「弹窗」改为 PS 式窄栏浮层面板 `ui/history_panel.py::HistoryPanel`（QUndoView 渲染，`setEmptyLabel` 首行=原始状态，行号=栈位置点击跳转，循环 `canvas.undo()/redo()` 复用每步记账并抑制撤回 toast，cleanIndex 行右缘圆点标保存点），入口 `ui/text_panel.py::install_history_launcher`（开合记忆 `history_dock_open`）。行名 = 命令构造处 `UndoCommand` 上下文文本，与 `ui/canvas.py::_notify_undo` 的撤回 toast 同源。绘制栈历史暂缺入口（窄栏仅在文本模式可见，用户拍板搁置）；跨页编辑历史（决策 3）落地时并入本面板按页分组展示。
3. **跨页编辑历史**：方向确认——单一全局线性栈 + 按页分组展示；本页撤完后提示并可跳页继续；不做分支历史（非线性编辑按时间序追加新组）。用户三项拍板：边界体验 = 再按一次才继续、全局替换保持分治、分三批先跨页历史。已随阶段 4 第一批落地并实机验收（2026-09-06）。
4. **跨页批量操作的组化与确认弹窗**：一次跨页批量操作（整理换行类）打包为单个命令组入栈，可整体撤销；撤销前弹确认对话框，列出影响的页/块，并提供「同时重渲染脏页」勾选项（复用现有批量重渲确认流程）。组内仅存各块前后端点快照，不存中间态。全局替换保持分治不并入命令栈（2026-09-05 用户拍板）。已随阶段 4 第二批落地并实机验收（2026-09-06）。
5. **图像修复撤销不保存完整图像（阶段 4 跨页语境）**：跨页历史下的修复类命令撤销 = 删除修复结果、按遮罩从原图还原该区域；重做所需仅存最后一次修复结果（区域裁剪）；对同一区域的连续修复聚合为一步（仅存首次修复前与最后一次修复后），不记录中间各次。**当前页的图像修复撤销行为维持现状不动**——现机制下用户不中途切页时修复本就可逐步撤回（含图像快照）；当前页文本编辑同样保持逐操作撤销现状。省内存方案以页屏障纪律为前提（栈外管线写入会使该页历史整体作废，不存在半新半旧还原）。
