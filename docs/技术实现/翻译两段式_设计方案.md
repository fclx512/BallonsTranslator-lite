# 翻译两段式（初译 → 章级润色）设计方案

> 状态：**规划稿，未实现；组件原型已验证，质量增益未证实**。2026-10-11 根据 94 页实测和多代理审查修订：章节由 AI 按剧情自主提出，页段只承担上下文预算切分；默认仅润色风险候选块，不把全量第二段当成既定收益。
> 前置阅读：`docs/技术实现/翻译agent化_设计方案.md`。

## 1. 目标与范围

- **初译**：优先忠实原文、指定译名、逐块对应和翻译指示，产物称直出稿。流畅表达仍是基本要求，不刻意制造生硬译文供第二段修补。
- **章级润色**：结合章内原文与直出稿改进连贯、语气和简洁度。事实、否定、数量、人称、说话人及明确固定的译名不得无依据改变；原稿合适就保留。
- **人工浏览**：最终稿写入后挂页级「待浏览」，用户逐页看译文并调整排版。浏览状态只说明看过，不代表逐块质量已获认可。
- **三层范围**：AI 先按连续叙事提出**逻辑章节**；客户端再按上下文容量把每章切成连续的**预算页段**；润色请求默认只覆盖页段中命中的**风险候选块**。页码用于定位、顺序校验和预算切分，不直接代表剧情章节。单页信息不足以判断剧情关系时，必须依赖章节内其他页或只读参考，不能把每页当作独立上下文。

两段式是质量假设，不预先承诺优于现有单段翻译。使用同模型的不同任务提示词作分工，不能把 persona 切换当成独立质量验证。v1 不新增章节编辑器、章节梗概体系、独立润色模型选择器或自动 OCR 修正。

## 2. 执行链与结束语义

```text
整本/继续运行入口：固定本轮页集合、配置及原文快照
        ↓
逐页初译 → 保存有效直出稿（不覆写最终译文，不导出空字/旧稿结果图）
        ↓ 明确屏障：生产结束 + 本轮初译结算 + 翻译线程退出
AI 按连续叙事提出逻辑章节 → 客户端校验章节覆盖与顺序
        ↓ 按上下文容量把每章切成连续预算页段
风险筛选 → 展示候选范围与预计成本 → 用户确认、缩小范围或跳过
        ↓ 后台请求；先收齐当前章节候选，候选不写项目
        ↓ 主线程检查输入仍有效、前置同步、版本备份
整章写回 → 文本后处理/排版 → 当前页及非当前页结果图保存
        ↓ 本轮最终保存及图像保存队列结束
报告完成（成功/部分完成/回退/跳过有区分）→ 人工逐页浏览
```

### 2.1 协调屏障与线程归属

现有 `ui/module_manager.py::_imgtrans_pipeline` 尾部的 finalize 调用只是可改造入口：并行初译在 `ui/module_manager.py::TranslateThread`，当前没有等待其完成的屏障；取消后也可能到达收尾。不能直接以该位置证明「初译全部结束」。

- 编排层记录本轮目标页及每页成功、失败、取消的结算结果，生产结束后等待本轮翻译消费完成和线程退出；失败页不能仅因完成计数增加就变成成功。
- 后台仅执行 API 和纯数据计划。项目块替换、当前页同步、场景重建、页状态及文本历史处理在主线程完成；不得在后台调用 QWidget 或带 UI 的批量写回。
- 新的润色完成条件不能直接复用现有 `ui/module_manager.py::proj_finished` / `ui/module_manager.py::finishImgtransPipeline` 判据：它们存在未启用 OCR 时提前完成、取消后仍发完成信号等路径。两段式应维护独立的本轮结算状态，只有初译、候选处理、主线程写回、工程保存和目标图像保存全部明确结算后才发整体完成。
- 拟新增的翻译器 finalize 只负责产出润色候选，不自行保存项目或操作画布；编排层传入本轮上下文，禁止依赖上次运行遗留的项目/页集合。同一个翻译器实例的 client/key/限流状态禁止被初译和润色并发消费；取消标志和状态回调也不能在两个任务之间共享。

### 2.2 用户看到的流程

1. **先生成初译草稿**：程序逐页翻译并保存草稿，原来的最终译文和画布不被覆盖。用户可以继续工作，也可以等待整本初译完成。
2. **AI 理解剧情并提出章节**：程序根据前后文、人物关系、场景和语气变化提出章节候选，同时显示章节数量和低置信度提示。页码只用于定位，不要求用户自己按页分章。
3. **列出值得复核的地方**：程序在每个章节中标出可能影响剧情的否定、数量、情态、称呼、专名、长句和 OCR 不确定块，并显示预计请求量。没有命中风险时不发第二段请求。
4. **用户决定范围**：用户可以确认全部候选、缩小到某些章节或跳过润色。全量润色是明确的额外操作，不能在用户没有看到范围和成本时自动发生。
5. **后台准备候选**：程序按章节内部的上下文容量切成若干请求段。这个切分只为控制单次请求大小，用户仍按剧情章节查看结果；模型不能写入候选之外的块。
6. **整章一次写回**：程序先检查用户是否改过原文、最终译文或排版。冲突块保留人工内容，其余候选才写入；写回前显示“将写入、保留人工、回退直出稿”三类摘要。
7. **浏览和处理待办**：写回成功后页面标记为“待浏览”。润色没有改动的块、回退到直出稿的块和保存失败的页都会在结果报告中单独列出；回退块进入“译文待重译”队列。

用户可以在页段或章节边界暂停。暂停会保留已完成的章节和草稿，恢复时先告诉用户哪些内容仍有效；取消则丢弃尚未提交的候选，不用草稿覆盖现有最终译文。

### 2.3 失败、取消与局部运行

| 情况 | v1 行为 |
|---|---|
| 某块初译失败 | 无本轮有效直出稿，排除该块润色；保留已有最终译文，报告缺失，不用旧草稿冒充新稿 |
| 润色段失败或超限 | 该段回退有效直出稿，其他段保留校验通过的润色候选；章内一起写回，标明回退范围 |
| 划章失败/格式非法 | 先保留 AI 已返回的可解释边界；若不能形成合法章节，退回客户端按连续页段做保守分段，不能把全项目塞进一次请求；该次结果标为降级，不冒充剧情章节成功 |
| 润色风险筛选为空 | 不发润色请求，保留有效直出稿并报告“本章没有命中风险候选”；用户仍可在确认页主动选择全量润色 |
| 用户暂停 | 不再开始新的页或预算页段；已收齐且通过校验的章节候选照常完成一次提交后暂停，未收齐章节候选整体搁置并保留草稿 |
| 用户取消 | 不再发新请求；丢弃尚未提交的本章候选，保留草稿与此前已完成章；不自动用草稿覆盖已有最终稿 |
| 单页/单框/选区翻译 | 沿现有行为直接写最终译文，不隐式启动整本润色 |
| 继续运行/指定页集合 | 只写本轮有效目标块；同章未选页面只作只读参考，不扩大写入范围 |

取消须在请求前、响应后、主线程提交前检查；网络请求无法即时中断时，迟到响应不得写回。取消不是普通失败，不发强制收敛请求。暂停要记录阶段、章节和预算页段，重启后可从最近一个已持久化检查点继续。没有有效成果的章不创建空操作版本。重启恢复只复用可验证的草稿，不因字段非空自动跳过初译。

## 3. 数据契约

### 3.1 直出稿及有效期

拟为 `utils/textblock.py::TextBlock` 增加持久字段 `translation_draft: str = ""` 和 `translation_draft_source_hash: str = ""`。后者是与初译实际输入一致的规范化原文摘要：统一换行，不忽略有意义的字符差异。

- `utils/textblock.py::to_dict` 全量导出实例属性，旧工程缺字段可由默认值兼容；这只保证序列化，不代表恢复流程已完成。
- 原文修订、合并/拆框、重新检测使旧草稿失效。运行时重新核对摘要，即使某条编辑路径没显式清字段也不能误用；合并/拆框不能继承成员草稿摘要作为新块有效稿。
- 页级运行信息拟存于 `utils/proj_imgtrans.py::_image_info`：本轮源/目标语言、profile 模型与提示词/术语/翻译指示等有效输入的摘要，以及草稿/完成/回退/取消状态；不保存密钥。初译草稿签名与润色输入签名分开：只改变术语或润色提示时，不应无条件让仍然有效的初译草稿失效；改变原文、初译模型或初译提示时才重新初译。恢复入口要说明哪些页因签名变化需要重跑。
- `translation_draft` 是最近一次有效初译产物；`translation` 是实际呈现的最终稿或显式回退稿。人工改最终译文不改直出稿；人工改原文使直出稿失效。旧草稿可留作历史对照，但不允许继续润色或「切回直出」。草稿无效时应灰显并禁止写回，避免用户误把旧稿当成当前候选。
- 初译写回时同样检查原文/块对应关系未变。每页成功后保存草稿检查点，但检查点应允许攒批或按章节落盘，不能照字面变成每页一次全工程备份；完成状态与对应持久化成功绑定。

章任务使用连续局部 id 1..N，另外固定映射到页名和块位置/快照；空原文不进入模型任务。不把各页重新从 1 编号的块直接拼接为全章 id。模型输入中不展示原始页块编号或探索 UID，参考数据中的这些标识必须明确标为不可提交；越界、未知或协议混用 ID 使本次整单候选作废，不得接受合法部分再补缺。页代数只能发现部分结构变化，不能替代原文、最终译文及 rich_text 的内容比对。

### 3.2 逻辑章节与预算页段

拟新增工程顶层 `chapter_table: [{name, pages: [页名…], reason, confidence, order_snapshot_hash}, …]`，存取参考 `utils/proj_imgtrans.py::load_from_dict` / `utils/proj_imgtrans.py::to_dict`。章节是 AI 根据连续剧情提出的逻辑分组，不能等同于单页，也不能由页数阈值直接决定；预算页段是客户端为了单次请求容量从逻辑章节中切出的连续页范围，两者独立。

AI 划章任务读取固定页索引、每页有限原文抽样、已有直出稿摘要及必要的前后文线索，输出章节边界、章节名、划分理由和置信度。它可以把信息量很少的页面与前后剧情合并，也可以在场景、人物关系或叙事转折处提出边界；不得为了凑固定页数强行拆章。章节候选不直接写入工程，先由客户端验证：页名存在、全项目页唯一覆盖、按当前页序连续且有序、没有未知页、重页、漏页、逆序或空章，并核对页序快照哈希。

章节表非法或置信度不足时，客户端应保留可解释的候选并提示用户；确实无法形成合法章节时才使用连续预算页段作为降级分组，并在结果报告中标明“未使用 AI 剧情章节”。不新增章节编辑器，但允许用户在确认阶段跳过低置信度章节或缩小润色范围。页集合/顺序变化、章节输入签名变化或页序快照不一致时，章节表失效并重新划分；重新划章不覆盖人工最终译文。局部运行仅取逻辑章节与本轮目标页的交集，未选页可作为只读参考。

### 3.3 页级待浏览

拟在 `utils/proj_imgtrans.py::_image_info` 增加 `review_pending`。最终稿写回后置位；回退稿也置位；新一轮写回重新置位。它不替代块级「稍后重译」或「稍后校对」，也不清除这些具体问题。

## 4. 环节设计

### 4.1 初译写回与阶段上下文

对 `modules/translators/base.py::translate_textblk_lst` 的写入目标参数化，但只由两段式整本编排显式启用草稿目标；不能按 AgentTranslator 类别一律改写草稿。非 agent 翻译器与普通单页/单框路径保持现有最终稿写回。

现有 `modules/translators/agent/prompts.py::build_history_snippet` / `modules/translators/agent/prompts.py::_page_fully_translated` 和 `modules/translators/agent/tools.py::execute_agent_tool` 经 `utils/proj_compact.py::build_detail` 读取最终译文。草稿阶段必须提供任务专用只读视图：

- 初译历史读取本轮已经完成的有效直出稿，不能读空最终稿或上次译文冒充本轮历史。
- 两段式初译探索工具也使用同一视图；普通工具/其他工作台的最终译文语义不改。润色任务使用冻结的 `polish` 视图：原文、直出稿、页序、翻译指示和说话人线索可读，最终译文只作为明确标注的只读参考。
- 读取视图必须由调用方显式传入 `final`、`draft` 或 `polish`，不能临时替换块对象中的 `translation` 字段。这样可以保证后台构造候选时不会污染画布、文本面板或普通翻译路径。
- 同章未处理页可以作为只读参考，但不得进入当前任务的可提交 ID 集合；单页信息不足时优先扩大只读上下文，而不是把单页判断当成完整剧情判断。

OCR 不确定仍由人工 `utils/block_tags.py::set_manual_tag` 挂 `utils/block_tags.py::OCR_REVIEW_ID`。拟在 `utils/block_tags.py::DIRECTIVE_INSTRUCTIONS` 补提示，经 `utils/block_tags.py::directive_instructions` 给初译和单框重译使用：允许结合上下文作有依据的理解，不得把不确定内容补成确定事实。不得因译文流畅就清除待校对；不追加 vision/OCR 子管线。旧人工待办 ID 的读侧兼容沿用现有标签规则。

### 4.2 AI 划章与预算分段

初译屏障后先用单轮 JSON 调用提出逻辑章节。输入不是逐页孤立任务，而是固定页索引、每页有限原文抽样、初译结果摘要，以及足以判断场景和人物关系的前后文线索；输出章节页范围、名称、边界理由和置信度。该调用不伪装成逐页翻译，禁止错误响应落项目。章节候选通过 §3.2 的客户端校验后才进入后续流程。

通过校验的每个逻辑章节，再按连续页累计估算 system、原文、直出稿、术语、工具 schema、只读参考与预留输出，切成一个或多个预算页段。页段只解决单次请求容量，不能重新定义剧情章节；页段边界尽量落在块或场景边界，无法避免时必须携带前后页只读参考。输入预算和单次输出上限分开控制。`modules/translators/agent/loop.py::run_agent_task` 的累计 token_budget 是请求后的软收敛条件，不能替代首次请求前的容量检查。

每个预算页段内的块只在一个写入任务出现；逻辑章节的其他页和相邻章节页可以作为明确不可提交的只读参考。收到上下文/输出截断错误时有限次缩段；单块仍无法容纳则回退并提示，不无限重试。模型上下文上限未知时采用保守上限，实测记录所用值，不凭模型名字硬编码供应商容量。`finish_reason` 必须同时从流式和非流式响应保留；供应商不返回 usage 时记录未知，用请求次数/输入估算及明确输出上限兜住成本。

### 4.3 润色任务及护栏

润色默认只处理风险筛选命中的块，不对整本所有块自动发第二次请求。候选生成使用低成本、可解释的规则和已有数据，优先标记否定、数量、时间、情态/推测/传闻、人称、称呼、固定译名、跨块长句、OCR 待校对、初译与邻近上下文明显不一致的块。命中结果先按逻辑章节汇总，展示候选块数、预算页段数、预计请求量和 usage 估算；用户可以确认、缩小范围或跳过该章。整章/全量润色保留为用户主动确认后的可选操作，不作为默认质量承诺。

通过确认的候选直接调用 `modules/translators/agent/loop.py::run_agent_task`，独立组装审校 system/user 消息；不走逐页语义的 `modules/translators/trans_agent.py::_run_agent_task` 包装，也不调用 `modules/translators/trans_agent.py::translate` 的普通直译 backfill。缺块由编排层回退到对应的有效直出稿，并把回退块标为 `utils/block_tags.py::TRANS_REVIEW_ID`，进入译文待重译队列。复用 `modules/translators/trans_agent.py::_agent_chat` 前须完成 client/key 初始化，确保 API 配置冻结且无并发调用；取消检查要穿透 API 重试等待。

- 任务 ID 只展示一套连续局部 id 1..N；原页块编号和探索 UID 只在客户端映射，任何参考数据都明确标为不可提交。越界、未知或混用 ID 使本次整单候选作废，不能接受合法部分再补缺；达到有限重试上限则回退。普通合法分批提交与协议错误分开处理。
- 复用 `modules/translators/agent/validator.py::validate_submission` 的形状、ID、非空、清洗和源词残留检查。`modules/translators/agent/validator.py::_residue_terms` 不验证目标译名；完整提交可能在首次警告后即结束，因此不得声称术语已被校验器锁定。
- 润色补明确固定译名的目标检查。现有 `modules/context/glossary.py::GlossaryEntry` 只有 source/translation/note，没有专名类型；v1 约定 note 含显式标记 `[固定译名]` 的条目才要求保留原文中明确出现的称名及指定字符串，不新增字段或编辑器。旧词条默认不升级为硬检查，也不让模型自行猜词条类型。恒等映射不能自动豁免被换成另一名字；普通词、未显式要求保留称名的省略及屈折变化不强制子串命中。
- 提示词固定事实/数量/否定/人称/说话人约束，不要求为润色而改写。固定译名检查不能证明语义完全正确，仍靠人工样本验证。情态、传闻归因和称呼对象身份的改变属于高风险退化，应优先进入固定验收样本。
- diff 相似度只作诊断：短句和完全合法不变稿不反复催改，不额外烧请求；结果报告记录改动块数、未改动块数、明显长度变化、回退块数和冲突块数，不把改动数当成质量评分。
- v1 润色只提供提交和术语查询；已经输入整段原文/直出稿，不先开放全项目 read/search。默认最多 2 个普通轮次加现有 1 个强制收敛轮次；取消不发强制收敛请求。每个预算页段有独立输入/输出/累计请求预算。
- 润色任务的实际 reasoning 模式通过 per-task 参数传入，不能临时修改共享 profile。章节梗概暂不新增；已有项目梗概可作为标明“背景、非指令”的稳定前缀。

#### DeepSeek 协议前置条件（本轮实测新增）

默认思考模式下，DeepSeek Chat Completions 不支持 required/指定函数的 tool_choice；带 tools 的多轮还要求回传 reasoning_content。[官方请求协议](https://api-docs.deepseek.com/api/create-chat-completion/)、[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)与本轮默认模式收敛请求 400 的实测一致。

现有 `modules/translators/agent/loop.py::_assistant_message` 只保留 content/tool_calls，`modules/translators/agent/loop.py::FORCED_TOOL_CHOICE` 指定提交函数；不能因首轮 auto tools 成功就认为完整循环兼容。`utils/reasoning_params.py::build_reasoning_kwargs` 当前把 none 当「不覆盖」，在默认思考的端点并不等于关闭思考。

v1 对本方案的 DeepSeek 工具任务采用显式非思考兼容请求（OpenAI SDK 的 extra_body.thinking.type=disabled），只作用于该任务，不改生产 profile 或其他供应商；状态与输入签名记录实际模式。如果以后要保留思考模式，必须另验完整 reasoning_content 回传和不指定函数的有界收敛策略，不能偷偷绕过提交校验。初译/单段基线/润色应在相同实际模式下比较；本轮初译默认思考、润色非思考的结果只能证明原型兼容，不能隔离出两段式质量增益。

质量判据补充：原文的判断不确定性、传闻归因、称呼对象身份必须保留；说话人线索不能自动当成被称呼人的性别。已观察到「不能断言没事」被润色为「说不出口」，应作为退化样本留存，不把所有改写都算优化。

### 4.4 主线程整章提交与版本

候选未提交前不修改工程。主线程先让当前编辑会话落账、同步当前页，再核对请求快照。原文、块身份/顺序、最终译文或 rich_text 已变化的块列为冲突，保留人工结果；其他合格块仍可写入，报告缺失和冲突。

走 `ui/batch_ops.py::BatchOperation` 版本外壳，遵循其前置同步 → 数据替换 → 页代数 → 当前页重建顺序：

1. 从**提交时的当前块列表** deepcopy，只改通过核对的目标块文本；保持期间修改的字体、位置和其他样式，不用请求前旧副本整体覆盖。
2. 写最终译文，同时清旧 rich_text；运行最终稿后处理、竖排数字组合及所需排版，见 §4.5。
3. 批量写回完成页代数与当前页视觉重建；显式作废涉及页文本历史，不能在新数据写入后再用旧 UI 内容反向同步覆盖。
4. 页级待浏览状态与本轮结果记录纳入同一次最终保存；版本必须能恢复这些状态。快照失败不得写入。
5. 整章有限次失败回退也经相同提交检查，不能绕过人工编辑保护。

`ui/batch_ops.py::BatchOperation.apply` 返回 started 只说明已开始写入，不保证写回验证和保存全部成功；检查 writeback.verified、error 与最终保存结果。它不是异常自动回滚的数据库事务：保存失败保留版本并报告，不发整体成功。

`ui/mainwindow.py::_sync_and_commit_project` 当前捕获保存异常后仅记日志；作为批量 commit 回调时不能据「没有抛异常」认定保存成功。两段式提交适配需提供明确成功/失败结果，或先同步再使用可传播错误的项目保存调用，确保失败不被外壳误报成功。

`utils/batch_versions.py::restore_latest` 恢复整项目快照，不是只改某章。批量版本回滚可能撤掉后续人工编辑，也不会自动把草稿拷成最终稿；**不能替代「切回直出稿」**。v1 保留单块回直出，整页下一优先级，整章专用否决暂缓。章数较多时记录快照体积与耗时，再决定是否需要优化，先不另建备份机制。

### 4.5 最终渲染、保存与浏览

初译阶段保留草稿与修复图，不调用原有「译完就嵌字并导出」链路去处理空/旧最终稿。需要拆分 `ui/mainwindow.py::on_pagtrans_finished` 中的一次性样式初始化和最终文本处理，避免最终提交重跑样式覆盖、字号扣减等非幂等步骤。

最终稿写入后复用 `ui/mainwindow.py::postprocess_translations` 与竖排数字组合/排版功能，再重建场景、保存工程和结果图。`utils/proj_imgtrans.py::mark_page_needs_rerender` 仅标脏且排除当前页，不能当作已完成整章导出。当前页显式保存，非当前页经 `ui/mainwindow.py::_rerender_dirty_pages` 或相同主线程渲染流程处理；等待 `ui/io_thread.py::ImgSaveThread` 队列保存结束并检查失败，随后才发最终完成信号。

图像保存须为本轮目标页绑定成功/失败回执。现有 `ui/io_thread.py::on_exec_failed` 会移除失败项，故队列空/线程退出不等于保存成功；旧结果文件存在也不能作为本轮保存的成功证据。

本轮组件演练还确认需要显式恢复重渲前页面：`ui/mainwindow.py::_rerender_dirty_pages` 遍历时直接更改项目当前页，末尾仅 setCurrentRow；列表行本来未变时不会触发切页信号，项目/画布可能留在最后一个重渲页。落地时恢复项目当前页、画布、文本场景、标题与列表的完整一致状态，不能只依赖选中行再次赋值。`utils/batch_versions.py::restore_latest` 自身保留调用时的当前页，不把此问题误归因于它恢复了备份页。

- 对照：`ui/scenetext_manager.py::TextPanel` 工具栏新增两字短钮，`ui/textedit_area.py::TransPairWidget` 新增第三个只读面；可见性扇出参考 `ui/textedit_area.py::setSourceVisible` / `ui/textedit_area.py::setTransVisible`。拟新增 pcfg 字段须在 `utils/config.py::ProgramConfig` 声明。使用封装输入控件，不复用可编辑译文框切换显示草稿。
- 画布始终显示最终稿，草稿对照不引起画布改稿。
- 人工进入页面后清待浏览；程序恢复项目、管线自动切页、重渲遍历/恢复和列表重建不清。用可嵌套、try/finally 恢复的程序导航上下文包住完整操作，不能只用某槽内一次性复位的布尔标志。
- 接入 `ui/mainwindow.py::pageListCurrentItemChanged` 时核对所有绕开此槽的直接 set_current_img 路径。当前页在提交时已经可见，不因此自动视为浏览；用户之后的明确进入/浏览动作才清标记。
- 角标使用现有页列表绘制模式，程序列表重建保持 blockSignals 防重入。浏览状态清除须保存，项目恢复不误清。
- 单块「切回直出稿」仅对有效草稿开放，走 `ui/textedit_commands.py::ApplyBlockTextCommand` 命令及最终文本渲染处理，不改变原文或其他块，不等同版本回滚。

## 8. 实现顺序

1. 先补自动契约：任务 ID 严格整单拒绝、finish_reason/usage 未知记录、DeepSeek per-task 模式、草稿/最终/润色视图，以及取消穿透 API 重试；同步确认流式和非流式路径。
2. 建立独立的本轮页级结算与完成屏障，覆盖 parallel / 串行 / low_vram，显式区分成功、失败、取消、暂停和线程退出；不得复用现有有歧义的整体完成判据。
3. 落地草稿字段、原文摘要、拆分后的初译签名/润色签名与恢复检查点；整本显式写入草稿目标，普通单页/单框仍写最终稿；历史和探索接入 `final`/`draft`/`polish` 视图。
4. 实现 AI 剧情划章候选、客户端章节校验与页序快照，再实现逻辑章节到预算页段的容量估算、缩段和降级报告；章节表保持无编辑器、可复用但可失效。
5. 实现风险候选筛选、章节级成本预览、用户确认/缩小/跳过，以及润色严格 ID、固定译名护栏和缺块回退直出稿；整章/全量润色必须是显式确认动作。
6. 实现主线程整章提交、版本/人工修改保护、最终文本处理、渲染保存和每页图像回执；保存失败不得发整体成功。
7. 实现暂停/恢复、阶段进度、候选对照、三态草稿面、待浏览角标、回退块待重译队列和完成报告；整章提交前显示将写入/保留人工/回退三类摘要。
8. 以固定退化样本比较单段、初译和风险润色的准确性、改动收益、耗时、请求量和 token；只有出现可复核纠错收益，才考虑扩大候选范围、启用全量默认或增加工具。

## 9. v1 范围取舍

章节表编辑入口暂不做；单框重译直接更新最终稿但不伪造新直出稿；缺有效稿块跳过并提示；保留单块回直出，整页后续优先、整章暂缓；润色默认只处理风险候选，整章/全量润色必须由用户确认；章节梗概独立处理。预算阈值、风险规则和具体轮数通过实测回填，不将一次小样本结果写成普遍质量承诺。

## 10. 验证方案与结果登记

用户授权用 `scripts/mw_repro.py` 的 MainWindow 演练台合成工程，并调用配置中已有的 DeepSeek 接口。验证者只编写隔离临时探针/回填结果，**不实现生产功能、不修生产代码、不提交**。

### 10.1 环境与调用边界

- 从当前配置读取 DeepSeek profile，核对可用模型/端点与实际成功响应；不输出 key、完整配置或认证请求头。若默认全局 profile 与用户指定不一致，记录差异，按本次授权在隔离进程显式选择已有 DeepSeek，不改生产选择器、不回退其他供应商。
- 演练台使用独立配置副本、临时合成工程与证据目录；加载之前将配置路径指向副本，关闭最近工程/更新副作用，关闭窗口的自动保存也只能写副本。真实工程、其他运行中窗口不碰。
- 先用少量日文漫画式对话：4 页×3 块，覆盖固定人名/称呼、跨页指代、否定/数量、说话人线索、拟声及 OCR 不确定提示；空块用本地契约验证。初译、现有单段基线和润色共享原文/术语/配置，记录提示词差异，不能把三者输入差异当作单纯润色增益。
- 初轮最多 16 次真实请求（含工具/重试），每请求预留有限输出；只在明确可修正的请求问题上有限重试。记录请求数、usage、耗时、模型、端点和 profile 配置摘要；供应商未返回 usage 记未知，不估成零。无价目核验时不编造人民币费用。
- 真实窗口模式运行演练台；截图、数据/显示一致性、结果图和正常关闭作为组件证据。不可用或模型调用失败记 FAIL/BLOCKED；未实现入口记 NOT_IMPLEMENTED；假模型/离屏结果不标真机或真实 API PASS。
