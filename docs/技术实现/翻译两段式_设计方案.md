# 翻译两段式（初译 → 章级润色）设计方案

> 状态：**规划稿，未实现**。主干已与需求方对齐，本文档供交叉复核；复核重点与开放问题见 §9。
> 前置阅读：`docs/技术实现/翻译agent化_设计方案.md`（现有单段 agent 翻译的设计与护栏）。

## 1. 背景与动机

现有 LLM 翻译是单段式：一次 agent 任务里，模型同时承担「守硬约束」（术语表、指示标签、id 对应——由校验器强制）与「追软目标」（流畅、传神——只能靠提示词）。同时 OCR 错漏会污染原文理解，而模型收不到任何图像信息。上下文越大越容易出错，把术语表、原文、风格要求一次性塞进一个任务里要求"信达雅"不现实。

本方案把质量工作拆成两段，各自收窄目标：

- **初译**：只求准确——术语对、指示标签遵守、id 对应；产物称**直出稿**。
- **章级润色**：拿到术语已锁定的直出稿后只做语言层润色（连贯、语气、简洁），并整章统一（人名、称呼一致）。

人工介入收敛为一次浏览：润色稿写入后逐页挂「待审查」，用户浏览页面（顺带调整排版样式）即视为接受——译文审查与样式调整共用同一次走查。

## 2. 链路总览

```text
逐页初译（modules/translators/trans_agent.py::AgentTranslator 页任务，
          写 translation_draft，不写 translation）
        │ 全部页初译完成
        ▼
章节划分轻任务（单轮直出，产出章节表：章节名 + 有序页名区间）
        │ 逐章
        ▼
章级润色（run_agent_task 独立任务；输入 = 全章 (原文, 直出稿) 对）
        │ 校验复用 + 雷同检测
        ▼
整章一次性写入（translation = 润色稿，清 rich_text）
        + 整章重渲标记 + 挂页级待审查
        │
        ▼
人工逐页浏览（切页即清除待审查；可单块否决切回直出稿）
```

失败语义：润色失败／超限／取消 → 回退以直出稿落盘（`translation = translation_draft`）并照常挂待审查，**不整页报废**——与现有 agent 失败→直译补漏的回退链同构。章节划分失败 → 全项目视为单章，退化不阻塞。

## 3. 数据模型

### 3.1 直出稿字段

`utils/textblock.py::TextBlock` 新增持久化字段 `translation_draft: str = ""`。

- 序列化零改动：`to_dict` 为 `vars(self)` 全量导出，带默认值新字段自动随工程 JSON 落盘；旧工程缺键由 dataclass 默认值兜底（`rich_text`、`tags` 等字段为同批先例）。
- 语义：`translation_draft` 恒为初译产物；`translation` 恒为最终呈现（润色稿，或回退时的直出稿）。
- 消费面已核：画布、面板、撤销、批量合并、紧凑索引、txt 导出等全部按名访问 `blk.translation`，不受新字段影响。

### 3.2 章节表

工程顶层键 `chapter_table`：有序列表 `[{name, pages: [页名…]}, …]`，覆盖全部页（用页名不用页号，页序变动时稳定）。存放照 `llm_compact_memory`（剧情梗概）三件套先例：`utils/proj_imgtrans.py::ProjImgTrans` 内存属性 + `load_from_dict` 用 `.get()` 容错 + `to_dict` 按需写键。

### 3.3 页级待审查标识

持久状态，存 `ProjImgTrans._image_info[页名]`（随工程落盘）：`review_pending: true`。与块级 `trans_review_pending` 分层：页级答"人看没看过"，块级答"这里有什么具体问题"。

## 4. 各环节设计

### 4.1 初译（改造点：写入目标）

`modules/translators/base.py::translate_textblk_lst` 的写回目标参数化：AgentTranslator 路径写 `translation_draft`；**非 agent 翻译器行为不变**（直写 `translation`，无润色概念，两段式整体跳过）。

OCR 不确定提示：人工校对阶段对无法确定的块挂 `utils/block_tags.py::OCR_REVIEW_ID`（「稍后校对」，人工打标唯一写入点 `utils/block_tags.py::set_manual_tag` 已支持）；在 `utils/block_tags.py::DIRECTIVE_INSTRUCTIONS` 表新增 OCR_REVIEW_ID 条目（"原文可能不准确，可结合上下文做有依据的推测性翻译"）。初译与单框重译两条通道经 `utils/block_tags.py::directive_instructions` 自动带上同一提示，零新机制；该表同时被框级动作载荷组装（`ui/mainwindow.py`）消费，行为自动一致。**数据源是人工判断**，不依赖 onnx 低置信自动挂标（`ocr_low_conf` 仅作参考）。

### 4.2 章节划分轻任务

全项目初译完成后，在收尾处做**单轮直出**调用：不走 agent 循环（无探索工具、无 submit 协议），一次 chat + JSON 解析即可；输入页索引 + 每页原文抽样，输出章节表。精度要求低。客户端构造复用 `modules/translators/trans_agent.py::AgentTranslator` 的 key 选择与初始化。

### 4.3 章级润色

- **任务形态**：直接调用 `modules/translators/agent/loop.py::run_agent_task`——无状态状态机、纯参数注入（`tests/test_agent_translator.py` 已有假 chat 驱动先例）。**不要**走 AgentTranslator 的同名私有包装 `_run_agent_task`：它的 system/user 组装硬编码了逐页翻译语义。chat 复用 AgentTranslator 实例的 `_agent_chat`（client/key/限流/token 计数全套现成）。
- **输入**：全章 (原文, 直出稿) 对 + 命中术语表；system 定位为「审校/润色」persona，与初译分离（缓解同模型自审放行）。剧情梗概按现有 `build_system_message` 通道注入。
- **提交协议**：沿用 `submit_translations` 形状，`valid_ids` 传全章块 id 集；`modules/translators/agent/validator.py::validate_submission` 复用（术语残留、译文=原文、「先警告后打回」状态机免费获得）。
- **新增雷同检测**：润色稿与直出稿做 diff（difflib 相似度），超阈值在提交反馈中**警告标记**（不打回）——润色者维持原稿是合法输出。
- **工具与预算**：保留只读探索组 + `search_glossary`（一致性修复需要查别页译名）；轮数上限取小值（参数化，默认 4～6），独立 token 预算。
- **挂点**：`AgentTranslator.finalize()`——管线收尾统一调用的残留钩子（当前无任何翻译器实现它），天然覆盖 parallel／串行／low_vram 三条路径，且不触发单框／单页模式。时点在修复（inpaint）与逐页嵌字之后，润色写入后整章重渲（见 4.4）。

### 4.4 整章写入

走 `ui/batch_ops.py::BatchOperation` 事务外壳（同构先例：全局替换 `ui/textedit_commands.py::GlobalReplaceApplier`）：

1. 构造 deepcopy 的新块列表（批量写回是整列表替换，不能就地改旧对象）；
2. 写 `translation`（润色稿）+ **同步清 `rich_text`**——画布渲染 rich_text 优先于 translation，不清则画布仍显示旧稿（`ui/textedit_commands.py::ApplyBlockTextCommand` 已有同款做法）；
3. `bump_page_generation` + `mark_page_needs_rerender`（`utils/proj_imgtrans.py::ProjImgTrans` 现成机制）触发整章重渲；
4. 对涉及页做文本历史失效（管线整页写入先例同款）；
5. 各页挂 `review_pending` 待审查标识；
6. 撤销走 `utils/batch_versions.py` 版本快照（批量操作唯一撤销路径，与画布撤销栈分治；回滚 UI 流程照现有批量回滚先例）。

### 4.5 人工审查浏览

- **直出/润色对照**：文本面板（`ui/scenetext_manager.py::TextPanel` 的 textToolBar）在「原文/译文」两个 `ui/custom_widget/label.py::TextCheckerLabel` 旁新增第三个切换钮（pcfg 持久键），控制面板侧**第三个只读显示面**（TransPairWidget 内新增只读控件；可见性扇出仿 `ui/textedit_area.py::TextEditListScrollArea` 的 setSourceVisible/setTransVisible 模式新增一个方法）。**禁止**复用译文框换内容显示直出稿——落账与撤销重放会把显示值当数据写回。按钮文案取两字短词，防 360px 定宽溢出。
- **画布不跟渲**：画布始终渲染最终写入稿，对照只在面板侧。
- **切页即清除**：挂 `ui/mainwindow.py::pageListCurrentItemChanged`——全部切页入口的唯一收敛点（列表点选、画布翻页快捷键、工作台/搜索跳页都经它），`set_current_img` 之后清除该页待审查标识并刷新角标。
- **人工/程序切页区分**：程序性切页（打开项目恢复上次页、批量操作后恢复原页）会走同一槽，不得视为"用户已浏览"。加程序性切换标志位：程序性切页前置位、槽内检查后复位（Qt 惯用手法）。
- **角标**：页列表现成画点先例（绿点/橙点占右上、右下），待审查用左上角新色点，配色缓存仿现有静态缓存模式。
- **否决动作（v1）**：单块「切回直出稿」——把 `translation_draft` 拷入 `translation`（走单块命令，连带清 `rich_text`）；整页/整章否决见开放问题。

## 5. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 初译产物直写 `translation_draft` 字段（修订讨论原案"内存暂存"） | 序列化自动、崩溃可恢复、免维护暂存结构；对照显示本就需要持久直出稿 |
| D2 | 润色前 `translation` 保持旧值/空，整章写一次 | 一次撤销、一次渲染、一次保存语义；避开"用户看到一半初译稿又变润色稿" |
| D3 | 润色挂点选 `finalize()` | 三条翻译路径统一覆盖；多点插入易漏；嵌字后才润色可接受（整章重渲机制现成） |
| D4 | 章节划分独立轻任务，不由初译任务顺手产出 | 初译是页粒度任务、无跨页会话，各自报章节边界必打架 |
| D5 | 待审查清除区分人工/程序切页（已拍板：有必要） | 程序性切页（恢复原页等）不应视为"用户已浏览" |
| D6 | OCR 不确定 = 人工打标 `ocr_review_pending`，不依赖模型置信度（已拍板） | 需求方工作流是翻译前人工过一遍检查纠错；onnx 自动标仅作参考 |
| D7 | 润白润检测 = 简单 diff 阈值 + 警告标记，不打回（已拍板） | 暂无成熟的质量评价思路，先落最低限度护栏 |
| D8 | 直出对照做面板第三显示面，画布不跟渲 | 复用译文框会被落账/撤销污染；画布重渲成本高且无必要 |

## 6. 已知坑与约束（实现时必读）

1. **rich_text 优先**：任何写 `translation` 的路径必须同步清 `rich_text`。
2. **上游契约漂移巡检**：TextBlock 新增字段会触发 `scripts/check_upstream_drift.py` 报漂移，需 `--update-baseline` 更新基线。
3. **页列表重入**：页列表全量重建内部 setCurrentItem 会重入切页链，标识刷新须沿用现有 blockSignals 手法。
4. **初译阶段逐页收尾回调**：现有"每页译完即嵌字+存盘"回调链在 `translation` 为空时的行为需要确认/守卫；初译阶段照旧出无字中间图、润色后整章重渲覆盖，改动面最小。
5. **死副本**：`ui/text_engine/editing/widgets.py` 有一份同名 `TextEditListScrollArea`（全仓无导入者），改显隐扇出时别打错文件。
6. **LLM OCR 无低置信信号**：`modules/ocr/ocr_vl_manga.py` 明确不挂 `ocr_low_conf`——D6 已把数据源定为人工打标，此局限不构成缺口。
7. 新增 pcfg 键须声明到 `utils/config.py::ProgramConfig`，否则运行时 AttributeError。

## 7. 可行性调研结论（摘要）

两轮只读调研结论：全链路无阻塞性障碍。直接复用——`run_agent_task` 独立调用、`validate_submission`（纯函数 + 参数化 id 集）、章节表存放（`llm_compact_memory` 三件套先例）、TextBlock 序列化（`vars` 全量导出 + 默认值兜底）、页角标画点、切页收敛槽、`BatchOperation` 写入外壳、tag 徽标。需改造——初译写回契约（§4.1）、finalize 挂点（§4.3）、面板第三显示面（§4.5）、雷同检测（§4.3）。

## 8. 实现顺序建议

1. TextBlock `translation_draft` 字段 + 漂移基线更新
2. 初译写回契约参数化 + `DIRECTIVE_INSTRUCTIONS` 新条目
3. `finalize` 挂点：章节划分轻任务 + 章节表存取
4. 章级润色任务（validator 复用 + 雷同检测）+ 整章写入外壳
5. 页级待审查 + 角标 + 切页清除（含人工/程序区分）
6. 面板第三显示面 + 切换钮 + 单块切回直出

## 9. 开放问题（复核重点）

1. **章节表的编辑入口**：v1 是否需要 UI，还是先只读展示/靠重跑轻任务覆盖？
2. **单框重译与两段式的交互**：润色后单框重译（现有 `translate_with_context` 通道）的产物直接写 `translation`（跳过草稿态）是否可接受？
3. **混合状态边界**：章内部分块无直出稿（如中途清空重翻）时，润色按缺块跳过还是整章降级？
4. **否决粒度**：整页/整章「切回直出稿」要不要 v1 就做（批量版本回滚可部分替代）？
5. **润色轮探索工具取舍**：全保留（成本高）还是只留 `search_glossary`（一致性修复可能不够用）？
6. **章节化梗概**：翻译注入的剧情梗概从"全项目一条"改为"当前章 + 前章一句话"是否随本方案做（可独立成篇）？
