## 一、背景与设计目标

### 1.1 背景

上游 v1.5.9 对文本引擎做了大重构：将原本单个 ~1500 行的 `TextBlkItem` 拆分为
`ui/text_engine/` 包（约 7000+ 行新代码），新增**可组合变换栈**
（Projective / Bend / Sine / Grid 四种全局变换 + Glyph Slant 字形倾斜），
并配套 4478 行测试（`tests/test_text_transform_undo.py`）。

本 fork 的基点（2026-05-06）早于这次重构两个多月，本地仍是旧架构
（`ui/textitem.py` + `ui/scene_textlayout.py` + `ui/texteditshapecontrol.py`）。

### 1.2 设计目标声明（2026-08-03 确定）

1. **底层架构尽可能跟进上游**，与上游保持同步以便参考和移植。
   差异越大，后续移植包袱越重；本 fork 的开发完全依赖 AI 协作，
   设计考虑必然不如上游作者全面，故不轻易偏离上游的底层设计决策。
2. **对代码量不敏感**。只要没有明显影响性能的功能项，不因"代码多"砍功能。
3. **上游的 UI 排布与交互方式不照搬**。高级样式功能（文本变换）是要做的，
   底层代码支持需要跟上，但 UI/交互按本 fork 的习惯自主设计
   （详见[第七章 设计边界声明](#七设计边界声明照搬与自研)）。
4. 减法原则仍然生效，但只作用于**交互路径与 UI 呈现**，不作用于底层能力。

### 1.3 与既有调研文档的关系

- `docs/技术实现/排版技术.md` 第三节记录了 PR#1238 早期版本（四个独立变换字段：
  hs/vs/box slant/glyph slant）的调研，当时决定"暂搁置"。

## 二、上游 v1.5.9 文本引擎架构总览

### 2.1 文件地图（上游路径 → 本地对应/未来落点）

| 上游 v1.5.9 路径 | 职责 | 本地现状 |
|---|---|---|
| `utils/textblock.py` | `TextBlock` 模型（逻辑矩形/角度/元数据） | `utils/textblock.py`（基本一致） |
| `utils/fontformat.py` | `FontFormat` 持久化排版 + `TextTransform` 类族 | `utils/fontformat.py`（缺变换字段） |
| `ui/text_engine/item.py` | `TextBlkItem`：薄 Qt 集成层 | `ui/textitem.py`（单体大杂烩） |
| `ui/text_engine/layout.py` | `SceneTextLayout` 水平/垂直布局 | `ui/scene_textlayout.py` |
| `ui/text_engine/geometry.py` | **`TextItemGeometryController`：几何/变换唯一所有者** | 无（逻辑在 textitem.py 内） |
| `ui/text_engine/effect_renderer.py` + `rendering/` | 描边/阴影/渐变/栅格化 | `ui/text_graphical_effect.py` 等 |
| `ui/text_engine/shape_control.py` | resize/旋转手柄 | `ui/texteditshapecontrol.py` |
| `ui/text_engine/transforms/` | 变换数学、编译、面板、控制手柄 | 无 |
| `ui/text_engine/editing/` | 场景项管理、undo 命令 | `ui/scenetext_manager.py`、`ui/textedit_commands.py` |

### 2.2 系统分层

```text
Project JSON
  -> TextBlock + FontFormat                持久化状态（模型）
  -> TextBlkItem + QTextDocument           实时编辑状态
  -> SceneTextLayout                       水平/垂直排版
  -> TextEffectRenderer                    填充/描边/阴影/渐变
  -> TextItemGeometryController            边界与视觉映射（变换承载）
  -> QGraphicsScene                        交互/视图/导出
```

**核心原则：`TextBlkItem` 只是 Qt 面向集成点，不是各子系统的所有者。**
Qt 虚方法与信号留在 item，但布局/效果/几何/变换各自有明确 owner；
新增变换变体禁止在 `TextBlkItem` / controller 里加类型分支。

### 2.3 三层状态边界（必须严格遵守）

| 层 | 内容 | 规则 |
|---|---|---|
| 持久模型状态 | `TextBlock` + `FontFormat`（含变换栈） | 项目 JSON 只存这个 |
| 实时编辑状态 | `QTextDocument`、光标、选区、IME | 只活在运行时 |
| 派生状态 | 布局记录、effect padding、映射、pixmap、缓存 | **永不持久化** |

- `TextBlkItem.initTextBlock()` 是唯一真实构造路径。
- 页面切换/保存/undo 前必须 resolve 未决编辑与预览。
- effect padding 是派生布局状态，**不得产生 QTextDocument undo 步**。
- 永不要把视觉 bounding box 写回逻辑模型矩形。

### 2.4 坐标空间（跨 owner 时必须声明）

| 空间 | 含义 |
|---|---|
| Project/page | 页面上持久化的块矩形 |
| Item-local logical | 变换/效果之前的文本框（无 padding） |
| Item-local source | 绘制表面（含 effect padding） |
| Item-local visual | 施加视觉映射后的结果 |
| Parent/scene | 位置、旋转、父项变换 |
| Device | 视图缩放、设备比例、导出变换 |

持久化的逻辑矩形**不含** effect padding；source 矩形含 padding。

## 三、核心机制详解（承载复杂变换而不出问题的关键）

### 3.1 `TextItemGeometryController` — 几何唯一所有者（geometry.py）

每个 `TextBlkItem`（包括中性态）拥有一个 controller，独占：

| 状态 | 说明 |
|---|---|
| `display_rect` / `source_rect` | 含 padding 的绘制表面 |
| `logical_rect()` | 逻辑矩形（= unpad(source_rect)） |
| `compiled` | `CompiledTextTransform`（native 矩阵 或 表面映射器） |
| `visual_mapper` | 非线性变换复合映射器（None = 无非线性变换） |
| `surface_renderer` | 非线性表面 warp 渲染器（懒创建） |
| `preview` | 拖拽预览态（TextTransformState），commit 前不落模型 |
| 输入映射状态 | `begin_input_mapping` / `end_input_mapping` + `_input_previous_source` |

关键方法：

- `set_rect()` / `resize()`：逻辑几何入口；`_resize_standard`（原生路径）与
  `_resize_transformed`（变换路径）分派。
- `refresh_compiled_geometry(force)`：按输入 key（栈+方向+logical/source rect）
  编译或复用；**幂等**，settle 后 `flush_deferred_compilation()` 通知覆盖层。
- `paint_item()`：原生路径直接委托 effect renderer；非线性路径走表面 warp。
- `item_change()`：捕获 Qt `ItemRotationHasChanged` / `ItemTransformOriginPointHasChanged`，
  用 `update_transaction()` 批量重装补偿矩阵——这就是"旋转+变换不打架"的机制。
- `release_render_resources()`：页边界释放全部 item 缓存。

### 3.2 变换模型 — 冻结的规范值（utils/fontformat.py）

```python
@dataclass(frozen=True)
class TextTransform:
    transform_type: str
    is_nonlinear: ClassVar[bool] = False   # QTransform 无法表达 → True
    def normalized(self) -> TextTransform: ...   # clamp + round 到规范值
    def is_neutral(self) -> bool: ...            # 精确中性判定
    def with_value(self, name, value): ...       # 改单字段并重新规范化
```

- **变体**（`TEXT_TRANSFORM_TYPES` 注册表）：
  | 类型 | 字段 | 非线性 |
  |---|---|---|
  | `projective` | hs/vs 缩放、水平/垂直 slant、绕 X/Y/Z 旋转、perspective | 否（编译为单个 QTransform） |
  | `bend` | 有符号圆弧弯曲 | 是 |
  | `sine` | x/y 频率（整数 0–64）、相位、振幅（0–1） | 是 |
  | `grid` | 归一化控制点 + 1–32 网格划分 + bilinear/catmull_rom 插值 | 是 |
- `TextTransformStack`：不可变有序元组；**neutral 条目保留在模型中但运行时跳过**；
  `has_nonlinear` 属性。
- `TextTransformState` = stack + `glyph_slant_angle`：一次 undo 操作捕获完整可见状态。
- `normalize_text_transform_value(v, min, max)`：有限性校验 + clamp + round(6)，
  模型/UI/undo/持久化共用这一个规范函数。
- 持久化格式（JSON，只存规范值，不存矩阵/映射/缓存）：
  ```json
  {
    "text_transform": [
      {"transform_type": "projective", "horizontal_scale": 1.1,
       "rotation_x": 15.0, "perspective": 0.4},
      {"transform_type": "bend", "bend": 0.35}
    ],
    "glyph_slant_angle": 10.0
  }
  ```
- 容错策略：被动加载时非法条目**逐个丢弃并告警**（部分保留非全丢弃），
  与我们的项目加载容错策略一致；`coerce_text_transform` 对非规范值抛错。

### 3.3 编译管线 — 一个栈编译成一个产物（transforms/registry.py）

`compile_text_transform_stack(stack, logical_rect, source_rect, vertical)`
是唯一策略边界，按顺序：

1. 为每个活动阶段构建 context（当前 logical/source bounds + 书写方向）；
2. 调注册的 stage_factory 得到矩阵或 mapper；
3. 验证矩阵：有限性、可逆性、**透视地平线安全**（防止投影翻转）；
4. 折叠相邻矩阵阶段；
5. 仅当后续阶段需要时才推进 bounds（后阶段看到前阶段输出 bounds）。

产物只有两种：

| 情况 | 产物 | 渲染路径 |
|---|---|---|
| 纯矩阵栈（或无变换） | 折叠为单个 `QTransform` | Qt 原生，零额外开销 |
| 含任一非线性阶段 | 全部阶段进入一个 `CompositeTextTransformMapper` | 表面只 warp 一次 |

`compensated_native_transform_matrix()`：解决 Qt `QGraphicsItem` 先旋转后
transform 的顺序问题，安装 `C = R⁻¹·S·R` 使最终组合 `R·C == S·R`
（先块变换后旋转）。**中性/零旋转快速路径必须精确**——浮点残留会触发
不必要的自定义几何与缓存行为。

### 3.4 非线性渲染 — 表面捕获 + 一次 warp（geometry.py + rendering/surface.py）

`paint_item()` 的 warp 路径（`NonlinearTextSurfaceRenderer`）：

1. 把 fill/渐变/描边/阴影**全部画进一个带 padding 的源 pixmap**
   （渲染时 defer 光标绘制，记录光标位置）；
2. 源像素转**预乘 alpha**（防止透明边缘借色产生彩边）；
3. `cv2.remap` 反向采样：按 64 行 band 分块，`mapper.inverse_arrays()`
   逐块算映射坐标 + valid 掩码，无效点置 -1（透明）；插值 settle 后用
   `INTER_CUBIC`，交互预览用 `INTER_LINEAR`；
4. 完成后叠加**映射过的光标**（`RasterOp_NotDestination`，对完成后的
   目标反转，保证与文本和页面背景都形成反差）；
5. 缓存分两层：**remap 坐标缓存**（key = mapper geometry + rect + scale，
   几何变化才重算）与**表面像素缓存**（key 另含内容，文本/选区/IME
   变化只重画像素复用坐标）。

栅格分级：交互中 0.5x（预览/reshape），定格后按 1x/2x/4x/8x tier
（`plan_effect_raster` 有界分配策略）。分配失败：交互降级并告警一次，
**导出必须记录错误而非静默缺字**（`EffectRasterAllocationError` 跨 Qt
paint 回调捕获）。

### 3.5 交互不变量（"不出问题"的细节所在）

1. **单一映射边界**：paint、轮廓、命中测试、光标、resize 全部走同一个
   mapper 的 forward / inverse。Qt text control 仍是唯一编辑器，
   视觉输入经 `layout.input_point_mapper` 反映射到源布局坐标，
   **不实现第二套文本编辑器**。
2. **`previous_source` 分支连续性**：非线性逆映射是多值的，
   `inverse_point(point, previous_source)` 用上一帧源坐标保证连续，
   防止光标/命中在分支间跳变。拖拽期间由 `begin_input_mapping()` 保持。
3. **resize 用冻结坐标系**：`beginResize()` 冻结拖拽起始的
   scene↔source 映射与锚点；每帧从初始矩形推导，不用"被上一帧改动过的
   几何"映射本帧（否则反馈崩溃）。只有 reshape 映射用 `extrapolate=True`。
4. **全量 update**：非线性 warp 下 Qt 只失效源局部脏矩形，而选区/光标
   可能被移到脏区外，因此编辑变化请求 `TextBlkItem.update()` 全量刷新。
5. **光标探测**：编辑中缓存命中时用 0 透明度 `base_paint` 探测一遍，
   维持 Qt 原生光标闪烁可见性。
6. **多选 undo**：一次用户动作 = 一条 `SetTextTransformCommand`，携带所有
   目标的完整 before/after `TextTransformState`；命令只拥有变换状态与
   覆盖层刷新，不消费 `QTextDocument` 历史。

### 3.6 效果渲染与 Glyph Slant

- `TextEffectRenderer` 独占描边/阴影/渐变及其 padding；
  padding 变化保持逻辑矩形不变，只刷新源表面与映射。
- Glyph Slant 是**栈前排版效果**（在 fill/stroke 之前逐字形绕基线倾斜），
  不可重排、不入栈。固定顺序：
  `Qt shaping → Glyph Slant → fill/stroke/shadow → 全局栈`。
- 变回中性态是生命周期对称操作：恢复原生效果、清变换表面、释放专用 owner。

### 3.7 缓存与性能纪律

- 编译缓存按 `_compiled_input_key`（栈+方向+两个 rect）复用。
- 富文本编辑产生多个中间尺寸 → `is_formatting` 期间 `_compile_deferred`，
  编辑块 settle 后编译一次（`flush_deferred_compilation`）。
- 所有缓存 bounded（数量+内存）、按 owner 命名空间、页边界可释放；
  交互期间不保留最终表面缓存。
- Grid 变换：控制点存**归一化坐标**，字体/框/方向变化后重编译而非粘旧像素；
  密集 Newton 逆映射用 Numba 内核（异步 warm-up，失败回退 NumPy，
  Qt 线程永不等待编译）。签名缓存存 `.btrans_cache/numba`，跨应用更新存活。

4. **`punctuation_position` 默认 Simplified**（中）：移植后默认值必须保持（5.1.2）。
5. **两套缓存并存期**（中）：`_full_pixmap` 在阶段 2 验收后立即废弃（见 §八.8）。

7. **上游带回已删命令**（低）：`AutoLayoutCommand`/`ffmt_change_angle`（5.2 #11）。
