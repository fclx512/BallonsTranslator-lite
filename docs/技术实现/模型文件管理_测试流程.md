# 模型文件管理 测试流程

> 状态：已落地（2026-09-20）。机制设计见 `docs/技术实现/模型文件管理_设计方案.md`，
> 首个客户的模型细节见 `docs/技术实现/paddle-ocr-for-manga_接入调研.md`。
>
> 分四层，前两层随时可跑、后两层按需跑：
>
> | 层 | 内容 | 耗时 | 需要什么 |
> | --- | --- | --- | --- |
> | 1 自动 | 单测（`tests/test_model_files.py`、`tests/test_model_downloads.py`） | 秒级 | 无 |
> | 2 静态 | `scripts/verify.py` 七步 | 秒级 | 无 |
> | 3 机制手工 | 用三个既有小权重走一遍下载／取消／删除 | 十分钟 | 网络（可只验删除） |
> | 4 客户接入 | `paddleocr_vl_manga` 端到端 | 一小时 | 1.9GB 下载 + GPU |

## 0. 前置

- 用**仓库自带解释器**：`ballontrans_pylibs_win\python.exe`（单测要 import 本仓引擎，
  系统 Python 里没有 cv2/torch/qtpy）。
- 所有命令在仓库根目录执行。
- 手工验收**必须在窗口模式**下跑：离屏平台（`QT_QPA_PLATFORM=offscreen`）没有可用字体、
  也拉不起 `FramelessWindow`，界面手感类结论一律无效。
- 手工验收的样本用三个既有小权重，装删成本低：
  `ysgyolo`（15MB）、`ppocrv6_onnx`（检测 59MB + 识别 73MB）、`lama_large_512px`（195MB）。
  它们的落盘路径与体积可在设置页 Models →「模型文件」直接读到。

## 1. 自动层：单测

```
ballontrans_pylibs_win\python.exe -m pytest tests/test_model_files.py tests/test_model_downloads.py -q
```

期望：`59 passed`（2026-09-20 实测；两个文件独立可跑）。

| 文件 | 覆盖 | 钉住的关键判据 |
| --- | --- | --- |
| `tests/test_model_files.py` | `utils/model_files.py` 的落盘判据、体积与释放，「模型文件」节的卡片行构建，以及 `RowTable` 卡片模式的列宽与就地更新 | 删除白名单只认声明路径；被 git 跟踪的字典文件永不删；目录拒删；空目录收尾不越过 `data/models`；**Shell 返回码不当成功判据**；Shell 调不通时绝不退化为永久删除；卡片模式的列宽规则在构造时就生效（否则单列被压成窄条）；`update_row` 不重置勾选 |
| `tests/test_model_downloads.py` | 后台任务层、加载期行为、惰性元数据扫描 | `background_download_only` 置位的模块加载期**不下载**且抛 `MissingModelFilesError`；未置位的模块行为不变；`_ensure_module_deps` 恒返回真且起任务；注册表防重复／可取消／结束摘除／失败只告知一次；新模块的 `background_download_only` / `model_package` / `requires_packages` / 15 条落盘路径**能被静态扫到** |

两条纪律，改测试时别破：

1. **不碰网络**。下载器（`utils/download_util.py::download_and_check_files`）与线程启动
   都被替身挡掉；把替身去掉就会真去下 1.9GB。
2. **不送回收站**。删除用例一律走 `use_trash=False`；回收站只在
   `utils/model_files.py::trash_available` 上做可用性探测，真送回收站属于第 3 层人工验收。

## 3. 机制手工验收（不需要大模型）

把要测的权重先**挪走**（改名即可，别删），让模块处于「缺文件」态；验收完挪回来。

「模型文件」节是**勾选 + 下方动作行**：先在卡片列表里勾中要处理的模型，再点下方
`Download` / `Cancel` / `Delete` / `Open folder`。所以下面凡提到「动作」都先勾行。

| # | 操作 | 期望 | 看哪儿 |
| --- | --- | --- | --- |
| M1 | 底部栏把某阶段选成缺文件的模块 | **不弹任何确认窗**，模块照常切换；终端出现 `Start background download for …` 与 tqdm 进度条 | 终端、`logs/` |
| M2 | 下载期间继续用界面（翻页、拖画布、改设置） | 界面不卡、不锁 | 手感 |
| M3 | 设置页 Models →「模型文件」，看那一行 | 该行徽章显示下载百分比（`Downloading…` → `n%`）；勾选后动作行的 `Cancel` 出现 | Models 页 |
| M4 | 勾选该行后点 `Cancel` | 秒级停下；**已下完的文件保留**，未写完的 `.partial` 临时文件消失；徽章回到「Missing n」 | 终端、目录 |
| M5 | 缺文件时直接跑管线 | 弹「Missing Model Files」，文案指路 Models →「模型文件」；Cancel 可中止 | 运行对话框 |
| M6 | 缺文件时选用该模块（不跑管线，让它在加载期加载，例如关掉按需加载） | 弹窗含模块名与「去设置页下载」的指引，而不是底层路径报错 | 主窗 |
| M7 | 装好文件后勾选该行点 `Delete` | 确认框列出**待删文件与总体积**，并写明「可从回收站还原」 | 确认框 |
| M8 | 确认删除 | 文件进回收站；徽章变「Missing n」；**底部栏与运行对话框的下拉里该模块变琥珀色**；声明过的包目录若空了会被清掉，`data/models/` 本身不动 | 资源管理器、界面 |
| M9 | 去回收站还原刚才的文件 | 能还原；回 Models 页重进（`showEvent` 会重算）后徽章变「Ready」 | 资源管理器 |
| M10 | `Open folder` | 勾 **1** 行时可用并打开该包目录（未创建则先建后开）；文件型包（`ysgyolo`、`lama_large_512px`）打开 `data/models/`；勾 0 行或 ≥2 行时禁用 | 资源管理器 |
| M11 | 下载进行中直接关窗 | 立刻退出，终端不出现 `QThread: Destroyed while thread is still running` | 终端 |

M8 的琥珀色联动同时覆盖两条接线：`ui/mainwindow.py::MainWindow` 的
`refresh_module_selector_status`（底部栏）与 `ui/run_pipeline_dialog.py` 的
`RunPipelineDialog` 同名方法（运行对话框）。

### 回收站判据的实测背景（改删除逻辑前必读）

`SHFileOperation` 的**返回码在本机完全不可信**。同一批文件实测：

| 标志 | 返回码 | `fAnyOperationsAborted` | 文件实际去向 |
| --- | --- | --- | --- |
| 无 | 0 | False | 回收站 |
| 仅 `FOF_ALLOWUNDO` | 1223 | **True** | 回收站 |
| `+ FOF_SILENT` | 2 | False | 回收站 |
| `+ FOF_NOERRORUI` | 2 | False | 回收站 |

所以 `utils/model_files.py::delete_paths` 一律**以调用后 `osp.exists` 判定成败**，
返回码只当诊断信息记进日志；`fAnyOperationsAborted` 也不采信。验证「到底进没进回收站」
不要看返回码，去看 `D:\$Recycle.Bin\<SID>\` 下的 `$I*` 元数据文件（UTF-16，内含原始路径）。

## 4. 首次客户接入验收（`paddleocr_vl_manga`）

依赖与权重两条路都要走通，别只验一条。

### S1 依赖

选一次 `paddleocr_vl_manga` 即会后台安装 `transformers>=4.57.1,<5`（终端可见 pip 日志）。
也可手工前置：`ballontrans_pylibs_win\python.exe -m pip install "transformers>=4.57.1,<5"`。
装上后在 Models →「模型文件」该行状态应不再是「所需依赖包未安装」。

### S2 权重（两通道）

- **自动通道**：Models 页点「下载」。国内网络先在「设置 → 网络与镜像设置」里一键国内镜像
  （`hf_endpoint = https://hf-mirror.com`）。共 15 个文件约 1.9GB，大头是 `model.safetensors`。
- **手工通道**：点「打开目录」把文件放进去（期望清单就在同一行），再回面板刷新核对
  「缺 N 个文件」是否归零。

### S3 最小自测脚本（脱离应用，先证模型本身可用）

模型与 processor 都从本地目录加载；本机 `torch.cuda.is_available()` 应为真。

```python
import torch
from PIL import Image
from transformers import AutoModelForCausalLM, AutoProcessor

model = AutoModelForCausalLM.from_pretrained(
    "data/models/paddleocr_vl_manga",
    trust_remote_code=True, dtype=torch.bfloat16,
    attn_implementation="sdpa",
).to("cuda").eval()
processor = AutoProcessor.from_pretrained(
    "data/models/paddleocr_vl_manga", trust_remote_code=True, use_fast=True,
    add_prefix_space=None,   # 不可省，见下方说明
)

img = Image.open("examples/02.png").convert("RGB")
messages = [{"role": "user", "content": [
    {"type": "image", "image": img}, {"type": "text", "text": "OCR:"}]}]
text = processor.apply_chat_template(messages, tokenize=False,
                                     add_generation_prompt=True)
inputs = processor(text=[text], images=[img], return_tensors="pt")
inputs = {k: (v.to("cuda") if isinstance(v, torch.Tensor) else v)
          for k, v in inputs.items()}
with torch.inference_mode():
    out = model.generate(**inputs, max_new_tokens=256,
                         do_sample=False, use_cache=True)
print(processor.batch_decode(out[:, inputs["input_ids"].shape[1]:],
                             skip_special_tokens=True)[0])
```

**`use_cache=True` 不能省**：权重仓库的 config 与 generation_config 都写死 `false`，
不覆盖则自回归解码不走 KV cache，慢数倍。同时记下峰值显存与单块耗时，回填调研文档 §3。

**`add_prefix_space=None` 也不能省**（2026-09-20 实测踩过）。仓库
`tokenizer_config.json` 里 `tokenizer_class: LlamaTokenizer` ＋ `add_prefix_space: false`，
而 transformers 的 `LlamaTokenizerFast.__init__` 一见到 `add_prefix_space` 非 None 就会覆写
`from_slow=True`，于是**绕开仓库自带的 `tokenizer.json`**、去构造 slow 版再转换；没装
sentencepiece 时直接抛：

```
ValueError: Cannot instantiate this tokenizer from a slow version.
If it's based on sentencepiece, make sure you have sentencepiece installed.
```

应用里表现为「跑管线时 OCR 失败」。传 `add_prefix_space=None` 抑制 `from_slow`，
直接吃 `tokenizer.json`——该文件的 `pre_tokenizer` 为空（这个字段对它本就不适用），
两条路径的 token id **逐条一致**（17/17 样本、词表 101314 全同、chat 模板 token 相同），
所以是等价做法，且不必引入 sentencepiece 依赖。复算工具：`scripts/probes/ocr_vl_tokenizer.py`。

### S3.5 真机验收探针（可选，但它把 S3/S4 的数字都测了）

```
ballontrans_pylibs_win\python.exe scripts/probes/ocr_vl_manga_accept.py
```

拿施工区副本里块数最多的一页跑：逐块识别并与项目内既有（ppocrv6 的）文本并排打印、
算字符相似度；再试一次「整页一次喂」；输出峰值显存与单块耗时，报告写
`tmp/vl_e2e_report.md`（UTF-8，别走 PowerShell 管道——控制台是 GBK）。
2026-09-20 实测结论见 `docs/技术实现/paddle-ocr-for-manga_接入调研.md` §3。

### S4 应用内对比

选 `paddleocr_vl_manga` + device=cuda 跑一页，与 `paddleocr_v6_onnx` 的原文逐块对比。
重点看**竖排块、拟声词、密集旁白**三类——这是本模块相对 onnx 系的卖点所在。
`max_new_tokens` 默认 256；密集旁白若被截断，调到 512 再看。

### S5 批量开关（默认关）

`batch_size` 默认 1。调到 2 以上时**必须逐块比对结果**：批量左 padding 与该模型 mrope
位置编码的兼容性尚未验证，批量错了是**静默出错**（拿到错文本而不是报错）。
验不过就保持 1——质量不变，只慢些。

## 5. 只能人工看的验收项

自动化覆盖不到、但会直接影响观感的几条：

1. 下载期间界面**确实**不卡（M2）——这是本轮定稿行为的第一诉求。
2. 终端进度条与日志可读（tqdm 写 stderr，`LOGGER` 双写 console 与 `logs/`）。
3. 「取消」的响应延迟（逐块检查取消标记，1.9GB 单文件也应在秒级内停）。
4. 删除确认框的文案是否够明确：列出文件、总体积、可否还原。
5. 「模型文件」节的卡片在 125% / 150% 缩放下是否还整齐。卡片是 `RowTable` 的 delegate
   自绘（按字体度量算高度与徽章让位宽度），所以缩放只改字体就够；要调的是
   `ui/model_files_panel.py` 顶部的 `_ROW_HEIGHT` / `_MAX_VISIBLE_ROWS`（列表可视行数与总高）。

## 6. 已知风险与待实测

| # | 项 | 现状 | 怎么验 |
| --- | --- | --- | --- |
| 1 | 实际速度 / 显存 | **已实测**（2026-09-20）：加载 3.8s、峰值 allocated 2.51GB / reserved 3.22GB、单块中位 192ms（首块约 0.9s）。数字见调研 §3 | 重跑 `scripts/probes/ocr_vl_manga_accept.py` |
| 2 | 竖排识别质量 | 训练集含竖排，理论可行 | S4 |
| 3 | 批量左 padding | 未验证，故默认 `batch_size=1` | S5 |
| 4 | 全半角 / 部首变体误差 | 官方自述的主要误差类型 | S4 观察；倾向交给 LLM 翻译器消化，不在此处做 NFKC 归一化 |
| 5 | HF 直连可达性 | 直连常超时、镜像可达 | S2 两条通道都走 |
| 6 | transformers 漂移 | 已 pin `>=4.57.1,<5`；**`add_prefix_space` 触发的 slow 路径依赖 transformers 内部行为** | 升级 transformers 后重跑 S3（尤其那行 processor 加载） |
| 7 | 与 onnxruntime CUDA 会话并存 | 两者峰值叠加，11.9GB 卡上仍有余量 | S4 时开着检测/修复模块一起跑，看是否 OOM |
| 8 | 取消后残留的 `.partial` | 由 `utils/download_util.py::download_url_to_file` 的 `finally` 清理 | M4 后检查目录 |
| 9 | 整页模式 | **实测不可用**：同一页 27 个块，整页一次喂只出 11 行、无坐标 ⇒ 检测必须由本项目检测器提供 | 重跑探针的 §4 段 |
| 10 | 权重更新后 tokenizer 路径 | 两条路径等价的结论建立在当前权重上 | 重跑 `scripts/probes/ocr_vl_tokenizer.py` |

## 7. 回退与清理

- **卸权重**：Models →「模型文件」→ 删除（进回收站，可还原）。手工放进去的额外文件
  不会被删——删除只针对模块声明过的落盘路径。
- **卸依赖**：`transformers` 不在 `requirements.txt` 里（模块自带 `requires_packages`），
  可 `ballontrans_pylibs_win\python.exe -m pip uninstall transformers` 单独摘掉。
- **单测残留**：`data/models/_pytest_model_files`（用例自清，异常中断时手工删）。
- **本机验收残留**：第 3 层用过的探针文件会进回收站，验收完顺手清空即可。
