## 一、问题定性（排查结论）

### 1.1 现状架构：一个文本块横跨三层撤销载体

| 层          | 载体                                                           | 写入方                                                                                                  | 回退方式                                 |
| ---------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------ |
| item 文档栈   | 每个 `TextBlkItem` 内部 QTextDocument 自带的 undo 栈                 | 画布直接键入、面板格式化（char format 类 setter 全部以文档编辑形式落盘）、镜像对账                                                  | 由命令层逐块"排水"                           |
| canvas 命令栈 | `ui/canvas.py` 的 `text_undo_stack`（QUndoStack）               | 旧版为 `ui/textedit_commands.py` 的 `TextItemEditCommand` / `TextEditCommand` 两条桥接命令（3a 已删除，改为 TypingSessionCommand/FormatGestureCommand 快照命令）/ 结构操作命令 | QUndoStack 标准撤销，04feaf8 起格式化命令由手势宏聚合 |
| panel 文档栈  | 右侧 `TransTextEdit` / `SourceTextEdit` 的 QTextDocument undo 栈 | 面板键入、画布→面板镜像同步                                                                                       | 由命令层逐块"排水"                           |

命令层的每条命令本质是**桥接**：undo 时对 item 文档与 panel 文档各调用一次文档级 `undo()`（回退一个 undo 块）。整个体系依赖一个核心假设：

> **canvas 命令 ↔ 每份文档恰好一个 undo 块，且两侧块序一致。**

所有已确认缺陷的本质都是这个假设被打破。


### 1.2 确认缺陷清单（按破坏力排序）

**① 跨事务并块（根因，已复现）**。面板连续键入被 Qt 自动合并（`old_undo_steps` 无增量 → `new_steps==0`），镜像对账 `ui/textedit_commands.py::sync_text_by_diff` 据此以 `joinPreviousEditBlock()` 把本次文本编辑**无条件并入 item 文档的最后一个 undo 块**。若最后一块是格式化事务（改字号/字重/行距/颜色等都会产生文档块），文本编辑被缝进格式块，后果三连：

- 文本撤销与格式撤销纠缠：Ctrl+Z 退字号连带退文本，或反之；
- 双文档块结构分叉（pdoc 一块、item 文档多块），命令层"各退一块"从第一步就退错内容；
- 本次键入在画布栈上**没有自己的命令**（pdoc 无新步 → `push_undo_stack` 信号不发射），物理上无法单独撤销。

该机制由 6e2e7d5（全文差异对账）引入，**早于 04feaf8**，但近期格式化相关批次让它显形。

**② 伪造计步切断手势宏（04feaf8 新增）**。镜像路径的 `ui/scenetext_manager.py::on_propagate_textitem_edit` 在对账发生变化时调用 `ui/canvas.py::push_text_command`（command=None，仅推进计数），而该入口会先触发旧版手势宏闭合（`ui/canvas.py` 的 `_close_format_gesture`，3a 已删除）。改字号后只要在面板打一个字，悬开的格式化手势宏就被无声切碎。

**③ 记账翻转（04feaf8 新增）**。`ui/scenetext_manager.py::on_push_textitem_undostack` 旧代码 `update_pushed_step=is_formatting`（键入 False、格式化 True，与"键入 = 命令(False)+伪造步(True) 各计一步"的旧约定配套）被改为键入 True、格式化 False。结果：画布键入**双计步**、格式化**零计步**，`num_pushed_textstep` 与栈位置漂移，脏状态判定（保存提示、`ui/canvas.py::text_change_unsaved`、批量替换回滚判定）失真。

**④ 次要隐患**。

- `ui/text_engine/item.py::set_cursor_cfmt` 在 `merge_char=True` 分支结束时无条件把 `block_change_signal` 复位为 False，不保存外层旧值，嵌套抑制可被打破（已由甲-2 修复）；
- **画布键入每字符独立成步（护网新发现）**：`ui/text_engine/item.py::keyPressEvent` 对每个可打印字符用 `beginEditBlock`/`endEditBlock` 包裹（ruby 插入准备），宏命令不与前命令 mergeWith——画布上键入 "AB" 产生 2 条撤销命令，与目标行为 1「连续键入聚合为一步」相悖；终局按键入会话聚合后自动解决（护网 `test_canvas_typing_aggregates_single_step` 以 xfail 锁定）；
- **Qt 合并语义实测**（护网诊断）：相邻插入恒合并——光标移动、失焦/聚焦均**不打断**；只有插入点不接前次末尾（非相邻插入）才新起撤销步。这是生产上 burst 的真实成因，也是终局键入会话「闭事务」边界的设计依据；
- 一次 `setFontSize` 产生 2~3 个文档步（实测），`num_steps` 记账松散，靠 Qt 块语义兜底；
- `ui/canvas.py::clear_undostack` 在宏合成期间清栈落在 Qt 未定义边界上（当前版本实测能兜住，但属踩线）。

### 1.3 复现证据（离线复现台）

复现台构成：offscreen 平台 + 真实 `Canvas` / `TextBlkItem` + 面板编辑器替身（复刻 `ui/textedit_area.py::handle_content_change` 的发射语义：`propagate_user_edited(joint_previous)` 与 `push_undo_stack(new_steps)`）+ 按 `on_push_textitem_undostack` / `on_push_edit_stack` 布线。序列「面板键入 A → 改字号 30 → 面板键入 B → Ctrl+Z ×3」：

| 步骤       | 期望      | 实际                                                |
| -------- | ------- | ------------------------------------------------- |
| 面板键入 A   | 栈 +1 命令 | 正常                                                |
| 改字号 30   | —       | item 文档 +2 步，宏开启                                  |
| 面板键入 B   | B 可独立撤销 | B 经 `joinPreviousEditBlock` 并入格式文档块；**栈上无 B 的命令** |
| Ctrl+Z ① | 只退 B    | 字号+B 一起退；**面板仍显示 AB（失同步开始）**                      |
| Ctrl+Z ② | 退字号     | A+B 一起退（面板侧 A+B 合并块被整体回退）                         |
| Ctrl+Z ③ | 退 A     | 落空（栈已耗尽）                                          |

纯 canvas 键入、纯面板键入、格式化宏聚合在无交错时均正常——问题只在**交错**时爆发。已验证 Qt 本身语义无问题（宏 push 调 redo、undo 逆序、合成中 clear 可自愈），病灶全部在应用层耦合。

### 1.4 根因归纳：为什么"只修 ①"走不通

pdoc 侧的 Qt 自动合并发生在过去且**无法事后拆块**（Qt 没有拆块 API）。只要命令层继续以"文档 undo 块"为排水单位、格式化继续以文档变更形式与键入共享同一文档栈，块边界错位就必然从别的缝里回来。镜像对账的 `joinPreviousEditBlock` 正是为了追平两侧块结构而生，但它追的是 pdoc 侧的合并状态、作用在 item 侧文档上，两端控制权分裂导致追平机制本身成为纠缠源。**这是支持"彻底重构"的核心论据。**

## 二、目标行为定义

1. 文本键入：连续键入聚合为一个撤销步（文本编辑器习惯）；输入停顿、失焦、选区变化、模式切换断开会话。
2. 格式化手势：一次手势（含实时预览的全部中间值）= 一个撤销步；多选块一次手势 = **一个**撤销步（PS 习惯，保住 04feaf8 的成果）。
3. 撤销/重做永不落空、永不回退错对象；任何操作序列后画布与面板文本保持一致。
4. **修改字号的实时预览保留**——重构的是提交语义（手势结束才落撤销步），不是预览本身。
5. 与批量替换快照回滚（GlobalReplaceApplier 体系）继续分治，不并入本体系。
6. 绘制栈（draw_undo_stack）本身不在本次范围；**但其命令对文本文档 undo 的跨界调用（见 4.2 普查）必须随终局改造**，属本计划范围内。
7. **预览悬开期间按 Ctrl+Z = 取消手势、恢复手势前原值**（不提交命令、不产生新撤销步）。评审补充，实现者不得自行发挥。
8. 脏状态（保存提示、`ui/canvas.py::text_change_unsaved`、批量替换回滚判定）终局一律走 `QUndoStack` 的 clean 机制（保存时 `setClean()`、判定用 `isClean()`），手工计步 `num_pushed_textstep` 随阶段 3 删除。

## 四、方向乙：彻底重构（主路线，推荐）

### 4.0 终局图景：单栈快照命令制

- item 文档与 panel 文档一律 `setUndoRedoEnabled(False)`——文档不再私藏撤销历史，三层栈**收敛为 canvas 命令栈一层**；文档编辑照常渲染（实时预览不受影响），只是不再产生隐藏的 undo 块。
- 每条命令 = **前后内容快照**（全文 + 必要的逐字符格式），undo/redo = 内容重放；`ui/textedit_commands.py::sync_text_by_diff` 的 diff 重放机制直接复用。
- 键入命令：按"键入会话"聚合——首键开事务，空闲/失焦/选区变化闭事务（定时器基础设施已在 04feaf8 落地，复用）。
- 格式化手势：预览期间文档随便变，手势结束发一条快照命令；**手势宏、悬开定时器、伪造计步全部失去存在理由，删除**。
- 计账：每条命令恰一个撤销步，`num_pushed_textstep` 语义随之归一（缺陷 ③ 自动消解）。

### 4.1 执行策略与阶段划分（评审修订：0 → 3 直通）

| 阶段   | 内容                           | 状态          | 与终局的关系            |
| ---- | ---------------------------- | ----------- | ----------------- |
| 阶段 0 | 调用点普查 + 行为特征护网 + 快照探针（见 4.2） | 主线          | 终局验收基准            |
| 阶段 1 | 格式化手势提交制（见 4.3）              | **降级为止血分支** | 仅当阶段 3 受阻需临时出货时启用 |
| 阶段 2 | 镜像对账重构（原 4.4）                | **取消**      | 排水机制终局整体废弃，不做     |
| 阶段 3 | 单栈化终局，拆 3a/3b 两个提交（见 4.5）    | 主线          | 终局                |

**路线：0 → 3 直通。** 评审结论：阶段 1 的核心机制（排水循环 + 按快照重放）在文档栈禁用后同样整体废弃，与阶段 2 同属过渡债；其有长期价值的只有**手势边界判定钩子**（选区变化/非格式化推送/空闲定时器），提取为阶段 3 的子任务。阶段 3 的风险由阶段 0 护网兜底；若 3 受阻且当前缺陷必须临时止血出货，才回头实施阶段 1。


### 4.2 阶段 0：调用点普查 + 行为特征护网 + 快照探针

**0-a 调用点普查（前置，✅ 已完成）**。全库普查 `.undo()` / `.redo()` / `availableUndoSteps` / `joinPreviousEditBlock` / `setUndoRedoEnabled` 的每一处调用，逐个标注「终局下的去向」（删除 / 改快照重放 / 不动）。普查已发现的关键点：

- **绘制栈跨界依赖（评审新发现）**：`ui/drawing_commands.py::RunBlkTransCommand`（管线运行命令，在绘制栈上）的文本回退直接调 `blkitem.redo()/undo()`、`transpairw.e_trans.redo()/undo()`、`e_source.redo()/undo()`——**依赖文本文档的私有 undo 栈**。终局禁用文档栈后这些调用静默空转，管线操作撤销残废。必须改造为快照重放，列入 3a（修正原「绘制栈不动」的表述）。
- **页面内查找替换同病（普查新发现）**：`ui/textedit_commands.py::PageReplaceOneCommand` / `ui/textedit_commands.py::PageReplaceAllCommand`（PageSearchWidget 页面内替换）以文档 undo/redo 做重放——它们**不是**分治不动的 GlobalReplaceApplier 快照体系，必须纳入 3a 快照化。
- `ui/textedit_area.py` 面板编辑器的 `undo`/`redo`（面板侧排水口），随 C 类一并删除。
- 完整清单见 [`docs/技术实现/撤销调用点普查.md`](撤销调用点普查.md)（A~H 分类 + 终局去向），3b 禁用前 B/C/D/E 类必须全部落地。
- `ui/text_engine/annotations.py` 的 `setUndoRedoEnabled` 保存/恢复逻辑：全局禁用后若恢复分支写回 True 会把文档栈偷偷重新打开，须核实恢复的是「进入时的旧值」而非字面 True。
- `ui/global_search_widget.py`、`ui/text_engine/effects/renderer.py`、`ui/text_engine/rendering/native_document.py` 的 `setUndoRedoEnabled(False)` 作用于独立暂存文档，与本体系无关，标「不动」。

**0-c 快照探针（评审补充，✅ 已完成，结论锁定）**。探针 `tests/test_snapshot_probe.py` 实测：

复现台已知坑（写给实现者）：offscreen 下 item 的 `hasFocus()` 需要 `gv.show()` + 事件循环后才成立，否则 `ui/text_engine/item.py::on_content_changed` 的发射门整体跳过（症状：键入不产生任何栈命令）；面板替身必须在挂接信号**之前**完成初始 `setPlainText`，否则初始化同步会触发对账（文本不一致时会真的去改 item 文档）；Qt 信号回调内的 Python 异常会 qFatal 直接终止进程（exit 127、无 traceback），复现台布线务必先行。

3a 执行中新增两坑（均已修复，写给后续实现者）：

- **构造期基线污染**：`initTextBlock` 的初始格式应用走 `set_fontformat`，会把手势基线捕获在「构造态」（空文本 + 默认字号）。该陈旧基线若被之后第一个真实手势沿用，undo 会把文本回退到构造态（症状：交错序列第二次 Ctrl+Z 清空画布文本）。修复：`initTextBlock` 末尾复位 `_ffmt_gesture_baseline`，且基线捕获在 `block_change_signal`/`in_redo_undo` 抑制态下跳过（重放/程序写入不是用户手势）。
- **陈旧水位伪象**：旧版 `new_steps > 0` 发射门在步数下降时（如 `setPlainText` 重置文档）不回写 `old_undo_steps`，留下陈旧水位。`tests/test_render_sync.py` 旧 check 7 的「文档步数对等」全靠该伪象凑出，水印修正后必然失败——3a 已按新语义改写该检查（锁文本收敛，命令级行为由护网锁定），勿据旧断言回推实现。

### 4.3 阶段 1（止血分支，默认不实施）：格式化手势提交制

仅当阶段 3 受阻且当前缺陷必须临时出货时启用。不动镜像链路，独立成立：

1. 手势判定沿用现有边界钩子（选区变化/非格式化推送/撤销重做入口/清栈）+ 空闲定时器，但语义从"宏悬开"改为"**事务悬开**"：手势开启时记录各受影响 item 文档的 `availableUndoSteps` 快照；
2. 手势闭合（同样的钩子触发）时统一收口：对每个 item 执行 `doc.undo()` **循环排水**到快照 → 以单一事务（beginEditBlock/endEditBlock）重放终值（一个文档块）→ beginMacro + 每块一条命令 + endMacro **同步完成**；
3. 多选一次手势仍是一个宏 = 一个撤销步；宏不再有悬开窗口（生命周期与手势严格重合），缺陷 ② 的切碎路径消失；
4. 排水期间以 `is_formatting` / `block_change_signal` 现有抑制机制防止排水产生的文档变更反向发射命令。

### 4.4 阶段 2：已取消

原镜像对账重构（去 joint 化 + 按步数排水）在终局整体废弃，不再实施。保留此节编号以维持引用稳定。

### 4.5 阶段 3：单栈化终局（拆 3a/3b 两个提交）

**3a：快照命令落地（与文档栈短暂并存）**

1. 快照格式按 0-c 探针结论实现；命令基类统一持前后全文快照（格式化命令沿用 `old_ffmt_values`/`new_ffmt_values` 值快照模式），undo/redo = 重放；
2. **统一重放守卫**：一个比 `is_formatting`/`block_change_signal` 更全局的「重放中」抑制标记，重放期间切断 `contentsChange` 全链路的命令再发射（评审补充，一等设计项）；
3. 键入会话聚合：首键开事务，空闲/失焦/选区变化闭事务（手势边界判定钩子从原阶段 1 提取，定时器基础设施复用 04feaf8）；
4. 预览悬开期间 Ctrl+Z 按第二节第 7 条实现：取消手势、恢复原值；
5. 脏状态切换为 QUndoStack clean 机制（第二节第 8 条）；
6. `ui/drawing_commands.py` 管线命令的文本回退改为快照重放（0-a 普查的跨界依赖）。

**3b：禁用文档栈 + 删除旧机制**

1. item/panel 文档 `setUndoRedoEnabled(False)` 全面切换（含切页、批量重渲、粘贴、合并等所有文档写入路径的回归排查，以 0-a 普查清单为边界）；
2. 删除文档步排水、`old_undo_steps` 步数记账、`joint_previous` 语义；
3. IME：预编辑期间本就不产生提交，提交后走常规命令路径，需实测验证。

### 4.6 删除清单（重构完成时应消失的机制）

- `old_undo_steps` / `updateUndoSteps` 步数记账（阶段 3b）；
- `ui/drawing_commands.py` 中对 `blkitem`/`e_trans`/`e_source` 文档级 undo/redo 的跨界调用（3a 改为快照重放后删除）。

## 五、回退路径与中止判据

1. **分阶段原子提交**：甲-1、甲-2、阶段 0、阶段 3a、阶段 3b 各一个提交，用户审查后入库；任一阶段可用 `git revert` 单独回退，不牵连其他阶段。
2. **中止判据**：某阶段完成后，护网测试或实机验收出现无法在一个工作日内定位的回归 → revert 该阶段；3a/3b 均无法落地且缺陷必须止血出货 → 启用阶段 1（止血分支）临时出货，再谋 3。
3. 甲-1/甲-2 已先行合入，与终局兼容，不构成回退负担。
4. 阶段 0 护网测试同时是回退后的回归保护。

## 六、验证策略

- 每阶段：`scripts/verify.py` 全绿 + 护网测试全绿 + 实机验收清单；
- 实机验收场景清单：纯键入 / 连续键入一步回退 / 中文 IME 输入 / 键入与格式化交错 / 多选格式化一次回退 / 改字号实时预览手感 / 预览悬开期间按 Ctrl+Z 取消手势 / 撤销后重做 / 撤销后画布与面板一致性 / 切页与批量重渲后的僵尸命令静默失效 / 批量替换回滚不受影响 / 管线运行命令的撤销重做 / 富文本（注解、着重号、分行格式）块上的全部场景；
- 富文本注意：内容快照必须是**全文 rich text 级**（逐字符格式），不能只存 FontFormat 标量；格式选型以 0-c 探针的往返保真实测为准。

## 七、风险清单

1. `setUndoRedoEnabled(False)` 与 IME 预编辑、注解 ruby 容器、效果栈渲染的相互作用需实测（阶段 3b 首项即验证）；
2. 快照内存与重放耗时：以 0-c 探针实测为准；上限策略 = 命令数上限（`setUndoLimit`）+ 必要时字节预算；
3. **绘制栈跨界依赖**：`ui/drawing_commands.py` 管线命令的文本回退依赖文档私有栈（见 0-a），3a 改造期间是该命令撤销功能最脆弱的窗口，护网须有对应回归；
4. **`setUndoRedoEnabled` 恢复语义**：`ui/text_engine/annotations.py` 等处存在「保存→恢复」式切换，全局禁用后若恢复分支写回 True 会偷偷重开文档栈；3b 切换前逐处核实恢复的是进入时旧值；
5. 本体系为 fork 私有重构，与上游撤销实现分道，后续反向移植不再覆盖撤销域；
6. `ui/text_engine/` 存在休眠拷贝（`ui/text_engine/editing/upstream_commands.py`、`ui/text_engine/editing/widgets.py` 等），重构只动活代码，休眠拷贝内的同符号不作为参考。
