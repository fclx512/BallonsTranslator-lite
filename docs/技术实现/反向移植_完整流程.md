# 反向移植完整流程（操作手册）

> 首个实战 PR：[#1261 字体排除功能移植](https://github.com/dmMaze/BallonsTranslator/pull/1261)（2026-08-08）。
> 规则与适配点以 [`反向移植_规范.md`](反向移植_规范.md) 为准，本文是端到端操作步骤 + 命令速查。

## 0. 环境约定

| 项 | 值 |
|---|---|
| fork 源 | `D:\ruanjian\BallonsTranslator-lite`（平铺结构） |
| 上游克隆 | `D:\ruanjian\BallonsTranslator`（包结构；`origin`/`upstream` 直指 dmMaze，只读） |
| 推送远端 | `myfork` → `https://github.com/fclx512/BallonsTranslator-lite.git`（就是 lite fork 仓库，无独立上游 fork） |
| 网络 | 本机 git 直连 GitHub 不稳定，需本地代理 `http://127.0.0.1:7897`，命令统一加 `-c http.proxy=...` |
| PR 语言 | **中文**（上游作者母语是中文，覆盖规范 7.2 的"英文"要求） |

⚠️ 两仓库历史不共享（merge-base 为空）→ 禁止 cherry-pick/format-patch，只能手工移植 + 适配。

## 1. 同步上游、开分支

```bash
git -C D:/ruanjian/BallonsTranslator -c http.proxy=http://127.0.0.1:7897 fetch origin dev
git -C D:/ruanjian/BallonsTranslator checkout -b feat/backport-<功能英文名> origin/dev
```

## 2. 移植

- 按规范 §3 路径映射搬文件：`ui/`、`utils/` → 加 `ballontranslator/` 前缀。
- 新文件直接建；同名文件（B 类）`diff` fork 版与上游版，只搬增量（防覆盖上游近期修复）。
- 适配点速查：import 加包前缀；`self.tr()` 英文源串（`en_US.ts` 是源）；pcfg 新字段带默认值；headless 兼容；不新增依赖。

## 3. 验证（提交前）

```bash
# 单测（PYTHONPATH 必须指向仓库根；勿用 `-m unittest tests.xxx`，会撞 site-packages/tests 命名空间）
PYTHONPATH=D:/ruanjian/BallonsTranslator python -m unittest discover -s tests -p "test_xxx.py" -v
# 含 doctest 的代码可另行跑 doctest 验证
```

- import 冒烟 / offscreen 交互冒烟（monkeypatch `QMessageBox`、注入假字体表，防模态阻塞与空字体表）
- headless 启动（EOFError 属正常终止）
- 旧 config.json 兼容（新字段缺省即默认值）
- i18n：`en_US.ts` 加 source → `zh_CN.ts` 补译文 → qm 重编译（fork 的 `scripts/qm_compile.py`）→ 加载验证

## 4. 提交（重点）

**一次 PR = 一个功能 = 若干小步提交**（代码、测试、翻译分开）。与 fork 侧的"提交聚合"相反：给上游的 PR 保持小步提交即可，无需聚合。

```bash
git add ballontranslator/utils/config.py ballontranslator/utils/shared.py
git commit -m "feat: add excluded_fonts config and font list filter helper（来源：BallonsTranslator-lite）"

git add ballontranslator/ui/configpanel.py
git commit -m "feat: add FontExcludeDialog and Hide Unused Fonts settings button（来源：BallonsTranslator-lite）"
# ... 测试、翻译各一个提交，依此类推
```

提交规范：

| 规则 | 说明 |
|---|---|
| 消息格式 | `feat: <一句英文描述>（来源：BallonsTranslator-lite）`；上游风格自由、英文为主 |
| 小步 | 代码 / 测试 / 翻译分提交，便于审查 |
| 禁 amend | 重写已推送 hash 会分叉（fork 规则同样适用） |
| 禁 AI 署名 | 不写 `Co-Authored-By` 等任何协作署名行 |
| 禁 push --tags | 发版只精准推 tag：`git push origin vx.y.z` |

## 5. push 前：rebase 到最新 dev

移植与 PR 准备期间上游 dev 可能又前进了，push 前先同步：

```bash
git -C D:/ruanjian/BallonsTranslator -c http.proxy=http://127.0.0.1:7897 fetch origin dev
git -C D:/ruanjian/BallonsTranslator rebase origin/dev
```

- 零冲突属正常（移植文件与上游演进文件通常不重叠）；有冲突按 diff 增量手工解决。
- rebase 后重跑一次单测，确认内容无损。

## 6. 推送（到 lite fork 仓库）

```bash
# 首次：添加推送远端
git -C D:/ruanjian/BallonsTranslator remote add myfork https://github.com/fclx512/BallonsTranslator-lite.git
# 推送（不带 -u，避免改动 tracking）
git -C D:/ruanjian/BallonsTranslator -c http.proxy=http://127.0.0.1:7897 push myfork feat/backport-<功能英文名>
```

为什么推 lite fork 仓库就行：GitHub 仍把 `fclx512/BallonsTranslator-lite` 记录为 dmMaze/BallonsTranslator 的 fork，跨仓库 PR 成立；PR diff 按分支 merge-base 计算，与 fork 默认分支内容无关。

## 7. 推送后校验（防止脏 PR）

```bash
curl -s --proxy http://127.0.0.1:7897 \
  "https://api.github.com/repos/dmMaze/BallonsTranslator/compare/dev...fclx512:feat/backport-<功能英文名>"
```

期望：`status: ahead`、`ahead_by: <提交数>`、`behind_by: 0`，`commits` 只含自己的提交。若 `diverged` 或数量异常，先修再提 PR。
（注意匿名 API 有 60 次/小时限流，代理出口 IP 共享，撞限流时可用网页抓取替代。）

## 8. 提 PR（浏览器）

- compare URL：`https://github.com/dmMaze/BallonsTranslator/compare/dev...fclx512:<分支名>?expand=1`（base 选 dev）
- 描述中文，要点：功能 / 为什么实用 / 来源（BallonsTranslator-lite）/ 改动文件清单 / 验证了什么、没验证什么 / 影响（旧 JSON、headless、新依赖明确"无"）

## 9. 收尾

1. PR 提交后：规范 §10 记录表登记/更新一行（含 PR 链接）。
2. 上游作者审查 → 可能要求改 UI/代码 → 改完 `git push --force-with-lease myfork <分支>`（覆盖推送前先经用户同意）→ PR 自动更新。
3. fork 侧文档改动（记录表、经验教训）按 fork 规则：**先展示，用户确认后提交**。

## 附录：提交与推送命令速查

| 操作 | 命令 | 备注 |
|---|---|---|
| 查状态 | `git status -sb` | 显示当前分支与未提交改动 |
| 小步提交 | `git add <文件> && git commit -m "feat: ...（来源：BallonsTranslator-lite）"` | 代码/测试/翻译分开 |
| 查看小步历史 | `git log --oneline -N` | push 前核对提交内容 |
| 同步最新 dev | `git fetch origin dev && git rebase origin/dev` | push 前必做 |
| 推送 | `git push myfork <分支>` | 不带 `-u` |
| 修改 PR 后覆盖推 | `git push --force-with-lease myfork <分支>` | 先经用户同意 |
| 校验 PR diff | `curl` compare API（见 §7） | 防脏 PR |
