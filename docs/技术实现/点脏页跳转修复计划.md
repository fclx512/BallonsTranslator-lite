# 点脏页（斜体页）跳转错乱修复计划

> 状态：**已完成**（代码改动 + 回归测试 + `verify.py` 全绿；2026-08-28 随 8b45049 提交，并经用户本机真实项目人工点验通过，按「收尾」写入 `daily_log.md`）。记录日期 2026-08-26。

## 背景

样式管理器批量改样式后，非当前页被标记为脏页（`page_needs_rerender`），`ui/mainwindow.py::updatePageList` 以斜体显示（无缩略图模式，≥100 页）。点击脏页时 `ui/mainwindow.py::pageListCurrentItemChanged` 在处理器内**同步重建整个页面列表**（`self.updatePageList()`）。该处理器挂在 `currentItemChanged` 上，重建期间的 `clear`/`addItem`/`setCurrentItem` 会再次触发 `currentItemChanged`，使处理器在第一次调用尚未返回时被**重入**，对非点击项重复执行完整页面切换（保存/切页/重绘/重渲染），导致落点错乱（现象：斜体页点击随机跳转，正体页正常）。干净页不进入该分支，故不受影响。

## 修复原则

点页流程保持单一顺序：**保存旧页 → 切到目标页 → 重绘 → 渲染目标页结果 → 静默刷新列表**；"刷新列表"这一步执行期间屏蔽 `currentItemChanged` 通知，禁止重入。不引入异步/延迟窗口。

## 改动清单（仅一个文件：`ui/mainwindow.py`，一个函数）

### 改动点：`pageListCurrentItemChanged` 的脏页分支（约在 `if self.imgtrans_proj.page_needs_rerender(new_pagename)` 处）

现状：

```python
if self.imgtrans_proj.page_needs_rerender(new_pagename):
    self.imgtrans_proj.clear_page_needs_rerender(new_pagename)
    self._save_result_image_only()
    self.updatePageList()
```

改为：

```python
if self.imgtrans_proj.page_needs_rerender(new_pagename):
    self.imgtrans_proj.clear_page_needs_rerender(new_pagename)
    self._save_result_image_only()
    # 重建列表期间屏蔽其信号，防止 currentItemChanged 重入本处理器
    # （重建是同步的，窗口内无事件处理，不会吞掉真实用户点击）。
    was_blocked = self.pageList.signalsBlocked()
    self.pageList.blockSignals(True)
    try:
        self.updatePageList()
    finally:
        self.pageList.blockSignals(was_blocked)
```

### 硬性约束（违反即引入新 bug）

1. **`blockSignals` 只允许包住"点脏页分支"里这一次 `updatePageList()` 调用**。禁止把屏蔽写进 `ui/mainwindow.py::updatePageList` 函数内部或全局应用。
2. 原因（务必先验证再动手）：打开项目流程 `ui/mainwindow.py::openDir` 调用 `updatePageList` 后，首屏画布渲染依赖"重建 → `setCurrentItem` → `currentItemChanged` → `pageListCurrentItemChanged` → `updateCanvas()`"这条既有隐式链路（`openDir` 内没有显式的 `canvas.updateCanvas()`）。全局屏蔽会破坏首屏渲染。**执行第一步：在 `openDir` 之后跟一遍这条链路，确认此依赖成立；若发现首屏其实由别处渲染，则本约束可放宽，但默认按本约束执行。**
3. 其余 `updatePageList` 调用点（`openDir`、样式管理器 `pages_dirtied`、全局搜索 `pages_dirtied`、批量重渲染路径、批量替换等）一律保持现状，不做屏蔽。

## 明确不做的事（防止实施时自由发挥）

- 不修改 `utils/proj_imgtrans.py`（脏标记数据层不动）。
- 不改变 `_save_result_image_only()` 的同步渲染时机（大图卡顿问题属二期，不在本计划）。
- 不动批量重渲染路径。
- 不引入 `QTimer` 延迟/异步重建方案（会产生信号窗口期，且保留冗余渲染）。
- 不新增任何 UI 字符串（无 i18n 影响；`scripts/i18n_check.py` 应与改动前一致）。

## 影响面说明

- 键盘翻页（shortcutNext/shortcutBefore 走 `setCurrentRow` → 同一处理器）翻到脏页时同样受修复保护。
- 缩略图模式（<100 页）走同一脏分支，同样修复。
- 屏蔽修复后，"点脏页 = 渲染一次结果图"，不再有重建重入导致的第二次冗余渲染。
