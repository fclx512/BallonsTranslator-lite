## 问题 / 需求

把本地 `TextBlkItem` 的渲染职责从"textitem 直画 + 快路径缓存"切换到上游
`TextEffectRenderer` 结构：描边/阴影/渐变/padding 推导归 `effect_renderer`，
背景先画的本地语义保留，本地縦中横/标点右上/`shadow_include_stroke` 等独有
逻辑保留。**中性态（空变换栈）必须零行为变更**。每个节点独立验收并记录本文档。

## 实施方案与路线图偏差（已与用户确认）

1. 布局不整体换成上游 `layout.py` —— 本地 `scene_textlayout.py` 已深度编织縦中横/
   标点右上/半角括号逻辑，改为在本地 layout 上补机制槽位（节点 B）。
2. `setRectFast` 保留（推迟到阶段 5），删除会回归拖拽 UX。
3. glyph slant 的 `custom_rendering` 守卫推迟到阶段 4（阶段 3 无 render_delegate
   场景可验证）。
4. `text_rendering` / `show_decorations_during_drag` 配置按路线图删除（节点 D）。

### ⚠️ 排障备忘

- **stroke_width 语义**：`stroke_width=4.0` 是"笔宽 = font_size_px × 4"的
  不合理预设值，会画出 192px 实心红块遮住阴影。UI 预设 `stroke_width_presets
  = [0.1, 0.15, 0.2, 1.0]`（分数语义）；测试统一用 `0.1`。
- **`setDocumentMargin` 是可撤销操作**：会向 doc undo 栈推入 1 步。曾试图在
  `setPadding` 内用 `setUndoRedoEnabled(False)` 包裹来消除——**禁用 undo 会
  清空整个 undo 栈**（Qt 行为，实测 insertText 后 toggle → 0 步），会摧毁
  用户文本编辑历史，不可行。上游 `updateDocumentMargin` 同样用
  `setDocumentMargin`，行为一致，故保留实现、测试断言"恰好 1 步 + 幂等"。
  这是阶段 3 之前的既有行为，非回归。
- **PyQt6 `QLinearGradient` 无 `colorAt()`**：用 `grad.stops()`（返回
  `[(pos, QColor), ...]`）。
- **offscreen 像素验证坐标**：`pixmap2ndarray` 数组 `(H, W, 4)`，axis 0 = 图像
  Y 行、axis 1 = X 列；文档的"纵轴有墨范围"= **axis 1** 聚类（曾误用 axis 0
  得到 X 列聚类）。竖排列宽 offscreen 下约 20px（非文档记录的环境 DPI），标点
  右移幅度因此只有 ~2px，断言用"严格右移"而非固定阈值。
- **直画 item 而非 scene.render**：scene 渲染在 offscreen 下有坐标映射/白底
  alpha 干扰，改 `item.paint(painter, opt, None)` + translate 局部坐标系 +
  透明底色，墨迹 bbox 与布局坐标一一对应。
