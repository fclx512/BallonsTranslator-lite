# 环形菜单（Pie Menu）实施方案

> 状态：阶段 0（旧样式清理）与阶段 1（删 preview + 快捷键冲突校验）已完成并验收；阶段 2（饼菜单核心）已实现并通过离线验证，用户审查后决定**交由有视觉能力的 AI 接手视觉修缮**（交互逻辑与状态机已定稿，不再改动）；接手文档见《环形菜单_视觉修缮交接.md》
> 日期：2026-08-10

## 一、背景与目标

画布区现有右键上下文菜单（`ui/context_menu_config.py`）交互不便：高频功能需要「右键呼出 → 移动定位 → 点击菜单项」至少两次点击。目标改为 Blender 风格环形菜单：**按 Tab 呼出 → 鼠标方向选择 → 松开触发**，一次手势完成，同时减少鼠标移动距离。

本方案是减法导向 fork 的交互增强：命令本体（`COMMAND_REGISTRY` → canvas 信号）完全复用，只替换交互外壳。

## 二、已确认的决策

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 交互模型 | Blender 正宗方案 + PS 式弹簧加载（短按 pin / 长按 release-commit） |
| 2 | 触发键 | `Tab`（删除 preview 功能腾出；preview 无其他引用，清理面已摸清） |
| 3 | 扇区结构 | 8 扇区，每扇区可放多个功能项，**扇区内按角度 fan 排布为浮动卡片**（最多 3 张） |
| 4 | 标签 | 纯文本，暂不配图标；卡片尺寸贴合文本 |
| 5 | 禁用项 | 灰显且**不可选中**（鼠标划过不响应，等同中心圆行为） |
| 6 | PIN 模式点击 | 扇区卡片上左键=触发、右键=取消；中心圆内左右键均=取消 |
| 7 | 右键菜单 | 暂时保留（删除设置里的自定义菜单对话框），稳定后清退或仅保留文本编辑区右键 |
| 8 | 新增 | 快捷键冲突校验（**优先处理**，作为本项工作的前置阶段） |

> **2026-08-10 审查修订**：#3 原「径向分内外层（内/中/外 3 环带）」改为**浮动卡片 + 扇区内 fan**——中心圆与卡片之间留出可见间距，卡片按 8 个方向放置、尺寸贴合文本，多卡片方向在扇区内按角度扇开（Blender 子饼风格），不再用环带/扇区形状约束。

## 三、交互模型（状态机）

### 3.1 触发条件

```
textEditMode ∧ ¬creating_textblock ∧ ¬editing_textblkitem ∧ 焦点在主窗口内 ∧ 配置面板不可见
```

- 与右键菜单的条件相比多排除「正在编辑文字块」——单键 Tab 在文字输入时必须让位（打字冲突）
- **审查修订**：不再要求「焦点在画布」——textEdit 模式下 Tab 在整个主窗口内都是饼菜单触发键；但焦点在**纯文本输入控件**（源/译文输入框、搜索框等 QTextEdit/QPlainTextEdit）内时 Tab 被吞掉（不触发、不插入制表符、不切焦点，防「场外干扰」）；焦点在对话框/独立窗口内时 Tab 保持原行为

### 3.2 状态机

```
[可触发] 按 Tab（非 autoRepeat）
  → 以鼠标全局位置为中心弹出菜单（8 扇区 × 浮动卡片），开始计时
  ├─ 短按（松开 < 250ms）→ PIN 模式：菜单钉住，等待鼠标
  │    角度 → 扇区；扇区内再按角度取最近 fan 卡片；中心圆内 = 无选中
  │    左键点击可用卡片 → 触发该项并关闭
  │    左/右键点击中心圆 → 取消并关闭
  │    右键点击任意处 → 取消并关闭
  │    Esc / 点击菜单外 / 切走应用（ApplicationDeactivate）→ 取消并关闭
  └─ 长按（松开 ≥ 250ms）→ release-commit：
        松开瞬间 → 当前高亮卡片触发并关闭；在中心圆 / 灰显卡片上 → 取消
```

### 3.3 扇区与卡片判定

- 扇区：`atan2(鼠标相对菜单中心) → 360°/8 取整`
- 卡片：扇区内的整段环带（中心圆外 ~ 菜单外沿）都是热区；扇区有多张卡片时按**角度最近**选卡片（fan 偏移 = 每张卡片均分该扇区 45° 角域）
- 死区：距中心 < 5px 不触发判定，防抖动
- 灰显卡片：不参与高亮，判定结果等同中心圆

### 3.4 快捷键冲突处理（核心技术难点）

触发键可能同时是已注册的 `QShortcut`。Qt 事件顺序：`ShortcutOverride` **先于** QShortcut 检查。

- `MainWindow.eventFilter`（app 级）拦截 `QEvent.ShortcutOverride`：命中触发键时 `accept()` 并 return True，吞掉快捷键
- 首次按下（`¬isAutoRepeat()`）→ 弹出菜单；释放 → 短按/长按分支
- 菜单必须用**独立无边框 QWidget**（`Qt.Tool | FramelessWindowHint | WindowStaysOnTopHint`），**不能继承 QMenu**——QMenu 的 exec 事件循环会卡住主窗口收 release 事件；普通 QWidget 不抢焦点（`WA_ShowWithoutActivating`），主窗口能正常收到释放事件
- 实现注：PyQt6 的 `QKeyEvent` **没有** `globalPosition()`，取全局光标用 `QCursor.pos()`

## 四、视觉规格（2026-08-10 审查修订版，草案默认值）

| 项 | 值 |
|----|-----|
| 菜单总直径 | ~344px（TOTAL_RADIUS=172） |
| 中心圆半径 | 45px（无选中区 + 方向箭头） |
| 卡片 | 圆角矩形，尺寸贴合文本（文本宽 + 2×8px 内边距）；中心在半径 ~118.5px 处单排 |
| 卡片与中心圆间距 | 卡片内沿 ≈72px，与中心圆（45px）之间有 ~27px 可见间距 |
| 扇区 | 8，每扇区最多 3 张卡片，多卡片在扇区内按 ±12° 步进 fan 排布 |
| 文本 | 纯文本，沿径向排布（读向朝外），不再截断（卡片贴合文本） |
| 高亮 | 主题色半透明填充（复用 `themeColor`/`isDarkTheme`） |
| 灰显 | 低透明度（文本 alpha≈110），不参与高亮 |

> **实现注（Qt 坑）**：旋转坐标系下的 `drawText(rect, AlignCenter, …)` 会把文本偏移到矩形边缘（偏移量 ≈ 文本宽，PyQt6 实测）。方案：文本先无旋转绘制到 `QPixmap`（此时对齐正确），再在旋转坐标系内 `drawPixmap` 合成（纯几何，旋转安全）。`_text_pixmap()` 按 (cmd_id, enabled, dark) 缓存。

### 阶段 1 详情：快捷键冲突校验

现状：`_ShortcutRow._add_shortcut()` 只防**同一动作**重复绑定，跨动作重复无检测。

设计：
- 数据源：生效键集 = `pcfg.shortcuts[action_id]` 优先，否则 `DEFAULT_SHORTCUTS[action_id]`
- `ShortcutEditor.refresh()` 汇总全部动作的键序列 → 出现 ≥2 次的键序列 → 对应 pill 标红（红底/红字）
- 校验时机：初始化渲染 + 每次 `shortcut_changed` 后
- 连带价值：删掉 preview 后，用户历史配置里残留的 Tab 占用会被标红暴露
