# 上游 v1.5.12 改动移植规划（2026-08-21）

> 依据调研：`docs/技术实现/上游v1.5.11之后提交调研.md`（范围 v1.5.11..v1.5.12 = 69 + 10 提交）。
> 决策人：fclx512（2026-08-21 圈选意见，见第 0 节）。
> 原则：**底层实现逻辑对齐上游以防不兼容；UI 与交互形态按我方既有理解保持/改善。**

---

## 0. 决策摘要

| 上游改动块 | 决策 |
|-----------|------|
| 底层逻辑修复（LLM schema / SSL / openai 图片 / xyxy / 光标） | **全部纳入**。openai 图片 base url（`5e29734`）暂无数在线图片修复功能支撑，先修好搁置不启用 |
| 文本引擎大改（PR #1278） | **全量移植**，拆节点按序推进以控制上下文；新功能 UI 先"堆上去"可用，底层完成后再统一整理；**字重（font_weight）不取上游实现**（本地现实现经实际审查更合理，保留我方） |
| 阅读顺序角标 + 路径重排（PR #1285） | 底层逻辑对比借鉴；UI/交互维持我方形态；**角标显示位置参照上游改为文本框外**（我方现显示在框内会遮挡文本） |
| 杂项修复（v1.5.12 三件 + grid 手柄 + 依赖升级） | 写入节点 5 收尾排查；Qt 6.11.0 已实测满足（上游升 6.11 的依赖无需动作） |

### 节点 0 — 底层逻辑修复（独立，不依赖引擎）｜工作量：小（约 1 会话）✅ 已完成（2026-08-21）

按序 5 项，均纯逻辑、模块隔离：

1. **LLM 动态 id Schema 修复**（上游 `ea70488`/`a993764`/`c6350e3`/`5a09876`/`8956326`/`9a2ed15`）

## 2. 风险与对账点

- **上游 utils 依赖漂移**：text_engine 引用上游 `ballontranslator/utils/`（textblock/fontformat/config/text_processing），迁移时逐符号核对，缺失先按上游实现补入（节点 2a 的依赖核对步骤）
- **字重分歧**：上游 FontWeight 枚举 + HTML 往返 vs 我方 int + `fix_fontweight_qt`；合并 annotations.py 时最容易在这里被"顺手覆盖"，需显式跳过并按本地逻辑适配（节点 1/2c）
- **96dcb09 与反移植交集**：`utils/textblock.py` 改动注意与已提交/规划的反移植落点冲突（节点 0，对账文档见上）
- **管线产物渲染衔接**：`ui/io_thread.py` → `pipeline_formatting.py` 的格式化应用路径与本地 drawingpanel 输出衔接
