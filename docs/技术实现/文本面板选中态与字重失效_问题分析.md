# 文本面板选中态与字重失效问题分析

> 状态：**已按同目录《文本面板选中态与字重失效_修复计划.md》实现完毕（2026-09-04，阶段 1–5 落地，实现偏差见该计划「九、实现备注」）**。
> 目标：右侧文本编辑区（`ui/text_panel.py::FontFormatPanel`）的选中态显示与字重编辑对齐 Photoshop 语义。

## 一、现象

1. 闲置（无选中）态面板显示一套"来源不明"的默认样式，选型逻辑不可感知；
2. 多选文本块时面板退回闲置样式——即使所有选中块样式完全一致（单选正常）；
3. 字重编辑有时不生效：脏页提示出现、JSON 已落盘，但跳转到对应块看到的仍是替换前的字重。

## 二、选中态 → 面板的同步链路（现状）

统一入口是 `ui/scenetext_manager.py::on_incanvas_selection_changed`：

| 选中数 | 调用 | 面板行为 |
|--------|------|----------|
| 1 | `ui/text_panel.py::set_textblk_item`（传 item） | 显示该块格式，正常 |
| 0 或 ≥2 | `ui/text_panel.py::set_textblk_item`（`multi_select=...`） | 落到 `textblk_item is None` 分支 → `ui/text_panel.py::set_active_format(self.global_format)` |

即：**闲置与多选共用同一条回落路径**，面板从未尝试读取选中块的公共格式。`multi_select` 参数唯一的用途是在字号显示后补 "+"，且补在全局格式的字号上。

`self.global_format` 即 `utils/config.py::global_fontformat`（新块默认格式），由 `ui/mainwindow.py` 注入面板。它会被两条路径动态污染，因此闲置态显示的样式"看起来随机"：

1. **闲置/多选态下的任何格式编辑都会写进它**：全局模式下 `ui/fontformat_commands.py::wrap_fntformat_input` 把编辑目标换成画布选中项（多选时编辑因此仍能作用于选中块），但 `ui/fontformat_commands.py::font_formating` 包装器同时把值写入 `global_format`；
2. **激活文本样式预设**：`ui/text_panel.py::on_active_textstyle_label_changed` 将预设 merge 进 `global_format`。

Photoshop 语义：无选中 = 保持上一次编辑的格式状态，不跳回默认集；多选 = 显示活动块（最后选中）格式 + 逐字段混合检测（混合字段显示空白）。

## 三、字重编辑失效机制

### 3.1 架构根源：同一视觉属性有两个真值

- `utils/fontformat.py::font_weight`：int 字重，渲染时经 `ui/text_engine/font_weight.py::coerce_font_weight` snap 到 100–900 canonical 枚举；
- `utils/fontformat.py::_style_name`：fork 附加的 face（样式）名。`QFont.setStyleName` 设置后，Qt 的 face 匹配**优先于** weight 数值。

fork 补丁 `ui/textitem.py::set_fontformat` 在引擎应用完格式后，只要 `_style_name` 非空就 `font.setStyleName(旧样式名)` 并对全文档 mergeCharFormat——旧 face 在这一步压过任何新写入的字重。

### 3.2 机制 A（主嫌疑）：批量应用不更新 `_style_name`

样式管理器 / 查找替换的字重编辑（`ui/style_format_editor.py::FieldEditor` 的 font_weight 字段）**只写 `font_weight`**。批量应用链：

`ui/fontstyle_manager.py::_apply_all` → `utils/base_styles.py::build_flatten_changes` / `utils/base_styles.py::build_variant_changes`（new_ffmt = 块旧格式 deepcopy + 变更字段，`_style_name` 沿用旧值）→ `ui/fontstyle_manager.py::_apply_ffmt_changes` → `ui/fontstyle_manager.py::_apply_changes_to_blocks` → `ui/text_engine/item.py::set_fontformat`。

- fork 补丁把旧 face 重新 pin 上去 → 当前页渲染仍是旧字重；
- 数据确实变了（`ui/fontstyle_manager_commands.py::BatchFontformatCommand` 入撤销栈、`utils/proj_imgtrans.py::mark_page_needs_rerender`、`pages_dirtied`/`data_committed` 发出），所以脏页提示与落盘都是"诚实"的；
- 跳转页面触发场景重建（`ui/scenetext_manager.py::updateSceneTextitems` → `ui/text_engine/item.py::initTextBlock` → `set_fontformat`），旧 `_style_name` 再次 pin → **永远显示旧字重**。

**"某些时候才失败"的原因**：只有 `_style_name` 非空的块才触发——被右侧字重下拉改过的块、或从带 `_style_name` 的全局格式派生的块（`utils/fontformat.py::merge` 非 compare 模式会连带复制该字段）。

补充：引擎 `set_fontformat` 从 `document().defaultFont()` 复制 QFont（经 `ui/text_engine/font_family.py::qfont_with_family`），**旧 styleName 残留不会被清除**——即使数据层清掉 `_style_name`，文档默认字体上的残留也会继续赢得匹配。

### 3.3 机制 B：QFontDatabase 查不到 → 静默跳过

右侧字重下拉路径（`ui/text_panel.py::apply_font_change` → `ui/textitem.py::setFontFamily`）依赖 `QFontDatabase.weight(family, style)` 回显字重。查不到（返回 -1）时 `ui/textitem.py::setFontFamily` 的 `raw_weight <= 0` 分支**直接 return**：

- act_ffmt 已写入新 `_style_name`/`font_weight`，面板显示与画布/数据脱节；
- -1 之后会被 `ui/text_engine/font_weight.py::coerce_font_weight` 折成 Normal(400)，污染数据。

典型触发场景：样式名属于被归并隐藏的别名家族（`utils/font_scan.py::build_font_data` 的归并语义；`utils/shared.py::FONT_STYLES` 覆盖全部真实 Qt 家族名，含别名）、可变字体命名实例。

### 3.4 机制 C：字重数值表示漂移

同一字重在三处的表示不一致：

| 环节 | 行为 |
|------|------|
| 查询/存储 | Qt6 下 `QFontDatabase.weight` 可能返回非 canonical 值（350/550 等可变字体/CJK 字体常见）；`utils/fontformat.py::fix_fontweight_qt` 只做 Qt5↔Qt6 刻度映射，不归一化，原值入库 |
| 渲染 | `ui/text_engine/font_weight.py::coerce_font_weight` snap 到最近 enum（平手时取枚举序靠前者） |
| diff/回显 | `utils/base_styles.py::_quantize` 对 font_weight 无量化步长（原值比较）；`ui/style_format_editor.py::FormatEditorPanel` 字重回显用 `==` 精确匹配 `QFontDatabase.weight`，失配时显示 "(default)" |

后果：diff 误判（改了但量化后同值 → 应用空转）、应用后渲染被 snap 到别的字重、回显错位。

## 四、修复方向（待拍板）

### 4.1 字重单一真值（根治现象 3，收益最大）

- **案 A（倾向）**：`font_weight` 为真值。所有格式应用路径按 `utils/shared.py::FONT_STYLES` 把 `_style_name` 重算为匹配 face 或清空；`set_fontformat`（含引擎 defaultFont）显式清除 styleName 残留；`ui/textitem.py::setFontFamily` 的 -1 分支改为显式回退而非静默跳过。旧数据兼容性最好（只有 `font_weight` 的块不受影响）。
- **案 B**：`_style_name` 为真值（更贴 PS 的 face 模型），`font_weight` 降级为从 face 派生的镜像。

关键约束：**任何** weight/family 变更路径都必须同步处理 `_style_name` 与文档内残留 styleName，否则按下葫芦浮起瓢。

### 4.2 多选显示（现象 2）

以最后选中块（`textitems[-1]`，同步链路已拿到）为镜像显示，逐字段检测混合态显示空白/"—"；编辑继续经现有多选通道作用于全部选中块，但**去掉对 `global_format` 的连带写入**。

### 4.3 闲置态（现象 1）

改为"保持上一次显示"（PS 语义），不再跳回全局格式；`global_format` 保留"新建块默认格式"单一职责，入口后移到真正新建块的时刻。需与 4.2 一起定交互细节。
