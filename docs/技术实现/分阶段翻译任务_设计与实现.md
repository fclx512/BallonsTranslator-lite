# 分阶段翻译任务

桌面端运行入口由 `ui/run_pipeline_dialog.py::RunPipelineDialog` 配置任务，由 `ui/pipeline_tasks.py::PipelineTasks` 在主线程负责生命周期和结果写回，由 `ui/pipeline_runner.py::PipelineRunner` 在后台逐页执行。检测、OCR、翻译、修复可以分别运行；旧的无界面命令行编排、单框翻译和旧进度框仍保留在各自兼容路径，不能随本任务删除。

## 使用流程

1. 点“运行”，选择“识别原文（检测 / OCR）”，可只开其中一个阶段并选择页范围。
2. 校对原文、阅读顺序，在工作台完成翻译准备；识别完成不等同于人工校对完成。
3. 再点“运行”，选择“翻译已校对原文”。默认只处理原文非空且译文为空的框，明确勾选覆盖才替换已有译文。
4. 少量不满意译文沿用单框重译确认卡；工作台批量重译只生成候选，应用时才写回并进入撤销栈。
5. 需要时单独运行“修复图片”，完成嵌字编辑后用“仅渲染”输出结果图片。

## 运行时交互

桌面管线运行期间使用覆盖在画布区的 `ui/pipeline_progress_overlay.py::PipelineProgressOverlay`。覆盖层阻止鼠标、滚轮、键盘和快捷键事件，配置、模块选择、工作台及快捷键也由 `ui/pipeline_tasks.py::PipelineTasks` 暂停；用户不能在后台处理期间换页或编辑，从而避免把一次整页计算结果丢在中途冲突上。窗口关闭会请求协作停止，已写回页面保留，当前未结算页面丢弃。

面板采用画布中央的集中任务视图：上方为任务、引擎、覆盖策略、整批已处理页数与用时；左侧为本页启用阶段，右侧为当前页、目标框数、最近响应轮次、已接收译文数与请求工具；下方为保存/跳过/错误统计、累计已报告 token 和近期活动。状态使用纯文本，禁止 emoji。阶段标记 `render` 在该视图中称“保存结果”，并不表示导出所有页面的结果图片。重译候选任务不显示保存阶段，明确要求审阅后应用。

轮次回调在整轮响应返回、工具执行前发出，因此“请求工具”不表示工具已经成功；已接收译文不表示已保存。整批已处理页数包含跳过、错误和拒收页，保存数只来自主线程成功写回；错误数含冲突项。token 为整次任务跨页累计，缺失用量的响应数单列。检测、OCR、修复没有统一逐块回调，显示忙碌状态，不显示伪造的 `0/N` 进度。新页到来清空本页状态，避免上一页阶段完成和块数残留。

近期活动保留最近 100 行，纯文本显示且不会把外部文本解析成富文本；阅读旧记录时不自动拉回底部。完整译文、工具返回内容、思维链和提交 JSON 不进入活动记录。面板常规尺寸为 760×640 逻辑像素，跟随宿主缩小；正文可滚动，底部动作固定。

停止分为三态：运行中 → 正在停止 → 疑似无响应。“停止任务”调用协作取消，等待当前调用返回，丢弃未结算结果并保留已保存页面；请求停止后才显示“结束程序”。宽限期为 30 秒，超时面板变为警示状态，不自动抢焦点弹框。用户主动点击“结束程序”后才出现二次确认；确认后先尽力保存并等待图像写盘，随后通过 `os._exit` 结束进程，不调用 `QThread.terminate()`。

## 数据与生命周期

- `ui/pipeline_runner.py::PipelineRunner` 使用项目快照运行，后台不写真实项目。每页结果通过 `page_ready` 交给主线程，`ui/pipeline_tasks.py::receive` 校验页签名后，经 `ui/batch_ops.py::BatchWriteback` 写回，再 `acknowledge` 放行下一页；只有接受的页面进入后续页面历史上下文。
- 页签名覆盖块内容、几何/样式、页代数、图像代数、源图文件状态及遮罩/修复图摘要。签名校验是数据一致性闸门，即使覆盖层已屏蔽交互也必须保留。
- 图像保存回执由 `ui/io_thread.py::ImgSaveThread` 的 `failure_count` 提供；启动前和结算前等待保存线程完成，保存失败不启动新任务。共享模块由 `module_manager.background_task_active` 保护，旧 CLI 和单块路径继续使用旧线程实现。
- 接受结果后当前页立即刷新画布。`utils/config.py::ModuleConfig` 中的 `render_after_pipeline` 默认开启，运行对话框可取消“处理后渲染已修改页面”；确认运行才保存此偏好。开启时逐页生成结果图，非当前页经 `ui/pipeline_tasks.py::render_page_image` 使用独立场景和图像缓冲，不切换用户画布；收到图像写盘成功回执才清除脏标记并放行下一页，失败保留脏标记并计入错误。关闭时只保存数据，结果图在访问时补渲染。重译候选不写项目，也不渲染。
- 模型选择在请求切换时即持久化，初始化参数页先恢复配置值再连接切换信号；未知模块报错，不按注册顺序任取首项。启动管线时再次核对已加载实例名称与所选模型，避免切换失败后误用旧实例。
- 任务结束后覆盖层转换为结果摘要卡，启动失败也复用该卡但会断开强制停止信号，避免“关闭”按钮误触发结束进程。重译候选仍只在当前进程内保留，应用前再次核对块签名。

## 验证范围

`tests/test_pipeline_runner.py` 覆盖快照隔离、空译文筛选、重译候选、取消迟到结果、部分失败、严格 ID、用量未知、页面签名冲突和主线程写回；`tests/test_pipeline_progress_overlay.py` 覆盖阶段显隐、输入拦截、跨页状态重置、纯文本活动、小宿主操作区、无响应状态及强制退出前保存。运行这些测试不代表翻译质量已提升，也不调用收费 API。

## 后续界面推广范围

统一视觉约定见 `docs/基础速查/打包控件功能使用说明.md`。本轮只改集中任务视图；`ui/mainwindow.py::run_imgtrans_render_only` 的“仅渲染”仍使用独立进度对话框，单框与兼容路径也保留原入口。

后续优先规划工作台：先统一任务页标题、范围/数量、状态与动作位置，再整理批量候选表和待办列表的密度、审批预览入口，最后处理翻译准备子页的长内容。保留批量操作确认与版本撤回、非删除待办队列的移除语义，以及原比例审批预览；视觉调整不改变这些数据与操作契约。工作台改版在管线视觉验收后另行讨论。
