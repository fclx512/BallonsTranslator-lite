# 分阶段翻译任务

桌面端运行入口由 `ui/run_pipeline_dialog.py::RunPipelineDialog` 配置任务，由 `ui/pipeline_tasks.py::PipelineTasks` 在主线程负责生命周期和结果写回，由 `ui/pipeline_runner.py::PipelineRunner` 在后台逐页执行。检测、OCR、翻译、修复可以分别运行；旧的无界面命令行编排、单框翻译和旧进度框仍保留在各自兼容路径，不能随本任务删除。

## 使用流程

1. 点“运行”，选择“识别原文（检测 / OCR）”，可只开其中一个阶段并选择页范围。
2. 校对原文、阅读顺序，在工作台完成翻译准备；识别完成不等同于人工校对完成。
3. 再点“运行”，选择“翻译已校对原文”。默认只处理原文非空且译文为空的框，明确勾选覆盖才替换已有译文。
4. 少量不满意译文沿用单框重译确认卡；工作台批量重译只生成候选，应用时才写回并进入撤销栈。
5. 需要时单独运行“修复图片”，完成嵌字编辑后用“仅渲染”输出结果图片。

## 运行时交互

桌面管线运行期间使用覆盖在画布区的 `ui/pipeline_progress_overlay.py::PipelineProgressOverlay`。覆盖层阻止鼠标、滚轮、键盘和快捷键事件，配置、模块选择、工作台及快捷键也由 `ui/pipeline_tasks.py::PipelineTasks` 暂停；用户不能在后台处理期间换页或编辑，从而避免把一次整页计算结果丢在中途冲突上。窗口关闭会请求协作停止，已写回页面保留，当前未结算页面丢弃。

面板按检测、OCR、翻译、修复、渲染显示阶段卡片，只显示本次任务实际启用的阶段。翻译卡片默认只显示轮次和工具摘要，展开后显示工具、已接受块数、token 用量和请求模式；思维链、工具返回内容、完整译文及 `submit_translations` JSON 永不进入 UI。检测、OCR、修复目前只有阶段级进度，因为底层模块没有统一的逐块回调。

停止分为三态：运行中 → 正在停止 → 疑似无响应。优雅停止调用协作取消，等待当前页/请求收尾；宽限期为 30 秒，超时后面板变为警示状态但不自动抢焦点弹框。用户主动点击强制停止后才出现二次确认；确认后先尽力保存并等待图像写盘，随后通过 `os._exit` 结束进程，不调用 `QThread.terminate()`。

## 数据与生命周期

- `ui/pipeline_runner.py::PipelineRunner` 使用项目快照运行，后台不写真实项目。每页结果通过 `page_ready` 交给主线程，`ui/pipeline_tasks.py::receive` 校验页签名后，经 `ui/batch_ops.py::BatchWriteback` 写回，再 `acknowledge` 放行下一页；只有接受的页面进入后续页面历史上下文。
- 页签名覆盖块内容、几何/样式、页代数、图像代数、源图文件状态及遮罩/修复图摘要。签名校验是数据一致性闸门，即使覆盖层已屏蔽交互也必须保留。
- 图像保存回执由 `ui/io_thread.py::ImgSaveThread` 的 `failure_count` 提供；启动前和结算前等待保存线程完成，保存失败不启动新任务。共享模块由 `module_manager.background_task_active` 保护，旧 CLI 和单块路径继续使用旧线程实现。
- 接受结果后当前页立即调用 `canvas.updateCanvas()`；非当前页只保存数据和图像，切页时走正常加载路径，不替后台主动切页或渲染非当前页。
- 任务结束后覆盖层转换为结果摘要卡，启动失败也复用该卡但会断开强制停止信号，避免“关闭”按钮误触发结束进程。重译候选仍只在当前进程内保留，应用前再次核对块签名。

## 验证范围

`tests/test_pipeline_runner.py` 覆盖快照隔离、空译文筛选、重译候选、取消迟到结果、部分失败、严格 ID、用量未知、页面签名冲突和主线程写回；`tests/test_pipeline_progress_overlay.py` 覆盖阶段显隐、输入拦截、翻译详情折叠、无响应状态及强制退出前保存。运行这些测试不代表翻译质量已提升，也不调用收费 API。
