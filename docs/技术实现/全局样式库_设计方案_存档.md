# 全局样式库 设计方案

> 状态：已完结归档（2026-09-20 用户确认后落地）——本篇为压缩存档，只留结论与指针；实施过程见 git 历史。

## 结论与决策

* 分层模型取自 Aegisub：用户自维护一套**跨项目持久**的全局样式模板，项目样式**独立**存在，两者**双向复制、拷贝语义（无引用）**，两边各自演化。
* **人工在环约束：库是纯模板存储，绝不自动应用到任何块。** 生效路径唯一——复制进项目 → 块按身份键归组（`utils/base_styles.py::discover_style_tree`）→ 用户在样式管理器显式批量应用。复制进项目**不重排块**，只有身份键吻合的块自动归属（与 Aegisub「把样式拷进脚本不重刷已有台词」一致）。
* 取代此前的「存预设 / 应用预设」（`ui/fontstyle_manager.py` 的 `_save_base_as_preset`/`_apply_preset`）：那个雏形只把参数批量应用到块，没有「复制为项目样式」语义，也没有浏览/改名/删除界面。**预设机制已退役**（`_preset_combo`/`_apply_preset`/`_save_base_as_preset` 整体移除）；`utils/config.py::text_styles` 原样保留给右侧文本面板的快速预设，不做迁移。
* 数据层 `utils/global_styles.py`：存储 `config/global_styles.json`（`utils/shared.py::GLOBAL_STYLES_PATH`，已 gitignore），裸 JSON 数组，条目结构与项目大样式同构，直接复用 `utils/base_styles.py::BaseStyle` 的 `to_dict`/`from_dict`。模块级单例 `utils/global_styles.py::global_styles`；`load_global_styles` 容错加载（坏条目跳过、坏文件不致命），`save_global_styles` 原子落盘（tmp + replace）且每次改动立即调用，不依赖应用退出。
* 库内 `name` 唯一（`ui/fontstyle_manager.py` 侧的 `unique_name` 冲突自动加后缀）；身份键 `(font_family, vertical)` **允许重复**——同字体同方向不同参数的模板可以并存，冲突只在复制到项目时按项目侧规则处理。`utils/global_styles.py::add_style` 深拷贝入库，`find_by_name` 供 UI 按 payload 定位条目。

## 复制语义与冲突规则

**库 → 项目**（`ui/fontstyle_manager.py::_copy_global_to_project`）：

1. 项目内已有同身份键大样式 → 弹窗「覆盖其参数 / 取消」（**唯一弹窗场景**）。覆盖 = 替换该样式的 `fontformat` 并改名，块归属关系不变，变体在重发现时自然重算。
2. 仅名字冲突（身份键不同）→ 自动加后缀「{name} 2」，不打扰。
3. 无冲突 → 追加新 `BaseStyle`（深拷贝），发 `data_committed` 持久化项目 JSON 并重选中。

**项目 → 库**（`ui/fontstyle_manager.py::_add_base_to_library`，大样式模式动作「收藏到库」）：库中已有同名条目 → 弹窗「覆盖 / 取消」，覆盖 = 整条替换 `fontformat`；无冲突 → `add_style` 深拷贝入库。**项目数据不动，不发 `data_committed`。**

**库内编辑**（`ui/fontstyle_manager.py::_apply_library_entry`）：编辑器值全量写回条目（模板无块级 override，不存在「只 flatten 改动字段」的问题），`sync_face` 重算 face 缓存后落盘；改名走 `_on_name_edited` 的库分支（冲突自动后缀）。

## UI 落点

* 左树 `ui/fontstyle_manager.py::StyleTreeWidget` 新增「全局样式库」区（复用「未分组」的表头行做法），条目为两行节点（名称 + 参数摘要 + 色板），payload `{"type": "global", "name": ...}`；左列底部「新建库样式」按钮（`_new_library_style`）补齐了此前「只能从未分组提升」的创建路径。
* **区带化（2026-09-23）**：库区与项目样式混在一条平铺列表里辨识度太低，三处一起改——①三个区（库 / 本项目样式 / 未分组）都改成**自绘区带行**（`ui/fontstyle_manager.py::_StyleItemDelegate` 的 `section` 分支：半透明底 + 加粗标题 + 条目计数），库区仍在最上；②库条目右侧的块数槽换成「模板」胶囊标签（`_theme_accent()` 描边——**不能沿用 `palette.Highlight`**，暗色主题下它就是选中底色，选中行的标签会整块隐形）；③`StyleTreeWidget.populate` 的 `setExpanded(True)` 从 `addTopLevelItem` **之前**挪到之后：insert 前调是空操作（item 未入 view，展开态存不下来），此前库区与未分组区默认收起，库标题紧贴项目样式、两段连成一片。代价＝大样式成为区头子项、变体深度 2，`StyleTreeWidget.select_payload` 随之改为递归遍历。
* 变体节点修正：行 1 不再重复父级大样式名，改显示差异摘要（`overrides_summary`）；行 2 显示归属说明（父样式名）。
* 右栏 `ui/fontstyle_manager.py::StyleDetail` 新增 `MODE_GLOBAL` 库条目模式（`show_library_style`）：名称编辑 + 预览卡 / chip 行 / `ui/style_format_editor.py::FormatEditorPanel` 全部复用，块分布区留空；动作 = 复制到项目 / 从库中删除。六个次要动作收拢为一行随模式显隐，「应用修改」仍是唯一主按钮（动作按钮按角色上色：`primary`＝应用、`danger`＝两个删除、`accent`＝收藏到库/复制到项目，规则见 `config/stylesheet.css` 的 `QPushButton[btnRole=…]`）。**无选中态**（`StyleDetail.show_empty`：刚打开、或选中项被删后重选失败）整套内容收起、只留一句引导——六个按钮的显隐各自写在对模式的 `show_*` 里，没有模式时曾全部亮着挤成一行被裁且无从触发。
* 变体 / 未分组模式原靠预设做的「整包参数替换」由查找替换的格式替换承接（能力重叠，见 `docs/技术实现/查找替换与样式管理器重构_设计方案_存档.md`）。
