# 多菜单可配置环形菜单 设计与交接文档

> 状态：已实现并通过离线验证（2026-08-11）。
> 本文档面向两类读者：① 后续接手此功能的开发者；② 未来可能承担**视觉修缮**的多模态 AI（参照 `环形菜单_视觉修缮交接.md` 的格式习惯）。记录设计思路、写法、全部视觉常量位置、数据模型、已知 Qt 坑、待修缮/扩展清单。
> 改动未提交，git 规则见文末。

## 一、一句话现状

画布区环形菜单从"单一 Tab 触发、内容写死"升级为**多菜单可配置**：默认 3 个菜单（Tab=编辑 / X=对齐 / C=视图管线），每个菜单绑定一个触发键、扇区数可调（4/6/8），在 **设置 → 环形菜单** 页面拖拽配置命令摆放与堆叠（每扇区最高 3 张卡片）。命令池扩为四类（基础编辑/文本操作/管线/视图），新增 undo/redo/缩放/适配窗口/翻页 6 个命令。触发键与快捷键冲突实时标红。

**目视操作路径**：

- 运行时：启动 app → 打开图片 → 文本编辑模式 → 光标放画布上 → 按 **Tab / X / C** 各弹各的菜单 → 方向瞄准 → 松开触发（短按 pin、长按 release-commit，与旧版一致）。

**离屏渲染预览图**：`scripts/_pie_preview_{light,dark}.png`（`_pie_preview.py` 生成，使用默认 windows 平台插件保证字体渲染）。

## 三、设计思路（为什么这样做）

核心决策链（均经用户逐点确认）：

1. **多菜单 = 每菜单一个触发键**。现有交互状态机（按住 → 方向瞄准 → 松开提交；短按 pin）是极坐标交互，天然适配"按键查表 → 弹对应菜单"。状态机零改动，eventFilter 从硬编码 Tab 泛化为按键匹配（`MainWindow._pie_menu_for_event`）。相比 Blender 正宗的"嵌套子菜单"（hover 扇区滑出子饼），平级多键成本低一个量级；数据模型留 `layout` 字段为嵌套/非环形形态做扩展位。
2. **命令池复用 `COMMAND_REGISTRY`（单一事实来源）**。不给饼菜单另建平行命令目录；`CmdDef` 加 `category` 字段（basic/text/pipeline/view）供配置页分组。右键菜单（`build_fn`）与饼菜单（`run_fn`）共享注册表。新增的 6 个命令 `hidden_in_customize=True`，只进饼菜单池、不进右键菜单自定义列表。
3. **`run_fn`/`enabled_fn` 签名统一收 `MainWindow`**（`mw`，内部 `mw.canvas`）。因为翻页/模式切换在 MainWindow 上，画布命令在 canvas 上；统一签名后两种命令共用一条执行链。右键菜单的 `build_fn(menu, canvas)` 完全不动。
4. **配置页"上半真机预览、下半分类池"**。预览直接内嵌 `PieMenu`（`preview=True` 模式：不设 Tool 窗口 flag、鼠标仅 hover/点击/拖放、永不提交），**渲染代码零复制**——"和实际样式一致"由构造保证，不画第二份示意图。预览用 painter scale 统一缩放（几何仍走逻辑坐标）。
5. **触发键与文本输入的两套规则**。文本输入框焦点时：Tab 保持"惰性吞"（现状，不插 `\t` 不切焦点）；字母/组合键触发键完全放行（照常输入——否则把 X 设成触发键后翻译框里打不出 x）。非输入框焦点 + 光标在画布 → 触发。
6. **允许删到 0 个菜单** = 饼菜单自然关闭（查表为空即不触发），不引入单独的开关概念。上限 4（编辑器拦截并提示），因为"每菜单一个触发键"的记忆负担随数量增长。

## 四、数据模型与迁移

`pcfg.pie_menus: List[dict]`（`utils/config.py`），默认值 `DEFAULT_PIE_MENUS`：

```python
{
    "id": "edit",            # 稳定标识
    "name": "Editing",       # 默认名=tr key（pie_menu_display_name 翻译）；用户改名=自由文本
    "trigger": "Tab",        # QKeySequence 字符串；空串=不可用触发键
    "sectors": 8,            # 4 / 6 / 8
    "layout": "ring",        # 扩展位：未来非环形/嵌套形态
    "slots": [ [...], ... ], # 恰好 sectors 个列表，每列表 ≤3 个命令 id
}
```

- 默认 3 菜单模板的方向直觉映射：对齐菜单"顶→上扇区、底→下扇区、左→左、右→右"；视图管线菜单"4 个管线命令在上半、翻页在下（下=下一页、左下=上一页）、缩放/放大在左半"。
- **迁移**（`ProgramConfig.load`）：旧配置 `pie_sectors` 是默认值 → 整体换成 3 菜单模板；用户自定义过 → 内容作为第一个"编辑"菜单 + 补 2 个默认菜单（可删）。
- **归一化**：`ui/pie_menu.py::normalize_pie_menu` 保证 sectors∈(4,6,8)、slots 数量与长度合法；运行时 `PieMenu.set_menu_config` 每次触发前由 MainWindow 注入（`_pie_menu_for_event` 查表 → `set_menu_config` → `start_hold`）。
- 配置页直接改 `pcfg.pie_menus` 并 `save_config()`（与快捷键面板同款"实时保存"模式），下次按触发键即生效。

## 五、代码结构与实现索引（接手必读）

| 文件 | 职责 |
|------|------|
| `ui/pie_menu.py` | 菜单本体。状态机 + 扇区数参数化（`self._sector_count`）+ preview 模式（缩放/编辑态/拖放/点击选择/右键移除）+ 命中测试 `_hit_test` / `sector_at` / `_drop_insert_index` |
| `ui/pie_menu_editor.py`（新增） | 配置页：菜单 tab 管理 + 触发键/扇区数/名称 + 实时预览 + 分类命令池 + 拖放编排 |
| `ui/context_menu_config.py` | `CmdDef.category`、6 个新命令、`run_cmd(mw, id)`/`cmd_enabled(mw, id)` 签名 |
| `ui/mainwindow.py` | `_pie_menu_for_event` 按键查表；`_pie_handle_*` 泛化（Tab 类/字母类规则） |
| `utils/config.py` | `pie_menus` + `DEFAULT_PIE_MENUS` + `migrate_legacy_pie` |
| `utils/shortcut_conflicts.py`（新增） | `find_conflict_keys(mapping)` 纯函数，快捷键面板与触发键校验共用 |
| `ui/canvas.py` | 新增公开 `fitToWindow()`（薄封装私有 `_fitToWindow`） |
| `scripts/pie_menu_test.py` | 离线断言（含多菜单/迁移/编辑器逻辑） |
| `scripts/_pie_preview.py` | dark/light 预览图生成 |

**几何与命中（运行时与预览共用同一套）**：

- 卡片中心：`PieMenu._card_center`（半径 `CARD_RADIUS`，多卡片沿切线堆叠 `CARD_STACK_GAP`）。
- 命中：`_hit_test`（优先卡片矩形，回退整扇区方向）与 `sector_at`（仅角度）都在逻辑坐标下工作；preview 模式下鼠标/拖放坐标先除 `_preview_scale` 还原逻辑坐标。
- 拖放插入位置：`_drop_insert_index` 把落点投影到扇区切线，得出 0..k 的插入下标；同扇区移动时源移除会使目标下标 -1（`dropEvent` 内处理）。

**配置页交互信号**（`PieMenu` preview 模式对外）：

| 信号 | 含义 |
|------|------|
| `command_dropped(sector, idx, cmd_id, src_sector, src_idx)` | 拖放落地（src=-1 为池新增） |
| `slot_remove_requested(sector, idx)` | 右键卡片 |
| `slot_selected(sector, idx)` | 左键点击卡片（编辑态选中环） |

mime：`application/x-pie-cmd`（命令 id）+ `application/x-pie-src`（"sector,idx"，预览卡片拖出时携带）；`CommandPalette` 与 `PieMenu` 双向识别。

## 六、视觉常量与配色位置（视觉修缮必读）

全部视觉在 `ui/pie_menu.py`，几何常量在文件顶部：

```python
TOTAL_RADIUS = 210.0          # 逻辑菜单半径（窗口/预览直径 = 2×WINDOW_RADIUS）
WINDOW_MARGIN = 40.0          # 透明边距，防堆叠卡片被窗口边缘无声裁剪
CENTER_RADIUS = 42.0          # 中心圆环半径
CENTER_INNER_RADIUS = 22.0    # 中心扇形填充内半径（空心）
CARD_RADIUS = 142.0           # 卡片中心固定半径
CARD_PAD_X = 8.0 / CARD_PAD_Y = 4.0
NUM_MARGIN = 8.0 / NUM_WIDTH_EXTRA = 2.0
CARD_STACK_GAP = 4.0          # 同扇区多卡片切向堆叠间距
SECTOR_MAX_CARDS = 3
CARD_CORNER_RADIUS = 5.0
CENTER_RING_WIDTH = 2.0
TITLE_OFFSET_Y = 28.0
```

配色在 `paintEvent()` 的 `is_dark_theme()` 分支（深 `QColor(35,37,46,200)` 卡片底 / 浅 `QColor(255,255,255,220)`；中心环、扇区数字、卡片描边、标题均就地定义）。强调色用主题变量 `@accentPrimary`，文本 `@textColor`。

**新增的编辑态绘制**（仅 `preview=True` 且 `set_edit_mode(True)` 时出现，运行时完全不可见）：

| 元素 | 位置 | 说明 |
|------|------|------|
| 虚线扇区引导 | `_paint_edit_guides` | 文本色 alpha 45 的径向虚线，让空扇区"看得出能放" |
| 拖放目标高亮 | `_paint_drop_target` | 目标扇区整块 wedge（accent alpha 70）；满 3 时红色 `QColor(220,60,60,90)` |
| 选中环 | `_paint_cards` 内 | 选中卡片虚线圆角描边（accent，dash） |

预览缩放：`set_preview_scale(scale)` 只改 painter transform + widget 固定尺寸，几何不动（配置页用 0.72）。

## 七、已知 Qt 坑（改渲染/交互时必须知道）

1. **`QPen` 没有 `setAlpha`**（本轮踩过：`_paint_edit_guides` 最初 `pen.setAlpha(45)` 在 paint 里抛异常导致 grab 硬崩、无回溯）。透明度设在 `QColor` 上再传给 QPen。
2. **`QDrag` 在 Qt6 属 `qtpy.QtGui`**（不是 QtWidgets）。
3. **`QTabBar` 没有 `clear()`**——重建 tabs 需循环 `removeTab(0)`。
4. **`self.tr()` 返回 Python str**，无 `.arg()`；`%1` 占位符用 `.replace("%1", ...)`（PyQt 惯例）。
5. **PyQt6 `KeyboardModifier` 是 Flag 枚举，`int()` 不可用**——触发键匹配需 `getattr(mods, "value", mods)`。
6. **PyQt6 `QKeyEvent` 无 `globalPosition()`**——用 `QCursor.pos()`（既有约定）。
7. **离屏平台字体渲染异常**——`_pie_preview.py` 用默认 windows 平台插件。
8. **i18n_check 的隐式拼接盲区**：`self.tr("a" "b")` 跨行拼接检测不到（本项目规范禁用，配置页提示语已拆成单行字面量）。命令 label 与分类名全是 `tr(variable)`/`QCoreApplication.translate` 间接调用 → i18n_check 恒报 orphan，需按惯例在 ts 对应 context 手动加 `<message>`（`PieMenuEditor`/`Canvas`/`ConfigPanel` context 已补）。

## 八、待修缮 / 扩展清单

**视觉/体验（可交给多模态 AI）：**

- 弹出/扇区切换动画（缩放 + 淡入 ~80ms）——旧版阶段 1 明确跳过
- 卡片 hover 过渡（填充色渐变）
- 高分屏 DPR 高清文本适配（未做，草案）
- 编辑态虚线扇区引导的视觉细节（透明度/颜色随主题再调）
- 配置页预览区的容器观感（目前是居中裸预览，无面板底/投影）

**功能/架构扩展位（数据模型已留）：**

- `layout` 字段：非环形形态（线性条需要重写一套 hit-test，成本与嵌套子菜单同级）
- 嵌套子菜单（hover 扇区滑出子饼）——状态机需加一层
- 命令池继续扩（如模式切换/竖排切换等，补 `CmdDef` 即可入池）
- 扇区内"拖到卡片之间插入"的精细定位已实现（`_drop_insert_index`），但无"拖到边缘溢出换扇区"的跨扇区连续拖拽

**已知开放行为：**

- 菜单打开期间按**其它**菜单的触发键会取消当前菜单（复用 Tab 的取消语义）
- 删除全部菜单后 `pie_menus` 为空数组，运行时查表为空 = 饼菜单关闭（预期行为）
- 同一命令允许出现在多个菜单/扇区（有意不去重）
