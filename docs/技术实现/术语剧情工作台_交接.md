# 术语/剧情工作台 实现与优化交接

> 交接文档：面向接手本模块优化的 AI/开发者。覆盖功能实现、数据流、线程模型、UI 结构与已知的优化空间。文中引用一律 `路径::符号` 格式，均可在仓库中定位。

## 1. 定位与入口

术语/剧情工作台（glossary/story agent workbench）是主窗口左侧的浮层面板，用户在这里让 AI 阅读项目页面原文，产出**术语表**与**剧情上下文**（每页摘要 + 全局梗概）；这些数据随后被**翻译 agent** 在正式翻译时自动消费，形成闭环。

- 面板：`ui/glossary_agent_panel.py::GlossaryAgentPanel`（三页 Tab：Chat / Glossary / Story + 底部 Apply 行）
- 入口：`ui/mainwindowbars.py::LeftBar` 的 glossaryChecker → `ui/mainwindow.py::on_set_glossary_widget` → `_showWorkbenchPanel`/`_hideWorkbenchPanel`（与全局搜索同槽位的加宽版本，宽度常量 `ui/mainwindow.py::WORKBENCH_WIDTH`）
- 替代了已删除的 one-shot `GlossaryExtractorDialog`（登记于 `scripts/audit_registry.json`）

## 2. 架构总览：两套 agent、一份数据

```text
                    ┌─────────────── 工作台(准备数据) ───────────────┐
  项目页面原文 ──只读工具──▶ AI 会话 ──patch──▶ 草稿(Glossary/Story Tab)
                    │    (Chat 页指令驱动)        │ 人工审阅/修改
                    └──────────────────────────── ▼
                                  「Apply draft…」唯一落盘出口
                                   ├── 术语 json 文件 (pcfg.module.llm_glossary_path)
                                   └── 项目内存 (每页摘要 + 全局梗概, 随项目保存)
                                            │
                    ┌────────────── 翻译 agent(消费数据) ────────────┤
  翻译触发 ──▶ 按当前页匹配术语 + 梗概进 system 前缀 + 前页历史
                    └──▶ 多轮 function calling ──▶ submit_translations 落回文字块
```

两套 agent 共享 `modules/translators/trans_agent.py::AgentTranslator` 的 profile/客户端/重试/RPM 基建，但循环与提示词分开：

| | 翻译 agent | 工作台会话 |
|---|---|---|
| 循环 | `modules/translators/agent/loop.py`（收敛式，强制提交） | `modules/context_agent/session.py::run_agent_session`（会话式，纯文本回复即结束） |
| system prompt | `modules/translators/agent/prompts.py` | `modules/context_agent/prompts.py::build_system_prompt` |
| 写出口 | 仅 `submit_translations` | `submit_glossary_patch` / `submit_story_patch`（只写草稿，零写盘） |
| 只读工具 | list_pages / read_pages / search_blocks / get_page_info（`utils/ai_tools.py` 执行器） | 同左 + `read_page_summaries`（优先读草稿摘要，省 token） |

## 3. 数据流与存储位置

| 数据 | 存储位置 | 写入时机 |
|---|---|---|
| 术语表 | json 文件，路径 `utils/config.py::ModuleConfig` 的 `llm_glossary_path` | 工作台 Apply（`ui/glossary_agent_panel.py::apply_glossary`）；翻译设置区 Browse 只改路径 |
| 每页剧情摘要 | `proj._image_info[页名]["llm_visual_summary"]`（键常量 `modules/context_agent/story.py::PAGE_SUMMARY_KEY`） | 工作台 Apply（`apply_story`）→ 随项目保存持久化 |
| 全局梗概 | `proj` 的 `llm_compact_memory` 属性（`modules/context_agent/story.py::SYNOPSIS_KEY`） | 同上。注意：曾因 setattr 不落 `to_dict` 导致保存即丢，已修 |
| 翻译时用不用剧情 | 布尔开关 `llm_story_context`（`utils/config.py::ModuleConfig`） | 主窗口翻译设置区「注入剧情上下文」checkbox |
| 草稿（内存态） | `modules/context_agent/draft.py::GlossaryDraft` / `modules/context_agent/draft.py::StoryDraft`，worker 线程内为权威副本 | 打开面板时从上述存储载入基底 |

### 草稿保护机制（不要破坏的契约）

`modules/context_agent/draft.py` 的 patch 应用规则：用户手编行（origin=user）与基底行（origin=existing）**受保护**，AI 提议冲突时返回 conflict 行而不是应用；AI 只能改自己创建的行。`origin` 三态经 `ui/glossary_agent_panel.py::_ORIGIN_LABELS` 映射为 base/AI/you 显示。接手时不要把「AI 直接覆盖用户行」当优化点——这是设计。

## 4. 线程模型（关键契约，改动前必读）

`ui/glossary_agent_panel.py::GlossaryAgentWorker` 是 QObject，`moveToThread` 到自有 QThread。**它通过信号/槽（跨线程自动 QueuedConnection）执行，不能直接方法调用**——直接调用会在调用者（主）线程同步执行，长任务会冻结 UI（历史 bug，已修）。

- 面板 → worker 的操作入口全部是 `*:_requested` 系列信号（`instruction_requested` / `prefill_requested` / `glossary_edit_requested` / `glossary_remove_requested` / `synopsis_edit_requested` / `summary_edit_requested` / `summary_remove_requested` / `glossary_apply_requested` / `story_apply_requested`），在 `ui/glossary_agent_panel.py::_wire_worker` 连接。
- 唯一例外：`request_stop` 直调——只写取消标志，越早生效越好。
- worker → UI 是单向信号刷新（`log_line` / `chat_delta` / `glossary_synced` / `story_synced` / `round_finished` / `round_failed` / `applied` / `busy_changed`）；UI 永不直接读 worker 状态（busy 检查经 `GlossaryAgentWorker._busy` 布尔，GIL 下安全）。
- worker 生命周期：懒创建（面板 showEvent 且已打开项目）；项目切换时 `ui/glossary_agent_panel.py::refresh_project_state` 先 `_shutdown` 再按需重建。
- 翻译 agent 路径的线程语义不同：它跑在 `ui/io_thread.py` 的管线线程，与本面板无关，不要耦合。

## 5. 流式输出链路

```text
worker 线程: AgentTranslator._agent_chat(on_delta=…)      # stream=True 逐 chunk
  └ modules/context_agent/session.py::run_agent_session(stream_cb=…)  每轮透传
      └ worker: chat_delta.emit(delta)
          └ 主线程 UI: 80ms QTimer 节流合并 → 更新流式气泡(_flush_stream)
```

- `modules/translators/trans_agent.py::_agent_chat` 新增可选 `on_delta`：非 None 时走 `stream=True + stream_options.include_usage`，聚合出与非流式同构的 message（`modules/translators/trans_agent.py::_consume_agent_stream`，tool_calls 按 index 分片拼装）；端点 400 且报错含 "stream" 时自动降级非流式重发。
- 翻译管线（`_run_agent_task`）不传回调，维持非流式，行为不变。
- UI 侧状态机：`_ensure_stream_label` 创建气泡 → `_on_chat_delta` 累积 → `_flush_stream` 节流刷新 → `_finish_stream` 收束（`round_finished` 覆盖为最终回复；空内容气泡移除）。轮次边界靠 turn 状态行信号收束上一轮气泡。
- 未实现：流式期间无打字指示动画；Markdown 不渲染（纯文本 QLabel）。

## 6. UI 结构

### Chat 页（气泡流，参考已删除的旧 AI 助手面板实现）

- 容器：QScrollArea（widgetResizable）+ 垂直布局，末尾 stretch，新消息插在 stretch 前并滚动到底（`_insert_chat_widget`）。
- 四种消息控件，全部 QLabel + objectName 区分（无 QTextBrowser——历史 bug：引导 HTML 的列表/链接字符格式被 append 继承污染整个日志流）：
  | objectName | 用途 | QSS 落点 |
  |---|---|---|
  | `AIChatGuideCard` / `AIChatGuideTitle` / `AIChatGuideBody` | 顶部常驻引导卡 | `config/stylesheet.css`「Glossary/Story agent workbench chat bubbles」段 |
  | `AIChatUserBubble` | 用户指令，右对齐，最大宽 88% viewport | 同上，底色 `@accentPrimary20` |
  | `AIChatAssistantBubble` | AI 回复（含流式中气泡），左对齐全宽 | 同上，底色 `@bubbleAIBackground`（themes.json 既有主题变量） |
  | `AIChatStatusLine` / `AIChatErrorLine` | 轮次状态/落盘回执/错误小字 | `@disabledForegroundColor` / `@dangerColor` |
- 引导卡内示例指令是可点击链接（QLabel `linkActivated`，href=`cmd:<序号>`，序号查 `_guide_commands`——指令文本走 i18n，避免 QUrl 非 ASCII 编码问题）。
- 所有颜色走主题占位符（`ui/misc.py::build_stylesheet_from_dict` 替换），禁止硬编码色值。

### Glossary / Story 页

QTableWidget 草稿表 + 按钮行。表格样式在 `config/stylesheet.css`「Item views: tables」段（QTableWidget/QHeaderView::section/QTableCornerButton 全套主题化规则）——**这段是 Windows 10/11 原生 style 绘制分歧的修复**（Win10 windowsvista / Win11 windows11 画法不同导致表格融入背景），不要移除。Origin 列只读，文字按来源着色（`ui/glossary_agent_panel.py::_ORIGIN_THEME_KEYS`：base 灰 / AI 强调色 / you 绿，`ui/misc.py::get_theme_color` 解析主题变量，同步时计算——主题切换后需下次同步才刷新，可接受）；用户编辑经 `itemChanged` 回写 worker。

**Tab 徽章即状态总览**：`ui/glossary_agent_panel.py::_update_tab_badges` 在每次同步后把 Tab 标题刷为 `Glossary (N)` / `Story (已有摘要/总页数)`，不点进 Tab 也能看出准备度。

**引导卡动态化**：`ui/glossary_agent_panel.py::_refresh_guide_card` 按 UI 镜像统计（缺摘要页数、术语表是否为空）生成三条指令（补摘要 / 首次提取或校对术语 / 检查摘要时效），同步与项目切换时重建；统计来源是两张表而非 worker 状态。

**一键准备**：Apply 行左侧「Prepare for translation…」（`ui/glossary_agent_panel.py::_on_prepare`）= 词频 prefill（无 AI）+ 组合 AI 指令（补术语 + 补缺失摘要 + 更新梗概，以用户气泡上屏）。属耗时/耗费操作，先经 `ui/glossary_agent_panel.py::_prepare_confirmed` 弹窗说明步骤与 API 花销；「不再询问」写 `pcfg.workbench_confirm_costly`（`utils/config.py::ProgramConfig`，默认 True）并立即 `save_config()`，恢复入口在翻译设置区 Context 框的 checkbox（`ui/mainwindow.py` LLM context settings 段）。

### 空态限制（未打开项目）

- 判据：`ui/glossary_agent_panel.py::has_project`——`proj.directory` 非空（与 `ui/mainwindow.py` 现有守卫同语义）。
- 实现：面板根改为 QStackedWidget，page 0 是空态提示页（objectName `WorkbenchEmptyHint`），page 1 是三页内容；空态时内容页整体不可达，天然禁用全部交互。
- 刷新点：`ui/mainwindow.py::openDir` 与 `openJsonProj` 成功路径末尾调用 `refresh_project_state`（`openImages`/`saveProjectAs` 都走 openDir，自动覆盖）；`showEvent` 仅在 `has_project` 时建 worker。

## 7. i18n 约定

- 本模块的 tr 字符串分两类：面板实例方法内的 `self.tr()` 正常走扫描；`ui/glossary_agent_panel.py::_STOP_REASONS` / `_ORIGIN_LABELS` 是模块级翻译表，已在字面量定义处用 `QCoreApplication.translate` 显式标注上下文（AGENTS.md 规则）。
- 同步命令：`python scripts/ts_auto_fill.py --fill-missing --apply`，译文手工补（含引号串注意 XML 转义差异：ts_auto_fill 写 `"`, 手工脚本用 `&quot;`）。

## 8. 已知薄弱点与优化方向（接手 AI 的工作清单）

按建议优先级排列；动手前先读第 4 节线程契约。

1. **Chat 历史不持久化**：面板关闭/项目切换即丢对话气泡。可考虑随项目目录存一份会话日志（注意只存展示层，草稿状态仍以 worker 为准）。
2. **AI 回复不支持 Markdown/富文本**：当前纯 QLabel。换 QTextBrowser（每个气泡独立实例，避免旧版共用文档状态的坑）可支持代码块/列表；注意 QTextBrowser 高度自适应需手动 `document().size().height()`（旧 AI 助手面板的实现可考：git 提交 `8326a8e` 的父提交里曾有 `ai_chat_panel.py`，其 `append_stream_chunk` 有现成做法）。
3. **打字指示缺失**：流式首 delta 前（工具调用轮可能长达数十秒）气泡显示静态「…」。旧版有三点脉冲动画（QTimer 350ms）可移植。
4. **气泡时间戳/复制按钮**：旧版有 hover 复制/删除操作钮，本次为减法未移植；若用户反馈需要可从旧 AI 助手面板（同上 git 历史）的 hover 操作钮实现借鉴。
5. ~~**引导卡指令是静态三条**~~ 已做：按项目状态动态生成，见第 6 节「引导卡动态化」。
6. **表格全量重建**：`_sync_glossary_table`/`_sync_story_tab` 每次 setRowCount 全量重建，术语上千行时可能卡顿；可做增量 diff。
7. **流式降级只覆盖 BadRequestError 含 "stream"** 的端点；其他不兼容端点（如某些网关对 stream_options 报错）会直接失败，可扩大降级面。
8. **`llm_glossary_path` 空时 Apply 走文件对话框**（`_on_apply`），但用户取消时剧情草稿也不会应用（两个 apply 是原子批）——语义可拆分或提示。更大胆的方向：Apply 按钮显示变更计数（「应用草稿 (N 项变更)」）或自动应用，取舍待用户拍板。
9. ~~**Glossary 页「Prefill (frequency)」按钮**~~ 已改名「Extract by frequency / 从词频提取候选」并加 tooltip 说明与 Chat 指令的关系。
10. **实机未验收项**（本交接前的实现批次）：Win11 表格边界观感、流式逐字效果、气泡宽度在侧栏拉伸时的自适应（`resizeEvent` 重设用户气泡最大宽）。
