# 全局样式库 设计方案

## 1. 背景与目标

引入 Aegisub 样式库的分层模型：用户自己维护一套**跨项目持久**的全局样式模板，每个项目保留**独立**的项目样式，两者之间双向复制。此前样式管理器里只有「存预设 / 应用预设」（`ui/fontstyle_manager.py` 的 `_save_base_as_preset`/`_apply_preset`，写入 `utils/config.py::text_styles`）这一雏形：它只做到「把参数批量应用到块」，没有「复制为项目样式」的语义，也没有浏览/改名/删除的管理界面，且与右侧文本面板的快速预设共用同一份存储。本方案以真正的全局样式库取代该机制。

目标行为（2026-09-20 用户确认）：

* 全局样式库 = 用户可编辑、保存、持久化的真全局样式集合。
* 项目样式独立存在；全局 ↔ 项目双向复制，拷贝语义（无引用），两边各自演化。
* 样式管理器交互顺势改进：预设行退役、动作区收拢、新建样式入口、变体节点信息修正。

## 2. 数据层

`utils/global_styles.py`（新增）：

* 存储：`config/global_styles.json`（`utils/shared.py::GLOBAL_STYLES_PATH`，已 gitignore）。文件为裸 JSON 数组，条目结构与项目内大样式同构——直接复用 `utils/base_styles.py::BaseStyle` 的 `to_dict`/`from_dict`。
* 模块级单例列表 `utils/global_styles.py::global_styles`；`load_global_styles` 容错加载（坏条目跳过、坏文件不致命），`save_global_styles` 原子落盘（tmp + replace），每次改动后立即调用，不依赖应用退出。
* 库内 `name` 唯一（`utils/global_styles.py::unique_name` 冲突自动加后缀）；身份键 `(font_family, vertical)` 允许重复——模板可以同字体同方向不同参数并存，冲突只在复制到项目时按项目侧规则处理。
* `add_style` 深拷贝入库；`find_by_name` 供 UI 按 payload 定位条目。

**人工在环约束：库是纯模板存储，绝不自动应用到任何块。** 生效路径唯一：复制进项目 → 块按身份键归组（`utils/base_styles.py::discover_style_tree`）→ 用户在样式管理器显式批量应用。复制到项目不重排块——只有身份键吻合的块自动归属，与 Aegisub「把样式拷进脚本不重刷已有台词」一致。

## 3. 复制语义与冲突规则

**库 → 项目**（`ui/fontstyle_manager.py::_copy_global_to_project`）：

1. 项目内已有同身份键大样式 → 弹窗「覆盖其参数 / 取消」（唯一弹窗场景）。覆盖 = 替换该样式的 `fontformat` 并改名，块归属关系不变，变体在重发现时自然重算。
2. 仅名字冲突（身份键不同）→ 自动加后缀「{name} 2」，不打扰。
3. 无冲突 → 追加新 `BaseStyle`（深拷贝），发 `data_committed` 持久化项目 JSON 并重选中。

**项目 → 库**（`ui/fontstyle_manager.py::_add_base_to_library`，大样式模式动作「收藏到库」）：

1. 库中已有同名条目 → 弹窗「覆盖 / 取消」，覆盖 = 整条替换 `fontformat`。
2. 无冲突 → `add_style` 深拷贝入库。项目数据不动，不发 `data_committed`。

**库内编辑**（`ui/fontstyle_manager.py::_apply_library_entry`）：编辑器值全量写回条目（模板无块级 override，不存在「只 flatten 改动字段」的问题），`sync_face` 重算 face 缓存后落盘。改名走 `ui/fontstyle_manager.py::_on_name_edited` 的库分支（冲突自动后缀）。

## 4. UI 结构

左树（`ui/fontstyle_manager.py::StyleTreeWidget`）：

* 顶部新增「全局样式库」表头区（复用「未分组」的加粗不可选中表头行做法），条目为两行节点（名称 + 参数摘要 + 色板），payload `{"type": "global", "name": ...}`。
* 左列底部加「新建样式」按钮（`ui/fontstyle_manager.py::_new_library_style`）：在库中新建条目并直接进入编辑——补齐了此前「只能从未分组提升」的创建路径。
* 变体节点修正：行1 原来重复父级大样式名，改为显示差异摘要（`overrides_summary`），行2 显示归属说明（父样式名）。

右栏（`ui/fontstyle_manager.py::StyleDetail`）新增 `MODE_GLOBAL` 库条目模式（`ui/fontstyle_manager.py::show_library_style`）：名称编辑 + 预览卡/chip 行/`ui/style_format_editor.py::FormatEditorPanel` 全部复用，块分布区留空；动作 = 复制到项目 / 从库中删除。

动作区重排：六个次要动作（重置为基准 / 提升为大样式 / 收藏到库 / 删除样式 / 复制到项目 / 从库中删除）收拢为一行，随模式显隐；「应用修改」仍为唯一主按钮。

**预设机制退役**：`_preset_combo`/`_apply_preset`/`_save_base_as_preset` 整体移除（职责被全局库取代）。变体/未分组模式原靠预设做「整包参数替换」的场景由查找替换的格式替换承接（能力重叠，见《查找替换与样式管理器重构_设计方案.md》§10）。`utils/config.py::text_styles` 原样保留给右侧文本面板快速预设，不做迁移。
