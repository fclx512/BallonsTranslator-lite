## 二、现状事实基础（普查结论，写给实现者）

1. **栈为画布级单实例**（`ui/canvas.py` 的 `text_undo_stack` / `draw_undo_stack`），非每页一栈；切页入口 `ui/mainwindow.py::pageListCurrentItemChanged` 统一调 `ui/canvas.py::clear_undostack`（双栈整体 clear）。**清栈的真正原因不是栈是页级的，而是命令持有 `TextBlkItem` 引用、场景重建后引用失效**（`ui/scenetext_manager.py` 注释明示）。
2. **清栈调用点清单**（跨页化后需逐个改语义，见三.8）：切页、`_rerender_dirty_pages`、批量渲染循环、txt/md 导入、`on_batch_rollback`、翻译回填（`ui/scenetext_manager.py::updateTranslation`）、场景重建分级（`ui/scenetext_manager.py::updateSceneTextitems`）。
3. **块标识**：`TextBlkItem` 只有位置序号 `idx`，`TextBlock` 无 uuid；但底层 `TextBlock` 对象随 `proj.pages` 存活、切页重建场景时被复用——可作跨页锚点。唯一整体换新路径是检测管线 `pages[imgname] = blk_list`。
4. **管线写入不走栈**：检测/OCR/整页翻译在工作线程直写数据，屏障靠「完成即切页清栈」+ `page_changing` 旗标 + 选中块翻译的 `_blktrans_at_page` 页守卫。无任何栈外写入拦截机制。
5. **全局替换**：`ui/textedit_commands.py::GlobalReplaceApplier`，多页直写数据 + `utils/proj_imgtrans.py::write_batch_backup` 项目级快照，回滚条 `restore_batch_backup` 整体还原 + 全栈清空。**已拍板保持分治不动**（一.2），但其回滚路径的「全栈清空」在跨页历史下语义要复核（三.8）。
6. **整理换行已是跨页单命令**：`ui/textedit_commands.py::NormalizeBreaksCommand` 一次手势跨页入栈、一次 Ctrl+Z 全退——但切页即丢。它是第一批改造的现成受益者与验收样本。
7. **历史面板一期**：`ui/history_panel.py::HistoryPanel`，QUndoView 直连 `text_undo_stack`，循环 `canvas.undo()/redo()` 跳转（安全阀 `_JUMP_STEP_CAP`），`cleanIndex` 行右缘圆点。绑定死文本栈 + launcher 装在文本面板窄栏，故绘制栈无入口。
8. **undoLimit 空栈限制**：`ui/canvas.py::apply_undo_limit` 仅空栈时 `setUndoLimit` 生效；跨页历史落地后文本栈几乎不再清空，该限制的触发窗口变化见三.7。
9. **修复命令**：`ui/drawing_commands.py::InpaintUndoCommand` 每步存前后两份矩形图像 numpy 副本 + 遮罩副本，引用页级缓冲 `proj.inpainted_array` / `proj.mask_array`；切页随栈清空释放。
10. **键入/格式化命令**：`ui/textedit_commands.py::TypingSessionCommand` / `ui/textedit_commands.py::FormatGestureCommand` 为快照命令，同样持有 item 引用，是去 item 化改造的主体。

## 三、第一批：跨页编辑历史（核心，先做）

### 3.1 栈形态与总不变量

- 文本域单一全局线性栈（沿用画布上的 `text_undo_stack` 实例，不新建栈）；每条命令携带 `pagename` 标签。绘制栈维持页级现状不动。
- **总不变量：undo/redo 永远在「命令所属页恰为当前页」时执行。** 跨边界不静默——走 3.4 的二次确认跳页。这把「非当前页重放」这个最大的技术风险（跨场景重建重放）整体消解掉，重放路径与现状完全一致。
- 切页**不再清文本栈**（绘制栈照旧清）。这是对 `ui/canvas.py::clear_undostack` 语义的拆分：文本栈从「clear」改为「按页失效」（3.3）。

### 3.2 命令去 item 化（锚点 + 执行期重解析）

1. 命令不再直接持 `TextBlkItem` 引用，改持**锚点二元组 `(pagename, TextBlock 对象引用)`**；快照内容（HTML 对 / FontFormat 值）不变。
2. 执行期重解析：undo/redo 先经 `ui/scenetext_manager.py` 的 blk→item 映射定位当前场景里的活 item（重建场景时维护该映射），再走既有重放路径；面板 widget 同理重解析。定位失败（块被删/页失效）→ 命令僵尸化（3.3）。
3. `TypingSessionCommand` / `FormatGestureCommand` / `NormalizeBreaksCommand` 等全部活文本命令统一改造；多块命令持锚点列表。

### 3.3 页身份与失效判定（页屏障细化，决策 6）

- **失效判定用页代数计数器**：每页维护 `edit_generation`（初始 0）；检测管线等栈外整体写入（`pages[imgname] = blk_list`）时对该页 +1。命令入栈时捕获当时的代数值；执行期代数不一致 → 该命令判定为**僵尸命令**。
- 僵尸命令的 undo/redo = 无操作，栈位置照常移动，toast 提示「该步所属页已被管线重写，已跳过」；历史面板中灰显（标题加后缀，如「(已过期)」）。不在栈中移除（QUndoStack 不支持中段删除），保持线性位置数学简单。
- **清栈语义重定义**：原「clear 整栈」的页级触发点（切页、翻译回填、当前页重载）改为「仅把该页的命令段僵尸化」；项目级触发点（工程重载、txt 导入、批量重渲）保留整栈 clear。逐点归属见 3.8。

### 3.4 跨页撤销边界交互（「再按一次才继续」状态机）

1. Ctrl+Z 时若下一命令的 `pagename` ≠ 当前页：**不执行**，toast「下一步将撤销第 X 页的编辑：再按一次继续」，并置 armed 标志（记录目标命令）。
2. armed 期间再按 Ctrl+Z：跳页（复用 `pageListCurrentItemChanged` 全链路：未决变换归属、条件保存、`set_current_img`）→ 跳页完成后**继续执行该步 undo**。一次按键 = 跳页 + 撤一步，不连撤。
3. **armed 失效条件**：任何其他操作（键入、格式化、切页、保存、面板点击）即解除 armed，避免陈旧确认误伤。超时不设（toast 消失但 armed 保留到下次操作，行为可预期）。
4. redo 对称：redo 越过页边界同样二次确认。
5. **历史面板行点击跳转不设二次确认**：点击目标行是显式意图，跳转循环（`HistoryPanel._on_row_clicked`）跨页时自动切页续走，每步仍是「先切到命令所属页再执行」。

### 3.5 历史面板按页分组

- QUndoView 直连栈模型是平铺的；分组展示需在 `ui/history_panel.py` 引入一层自定义 model/proxy：按命令的 `pagename` 聚合插入页头行（页名 + 该页剩余步数），命令行保持行号 = 栈位置语义（一期已定）。
- 保存点圆点逻辑不变（cleanIndex 行标点）；僵尸命令灰显。
- 绘制栈仍无入口（一期拍板搁置，维持）。

### 3.6 保存点语义升级为项目级

- 现状：条件保存发生在切页，`setClean()` 标记当前位置。跨页历史下保存动作升级为**项目级语义**——一次保存 = 全项目文本数据落盘 + `setClean()`，cleanIndex 表示「此位置之前的所有页编辑均已保存」。这与既有 `test_undo_limit.py` 的结论兼容（保存点被 undoLimit 截断 → cleanIndex -1 → 不假报已保存）。
- 撤销越过 cleanIndex → `isClean()` 转 False（有未保存修改），语义自然成立，无需新增按页脏判定；按页粒度的脏提示仍由 `_pages_needing_rerender` 体系（结果图层）承担，二者不合并。

### 3.7 undoLimit 影响复核

- 文本栈不再随切页清空 → `ui/canvas.py::apply_undo_limit` 的「空栈才生效」窗口大幅缩小：启动时与项目级 clear 时仍可设置；会话中途改上限基本不再落地（Qt 限制）。**接受为已知限制**并在设置项旁提示「切换工程或重载后生效」，不做 Qt 外的自造截断。
- 文本快照成本极小（0-c 探针：约 200 字符块重放 0.06 ms、100 条命令约 114 KiB），默认 `undo_steps_limit = 0`（无限）维持不变。

### 3.8 清栈调用点逐点改语义（实施清单）

| 触发点 | 现状 | 改为 |
| --- | --- | --- |
| 切页（`pageListCurrentItemChanged` / `_on_stylemgr_navigate`） | `clear_undostack` | 仅绘制栈 clear；文本栈不动 |
| 翻译回填（`ui/scenetext_manager.py::updateTranslation`） | `clear_text_stack` | 当前页文本段僵尸化 |
| 当前页重载（`SceneTextManager.updateSceneTextitems` 的 CURRENT_PAGE_RELOAD 级） | `clear_text_stack` | 当前页文本段僵尸化 |
| 工程重载 / txt·md 导入 / 批量重渲 | `clear_undostack` | 保留整栈 clear |
| 全局替换回滚（`on_batch_rollback`） | `clear_undostack` | 保留整栈 clear（快照整体换入后栈上所有命令不相干，语义仍成立） |
| 选中块翻译完成 | push `RunBlkTransCommand` | 不变（本就入栈，获得跨页存活） |

### 3.9 护网测试

- 扩展 `tests/test_undo_safety_net.py`：跨页交错序列（A 页编辑 → B 页编辑 → 回 A 页 → 撤 A → 越界 armed → 二次按键跳页续撤）；僵尸命令跳过；代数失效（模拟检测管线换 blk_list）；redo 对称越界。
- 新增：切页后历史仍在；面板行点击跨页跳转；保存点项目级语义（A 页保存 → 撤 B 页 → isClean 转 False）；undoLimit 限制回归（`tests/test_undo_limit.py` 既有结论不破）。

## 四、第二批：跨页批量组化 + 撤销确认弹窗（决策 4）

1. **范围**：用户发起的跨页批量编辑类操作——整理换行（`ui/textedit_commands.py::NormalizeBreaksCommand`）与**高级对齐（`ui/mainwindow.py` 的 `_PointAlignCommand`，2026-09-06 补入：它本就跨页入栈，同样存在撤销影响他页无提示的问题）**为首批受益者；字体样式管理器、全局替换**不入栈**（后者已拍板分治）。
2. **撤销前确认弹窗**：撤销目标是组化命令时，先弹对话框列出影响的页/块数，附「同时重渲染脏页」勾选（复用 `ui/mainwindow.py::_ask_rerender_dirty_pages` 流程）；确认后才执行 undo。组化命令在历史面板中显示为单行（组名）。
3. **组内仅存端点快照**（决策 4）：沿用 `NormalizeBreaksCommand` 既有模式（构造期抓 old、redo 侧持终值），不记录中间态。
4. 与第一批的接缝：组化命令同样带页标签与代数捕获；其覆盖多页 → 任一所属页代数失效即整组僵尸化。

### 4.1 落地备注（2026-09-06 实现定稿）

1. **确认门位置与豁免**：门在 `ui/canvas.py::_confirm_group_undo`，位于跨页门与僵尸判定之后——僵尸组命令不弹（本就无操作）；历史面板跳转路径（`auto_cross_page=True`）不弹（显式意图，且跳转可能途经多条组命令，逐条弹窗不可用）；仅影响当前页的组命令不弹（与普通撤销无异）。redo 方向不设确认。
2. **影响面接口**：命令暴露 `group_undo_summary()`（页名→块数，弹窗明细与历史面板摘要共用）与 `group_page_generations`（构造期多页代数快照，`ui/textedit_commands.py::command_page_stale` 对其逐页比对）。
3. **「同时重渲染」路径保留撤销历史**：`ui/mainwindow.py::_rerender_dirty_pages` 增加 `clear_history` 参数，组化撤销的重渲请求传 `False`——数据未变仅重渲图像，清栈会丢掉刚做撤销的 redo 能力；既有调用方（全局替换回滚等）保持清栈不变。
4. **标脏补缺**：两条组化命令在 redo/undo 时对非当前涉及页 `mark_page_needs_rerender`（此前整理换行/高级对齐改他页数据不标脏是既有缺口）；当前页不标脏语义不变。
5. **`_PointAlignCommand` 补齐锚点化**：item 引用改存 blk 身份（`(blk, old_pos, new_pos)`），执行期经 `ui/textedit_commands.py::resolve_blk_item` 重解析——原实现重放到脱离场景的隐形 item 上，属第一批同类隐患的存量点。
6. 护网：`tests/test_undo_group_confirm.py`（11 条：摘要/多页代数僵尸/确认拒绝与放行/auto 路径豁免/单页豁免/标脏/blk 锚点重解析/面板摘要）。
7. **闪退修复（实机验收发现）**：确认弹窗复选框无父构造传 `setCheckBox` 不留引用，PyQt6/Qt 6.11 下被 GC 回收 → 悬空指针 access violation 无声闪退（AV 行号随 GC 时机漂移）。修复 = 构造期挂父 `QCheckBox(text, box)`；完整教训见 [`docs/基础速查/经验教训.md`](../基础速查/经验教训.md) §3.3。

## 五、第三批：图像修复并入全局栈 + 命令瘦身（决策 5 + 2026-09-06 合并拍板）

> 2026-09-06 用户拍板合并（推翻本节旧「先只做瘦身、并入另议」倾向），核心取向：**尽可能省内存**；修复区保留独立体验但须让用户知道其仅当页有效。

1. **单一栈、双视图（防双真值源）**：修复命令只入全局跨页栈一份（不再以独立 draw 栈承载修复历史）；修复区的「独立历史面板」是全局栈的**当前页过滤视图**，不是第二份栈——同一操作双栈双入必失同步。切页时视图自然清空（即「切页就清理」的观感）、回到该页恢复显示；面板头部加提示（如「仅显示当前页的修复历史，跨页撤销请在全局历史中继续」），放置位置实施时定。
2. **端点快照省内存**：命令自持「修复前区域裁剪 + 最后一次修复后区域裁剪」，不再持页级图像缓冲引用/整矩形副本——快照自包含是跨页存活可行的前提（执行期合成进当页图像数组）。同区域连续修复聚合为一步（决策 5），仅存首前末后，不记中间态。`ui/drawing_commands.py::InpaintUndoCommand` 为改造主体。
3. **失效判定扩展**：第一批页代数机制扩展到图像侧——修复管线重跑、遮罩编辑、重渲等对页图像的栈外写入均使该页代数 +1，僵尸化语义与文本侧一致。
4. **交错撤销 UX**：全局栈中修复与文本命令按时间序交错，Ctrl+Z 跨模态回退；命令操作名标「图像修复」类文案，越页走第一批 armed 门；修复区面板行点击跳转沿用历史面板 `auto_cross_page` 语义。文本历史面板是否显示修复行实施时定（倾向显示，保持全局线性史完整心智）。
5. **分步实施（两个原子提交）**：3a 先在页级栈内完成 `InpaintUndoCommand` 瘦身（纯内存收益，当前行为不变）；3b 并入全局栈 + 修复面板过滤视图 + 提示文案。任一半可独立 revert。
6. 前提纪律：省内存方案以页屏障纪律为前提（栈外管线写入使该页历史整体作废，不存在半新半旧还原）——第一批的代数机制是其地基，图像侧扩展见本节 3。

### 5.1 落地备注（2026-09-06，3a 已实现待实机验收）

1. **聚合机制手写而非 Qt `mergeWith`**：`ui/drawing_commands.py::InpaintUndoCommand` 新增 `try_absorb`，由栈顶命令吸收新命令的 redo 端点（`redo_img`/`redo_mask` 换引用），undo 端点（首前快照）不动；绕开 Qt 合并是因为 `QUndoStack` 的 merge 时机与绘制栈手工计数器（`num_pushed_drawstep`/`saved_drawundo_step`）无法对齐——合并时栈 index 不动会被 `push_draw_command` 误判为截断。
2. **入口钩子在 `ui/canvas.py::push_draw_command`**：聚合条件 = 栈顶（`index()==count()`）+ 已有未保存改动（`saved_drawundo_step != num_pushed_drawstep`）+ 栈顶命令带 `try_absorb` 且吸收成功。干净保存点上不聚合——对保存点所在的干净命令吸收会让撤销越过保存点、回不到已保存状态；非栈顶（有 redo 残尾）不聚合，push 截断路径照旧。
3. **聚合后手动 `command.redo()`**：正常 push 由 Qt 调 redo 写缓冲，吸收路径命令不入栈须手动等价执行；计数器与 `saved_drawundo_step` 均不动（脏态保持，与栈坐标一致）。
4. 护网 `tests/test_inpaint_undo_merge.py`（9 条：单步聚合/首前非中间态/端点接管/异矩形/杂命令打断/干净点不聚合/非栈顶不聚合/记账不变量/跨画布拒绝）。

### 5.2 落地备注（2026-09-06，3b 已实现待实机验收）

1. **只迁修复命令**（`ui/drawing_commands.py::InpaintUndoCommand` 类标记 `image_history=True`）入全局栈，涂鸦（`StrokeItemUndoCommand`）留页级绘制栈维持现状——涂鸦层切页清空、内容经落盘合成进修复图，跨页存活需图层锚点化，收益风险比不划算（可推翻点）。`ui/canvas.py::push_undo_command` 按 `image_history` 先于模式分流到 `push_image_command`（原 3a 聚合钩子随之从 `push_draw_command` 移入）。
2. **图像代数独立计数**：`utils/proj_imgtrans.py::page_image_generation`/`bump_page_image_generation` 与文本代数分开（共享计数器会互相误杀：检测重跑不该作废修复历史、文本重写不该作废修复历史同理）。`ui/textedit_commands.py::command_page_stale` 按 `page_image_generation` 属性分支比对；`ui/canvas.py::_tag_text_command` 对图像命令捕获图像代数。`InpaintUndoCommand.undo/redo` 补自守卫（僵尸无操作，与文本快照命令同型）。bump 点：检测管线（遮罩重写）、修复管线（`ui/module_manager.py` 直写修复图）、切页/重渲循环离页时图像侧仍脏（`ui/mainwindow.py`，条件保存成功则不触发——保存点状态经磁盘重载精确复现，跨页往返历史存活）。
3. **图像脏记账第二对计数器**：`num_imgstep`/`saved_imgstep` 维护不变量 = 全局栈 `[0, index)` 区间图像命令数（保存点对应 cleanIndex 位置），驱动 `draw_change_unsaved`（修复图/遮罩落盘门 `save_rst_only` 语义不变）与 `update_saved_undostep`。涂鸦 Legacy 计数器不动、切页照旧清零；图像计数器项目级、切页不清。`push_image_command` 处理 undoLimit 截断平移（截断数 = `index0 + 1 - 新 count`，恰好隔离前端截断——push 撤销残尾的删除在差值中相消）；`_text_undo_step`/`_text_redo_step` 按消费命令同步 ±1。`invalidate_text_history_for_page` 跳过图像命令（文本原地重写不作废修复快照）。

## 六、回退路径与实施纪律

1. 三批各自原子提交，任一批可单独 `git revert`；第一批内部若过大，可再拆「栈语义+锚点改造」与「面板分组」两个提交。
2. 每批完成判据：`scripts/verify.py` 全绿 + 护网全绿 + 实机人工验收（验收场景表在第一批实施时扩充进人工验收场景文档）。
3. 中止判据沿用主计划：出现无法在一个工作日内定位的回归 → revert 该批。

## 七、风险清单

1. **跳页时机与异步加载**：armed 确认后的跳页走完整切页链路（含场景重建、图像加载），跳页完成后续撤一步的实现要挂在切页完成的确定点上，避免竞态。
2. **面板 widget 重解析**：命令 undo/redo 不仅要重找 item，还要重找配对的 `TransTextEdit`/`SourceTextEdit`（`pairwidget_list` 随场景重建），漏一处即画布-面板失同步（护网必须覆盖）。
3. **僵尸命令的用户心智**：连续多个僵尸步会让 Ctrl+Z「按了没反应」（有 toast），需在历史面板灰显 + toast 文案里把原因说清。
4. **QUndoView 分组改造**：自定义 model 与 QUndoView 内建行为的兼容（空标签首行、行号映射）是纯 UI 工作量，无技术风险但要防回归一期功能。
5. **休眠拷贝**：`ui/text_engine/editing/` 下存在同型休眠代码（`manager.py` 等），改造只动 `ui/scenetext_manager.py` 活代码，休眠拷贝内符号不作参考。
6. 全局栈使命令生命周期变长：快照持有 HTML/格式值内存随会话累积，默认无限上限下需在验收时观察长会话内存（必要时建议用户设上限）。

## 八、明确不做

- 不做分支/树状历史（决策 3 已定线性）；
- 不做撤销历史跨会话持久化（关闭工程即丢，沿主计划）；
- 全局替换不并入栈、不留双轨（一.2 拍板）；
- 字体样式管理器批量改动不入栈（决策 4 范围仅整理换行类）；
- 绘制栈不并入第一批全局栈（第三批并入，2026-09-06 拍板，见五）；
- 不在 Qt 外自造撤销步数截断（3.7 已知限制接受）。
