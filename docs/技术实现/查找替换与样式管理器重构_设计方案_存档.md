# 查找替换与样式管理器重构 设计方案

> 状态：已完结归档（2026-08-28 定稿，阶段 1-4 已实机验收）——本篇为压缩存档，只留结论与指针；实施过程见 git 历史。

## 1. 目标与范围
Word 式查找替换（文本外还能按**样式条件**查找并替换样式）+ 样式管理器 UI 重构（原左树参数不可见、右栏控件平铺）：

1. 纯数据层**块查询引擎**（`utils/style_query.py::BlockQuery`）：文本谓词与格式谓词自由组合，查找替换与样式管理器共用。
2. **统一替换提交流程**：单一"仅替换数据"按钮 + 脏页处理询问，取代原双替换按钮。
3. 样式管理器 UI 按"差异优先、预览即数据"重构；编辑器控件与查找替换格式条件编辑器同源。

**范围决策：只做块级 FontFormat 替换，不做字符级（rich_text 内联格式）**——字符级是另一套数据模型，留作将来独立议题。

## 2. 沿用的现状
- 查找/收集：`ui/global_search_widget.py::GlobalSearchWidget`（原文/译文/全部 + 正则/大小写/全词 + 结果树跳转）；`ui/global_search_widget.py::_collect_replace_targets` 的"当前页暂存 live widget、非当前页直写 `TextBlock` + `utils/proj_imgtrans.py::mark_page_needs_rerender`"**脏页语义正确，直接沿用**（搜索直读 `pages` 数据、不经渲染层，故查询引擎离屏可测）。
- 原双替换路径（`ui/global_search_widget.py::on_replace` 与已删除的"替换并全部重渲"按钮）阶段 2 合并为单按钮（§4.2）。
- 样式侧：身份键 `utils/base_styles.py::BaseStyle` = `(font_family, vertical)`，变体派生 `utils/base_styles.py::compute_override` / `utils/base_styles.py::discover_style_tree`；**部分属性替换语义已存在**——`ui/fontstyle_manager.py::_collect_changed` 只把动过的字段做成 patch，`utils/base_styles.py::build_flatten_changes` / `utils/base_styles.py::build_variant_changes` 生成全项目 `{pagename, blk_idx, old_ffmt, new_ffmt}` 交 `ui/fontstyle_manager_commands.py::BatchFontformatCommand`。**要解开的缺陷**：查询能力锁死在样式身份键上，做不了"字号 ≥20 且描边为红"这类自由组合。
- 脏页链路：`utils/proj_imgtrans.py::mark_page_needs_rerender`（唯一写入口，仅非当前页）/ `ui/mainwindow.py::pageListCurrentItemChanged`（切页惰性重渲）/ `ui/mainwindow.py::_rerender_dirty_pages`（批量）/ `ui/mainwindow.py::_sync_and_commit_project`（落盘）。

## 3. 总体架构：BlockQuery 谓词引擎（已落地，阶段 1）
```text
BlockQuery（utils/style_query.py::BlockQuery）
  text:   TextPredicate    # 复用 global_search_widget 的匹配能力：原文/译文/正则/大小写/全词
  format: FormatPredicate  # 字段级谓词：语义字段 → 目标值 | 未指定(任意)
  组合方式: AND（text 与 format 至少一个非空）；match(blk) -> bool
  collect(proj) -> [{pagename, blk_idx}]   # 全项目遍历 pages，直读数据
```

配套：可用字段 `utils/style_query.py::PREDICATE_FIELDS` = 身份键 + `utils/base_styles.py::DIFF_FIELDS`（上游效果栈进入 DIFF_FIELDS 后自动可查询）；分组 `utils/style_query.py::FIELD_GROUPS` 供样式管理器与查找替换格式编辑器共用；查询驱动的批量补丁 `utils/style_query.py::build_query_changes`。

**FormatPredicate 要点（仍生效的约束）：**

1. **语义字段抽象**：谓词按语义字段定义，**只经 `FontFormat` 公开属性读写**（`utils/textblock.py::TextBlock` 属性委托层），不碰内部 dict——为上游 effects 化预留的兼容缝（§7.1）。
2. **归一化比较**：每字段注册归一化函数（浮点走 `utils/base_styles.py::_FLOAT_QUANT` / `utils/base_styles.py::_quantize` 同款量化），比较 = 归一化后相等；数值字段另支持区间比较（"字号 ≥ 20"）。
3. **归一化注册制**：字段清单即注册表，新增参与 diff 的字段（如上游 `text_effects` 整栈）只需注册归一化函数（整栈序列化元组），不改引擎结构。
4. 排除字段：`_style_name`（内部）、`punctuation_alignment`（已弃用）、`deprecated_attributes`（迁移遗留）；v1 分组见 §5.3。

## 4. 替换语义与统一提交流程

### 4.1 替换模式（用户手动选择）
| 模式 | 语义 | 默认 |
| --- | --- | --- |
| **按块 patch** | 对命中块只替换"替换格式"中指定的字段，其余字段（含块自身 override）保留 | ✅ |
| **整块应用大样式** | 命中块整体替换为选定大样式的完整 FontFormat（下拉选择） | 可选 |

**身份键字段参与替换是合法操作**：patch `font_family` / `vertical` 会使块迁移到另一个大样式归属，应用后须触发样式树重发现（`discover_style_tree`）；顺序契约沿用 `utils/base_styles.py::build_flatten_changes` 的"先 collect 后更新 base"。

### 4.2 统一提交流程（已落地；撤销语义见 §4.4）
```text
[替换] 按钮（唯一，ui/global_search_widget.py::GlobalSearchWidget.on_replace）
  → ui/global_search_widget.py::replace_preparing（施加前信号）：_sync_and_commit_project（当前页 UI → 数据并落盘）
       → utils/batch_versions.py::BatchVersionStore 写一版备份（D35 版本仓库；须反映替换前完整状态，
         且须在收集器原地改写非当前页数据之前写好）
  → ui/global_search_widget.py::_collect_replace_targets 收集并施加：当前页暂存 live widget 引用；非当前页数据直写 + 标脏
  → ui/global_search_widget.py::replace_finished → ui/textedit_commands.py::GlobalReplaceApplier 施加当前页改动
       （构造期守卫下 edit/item 双文档各改一次并清其文档撤销栈；format_changes 契约 = utils/style_query.py::build_query_changes）
  → _sync_and_commit_project 落盘 → 面板出现回滚条（块数/页数 + "撤销本次替换"）
  → ui/mainwindow.py::_ask_rerender_dirty_pages 固定询问："替换完成，立即重渲已修改的页面？ [立即重渲] [稍后处理]"
       立即重渲 → ui/mainwindow.py::_rerender_dirty_pages；稍后 → 保留脏角标（切页惰性重渲 / run 对话框"仅渲染"）
```

**脏页询问策略（定稿）**：每次替换固定弹询问，不提供"不再询问"静默选项；将来启用后台脏页处理机制后由该机制接管。`_rerender_dirty_pages` 已是独立可复用入口（输入脏页集合、产出 QProgressDialog），**后台慢速处理只留缝**——换调度方即可，进度经 `ui/custom_widget/notification.py::NotificationCenter` 展示。**快照路径分两类的理由（历史约束）**：文本路径依赖编辑文档撤销栈、格式路径依赖 setHtml 全量换入，同块混用会在 undo/redo 时互相踩踏（clearUndoRedoStacks / 栈错位）；阶段 2.5 起两类统一为施加器一次性写入 + 快照回滚（§4.4）。

### 4.3 溢出裁剪（定稿：复用既有全局机制，不另造开关）
格式替换可能改变排版（字号/字距变大）致内容溢出原文本框、破坏 bounding 形状。**阶段 2 落地时发现 fork 已内建该能力**，全局替换直接继承：`utils/config.py::clip_text_overflow`（默认开启，标题栏有开关）+ `ui/textitem.py::on_document_enlarged`（`TextBlkItem`：裁剪模式下抑制盒子自动扩张、记录溢出状态）+ `ui/textitem.py::_paint_native`（溢出裁剪到块自身内容边界 + 黄色提示框；用户拖拽 `ui/textitem.py::startReshape` 自动解除裁剪态）。替换/重排溢出走同一条 `size_enlarged → on_document_enlarged` 链路，当前页与惰性重渲均覆盖；用户关闭全局裁剪时溢出表现为盒子自动撑大，与手动编辑一致（开关只影响裁剪行为本身）。**深拷贝契约**：`format_changes` 传入的 `FontFormat` 须在施加器入口深拷贝、写回 `blk.fontformat` 时亦深拷贝——否则共享对象被外部原地改写（如重建时排版回写）会串改替换目标值。

**撤销栈路径已废弃（2026-08-29 实机复盘，两轮修复后被快照方案整体取代）**：① `doc_replace` 后接 `doc_replace_no_shift` 对同一文档再套一次 span（双重替换）；② 命令与自动压栈的 `TextEditCommand` 双重记账、撤销时互相吞步（替换后 Ctrl+Z 无响应）；③ `availableUndoSteps` 在 `contentsChanged` 时刻滞后一步，推栈时机不可靠；④ 栈中残留命令在场景重建后引用已删 widget，Qt 虚函数内未捕获异常/悬空引用直接原生段错误（闪退）；⑤ 全快照命令语义收敛后仍复现"命令弹出但落点静默失配"（含仅替换当前页）。**裁决：批量操作不进任何撤销栈，撤销语义整体移交快照回滚（§4.4）。**

**撤销通知**：`ui/mainwindow.py::on_undo` / `ui/mainwindow.py::on_redo` 在历史位置实际变化时经 `ui/custom_widget/notification.py::toast`（anchor=bottom-left，key 去重）弹"已撤销/已重做"，连续撤销刷新同一条；历史位置未变且查找替换面板回滚条此刻可用时，提示可到面板整体回滚。**判据取面板而非"备份目录里有版本"**：最新一版若已是别的批量操作写的，面板那条也撤不了，提示会误导。

### 4.4 批量快照回滚（定稿并实施）
**语义：批量操作只有一把总闸——要么整批退回快照，要么不退。** 批量替换不进页栈、不与逐块编辑撤销混排（混排缺陷：批量后手工编辑再想回快照，逐个撤销全是无用功——快照恢复本就连带丢弃其后全部编辑；跨页批量命令压在单页栈里恢复范围也远超所见）。

- **版本轮转备份**（2026-09-16 与工作台批量任务归并同一机制，此后是**仓库唯一的批量备份口**）：`utils/batch_versions.py::BatchVersionStore` 把执行前项目数据写成一版，放**项目目录内子目录** `.bt_batch_backup/`（随项目走），记录该时刻脏页清单（含当前页）。查找替换只改文本与样式、不碰像素，故不产像素前图（工作台任务另存受影响矩形的像素前图）。版本数取设置面板「备份版本数」（默认 1、上限 5），超出删最旧——不做时间戳之外的额外区分，回滚只服务"后悔上一批量"。
- **跨会话有效**：版本文件在项目目录里，重开程序仍可撤销上次会话的批量操作；面板回滚条是**会话内入口**（替换后出现、下一次替换或回滚后消失）。空替换等路径用 `utils/batch_versions.py::BatchVersionStore` 的 `discard_latest` 丢弃刚写的那一版。
- **回滚**：`restore_latest` 用最新一版整体换回各页数据与 base_styles，按版本记录的脏页重标脏（已被重渲过的页结果图此刻必然过期），保持当前页不跳转，成功后消费该版本。入口两处：① 面板回滚条（"已替换 N 块 across M 页 ｜ 撤销本次替换"，经 `ui/global_search_widget.py::batch_rollback_requested` 发往 `ui/mainwindow.py::on_batch_rollback`）；② 见底 toast 指引。**按版本号校验**（`expect_seq`）：面板记着它那一版，若期间有更晚的批量操作写新版，面板侧判为不可用、主窗口侧也拒绝执行（避免撤错对象）。回滚后清空画布撤销栈、重建当前页场景、重新落盘并走 `_ask_rerender_dirty_pages` 固定询问；确认框讲清"将丢弃批量替换之后的全部修改（含其后手动编辑）"。
- **顺带简化**：`ui/mainwindow.py::_rerender_dirty_pages` 删除 `clear_stack` 参数与 `_batch_rerendering` 守卫（保栈只为命令重绑定服务，命令栈路径移除后无所保）。

## 5. 样式管理器 UI 重构

### 5.1 设计三原则
1. **差异优先**：变体只展示 override 字段，其余折叠为"与基准一致"；改动字段高亮。
2. **预览即数据**：预览卡是参数的第一显示层，取代大部分文字摘要行。
3. **编辑器复用**：右栏分组控件 = 查找替换格式条件编辑器的控件来源。

### 5.2 右栏：预览卡 + 差异优先分组（已落地）
布局（`ui/fontstyle_manager.py::StyleDetail` 重写）：标题行（名称 + 竖排标记 + 块数）→ 真实字体实时渲染的**预览卡** → 只读 chip 行（点击滚动定位分组）→ 四组折叠区（组头徽标"与基准一致 / ● n 已修改"）→ 应用按钮 → 页 chip 行（tooltip 列块号，点击跳该页首块，复用 `navigate_to_block`）。

- **预览卡** `ui/fontstyle_manager.py::StylePreviewCard`：QTextDocument 近似渲染（字体/字号/颜色/粗斜下划/行距；竖排逐字堆叠近似），编辑字段实时刷新；**chip 行** `ui/fontstyle_manager.py::_ChipBar` 手工 resizeEvent 换行——**PyQt6 下 Python 自定义 QLayout 子类在布局激活时原生段错误，勿走 QLayout**。
- **四组折叠区** `ui/style_format_editor.py::FormatGroupCard`（组头徽标，改动组自动展开、字段高亮）+ `ui/style_format_editor.py::FormatEditorPanel`（字段清单来自 `utils/style_query.py::FIELD_GROUPS`；`FormatEditorPanel.changed_values` 量化 diff 语义与旧 `_collect_changed` 一致，基线为 None 且编辑值是中性默认时不算变更）。原"13 行只读属性行 + 平铺编辑控件"双视图已删。
- **效果组只读摘要**（2026-08-30 实机反馈调整）：阴影/渐变/变换/斜切不给编辑控件（占空间且交互效率低），组头徽标笼统标记 `ui/style_format_editor.py::effects_tokens`（激活语义与预览 chips 一致）；保存/应用样式时效果字段原样透传，`changed_values`/`current_values`/`sync_into` 均不含效果字段（§7.1 效果栈迁移时整组替换为效果卡片栈）。
- **折叠组标题修复 + `bold` 弃用**（2026-08-30 二轮验收）：`FormatGroupCard` 组头曾漏 `setText` 只显徽标无组名——补 `self._toggle.setText(self.title())`；`bold` 弃用（字重全走 `font_weight`）——从 `utils/style_query.py::FIELD_GROUPS`、`utils/base_styles.py` 的 `_SIGNATURE_FIELDS`/`DIFF_FIELDS`/`_BOOL_TOKENS`、编辑器字段清单与树摘要/预览 chips 全部移除，`utils/fontformat.py::FontFormat` 数据字段仅为旧项目兼容保留（`ui/text_panel.py`/`ui/textitem.py` 镜像写入不动）。
- **变体模式**：`FormatEditorPanel.set_format(only_fields=...)` 只渲染 override 字段，无字段的组隐藏；"重置为基准"= `ui/fontstyle_manager.py::_reset_variant_to_base`（基准值写回变体块，重发现后变体溶解）。**动作区**：未分组 → 提升为大样式（`_promote_to_base`），大样式 → 存预设 / 删除，应用按钮统一为一个（`_apply_all`）；原 `StyleBlockList` 树已删。

### 5.3 字段 → 分组映射（v1，本地 FontFormat 字段）
| 分组 | 字段（`utils/fontformat.py::FontFormat`） |
| --- | --- |
| 文本 | `font_family`、`font_size`、`font_weight`、`italic`、`underline`、`strikeout`（`bold` 已弃用，见 §5.2） |
| 颜色与描边 | `frgb`、`srgb`、`stroke_width`、`opacity` |
| 排版 | `alignment`、`vertical`、`line_spacing`、`line_spacing_type`、`letter_spacing`、`ligature_common`、`ligature_discretionary`、`ligature_contextual`、`oldstyle_nums`、`standard_vertical_roman_alignment` |
| 效果（只读摘要，可替换实现见 §7.1） | `shadow_radius`、`shadow_strength`、`shadow_color`、`shadow_offset`、`shadow_include_stroke`、`gradient_enabled`、`gradient_start_color`、`gradient_end_color`、`gradient_angle`、`gradient_size`、`text_transform`、`glyph_slant_angle` |

### 5.4 左树：两行节点（已落地）
行1 = 色板 + 名称 + 块数；行2 = 灰字参数摘要；变体行2 只列差异字段（天然短）；另有"未分组"节。**2026-09-23 区带化**：左树改为三个**自绘区带行**分区的结构（全局样式库 / 本项目样式 / 未分组，区带 = 半透明底 + 加粗标题 + 条目计数），库条目右侧块数槽换成「模板」胶囊标签（来源是模板的唯一行内标识）——区带行的显示数据同样走 `_DISPLAY_ROLE`（`{"section": True, "title": …, "count": n}`），且 `populate` 的 `setExpanded(True)` 必须**晚于** `addTopLevelItem`（insert 前是空操作，曾导致库区/未分区默认收起）。落点：`ui/fontstyle_manager.py::StyleTreeWidget` populate 写两行显示数据（`_DISPLAY_ROLE`）；`ui/fontstyle_manager.py::_StyleItemDelegate` 自绘（色带 / 色板 / 名称 / 右对齐块数或标签 / 灰字摘要；选中文本行取整截断 guard 先判溢出再 elide，选中底色用主题强调色而**不是** `palette.Highlight`——后者与 QSS 给缩进区铺的 `@accentPrimary20` 不同色，行上会留接缝）；大样式行2摘要 `ui/fontstyle_manager.py::_base_summary`（翻译 token 在定义处 `QCoreApplication.translate` 显式标注上下文），变体行2沿用 `utils/base_styles.py::overrides_summary` ASCII token（生成数据不译）；完整信息在 tooltip。

## 6. 查找替换 UI（格式条件）（已落地；实测"太挤"改浮层展开）
`ui/global_search_widget.py::GlobalSearchWidget` 新增（第三行工具条 + 按钮锚定下拉浮层）：

- **双入口**：查找侧"格式条件"与替换侧"替换格式"两个互斥 checkable 按钮（`QToolButton#FormatToggleBtn`，QSS checked 态走强调色），点击展开 `ui/custom_widget/float_drop_panel.py::FloatDropPanel` 浮层（**左缘钉在搜索栏右缘、向画布方向展开**，搜索栏保持完全可见可交互；Esc/×/再点按钮关闭，无 pcfg 开合记忆），内含 `QStackedWidget` 承载的两个 `ui/style_format_editor.py::FormatEditorPanel` 页（复用阶段 3 四组折叠控件；效果组仍只读徽标）。**不用内嵌布局的原因**：字段行（字体下拉等）最小宽 ~390px，内嵌会把整栏最小宽撑到 ~470px，与 300px 动画列宽冲突，子控件超界裁切、圆角被截；浮层不参与布局无此压力。宿主**首次打开时惰性解析**为 `window.centralWidget()`（构造期控件树未挂进主窗口，`window()` 不可靠）。动过的字段数以 `(n)` 追加在按钮文案与浮层标题；查找页头"清空"复位基线，替换页头为「模式下拉 + 清空」。
- **替换模式**：`ui/global_search_widget.py::_replace_format_payload` 按模式下拉二选一——按字段 patch（默认，只动替换格式面板中动过的字段）或整块应用大样式（下拉取自 `proj.base_styles`，选中即深拷贝完整 FontFormat）；模式/样式下拉仅在替换格式入口开启时可见。
- **查询即预览**：查找格式条件由 `ui/global_search_widget.py::_find_format_conditions` 读面板实时 diff（基线 `FontFormat()`），生成 `utils/style_query.py::FormatCondition`（eq，量化比较）组合为 `utils/style_query.py::FormatPredicate`；条件变更后 Enter 重新搜索。**搜索语义**：格式条件激活时范围下拉的原文/译文维度仅作用于文本谓词（格式是块级），命中 = 文本谓词 AND 格式谓词；无文本条件时**格式-only 命中以块级条目展示**（无高亮 span，点击照常跳块）。
- **替换语义**：`_collect_replace_targets` 按同一查询门控收集——文本路径沿用"当前页 live widget 暂存 / 非当前页直写 + 标脏"；格式 patch **收集期不写数据**，暂存为 `format_changes`（old/new_ffmt 均深拷贝，契约 = `utils/style_query.py::build_query_changes`），由 `ui/textedit_commands.py::GlobalReplaceApplier` 施加期一次性落点（当前页 live item + 数据层兜底、非当前页直写标脏）；回滚条计数按 (页, 块) 去重（`ui/global_search_widget.py::_show_rollback_strip`）。快照回滚、脏页询问、溢出裁剪链路不经本节改动（§4.2/§4.3/§4.4 语义不变）。

## 7. 上游适配评估（v1.5.12 后未发版重构）
上游 dev（09a7aad..8108436，2026-08-21 后）有两组相关底层重构，**均未发版**：

### 7.1 文字效果域重构（影响效果组：留缝）
上游新增不可变类型化效果栈 `ballontranslator/utils/text_effects.py`（TextEffectStack：solid/渐变 paint、blend 模式、filters（bloom/blur/glitch/grain/noise）、alpha mask、阴影类型、描边位置）与 `ui/text_engine/effects/` 全新包；`FontFormat` 的 `text_effects` 成为描边/阴影/渐变/不透明度的**唯一权威所有者**，旧扁平字段（`shadow_*`、`gradient_*`、`opacity`、`stroke_width`、`srgb`）降级为 legacy view（属性钩子兼容读写，旧项目自动迁移）。

**判定：本方案数据层设计不变，留三道缝。** ① §3 约束谓词只走 FontFormat 公开属性——迁移后 legacy view 仍兼容读，谓词定义零改动；② §5.3"效果"组边界恰好对齐上游 effects 迁移边界，移植时该组内部实现整体替换为效果卡片栈，不波及其余三组与整体布局；③ §3 归一化注册制使 `text_effects` 整栈可作为单个字段注册（序列化元组归一化）参与 diff/谓词。**不为未发版内容提前重构数据层。**

### 7.2 字体注册表与字重选择器（影响文本组：**已拍板不移植，勿复活**）
上游新增 `ballontranslator/utils/font_registry.py`（字体 name 表解析、weight 映射、持久化、`resources/font_registry_overrides.json`）+ 字重选择器 rework（仅显示有效字重、bold 回退）。**判定（2026-09-05 用户拍板：不移植）**：已评测该逻辑，认为不如本 fork 的 `font_weight` 真值化 + face 派生设计（`utils/face_resolver.py`），保留现有实现，本缝关闭。

### 7.3 移植顺序建议
本重构四阶段不依赖上游未发版内容；§7.1 效果组替换在上游发版后的移植批次中执行（效果栈重启时机与方案另见 `docs/技术实现/效果栈移植与窄栏图标重绘_计划_存档.md`）；§7.2 已拍板不移植。
