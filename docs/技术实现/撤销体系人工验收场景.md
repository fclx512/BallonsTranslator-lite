## 一、通用观察点

每个场景操作时顺手核对四件事，异常即记录：

1. **一致性**：画布文字与右侧译文框文字始终相同；
2. **保存状态**：标题栏角标与你的直觉一致（改了→未保存；撤回到保存点→已保存）；
3. **编号徽标**：画布块角标编号与右侧列表顺序一致；
4. **控制台**：从 `launch.bat` 启动时终端无异常堆栈。

另请留意「按了没反应」的撤销步：记录出现前做过哪些操作，这正是本清单要暴露的信息。

## 三、场景

### A 组：管线命令与双栈（最高风险）

**S1 管线完成时切模式（异步竞态）**

- 目的：选区翻译在后台异步运行，完成后才把撤销命令入栈，且按完成时刻的模式决定入哪个栈。本场景暴露落栈错乱。
- 步骤：
  1. 嵌字模式，框选 2 个文字块，运行选区「翻译+修复」档（选耗时档位，给后台留窗口）。
  2. 翻译进行中立刻切到文本模式，在某个块的右侧译文框里打几个字。
  3. 等翻译完成（右侧译文被管线更新）。
  4. 连按 Ctrl+Z，每按一次核对通用观察点。
  5. 撤完后再切回嵌字模式，继续 Ctrl+Z 到头。
- 预期：全程不崩溃、不串块，画布与右侧文本每一步一致。大致顺序应为：第一步 Ctrl+Z 撤掉管线写入（译文回到你手打的字、修复图回退），之后是你自己的编辑逆序回退——若观察到不同顺序、某格无反应、或保存状态误报，记录。

**S2 空撤销步**

- 步骤：嵌字模式选 1 块跑「翻译+修复」档 → 完成后连按 Ctrl+Z 到头 → 数「按了但画面无变化」的格数。
- 预期：允许恰好 1 格空步（R2 已知）；除该格外每格都有可感知变化。记录实际格数。

**S3 跨模式交错撤销**

- 步骤：
  1. 嵌字模式对某块做一次图像修复（或画笔涂改）。
  2. 切文本模式，改这块译文几个字。
  3. 切嵌字模式 Ctrl+Z：应只回退修复，文字保持第 2 步后的样子。
  4. 切文本模式 Ctrl+Z：应只回退改字。
  5. 全程 Ctrl+Shift+Z 重做一遍。
- 预期：每一步只回退对应那类变化，两处内容从不互相污染。

### B 组：绘制栈记账与保存状态

**S4 重做越界**

- 步骤：嵌字模式做 2 个操作（如两次修复）→ Ctrl+Z 全部撤销 → 连按 Ctrl+Shift+Z 超过 10 次 → 观察标题栏 → 再做一次正常编辑并撤销。
- 预期：越界后画面不再变化；若标题栏误报「未保存」即 R4 实锤；后续编辑与撤销应能恢复正确状态。

**S5 带遮罩删除**

- 步骤：对有修复遮罩的文字块按 Delete 删除 → Ctrl+Z → Ctrl+Shift+Z。
- 预期：删除后块从画布与右侧列表消失、遮罩区图像还原；撤销后块回原位，文本/位置/遮罩不变；重做等同再删；保存状态全程合理。

### C 组：键入会话

**S6 空闲切步**

- 步骤：右侧译文框打「AAAA」→ 等 2 秒 → 接着打「BBBB」→ Ctrl+Z。
- 预期：第一步只去掉「BBBB」，再按去掉「AAAA」。

**S7 IME 输入**

- 步骤：中文输入法下，①画布双击进入某块，拼音组合未提交时按 Ctrl+Z；②提交一个词后撤销；③连续提交三个词后连按撤销。④右侧译文框重复①–③。
- 预期：组合中撤销不崩溃、无残留拼音；提交后按词回退不逐字母乱退；画布与右侧一致。

**S8 原文面板的已知降级**

- 步骤：点进某块「原文」框 → 在末尾打「XY」→ 鼠标把光标点到开头 → 拖选开头 2 个字按 Delete → 连按 Ctrl+Z。
- 预期：这次删除**不可撤销**（R8 已知设计）：Ctrl+Z 先撤销「XY」，再往下撤更早操作；删除内容无法恢复，但不崩溃、不串块。确认现状与设计一致并记录感受（是否需要改进为可撤销）。

**S9 打字中切页**

- 步骤：页 1 右侧译文框打几个字 → 1.5 秒内点页列表切到页 2 → 再切回页 1。
- 预期：打的字还在（依赖切页自动保存默认开启）；页 1 的 Ctrl+Z 无效果但不崩溃；页 2 同样为空历史。

### D 组：格式化手势

**S10 预览悬开取消手势**

- 步骤：框选 2 块 → 拖字号滑杆（画布实时变大）→ 松开鼠标 → 1.5 秒内按 Ctrl+Z → 再按一次 Ctrl+Z → 然后重新拖一次字号并等 2 秒，Ctrl+Z。
- 预期：悬开期的 Ctrl+Z 使字号弹回原值且**不产生**撤销步（第二步 Ctrl+Z 撤的是更早的操作）；正常落账后的字号是一步回退。

**S11 键入↔格式化交错（重点回归）**

- 步骤：①右侧某块译文末尾打「甲」；②把该块字号改成明显更大的值；③紧接着打「乙」；④连按 Ctrl+Z 三次；⑤再 Ctrl+Shift+Z 三次。
- 预期：④依次为：只去掉「乙」→ 只回字号 → 只去掉「甲」，每步画布与右侧一致；⑤完整还原到打完「乙」的状态。

**S12 多选单步**

- 步骤：框选 3 块 → 拖字号 → 等 2 秒落账 → Ctrl+Z 一次 → Ctrl+Shift+Z 一次。
- 预期：3 块字号一步全回、一步全进。

**S13 离散格式按钮**

- 步骤：选中 1 块，依次点粗体、斜体 → Ctrl+Z 两次 → Ctrl+Shift+Z 两次。
- 预期：逆序回退斜体、粗体；重做按原序恢复。

### E 组：结构操作

**S14 删除/恢复完整性**

- 步骤：页内 3 块，Ctrl+F 页内搜索一个三块共有的词，记下结果计数 → Delete 删中间块 → 观察搜索计数变化 → Ctrl+Z。
- 预期：撤销后块回原位，列表明细顺序、编号徽标、原文译文都对，页内搜索计数恢复删除前。

**S15 合并后撤销**

- 步骤：相邻两块 A、B 右键合并 → 在合并块译文末尾打几个字 → Ctrl+Z → 再 Ctrl+Z → 再全程 Ctrl+Shift+Z。
- 预期：第一次只退字；第二次退合并，A、B 恢复为两块且原文/译文/位置与合并前一致，打进的字无残留；重做完整还原。

**S16 重排/粘贴/新建**

- 步骤：①右侧列表拖动某行换位 → Ctrl+Z / Ctrl+Shift+Z；②画布复制 2 块再 Ctrl+V 粘贴 → Ctrl+Z → Ctrl+Shift+Z；③画布拖拽新建一个块 → Ctrl+Z → Ctrl+Shift+Z。
- 预期：各自一步回退/重做；内容、顺序、编号徽标正确。

### F 组：页面语义、富文本、保存

**S17 切页清栈（当前设计基线）**

- 步骤：页 1 打字+改字号 → 切页 2 → Ctrl+Z 数次 → 切回页 1 → Ctrl+Z。
- 预期：任何时刻 Ctrl+Z 都无效但不崩溃——撤销不跨页是当前设计。本场景为跨页历史改造记录基线。

**S18 跨页批量操作**

- 步骤：
  1. 批量整理换行（对话框入口），让它处理含当前页在内的多页 → 不切页直接 Ctrl+Z → 切到其他页核对内容是否一并回退。
  2. 重新执行整理换行 → 这次先切到别的页再切回来 → Ctrl+Z → 确认历史为空、各页数据保持「已整理」且无损坏。
  3. Ctrl+G 全局替换跨页批量替换 → 走其自带的批量回滚撤销 → 确认回滚正常且不影响文本撤销栈。
- 预期：①当页撤销时其他页数据一并回退；②切页后撤销为空但数据完好；③全局替换回滚正常。

**S19 批量重渲僵尸命令**

- 步骤：全局替换弄脏多页后，接受批量重渲确认弹窗让其实际执行 → 完成后立即连按 Ctrl+Z 多次。
- 预期：不崩溃；旧命令静默失效（允许「按了没反应」）；不产生错误内容。

**S20 整页翻译不可撤销**

- 步骤：整页运行管线（检测→OCR→翻译全部块）→ 完成后 Ctrl+Z。
- 预期：当前设计为不可撤销（历史被清空）——Ctrl+Z 无效不崩溃。与 S1 选区运行（可撤销）对照，记录你期望的行为，供跨页历史改造定需求。

**S21 富文本保真**

- 步骤：选一个设置了 ruby 注解/着重号/分行格式的块（没有就先做一个）→ 在其中间打几个字 → Ctrl+Z → Ctrl+Shift+Z；再用 Ctrl+F 页内替换替换其中一个词 → Ctrl+Z → Ctrl+Shift+Z。
- 预期：撤销/重做往返后 ruby、着重号、分行格式不丢失，注解位置正确。

**S22 保存联动**

- 步骤：
  1. 改一处 → 标题栏「未保存」→ 保存 → Ctrl+Z → 应「未保存」→ Ctrl+Shift+Z 回到保存点 → 应「已保存」。
  2. 打字后 1.5 秒内保存 → 切页再切回（或重开项目）→ 确认刚打的字已进文件 → 继续打字 → 标题栏应变「未保存」。
  3. 打字后 1.5 秒内直接切页（自动保存路径）→ 切回 → 内容不丢。
- 预期：三条全部成立。

## 五、相关决策记录（2026-09-04）

1. **最大撤销步数（一期，✅ 2026-09-05 落地）**：Qt `QUndoStack.setUndoLimit` 实现；`utils/config.py::ProgramConfig` 的 `undo_steps_limit` 字段（默认 0 = 无限，范围 0–500，UI 直接显示数字 0 表示无限、不用特殊文本——不会有人专门禁用撤销，0 无歧义），入口在 ConfigPanel → 界面 → Canvas；文本/绘制两栈同时生效。**⚠️ Qt 限制（实现绕开）**：`setUndoLimit` 仅在空栈上生效，非空栈上调用只打警告并被忽略（Qt 文档化行为，Qt4 起如此；早期探针恰在空栈设置，误得出「缩容惰性」结论，后经非空栈复测纠正）——`ui/canvas.py::apply_undo_limit` 以空栈守卫落地：启动时栈空立即生效，会话中途改设置由下次清栈（切页/整页管线，各 `clear_*` 处再应用）生效。其余前置实测结论（固化为 `tests/test_undo_limit.py`）：保存点被截断时 Qt cleanIndex 落 -1、`isClean()` 恒 False（不假报「已保存」，**无需**自造判定）；保存点幸存时 cleanIndex 正确平移、可撤回。配套修正：`ui/canvas.py::push_draw_command` 截断时同步平移绘制栈手工计数器（`num_pushed_drawstep`/`saved_drawundo_step`），保存点被截落 -1 哨兵保持「未保存」。
