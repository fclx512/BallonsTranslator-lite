# 反向移植规范（fork → 上游）

> 目标：把本仓库（BallonsTranslator-lite）低耦合的实用小功能，规范化地移植回上游官方仓库（dmMaze/BallonsTranslator），最终以 PR 形式提交。
> 本文件即为完整规范（无额外配套技能文件）。
> 记录日期：2026-08-07

---

## 1. 背景与两个仓库概览

反向移植是"顺向移植"（上游 → fork，见 `docs/基础速查/上游参考.md`）的镜像方向。上游是活跃维护的项目（作者已同意接收），移植质量直接影响 PR 能否被合并。

| 维度 | fork（源） | 上游（目标） |
|------|-----------|-------------|
| 路径 | `D:\ruanjian\BallonsTranslator-lite` | `D:\ruanjian\BallonsTranslator` |
| 版本 | 0.6.0（发版后以仓库实际为准） | 1.5.11（dev 活跃演进，以实际为准） |
| 包结构 | 平铺：`ui/` `modules/` `utils/` 在根目录 | 包：`ballontranslator/` 下挂 `ui/` `modules/` `utils/` |
| 上游 remote | `upstream-tmp` → dmMaze/BallonsTranslator | `origin` / `upstream` → dmMaze/BallonsTranslator |
| 历史 | 独立演进（2355 提交） | 活跃维护（dev 分支） |
| ui 组织 | 自研子目录（`custom_widget/`、`text_engine/`）+ 大幅修改 | 2026-08 起已吸收 `text_engine/` `custom_widget/` 等（原"扁平 34 文件"已过时），其余扁平 |
| i18n | `translate/zh_CN.ts` + `scripts/i18n_check.py` 等自研工具链 | `resources/translate/` 9 语言 + `BallonsTranslator/scripts/update_translation.py`（pylupdate5） |
| 测试 | pytest + subprocess 隔离 | unittest（少量正式测试）+ 手动验证 |

**核心结论：两仓库 git 历史完全不共享（`git merge-base` 为空）。** 因此：
- ❌ 禁止 `git cherry-pick`、`git format-patch` 直灌——hash 对不上，且文件路径/内容已分叉，apply 必然失败或产生错误结果。
- ✅ 只能**手工移植**：复制代码 → 逐处适配 → 在上游结构里重写适配版提交。

## 2. 上游开发规范（AGENTS.md 规则）

上游无 CI、无 lint、无 CONTRIBUTING.md，**唯一规范就是仓库根 `AGENTS.md`**。PR 审查人（作者）以它为准。移植的每一行改动都必须过一遍这些规则。

> ⚠️ **上游 AGENTS.md 活跃维护**（2026-08-09 作者已新增 UI Styling Rules / Qt Event Filter Rules）。本节约为快照，**每次移植前必须重读上游根 `AGENTS.md` 全文**，以最新规则为准。

### 2.1 重构规则

| 规则 | 中文要点 | 移植含义 |
|------|---------|---------|
| Preserve behavior unless explicitly asked | 除非明确要求否则保持行为不变 | 移植是"搬功能"，不是"顺手重构" |
| Prefer small, reviewable refactors | 小步、可审查的重构 | 一次 PR 只做一件事 |
| Do not change project JSON shape without migration | 不改公开项目 JSON 结构（除非给迁移） | 新增字段必须带默认值 |
| Be careful with Qt signal/thread in `ui/module_manager.py` | 对 module_manager 的信号/线程保持谨慎 | 涉及它的改动要格外小心 |
| Do not rename registered module keys | 不改已注册模块 key（除非加兼容别名） | 模块级移植禁止改 key |
| Keep model-loading lazy/eager behavior | 保持模型懒/急加载行为 | 新模块照抄上游的加载节奏 |
| Avoid adding dependencies unless approved | 不新增依赖（除非批准） | 移植禁止引入新依赖 |

### 2.2 新功能规则

1. **从现有架构出发**：优先扩展 `ui/`、`modules/`、`utils/config.py`、`utils/proj_imgtrans.py` 的模式，不引入新框架/全局服务。
2. **功能放显式配置/控件/模块参数后**：行为可能让现有用户意外时必须可开关。
3. **项目 JSON 兼容**：新保存字段给默认值，旧项目文件不得报错。
4. **新自动化模块**用现有注册表模式 + 稳定 key。
5. **UI 响应性**：长任务（OCR/翻译/修复/IO/下载/模型加载）不得阻塞 Qt 主线程。
6. **尊重 headless**：影响管线的功能在 `--headless` 下须可用或安全无操作。
7. **避免强制新依赖**：可选集成失败时给清晰错误或设置提示。
8. **模型/下载行为显式**：不擅自下载大文件或联网，除非走现有路径或用户操作。
9. **非 UI 逻辑加测试或 import check**；UI 重度变更记录手动验证。
10. **用户数据安全**：不覆盖源图/已有翻译/遮罩/项目 JSON。
11. **本地化**：新可见 UI 字符串用周围代码已有的 Qt 翻译模式（`self.tr()`）。
12. **增量交付**：大功能拆分为领域/配置、管线、UI、持久化几个 PR。

### 2.3 代码注释规则

- 核心类和复杂函数 docstring 带标准 Python `>>> doctest` 片段。
- 注释只写"为什么"，不逐行解释；注释非显式意图、不变量、兼容约束、故障模式。
- Qt 线程/信号/模型加载/JSON 兼容/文件 IO，在顺序或副作用重要时加简短注释。
- 抽取复杂逻辑时，如保留旧实现的微妙行为，在抽取块前加一句注释。
- 不加样板注释、冗余 docstring。

### 2.4 完成标准（Done Criteria）

1. 现有工作流仍然运行。
2. 新行为可配置或清晰可发现。
3. 旧项目加载无错误。
4. 相关检查已跑，或已说明限制。

### 2.5 验证要求

- 窄范围 Python 改动：跑针对性 import check。
- 跑相关测试（如有）。
- UI/线程改动：说明未实际验证的内容。
- 用 `rg` 做仓库搜索。

### 2.6 UI 样式规则（2026-08 新增，移植 UI 必读）

- 轻量工具/设置对话框：优先 frameless `Qt.Dialog` + 透明外层 + 圆角主题令牌 `QFrame` 表面 + object-name 作用域样式；确认/进度等不可随意关闭的流程保留原生带标题对话框，且**不得因外点点击而关闭**。
- 控件与列表排版与应用 UI 保持一致；不用内容字体渲染选择器行来预览该字体——需要展示内容字体时用专门的预览控件。
- frameless 轻量面板复用 `ballontranslator.ui.framelesswindow` 的 `OutsideClickFramelessMixin`：mixin 放在 Qt 基类之前；面板保持默认 `hide()` 行为，带暂存编辑的对话框覆写 `_dismiss_transient_window()` 为 `reject()`，有自有弹窗需保持父窗打开时覆写 `_preserve_on_outside_click()`。

### 3.4 映射原则（不依赖上面的表）

1. **先查上游有没有同名/同职责文件**：`ls ballontranslator/ui/`、`rg <类名> ballontranslator/`。

## 5. 移植执行与适配点

### 5.1 执行步骤

1. 上游克隆切新分支（命名建议 `feat/backport-<功能英文名>`），基于最新 `dev`。
2. 从 fork 复制源文件到上游对应路径（§3 映射）。
3. 逐处修复 import：`from utils.xxx import` → `from ballontranslator.utils.xxx import`；fork 的相对导入同理加包前缀。
4. 跑 import check 确认无 `ModuleNotFoundError`，再逐项核对适配点。

### 5.2 适配点清单

| 适配点 | fork | 上游 | 处理 |
|--------|------|------|------|
| 模块注册 | `utils/registries.py`（`@register_*` 装饰器） | `ballontranslator/modules/lazy_registry.py` + `ballontranslator/modules/registry.py` | 新模块类照抄上游既有模块的注册写法 |
| 全局配置 | `pcfg` + `utils/config.py` 单例 | `pcfg` + `ballontranslator/utils/config.py`（同名，nested_dataclass） | 新配置字段加进上游 `ProgramConfig` dataclass 并给默认值 |
| i18n | `translate/zh_CN.ts`，源串英文 | `resources/translate/en_US.ts` + 8 语言，源串英文 | 同 Qt Linguist 体系，直接加 `<message>`；zh_CN.ts 也要加 |
| 样式 | `config/stylesheet.css`（大幅自研） | `resources/stylesheet.css` | 新控件样式先查上游是否已有；没有才加，且不能覆盖上游现有选择器 |
| 图标 | `icons/`（fork 目录） | `resources/icons/` | 新图标复制进上游 resources |
| 字体 | `utils/fontformat.py` 大量扩展 | 同名但分叉 | 动它按 B 类处理 |
| Qt 版本 | PyQt6 | PyQt6（qtpy 兼容层） | API 差异（如 `stops()` vs `colorAt()`）以 qtsix/qtpy 兼容为准 |
| 无头模式 | fork 无管线改动 | `--headless` 是上游一等公民 | 管线相关功能必须 headless 可跑或 no-op |

### 5.3 i18n 细节

- 上游 UI 字符串是**英文源**，`self.tr("English")`，翻译存 `resources/translate/<lang>.ts/.qm`（zh_CN、zh_TW、ja 无、ru、pt_BR、ko、es_MX、hu、fr，共 9 语言）。
- 新增字符串流程：代码里写 `self.tr("...")` → 跑上游 `BallonsTranslator/scripts/update_translation.py`（pylupdate5）更新 `.ts` → 手工补各语言译文（至少补 `zh_CN`）。
- ⚠️ **PR 只提交 `.ts`（翻译源文件），不提交 `.qm`**：作者明确 `.qm` 编译产物在正式版发布时统一更新，PR 里带上只会产生无意义的二进制 diff。本地要验证译文生效时临时编译 `.qm`（上游没写编译脚本，用 Qt 的 `lrelease` 或 fork 的 `scripts/qm_compile.py` 思路），**验证完不要提交**。
- ⚠️ 不要直接把 fork 的中文硬编码字符串带过去——上游禁止硬编码中文。
- 移植实践（2026-08 起）：新增字符串**补全 9 语言 `.ts`**（机翻起步、`zh_CN` 手工校），不再只补 `zh_CN`。
- ⚠️ **pt_BR.ts 是 6 空格缩进**，其他语言 4 空格——按缩进正则批量改 ts 的脚本要按语言分别处理（2026-08 踩过：功能 1/2 的脚本都漏了 pt_BR）。
- ⚠️ **tr() 的 context 必须匹配调用类**：动作名/占位符/提示在哪个类里 `self.tr()`，ts 的 `<context>` 就写哪个类名（如 `_ShortcutRow`、`ShortcutEditor`、`ConfigPanel`），放错运行时显示英文。

## 6. 验证规范

上游验证要求低但存在（§2.5）。按优先级：

1. **import check**（必做）：上游克隆跑 `python -c "import ballontranslator.<改动的模块>"` 或写个最小 `tests/` 文件。
2. **针对性 unittest**（非 UI 逻辑）：上游用标准库 unittest，样例见 `BallonsTranslator/tests/test_core_requirements.py`（mock 风格）。纯函数功能（如 `proj_compact`、`text_alignment`）应带测试。
3. **手动验证记录**（UI 改动）：启动 `python -m ballontranslator` 或 `launch_win.bat`，截图/描述操作路径，写进 PR 描述和 commit message。
4. **headless 冒烟**（管线相关）：`python -m ballontranslator --headless` 确认不崩。
5. **旧项目兼容**：拿一个旧 `.json` 项目文件加载测试。

## 7. 提交与 PR 流程

> 端到端操作步骤与命令速查见文末 [§11 端到端操作手册](#11-端到端操作手册)（首个 PR #1261 实战沉淀，原独立文档 `反向移植_完整流程.md` 已于 2026-08-23 并入本文）。

### 7.1 上游克隆侧

- 分支：`feat/backport-<功能英文名>`（基于最新 `dev`，先 `git pull`；多功能并行用 `git worktree add`，一个功能一个 worktree）。⚠️ 主克隆 `D:\ruanjian\BallonsTranslator` 停 `userspace_update` 分支（用户个人同步区），移植一律在 worktree 里做。
- 提交信息：上游 commit 风格偏自由（英文为主），建议 `feat: <一句话> (source: BallonsTranslator-lite)`。可带 `>>> doctest` 的代码按上游风格写。
- 一次 PR = 一个功能 = 若干小步提交（代码 + 翻译 + 测试分开提交）。翻译提交只含 `.ts`，不含 `.qm`（见 §5.3）。

### 7.2 推送与 PR

1. 用户需先 fork 上游到自己的 GitHub（当前上游克隆 `origin` 直指 dmMaze，是只读克隆）。
2. `git remote add myfork <用户的上游fork URL>` → push 分支。⚠️ 推送在 worktree 目录内执行即可（worktree 与主克隆共享 remote 配置）。
3. 向 dmMaze/BallonsTranslator 提 PR，**描述用中文**（作者母语是中文，首个 PR #1261 即中文实践，覆盖早期"英文"要求）。描述要点：
   - 功能是什么、为什么实用
   - 来源（BallonsTranslator-lite fork）
   - 改动文件清单
   - 手动验证了什么、没验证什么
   - 是否影响旧项目 JSON / headless / 新依赖（明确说明"无"）
4. **链式 PR（功能叠加分支）**：按依赖顺序提 PR（如 shortcuts → seq-badge → path-reorder），先推最底层的功能让上游先合并；后序 PR 的 base 选前序分支（`dev...fclx512:<后序>` 会算上前序未合并提交），或等前序合并后 rebase dev 再提。GitHub 对已合并提交会自动从 diff 排除，PR 描述里注明依赖关系。分支被 amend/rebase 过时，后序分支需同步 rebase 对齐 hash。

### 7.3 fork 侧收尾

- 移植完成后，在本文档 §10 记录表登记一条（事项/来源/状态/日期）。
- 如移植过程中发现 fork 与上游的差异点需要长期备忘，追加到 `docs/基础速查/经验教训.md`。
- **移植参考分支**：fork 远端 `test/upstream-port`（原名 `feat/backport-font-exclusion`，内容为上游原样代码快照，font-exclusion PR #1261 的移植源）。**仅用于移植测试/对照，禁止合并进 fork 主线**——其目录结构是上游 `ballontranslator/` 布局，与 fork 平铺结构完全不同（`git merge-tree` 实测 300+ 冲突），只能手工移植，不可直接 merge。

## 8. 常见坑

| 坑 | 说明 |
|----|------|
| 以为能 cherry-pick | 两仓库历史不共享，`git merge-base` 为空。任何"直灌"手段都会失败或带错内容。 |
| 整文件覆盖同名文件 | 上游同名文件在 fork 之后持续演进，覆盖会丢掉上游修复。必须先 `diff`，只搬增量。 |
| 硬编码中文 | 上游禁止。`self.tr("...")` 英文源 + 翻译文件。 |
| 漏掉 headless | 上游 AGENTS.md 明确要求，管线相关改动在 `--headless` 下必须安全。 |
| 顺手重构 | 移植 = 搬功能。顺手"优化"会让上游 review 者困惑，diff 变大难审。 |
| 带 fork 自研依赖 | 如把 fork 的 `custom_widget` 或 `textitem` 依赖一起拖过来，耦合度飙升，功能就不再"低耦合"。移植前用 `rg` 查清 import 依赖面。 |
| 动 module key / 项目 JSON 结构 | 上游明确禁止，除非加兼容别名/迁移。 |
| 把 `.qm` 编译产物提交进 PR | 作者明确 `.qm` 随正式版发布统一更新，PR 只交 `.ts`；提交 `.qm` 会产生无意义二进制 diff。本地验证译文可临时编译，验证完勿提交。 |
| 图标/样式不随代码 | 新控件引用 fork 的 CSS 选择器或图标，上游没有 → 界面样式崩。逐项核对。 |
| 功能撞车 | 上游已有同职责不同名功能（fork `ui/update_checker.py` vs 上游 `ui/update_dialog.py`+`utils/updater.py`）。按文件名查不到 ≠ 没有，先 `rg` 职责关键词再定 A/B 类。 |
| 链式 PR 顺序 | 叠加分支（功能 2 基于功能 1、功能 3 又 merge 前两者）必须按依赖顺序提 PR；后序 base 选前序分支或等前序合并后 rebase dev。分支被 amend/rebase 后，后序分支要同步 rebase 对齐 hash。 |
| worktree 冲突 | 上游克隆用多 worktree 并行移植；同一分支只能被一个 worktree 检出。主克隆 `userspace_update` 是用户个人同步区，严禁改动。 |
| 上游规则过时 | 上游 AGENTS.md 活跃维护（2026-08 新增 UI Styling / Event Filter 规则）。规范 §2 是快照，移植前必须重读上游 AGENTS.md 全文。 |
| 漏掉 tr() context | 字符串在哪个类里 `self.tr()`，ts 的 `<context>` 就写哪个类名；放错 context 运行时显示英文（2026-08 快捷键功能踩过）。 |

## 11. 端到端操作手册（首个 PR #1261 实战沉淀）

> 2026-08-23 由独立文档 `反向移植_完整流程.md` 并入。规则以本文 §5-§7 为准，本节只给端到端命令与操作顺序。

### 11.1 环境约定

| 项 | 值 |
|---|---|
| fork 源 | `D:\ruanjian\BallonsTranslator-lite`（平铺结构） |
| 上游克隆 | `D:\ruanjian\BallonsTranslator`（包结构；`origin`/`upstream` 直指 dmMaze，只读） |
| 开发模式 | 多 worktree 并行；主克隆停 `userspace_update`（用户个人同步区，勿动）；每个移植功能一个 worktree |
| 推送远端 | `myfork` → `https://github.com/fclx512/BallonsTranslator-lite.git`（就是 lite fork 仓库，无独立上游 fork） |
| 网络 | 本机 git 直连 GitHub 不稳定，需本地代理 `http://127.0.0.1:7897`，命令统一加 `-c http.proxy=...` |
| git 身份 | 上游克隆是只读 clone，无 `user.name`/`user.email`；首次提交前配 repo-local 身份（`fclx512 <duhang926926@gmail.com>`，与 fork 一致） |

| 依赖 | 上游克隆无 python：用 fork 捆绑的 `D:\ruanjian\BallonsTranslator-lite\ballontrans_pylibs_win\python.exe` + 已装到 `D:/ruanjian/up_deps` 的补齐依赖（python-docx/docx2txt/piexif/ordered_set） |

⚠️ 两仓库历史不共享（merge-base 为空）→ 禁止 cherry-pick/format-patch，只能手工移植 + 适配。

### 11.2 同步上游、开 worktree

```bash
cd D:/ruanjian/BallonsTranslator
git -c http.proxy=http://127.0.0.1:7897 fetch origin dev
git worktree add -b feat/backport-<功能英文名> ../BallonsTranslator-<短名> origin/dev
# 后续开发/验证/提交/推送都在新 worktree 目录里做
```

多条移植并行时各开一个 worktree；主克隆保持 `userspace_update` 不动。开分支前先重读上游根 `AGENTS.md`（活跃维护，§2 只是快照）。

### 11.3 移植与验证

- 按 §3 路径映射搬文件：`ui/`、`utils/` → 加 `ballontranslator/` 前缀；同名文件（B 类）先 `diff` fork 版与上游版，只搬增量（防覆盖上游近期修复）。
- 适配点速查见 §5.2，i18n 细节见 §5.3。
- 单测（PYTHONPATH 必须指向仓库根；勿用 `-m unittest tests.xxx`，会撞 site-packages/tests 命名空间）：

```bash
PYTHONPATH=D:/ruanjian/BallonsTranslator python -m unittest discover -s tests -p "test_xxx.py" -v
```

- import 冒烟 / offscreen 交互冒烟（monkeypatch `QMessageBox`、注入假字体表，防模态阻塞与空字体表）；headless 启动（EOFError 属正常终止）；旧 config.json 兼容；i18n 验证完**只交 `.ts`，不交 `.qm`**。

### 11.4 提交（与 fork 侧相反：给上游的 PR 保持小步提交，无需聚合）

```bash
cd <worktree>
git add ballontranslator/utils/config.py ballontranslator/utils/shared.py
git commit -m "feat: add excluded_fonts config and font list filter helper (source: BallonsTranslator-lite)"
git add ballontranslator/ui/configpanel.py
git commit -m "feat: add FontExcludeDialog and Hide Unused Fonts settings button (source: BallonsTranslator-lite)"
# ... 测试、翻译各一个提交，依此类推
```

- 消息格式 `feat: <一句英文描述> (source: BallonsTranslator-lite)`（英文括号，2026-08 实践定型）。
- 禁 amend（重写已推送 hash 会分叉；未推送的提交 amend 后，叠加其上的后序分支要 rebase 对齐）、禁 AI 署名、禁 `push --tags`。

### 11.5 push 前 rebase、推送、校验

```bash
git -C D:/ruanjian/BallonsTranslator -c http.proxy=http://127.0.0.1:7897 fetch origin dev
git -C D:/ruanjian/BallonsTranslator rebase origin/dev          # 零冲突属正常；有冲突按 diff 增量手工解决，rebase 后重跑单测
git -C D:/ruanjian/BallonsTranslator remote add myfork https://github.com/fclx512/BallonsTranslator-lite.git   # 首次执行一次即可，remote 共享
cd <worktree> && git -c http.proxy=http://127.0.0.1:7897 push myfork feat/backport-<功能英文名>      # 不带 -u，避免改动 tracking
```

为什么推 lite fork 仓库就行：GitHub 仍把 `fclx512/BallonsTranslator-lite` 记录为 dmMaze/BallonsTranslator 的 fork，跨仓库 PR 成立；PR diff 按分支 merge-base 计算，与 fork 默认分支内容无关。

推送后校验（防止脏 PR）：

```bash
curl -s --proxy http://127.0.0.1:7897 \
  "https://api.github.com/repos/dmMaze/BallonsTranslator/compare/dev...fclx512:feat/backport-<功能英文名>"
```

期望：`status: ahead`、`ahead_by: <提交数>`、`behind_by: 0`，`commits` 只含自己的提交。若 `diverged` 或数量异常，先修再提。注意匿名 API 有 60 次/小时限流（代理出口 IP 共享），撞限流时可用网页抓取替代。链式分支（叠加在未合并分支之上）compare 的 base 应选前序分支而非 dev，或等前序合并后 rebase dev 再校验；被 amend/rebase 的后序分支先重对齐 hash（见 §11.4）。

### 11.6 提 PR 与收尾

- **链式依赖**：按依赖顺序提 PR（先推最底层功能让上游先合并，如 shortcuts → seq-badge → path-reorder）；后序 PR 的 base 选前序分支（`compare/dev...fclx512:<分支名>` 会算上前序未合并提交），或等前序合并后 rebase dev 再提——GitHub 对已合并提交会自动从 diff 排除，PR 描述里注明依赖关系。
- compare URL：`https://github.com/dmMaze/BallonsTranslator/compare/dev...fclx512:<分支名>?expand=1`（base 选 dev）
- 描述中文，要点：功能 / 为什么实用 / 来源（BallonsTranslator-lite）/ 改动文件清单 / 验证了什么、没验证什么 / 影响（旧 JSON、headless、新依赖明确"无"）。
- 收尾：PR 状态变更后回填 §10 记录表一行（含 PR 链接）；fork 侧文档改动（记录表、经验教训）按 fork 规则**先展示，用户确认后提交**。
- 上游作者审查 → 可能要求改 UI/代码 → 改完 `git push --force-with-lease myfork <分支>`（覆盖推送前先经用户同意）→ PR 自动更新。

### 11.7 命令速查表

| 操作 | 命令 | 备注 |
|---|---|---|
| 查状态 | `git status -sb` | 显示当前分支与未提交改动 |
| 小步提交 | `git add <文件> && git commit -m "feat: ...（来源：BallonsTranslator-lite）"` | 代码/测试/翻译分开 |
| 查看小步历史 | `git log --oneline -N` | push 前核对提交内容 |
| 同步最新 dev | `git fetch origin dev && git rebase origin/dev` | push 前必做 |
