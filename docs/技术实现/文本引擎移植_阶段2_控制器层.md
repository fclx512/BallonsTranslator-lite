## 问题 / 需求

阶段 2 的目标：把上游 v1.5.9 的 `TextItemGeometryController` 全量移植到本地，
由它接管 `TextBlkItem` 的几何职责（display_rect 所有权、resize、paint 入口、
item_change、update 事务、绑定/构造链），item 变薄并对齐上游构造路径
（`bind_model → finish_initialization`）。**中性态（空变换栈 + glyph_slant 0）
必须零行为变更**；`_full_pixmap` 快路径与 `setRectFast` 本地快路径按跟进文档
§5.6 保留不动。非线性分支（grid/projective 等）调用 `_stubs.py` 占位模块，
阶段 4 只需换 import。

两个范围决策（用户已确认）：**完整移植 + 占位模块**（照搬上游整个 controller，
结构对齐）；**新增正式测试文件**（`tests/test_textblkitem_geometry.py` 提交进仓库）。

## 改动要点（4 个源文件 + 1 个测试文件）

### 1. `ui/text_engine/geometry.py`（新增，1323 行）— 核心移植

`TextItemGeometryController` 全量移植，import 前缀适配本地（qtpy）。关键方法与中性态语义：

| 方法 | 中性态行为 |
|---|---|
| `set_rect(rect, *, padding, repaint, update_blk_rect)` | 等价本地旧 `setRect`（pad → setPos → prepareGeometryChange → display_rect → layout.setMaxSize → sync_origin → repaint_background）；`update_blk_rect=True` 时回写 `blk._bounding_rect` |
| `resize(w, h, *, set_layout_maxsize, set_blk_size)` | `requires_custom_resize()=False` → `_resize_standard` |
| `_resize_standard` | **保留本地语义**（见设计决策 3） |
| `bounding_rect(base_rect)` | 中性 = 仅 `setSize(display_rect.size())` |
| `absolute_rect(max_h, max_w, qrect)` | 本地 `absBoundingRect` 数学逐字一致（int round/ceil、max_h/max_w 钳位） |
| `shape()` / `contains(point)` | 中性 = `addRect(display_rect)`，与 Qt 默认 `shape().contains` 一致 |
| `sync_origin()` | 相同 transformOriginPoint 时短路（Qt 内部 early-return，等价本地无条件 setCenterTransform） |
| `paint_item(painter, option, widget, base_paint)` | 中性 → `item.effect_renderer.paint_item(..., base_paint)`（阶段 3 前是 stub，直调 base_paint） |
| `item_change(change, value, base_item_change)` | 中性态/无 blk → 直接 `base_item_change`；不设 ItemSendsGeometryChanges |
| `finish_initialization` / `bind_model` / `initialize_layout` / `request_update` / `_flush_update` / `update_transaction` | 构造链与 update 事务（见设计决策 4） |
| `release_render_resources` | 清 mapper/renderer/preview + 复位 compiled |
| grid/projective 控制点 API（`_resize_transformed`、`install`、`_apply_box` 等） | 已移植，阶段 4 由占位模块替换后激活 |

## 设计决策记录

1. **完整移植 + 占位模块**：照搬上游 controller 结构（含非线性分支），不裁剪；
   阶段 4 只换 import，避免二次重构。
2. **中性态最小路径**：identity `CompiledTextTransform`、无 visual_mapper /
   surface_renderer / layout_renderer、`requires_custom_resize()=False`、不设
   `ItemSendsGeometryChanges`——所有非中性代码在阶段 2 不可达。
3. **`_resize_standard` 保留本地语义（零回归关键）**：本地 `if align_c or align_tl: pass`
   使 Left/Center 均**不补偿**，保中心的 pos_shift 照常应用（sceneBoundingRect 中心
   不变，位置随之平移）；上游 `if not align_center` 会让 Left 也补偿，得到"左上角
   位置不变、中心移动"的相反行为。移植只保留 vertical / Right 补偿分支，测试 3 锁定。
4. **构造链与 update 事务**：`bind_model → finish_initialization →
   refresh_compiled_geometry → _set_surface_mapper(None)/detach_surface_mapper →
   _apply_box → install（identity 相等→False）→ _flush_update（refresh_cache_policy
   返回 False）`，构造期全为 no-op，已逐段验证稳定。
5. **`refresh_cache_policy` 镜像 `_on_text_rendering_changed`**：Crisp→NoCache，
   Smooth→DeviceCoordinateCache；`is_editting()` 时短路（编辑态由 startEdit/endEdit
   管理）；cacheMode 已匹配时返回 False（构造期重复调用即 no-op）。
6. **qtpy 一致性**：全项目 70 文件用 `from qtpy.*`，新建 2 文件曾直接用 PyQt6 →
   已改 qtpy（launch.py 支持 `--qt-api` 多绑定，默认 pyqt6，多绑定下类型一致）。
7. **`blk._bounding_rect` 写回时机**：`set_rect` 默认 `update_blk_rect=True` 会写回
   （旧代码不写）——已核对全部消费方（mainwindow.py、point_alignment.py、
   textblock.py、scenetext_manager.py）均为读模型几何，写回更正确；
   `initTextBlock` 用 `update_blk_rect=False` 保旧行为。
8. **`setRectFast` / `_full_pixmap` 快路径不动**：按跟进文档 §5.6 约定保留，
   删除列为阶段 3 验收项。

## 排障备忘

1. **`self.finish_initialization()` AttributeError**：`finish_initialization` 是
   controller 方法，__init__ 里误写成 item 方法 → 改
   `self.geometry_controller.finish_initialization()`。
2. **测试段错误（access violation）**：`QGraphicsScene()` 在 `QApplication` 之前创建
   会在 Windows offscreen 平台崩溃（Qt 原生崩溃，非 Python 异常，无 traceback）。
   修复：先 `QApplication.instance() or QApplication([])`，再建 scene。
   排查手段：最小 probe 脚本逐步打印定位到 setUpClass L53；
   `python -X faulthandler` 拿到崩溃栈。
3. **`QStyleOptionGraphicsItem` 在 `qtpy.QtWidgets`**，不在 QtGui（初次测试 ImportError）。
4. **`_resize_standard` 注释一度写反**（"Left 本地保持位置不变"）——本地 Left 实际
   保中心（与 Center 一致），已修正注释并注明与上游差异，测试 3 锁定。
5. **几何测试首跑 segfault 的误导**：段错误表现为"无输出 + EXIT=139"，排查时优先
   用 `-X faulthandler` 区分"崩溃在 Qt 原生层"还是"Python 层异常"。
