## 二、Qt 关键事实（实施时直接引用）

以下结论来自 qtbase 源码阅读 + 本机 PyQt6 实证：

1. **匹配优先级**：`QFont.styleName` 非空且与某 face 的 styleName **精确相等（区分大小写）** 时直接命中、weight 完全被忽略；未命中则完全回退 weight/italic 距离匹配，残留名不毒化。Windows DirectWrite 下命中 face 低于请求 weight≥600 时会叠加合成假粗体（`DWRITE_FONT_SIMULATIONS_BOLD`）——"改字重看似偶尔生效"的来源。
2. **清残留**：`QFont.setStyleName("")` 与 `QTextCharFormat.setFontStyleName("")` 均可靠；`clearProperty` 彻底删属性后会从 `QTextDocument.defaultFont()` resolve 继承——**defaultFont 与字符格式两处必须同一次清/写**，且 weight 与派生 face 必须同一次 merge 写入，杜绝中间态。
3. **`QFontDatabase.weight(family, style)` 返回 -1 的三条件**：family 精确二分查不到（查询 API 不走别名，而渲染路径走别名——割裂根源）；style 与存储名大小写不匹配或被 Qt 的 style 名解析器误解析（"Semilight" 被当 Light）；不因懒加载返回 -1。可变字体命名实例正常出现在 `styles()` 中且 weight 正确。
4. **`QFont.setBold(False)` 无条件把字重重置为 Normal(400)**（qfont.h 内联实现），与原值无关；`bold()` 定义为 weight>Medium。
5. **face 反查**：`styles(family)` + `weight()` + `italic()` 枚举可靠；同一 (weight, italic) 可能多条（SemiBold/DemiBold 均 600），`styles()` 顺序不可依赖，tie-break 必须自定义。
6. **撤销快照保真**：撤销体系（快照命令制）的 before/after 格式快照来自 `ui/text_engine/item.py::get_fontformat`（Qt 规范化值）。**face 重算必须放在构建变更列表阶段（快照之前）**；消费端重算对快照保真有系统性偏差。

## 三、阶段 1｜真值化基建（无 UI 变化）

1. **新增 utils 层纯函数**（新建模块，命名实现时定，归 utils/ 管辖）：
   - `resolve_face(family, weight, italic) -> str`：按 family 枚举 `(styleName, w, i)` 并 memoize（font_scan 刷新点失效，即 `utils/shared.py::init_font_list` 之后重建）；w==-1 条目丢弃；先过滤 italic 相同者取 weight 最近，无匹配放宽 italic；tie-break 依次为 Qt 合成规范名优先（照抄 `styleStringHelper` 阈值逻辑）→ 名字短者优先 → 字典序兜底；family 未知返回 `""`。禁止用 `QFontDatabase.font()` 取值（它会制造带 styleName 的 QFont，正是污染源）。
   - `sync_face(ffmt)`：`ffmt._style_name = resolve_face(ffmt.font_family, ffmt.font_weight, ffmt.italic)`；`font_weight` 为 None 时不派生（返回 `""`，渲染端 Qt 走 weight 距离匹配）。
2. **写入点接入 sync_face**（重算一律先于快照）：
   - `ui/fontformat_commands.py::font_formating` 包装器：写 act_ffmt 后对属性字段联动重算（weight/family/italic 变更均触发）。
   - `ui/text_panel.py::apply_font_change`：`QFontDatabase.weight` 查到 -1 时不再入库，改按 resolve_face 派生回落；bold 镜像写入移除。
   - `ui/fontformat_commands.py::ffmt_change_font_family`：不再读 `act_ffmt._style_name` 单值广播；家族变更后逐块 sync_face（即"每块按自身 weight/italic 映射新家族 face"）。
   - `utils/base_styles.py::build_flatten_changes` / `utils/base_styles.py::build_variant_changes`：new_ffmt 构建后 sync_face。
   - 查找替换收集器（`ui/global_search_widget.py` 的 replace patch 构建）与样式管理器整包应用路径（`ui/fontstyle_manager.py::_apply_sig` 等）：同上。
   - `ui/text_panel.py::on_active_textstyle_label_changed`：merge 后对 global_format sync_face。
3. **渲染端**：
   - 删除 `ui/textitem.py::set_fontformat` 中 bold/_style_name 的 pin 补丁。
   - `ui/text_engine/item.py::set_fontformat`：`ui/text_engine/font_family.py::qfont_with_family` 拷贝后显式 `setStyleName(ffmat._style_name or "")`，覆盖 defaultFont 残留。
   - `ui/textitem.py::setFontFamily`：`raw_weight <= 0` 静默 return 分支改为按块当前 weight 派生回落；weight 与派生 face 同一次 merge 写入。
4. **bold 收口**：所有镜像写入撤除；`utils/fontformat.py` 的 `__post_init__` 做 bold=True→font_weight 700 的字段级折算（仅字段收敛，非存量迁移工程）。
5. **死代码顺带清理**：`utils/shared.py::VIRTUAL_FONT_STYLES`（无生产无消费）；`ui/text_panel.py::restoring_textblk`（恒 False 死守卫）；`scripts/audit_registry.json` 补登记 `ui/text_engine/formatting/commands.py`、`presets.py`、`advanced.py`（传递休眠，现仅锁 panel.py 入口）。

**验收**：老项目打开视觉不变（派生 face = 原 face 或就近）；右栏/批量改字重立即生效且跨页一致；pytest + `scripts/verify.py` 全绿。

- 阶段 1/2 与效果栈批次重叠文件多，务必等其提交后从最新 main 开工。
