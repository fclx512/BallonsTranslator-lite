# 字体自动取色：掩膜取色与检测模型解耦

> 状态：已实装（2026-10-03）；同日真机验收发现**通道口径反转**与
> 「误取气泡底」两类缺陷，修复并追加**人工取样调板**（见「人工取样调板」节）；
> 同日二版把人工取样从侧栏自绘视图搬到**真画布取色模式**（同节「取样入口」）；
> 三版追加**全书扫描 → 候选色 → 勾选入调板**（同节「全书扫描与候选色」）。

## 背景

fork 的文字检测器（`modules/textdetector/detector_paddlev6.py::PPOCRv6Detector`、
`modules/textdetector/detector_ysg.py`）都不产颜色，块上的前景色一律是默认黑；
管线结束时 `ui/mainwindow.py::MainWindow` 的 `on_pagtrans_finished` 又无条件用
全局样式色覆盖所有块——结果是**文字颜色与图片内容完全无关**。差分本/彩色拟声词
这类「每个角色或每类文字有自己的颜色」的素材，翻完后要逐块改色。

上游 BallonsTranslator 用「精确文本分割模型出掩膜 → 掩膜内取色」解决，
但那套检测器本仓库已砍（主业检测质量不达标）。本设计的目标是**保留取色能力、
砍掉对那个检测器的依赖**——因为「掩膜 → 取色」这半段几乎全是代码逻辑，
掩膜来源可以换。

## 核心判断：掩膜来源与取色逻辑解耦

掩膜有两个来源，两条路都实测可用：

1. **DBNet 概率图（首选）**：`PPOCRv6Detector` 的 ONNX 前向原始输出就是一张
   soft mask，`onnxocr` 的包装层只取框把它丢了。检测器改为自己做一次前向
   （预处理/后处理全用包装层的公开属性），**一次前向同时拿到检测框与概率图**，
   不增加推理成本。
2. **经典二值化（兜底）**：无概率图时（如 ysg 检测器或未来新检测器），以块外接
   矩形边带的中位色为背景基准，对色距图做 Otsu 阈值分离前景。

实测两条路在样张上给出**同一组色值**（例如同页黄色列分别为 `#fed615` 与
`#e5bf09`，粉拟声词两者都是 `#ff99fd`），所以「换模型也能用」成立。

## 算法（`utils/color_extract.py::extract_block_colors`）

1. 掩膜：概率图 ≥ 阈值后腐蚀 1px（去掉边缘渐变混合带）；无概率图走经典二值化。
2. **填充色 vs 描边色**：掩膜覆盖的是「文本区域」（填充+描边+光晕），直接取
   中位数会搅出脏色（实测白字黑边块的中位数是灰）。做法是把掩膜像素按颜色
   直方图**确定性**地分成两簇（取最高峰 + 与之色距足够远的次高峰，各像素就近
   归属后重算两轮），再按颜色本身判填充簇：
   - 彩度高的一簇为填充（漫画惯例：白/低彩度多做描边与光晕）；
   - 两簇都无彩时取更暗的一簇（黑字白边）；
   - 空心字（描边内露出页面底色）天然落进第一条——底色彩度低、描边彩度高，
     选出的正是要渲染的描边色。
3. **否决**：取出的前景色与所在区域背景几乎同色（LAB 色距 < 20）直接判无效——
   真文字不会与背景同色，命中说明掩膜只圈到了背景（小碎块常见）。
4. 置信度 = 覆盖率因子 × 选取置信（彩度差 / 明度差决定），低于
   `PPOCRv6Detector` 的闸门（0.45）不落块，块保持原色由全局样式兜底。

### 为什么不用几何判据（实测记录）

「填充被描边包裹、描边贴着掩膜边界」在原理上对，但实测不成立：DBNet 概率图
在 960px 下采样后是**文本区域团块**，不是字形掩膜（提到 2048 分辨率仍然如此，
黑字白边内容里概率高的反而是白色描边一侧）。于是三个几何判据全部落空：

| 判据 | 反例 |
| --- | --- |
| 距离变换「厚度」 | 空心字的光晕比填充区还厚 |
| 距掩膜边界的「接触度」 | 各簇实测都是 0.06~0.07，区分不出 |
| 距离变换「芯部」采样 | 团块最深处落在背景上，取到的是背景色 |

因此最终按颜色本身判——这也解释了为什么本方案对掩膜质量要求不高。

### 参数（模块顶部常量，改前先跑探针）

| 常量 | 值 | 作用 |
| --- | --- | --- |
| `PROB_BIN_THRESH` | 0.5 | 概率图二值化阈值 |
| `CLUSTER_MERGE_DIST` | 30 | 两簇色距低于此视为单色文本 |
| `CHROMA_LOW` / `CHROMA_MARGIN` | 14 / 10 | 「无彩」与「彩度相当」判据 |
| `FG_BG_MIN_SEP` | 20 | 前景≈背景的否决闸 |
| `COVERAGE_LOW` / `COVERAGE_HIGH` | 0.01 / 0.75 | 覆盖率因子区间 |
| `PALETTE_SNAP_DIST` | 45 | 调板吸附距离（LAB） |
| `PALETTE_DUP_DIST` | 10 | 画布取样近重不入板的判定距离 |

## 通道口径（2026-10-03 真机教训）

`extract_block_colors` 的输入/输出一律是 **RGB**——与
`utils/io_utils.py::imread` 一致（项目管线 `utils/proj_imgtrans.py::read_img`
交给检测器的就是它）。首版按 BGR 设计时，探针用 `cv2.imread`（真 BGR）读图，
把口径差整个掩盖了：探针全对、应用管线里颜色整体反转（#1B19D6 取成
#D6191B，逐通道镜像）。现在探针也改用仓库 `imread` 同口径，并用
`tests/test_color_extract.py::ChannelOrderTest` 钉死「RGB 进 RGB 出」。
给 cv2 显示/写图的调用方自行 `[::-1]` 转 BGR。

## 人工取样调板（误取背景色类缺陷的工程化解法）

自动判据（彩度/明度挑簇）对「掩膜成片吞进气泡底」「白描边被当填充」这类
系统性偏差无能为力，而每本书的字色是创作侧定死的（分角色配色）——所以
引入**人工取样调板**，用户采一次样、全本受益：

- **数据层**：`utils/proj_imgtrans.py::ProjImgTrans` 的 `fg_palette`
  （条目 `{"rgb": [r,g,b], "role": str}`，role＝角色名，见下节「说话人颜色
  标记」），随项目 JSON 持久化（`fg_palette` 键，空调板不落键，与
  `llm_compact_memory` 同策略；role 空不落 role 键）；`load_from_dict`
  对坏条目逐条跳过、对旧裸三元组宽进补占位名。
- **取样入口＝工作台「取色调板」页的开关 + 真画布取色模式**
  （`ui/workbench_palette.py::FgPalettePage`，
  挂在 `ui/glossary_agent_panel.py::GlossaryAgentPanel` 的扁平导航，
  任务 id `ui/workbench_tasks.py::FG_PALETTE`，落在「翻译」分组首位）。
  **落点在工作台是用户拍板**：取样颜色后续要加**角色标签**，翻译时把
  「颜色 = 角色」喂给翻译 agent 辅译——它是翻译辅助数据，不是画布样式
  操作。
  - **画布取色模式**（`ui/canvas.py::enter_color_sample_mode`）：与整本对齐／
    路径重排／区域再检测同级的**独占交互模式**，**只接管左键**（右键菜单与
    中键平移不变）。落点经模块级纯函数 `ui/canvas.py::page_pixel_from_scene`
    换算：`baseLayer` 带 `setScale(scale_factor)`，**页像素 = scenePos /
    scale_factor**（不除缩放会静默错一位，放大到 200% 才看得出来），越界不发
    信号。信号 `ui/canvas.py::color_sampled`（页名 + 页像素 xy）→ 面板转给
    调板页的 `ui/workbench_palette.py::accept_canvas_sample`。
    标志挂在 Canvas 上，**换页与 `updateCanvas()` 重建场景都不清**（跨页保持
    武装，翻页用画布的 A/D、PgUp/PgDn 快捷键）。退出路径：面板开关关掉、
    画布获得焦点时按 `Esc`（`ui/canvas.py::CustomGV` 接受 ShortcutOverride 后
    退出，不被全局 Esc 快捷键吃掉）、换项目/关工程、与其它任一独占模式冲突；
    退出时光标按 `ui/canvas.py::leave_color_sample_mode` 三件套两处都清
    （视图 + baseLayer）。
  - **首版已拆除**：曾把 `ui/workbench_preview.py::_PreviewCanvas` 塞进 460px
    侧栏当取样区（自带页下拉 + 缩放视图 + 取样模式）。画布本身就是现成的取样
    区，侧栏那份既浪费空间又多一套缩放/平移要学，故整体删除；`_PreviewCanvas`
    的 `set_sample_mode`/`sample_clicked`/`_sample_press`/`_emit_sample` 随之
    成为死代码并删掉。
  - 取色取的是**原图像素**（`read_img`，RGB）；LAB 距 < `PALETTE_DUP_DIST`
    的近重不入板。武装期间面板挂**常驻 activity 提示**
    （`ui/glossary_agent_panel.py::set_palette_sampling`，键
    `palette-sampling`）说明左键语义已被换掉；画布拒绝武装时（没开工程／被
    其它独占模式占用）开关立即回弹并 toast 原因。
  色表每行＝色块 + HEX + 角色名可编辑下拉 + 删除（见下节）。
- **吸附语义**（`utils/color_extract.py::_pick_fill_cluster`）：启发式首选
  色在 `PALETTE_SNAP_DIST` 内 → 精确取调板色（人工采样权威性高于启发式，
  置信度抬到 ≥0.9 保证过闸）；首选离调板远**且首选簇低彩**（疑似气泡底/
  描边被误挑为填充）→ 改试有彩的候选簇吸附；首选簇有彩（启发式挑到了真
  颜色，哪怕调板里没这个色）→ 信任启发式。低彩闸是防反吸：黑字白边 +
  调板含白（别处的白字）时，不许把白描边反吸成填充。
- **对已有块生效**：调板页有「重取当前页／重取整本颜色」——按原图对现有
  块重跑取色（无概率图走经典二值化，实测与概率图同色值），置信度闸门与
  检测管线相同；块列表不换新、不动页代数（保住撤销锚点），改动页标
  `mark_page_needs_rerender`，当前页视觉层刷新经面板注入回调走
  `ui/glossary_agent_panel.py::GlossaryAgentPanel` 的 `_refresh_canvas_after_write`。
- 检测时的吸附接线：两个检测器的 `extract_colors` 调用都透传
  `proj.fg_palette`（proj 为 None 时无调板，探针即此形态）。

### 全书扫描与候选色（2026-10-03 三版）

自动判据与人工采样之外，补一条「先看全书到底有几种文字色」的入口：调板页
`Scan Book Colors`（`ui/workbench_palette.py::FgPalettePage`）同步跑
`utils/color_extract.py::scan_project_colors`，结果只作**候选草稿**，勾选后点
`Add Checked to Palette` 才入调板。

- **数据来源＝块上已有的 `fg_colors`**（检测阶段
  `modules/textdetector/base.py::TextDetectorBase` 的 `extract_colors` 写入），
  **不重跑检测、不重跑管线**；有效性统一走
  `utils/proj_imgtrans.py::normalize_rgb`（int 截断，能吃 float 数组），聚类走
  `utils/color_extract.py::cluster_font_colors`。
- **代表色是众数（真实观测值），合并半径
  `utils/color_extract.py::CLUSTER_RADIUS` 默认 27 ≤
  `utils/color_extract.py::PALETTE_SNAP_DIST`(45)**。众数而非均值：注入判据
  `utils/proj_imgtrans.py::speaker_hints_for_blocks` 是**精确相等**，均值往往
  不是任何块的真实色，入库后一个块都不命中、静默失效。半径 ≤ 吸附距离保证
  **收敛路径**：候选入库 → 跑一次「重新取色（整本）」，整簇块被吸附成调板
  原值，精确相等开始命中。
- **候选行**：勾选＋色卡＋`#rrggbb`＋命中块数，命中吸附距离的标
  `[In palette]` 并**禁勾**（再入板只会重复）；下行最多 4 张样本缩略图，裁剪
  沿用 `ui/workbench_tasks.py::PageImageCache`（**不另写外扩/裁剪几何**），
  点击经 `jump_requested` 跳画布；裁不出图时显示「无可显示区域」。摘要行报
  「共 N 块 / M 块有颜色 / 发现 K 种」，单次色默认隐藏（勾
  `Show colors that appear only once` 才显示；关掉时不可见的行取消勾选，不会
  被「应用」带走）。
- **入库**：逐条追加 `{"rgb": …, "role": …}`（占位名经
  `utils/proj_imgtrans.py::ProjImgTrans` 的分配入口）→ `save()` → 重挂色表 →
  toast 提示去点「重新取色（整本）」对齐块色；候选保留并自然变成「已在调板」。
  候选状态（扫描结果、勾选、待改目标）**只存内存**，换项目/重扫即清，**不落
  项目 JSON**。
- **改色**：候选行「改色」把下一个画布取样路由到该候选（复用画布取色模式与
  面板接线，不另立入口）——下一次落点改该候选代表色并清目标，**不追加**调板
  条目；没有待改目标时画布取样仍是原语义（判重后追加占位名条目）。用途是在
  整页语境下重新确认拿不准的色。
- **刻意不做的（用户口径：不可信或复杂度过高的宁可不做）**：独立核对窗口与
  真瀑布流（候选区就在调板页里，缩略图随行换行）；簇的合并/拆分/手动划归
  （不对就不勾、或点「改色」重取）；样本级订正与批注；应用后自动改写块颜色
  （人工在环，只提示去点「重新取色」）；AI 赋真名联动与置信度排序（置信度
  根本没落盘，`extract_colors` 只在过闸门时写 `frgb`，算完即丢）；背景色/描边
  色分类（`utils/color_extract.py::ExtractedBlockColors` 的 `srgb` 字段不落盘）。

## 管线接线

- 取色在**检测阶段**完成。共用入口在基类
  `modules/textdetector/base.py::TextDetectorBase`（`extract_colors`）：
  `PPOCRv6Detector` 传概率图，`YSGYoloDetector` 传 `None` 走经典二值化兜底；
  开关是同名检测器参数 `extract colors`（各自 params 里声明，默认开）。
- **只写前景色**。`utils/textblock.py::TextBlock` 的 `bg_colors` 落在
  `utils/fontformat.py::FontFormat` 的 `srgb`，那是**描边色**视图，写进去会把
  已有描边的块涂成背景色；提取到的背景色只随返回值提供给上层。
- **与全局样式的交接**：`utils/config.py::ProgramConfig` 新增
  `let_fntcolor_flag`（0=由程序决定 / 1=使用全局设置），在
  `ui/configpanel.py::ConfigPanel` 的「应用设置」委派格里与字号/描边宽/对齐/
  书写模式/字体并列。选「由程序决定」时 `on_pagtrans_finished` 不覆盖前景色
  （保留自动取色结果或用户手改值），**描边色与其余效果仍随全局**——这样
  「每块字色不同 + 全员统一描边色」能同时成立。

## 描边机制的现状（本批未改语义）

- 描边色：全局样式效果卡指定 → 随全局下发给每个块；块级手动色经效果卡改。
- 描边宽：`let_fntstroke_flag` 决定「程序决定（按字色/背景色差自动）／使用全局」。
- 自动反色：`pcfg.stroke_auto_follow` 全局开关，只在**新建描边**那一次按当时
  字色反色，之后纯手动（2026-09-08 拍板）。
- 因此「全员固定描边色」现成可达：全局样式里给描边卡选色 + 关掉自动反色即可，
  自动取色不会碰描边色。

## 待实装：模块能力标注

检测器的取色能力目前是**按检测器硬编码**的（只有 `PPOCRv6Detector` 走概率图
路径）。仓库已有一套「模块能力元数据」先例：`modules/base.py::BaseModule` 的
`requires_gpu` 类属性经 `modules/__init__.py::GET_MODULE_REQUIREMENTS` 透出，
下载入口（`ui/model_downloads.py::gpu_required_message`）据此拒绝不合规的机器。

**标注机制本身尚未实装**（没有统一的「能力位」注册与查询入口）。实装时建议：
给检测器类加 `supports_color_extraction = True` 类属性（`PPOCRv6Detector` 走
概率图路径、`YSGYoloDetector` 走二值化兜底，两者均可置位），在
`GET_MODULE_REQUIREMENTS` 里按 `requires_gpu` 同款写法透出，UI 据此决定是否
显示「提取颜色」参数与「字体颜色 = 由程序决定」委派项，并对不支持的检测器给出
提示。在那之前，参数开关由各检测器自己的 `params` 承担（关掉即不取色）。

## 实测

样张：本机一本全竖排差分同人志（179 页 JPG，正文多色 + 随机拟声词）。

- 176 页有文字块，共 1220 块，**零取色失败、零低于闸门的块**（置信度分布：
  1020 块 = 1.00，18 块 0.8~0.99，2 块 0.6~0.7）。
- 目视抽查（`scripts/probes/probe_color_extract.py` 的块裁剪拼图）：黑字白边 →
  黑、黄字列 → 黄、蓝字列 → 蓝、粉拟声词 → 粉，跨页同一角色的色值稳定
  （如 `#569af6` / `#e5bf09` / `#fe9cfd`）。
- 已知取舍：白填充 + 彩边的空心字会取到彩边色（拼图上看「しこ♡」取粉）——
  与同页粉系拟声词一致，比取白更可读；多色混排的块取到的是主色簇。
- 复杂度背景上提取的「背景色」不可靠（插图底色），只用于否决与描边宽判定，
  不写进任何渲染字段。

### 复跑方式

```bash
# 单页/区间抽查，产物是每块的裁剪拼图（只含文本区）
```

## 说话人颜色标记（2026-10-03 实装）

方案定稿见桌面《说话人颜色标记_方案评估_2026-10-03.md》（用户拍板 v2）。
落地形态：**给颜色贴角色标签**（不是给角色填颜色），标记仅作为注入给翻译
agent 的**输入线索**，块上不存角色名。

- **数据层**：`fg_palette` 条目升级为 `{"rgb": [r,g,b], "role": str}`
  （role 空=未赋名，落盘 `utils/proj_imgtrans.py::to_dict` 时 role 空不落键）；
  宽进旧裸三元组，载入即补占位名（`load_from_dict`，用户手清的空 role 不重复赋名）。
- **占位名**：Excel 列式（A…Z、AA…，`utils/proj_imgtrans.py::palette_seq_to_name`），
  入板即固化进 role、**删除不复用**——分配序号落项目键 `fg_palette_seq`
  （fork 独有键，已在《上游兼容策略》§二登记为接受项）。`^[A-Z]{1,3}$`
  是「还叫占位」的识别口径，UI 与注入拼成 `Speaker A` 全称、存储只存短名。
- **调板页**（`ui/workbench_palette.py::FgPalettePage`）：色行＝色块 + HEX +
  **角色名可编辑下拉**（候选＝已有角色名，可自由输入；`editingFinished` 即存）
  + 删除钮；删除带角色的色条时 toast 报「该色被 N 个块使用」（精确相等口径）。
- **注入**（`modules/translators/agent/prompts.py::build_user_task_message`）：
  `speaker_hints` 与任务块对齐（未命中为 None，注入侧按位置还原块 id），
  只列块前景色与调板**有角色条目精确相等**的块；走 user message 独立小节、
  无开关、无标注整节省略。接线在
  `modules/translators/base.py::translate_textblk_lst`（按
  `supports_speaker_hints` 声明传参，其余翻译器不收该参数）。多色一角色天然合并。
- **AI 赋真名**（第一期）：翻译准备页「说话人赋名…」按钮
  （`ui/glossary_agent_panel.py::_assign_speakers_command`）
  拼指令——调板 + **已应用术语表快照**（会话只读工具不含术语表，故内联）
  + 各色台词样本（每色上限 8 条）；AI 只产出建议表进会话日志，**不写调板**。
- 框级「结合上下文重译」（`translate_with_context`）暂未带 speaker hints（只走页级管线）。
