# 查找替换与样式管理器重构 设计方案

> 状态：**定稿（2026-08-28）；阶段 1-4 全部完成（阶段 3 于 2026-08-30 落地并实机验收，阶段 4 于 2026-08-30 落地）**。含上游 v1.5.12 之后未发版重构的适配评估（§7）。
> §5/§6 的"规划中"符号已在阶段 3 落地时回填为 `路径::符号` 规范引用。

## 1. 背景与目标

引入 Word 式查找替换：除文本外，还能按**文本样式条件**查找，并对命中块做**样式替换**。同时重构现有简陋的样式管理器 UI（左树参数不可见、右栏全部控件平铺）。

目标：

1. 一个纯数据层的**块查询引擎**，文本谓词与格式谓词自由组合，查找替换与样式管理器共用。
2. **统一的替换提交流程**：单一"仅替换数据"按钮 + 脏页处理询问，消除现有双替换按钮的认知负担。
3. 样式管理器 UI 按"差异优先、预览即数据"重构，编辑器控件可与查找替换的格式条件编辑器复用。

范围决策：**只做块级 FontFormat 替换，不做字符级（rich_text 内联格式）**。字符级是另一套数据模型，留作将来独立议题。

## 2. 现状盘点

### 2.1 查找替换（可复用的部分）

- `ui/global_search_widget.py::GlobalSearchWidget`：全项目查找（原文/译文/全部 + 正则/大小写/全词）、结果树点击跳转。
- 替换原有两条路径（阶段 2 已合并）：`ui/global_search_widget.py::on_replace`（原走 `ui/textedit_commands.py::GlobalRepalceAllCommand`，阶段 2 短暂统一为可撤销命令，阶段 2.5 起改为快照回滚语义，见 §4.4）与已删除的"替换并全部重渲"按钮。**双按钮是本次要消除的复杂度。**
- `ui/global_search_widget.py::_collect_replace_targets`：当前页走 live widget、非当前页直写 `TextBlock` 数据 + `utils/proj_imgtrans.py::mark_page_needs_rerender`——这套脏页语义正确，直接沿用。
- 搜索遍历直读 `pages` 数据不经渲染层，查询引擎沿用此模式（离屏可测）。

### 2.2 样式体系（可复用的部分）

- 数据模型见 `utils/base_styles.py::BaseStyle`（身份键 = `(font_family, vertical)`）与变体派生 `utils/base_styles.py::compute_override` / `utils/base_styles.py::discover_style_tree`。
- **部分属性替换语义已存在**：`ui/fontstyle_manager.py::_collect_changed` 只把动过的字段做成 patch，`utils/base_styles.py::build_flatten_changes` / `utils/base_styles.py::build_variant_changes` 生成全项目 `{pagename, blk_idx, old_ffmt, new_ffmt}` 列表，交给 `ui/fontstyle_manager_commands.py::BatchFontformatCommand`。
- 缺陷：查询能力被锁死在样式身份键上，不能做"字号 ≥20 且描边为红"这类自由谓词组合。

### 2.3 脏页机制（沿用）

数据层唯一写入口 `utils/proj_imgtrans.py::mark_page_needs_rerender`（仅非当前页）；切页惰性重渲走 `ui/mainwindow.py::pageListCurrentItemChanged`；批量重渲走 `ui/mainwindow.py::_rerender_dirty_pages`；落盘走 `ui/mainwindow.py::_sync_and_commit_project`。

## 3. 总体架构：BlockQuery 谓词引擎（规划）

查询引擎已落地为 `utils/style_query.py`（阶段 1 完成），依赖 `utils/base_styles.py` 的量化设施：

```text
BlockQuery（utils/style_query.py::BlockQuery）
  text:   TextPredicate    # 复用 global_search_widget 的匹配能力：原文/译文/正则/大小写/全词
  format: FormatPredicate  # 字段级谓词：语义字段 → 目标值 | 未指定(任意)
  组合方式: AND（text 与 format 至少一个非空）
  match(blk) -> bool
  collect(proj) -> [{pagename, blk_idx}]   # 全项目遍历 pages，直读数据
```

阶段 1 补充落定：谓词可用字段 `utils/style_query.py::PREDICATE_FIELDS` = 身份键 + `utils/base_styles.py::DIFF_FIELDS`（上游效果栈进入 DIFF_FIELDS 后自动可查询）；字段分组 `utils/style_query.py::FIELD_GROUPS` 供样式管理器与查找替换格式编辑器共用；查询驱动的批量补丁 `utils/style_query.py::build_query_changes` 已就位（阶段 2 的命令层直接消费）。

**FormatPredicate 设计要点：**

1. **语义字段抽象**：谓词按语义字段（描边宽度、前景色……）定义，**只通过 `FontFormat` 公开属性读写**（`utils/textblock.py::TextBlock` 的属性委托层），不直接触碰内部 dict。这是为上游 effects 化预留的兼容缝，见 §7。
2. **归一化比较**：每字段注册归一化函数（浮点走 `utils/base_styles.py::_FLOAT_QUANT` / `utils/base_styles.py::_quantize` 同款量化），比较 = 归一化后相等。数值型谓词额外支持区间比较（如"字号 ≥ 20"）。
3. **归一化注册制**：字段清单即注册表，未来新增参与 diff 的字段（如上游的 `text_effects` 整栈）只需注册其归一化函数（整栈序列化元组），不改引擎结构。
4. v1 参与谓词/替换的字段分组见 §5.3 字段映射表；排除 `_style_name`（内部）、`punctuation_alignment`（已弃用）、`deprecated_attributes`（迁移遗留）。

## 4. 替换语义与统一提交流程

### 4.1 替换模式（用户手动选择）

| 模式 | 语义 | 默认 |
| --- | --- | --- |
| **按块 patch** | 对命中块只替换"替换格式"中指定的字段，其余字段（含块自身 override）保留 | ✅ |
| **整块应用大样式** | 命中块整体替换为选定大样式的完整 FontFormat（下拉选择） | 可选 |

**身份键字段参与替换是合法操作**：patch `font_family` / `vertical` 会使块迁移到另一个大样式归属，应用后需触发样式树重发现（`discover_style_tree`）。顺序契约参考 `utils/base_styles.py::build_flatten_changes` 的"先 collect 后更新 base"约束。

### 4.2 统一提交流程（已落地，合并原双按钮；撤销语义经阶段 2.5 改定）

```text
[替换] 按钮（唯一，ui/global_search_widget.py::GlobalSearchWidget.on_replace）
  → ui/global_search_widget.py::replace_preparing（施加前信号）：
       MainWindow._sync_and_commit_project（当前页 UI → 数据并落盘）
       → utils/proj_imgtrans.py::write_batch_backup 写单槽快照
         （快照必须反映替换前完整状态，且须在收集器原地改写非当前页
           数据之前写好）
  → ui/global_search_widget.py::_collect_replace_targets 收集并施加：
          当前页 live 路径 → 暂存 live widget 引用
          非当前页 → 数据直写 + mark_page_needs_rerender
  → ui/global_search_widget.py::replace_finished →
       ui/textedit_commands.py::GlobalReplaceApplier 施加当前页改动
       （构造期守卫下 edit/item 双文档各改一次并清其文档撤销栈；
         format_changes 契约 = utils/style_query.py::build_query_changes）
  → _sync_and_commit_project 落盘
  → 面板出现回滚条（本次替换的块数/页数 + "撤销本次替换"按钮）
  → ui/mainwindow.py::_ask_rerender_dirty_pages 固定询问：
       "替换完成，立即重渲已修改的页面？ [立即重渲] [稍后处理]"
       立即重渲 → ui/mainwindow.py::_rerender_dirty_pages
       稍后     → 保留脏角标，切页惰性重渲 / run 对话框"仅渲染"
```

**快照路径分两类的理由（历史）**：文本路径依赖编辑文档撤销栈，格式路径依赖 setHtml 全量换入，
同一块混用两套机制会在 undo/redo 时互相踩踏（clearUndoRedoStacks / 栈错位）。
阶段 2 曾让格式命中的当前页块连同其文本改动整体走快照（`ui/textedit_commands.py::NormalizeBreaksCommand`
同款模式）；阶段 2.5 起两类统一为施加器一次性写入 + 快照回滚，见 §4.4。

**后台慢速处理预留**（用户后续计划，本期只留缝）：`_rerender_dirty_pages` 已是独立可复用入口
（输入：脏页集合；产出：QProgressDialog 进度），未来后台任务机制只是换一个调度方，
经通知中心（`ui/custom_widget/notification.py::NotificationCenter`）展示进度。

**脏页询问策略（已定稿）**：每次替换操作固定弹出询问，不提供"不再询问"静默选项；仅当未来启用后台脏页处理机制后，由该机制接管询问。

### 4.3 溢出裁剪选项（已定稿：复用既有全局机制，不另造）

格式替换可能改变排版（字号/字距变大等），导致内容溢出原文本框、破坏块的 bounding 形状。

**阶段 2 落地时发现 fork 已内建该能力**，全局替换直接继承，无需在替换 UI 另加开关：

- `utils/config.py::clip_text_overflow`（默认开启，标题栏有开关）；
- `ui/textitem.py::on_document_enlarged`（`TextBlkItem`）：裁剪模式下抑制盒子自动扩张，记录溢出状态；
- `ui/textitem.py::_paint_native`：溢出文本裁剪到块自身内容边界 + 黄色提示框；用户拖拽调整（`ui/textitem.py::startReshape`）自动解除裁剪态。

替换/重排触发的 layout 溢出走同一条 `size_enlarged → on_document_enlarged` 链路，
当前页与惰性重渲场景均被覆盖。若用户关闭全局裁剪，替换后溢出则表现为盒子自动撑大——
与手动编辑行为一致，符合"开关只影响裁剪行为本身"的预期。

**撤销行为（阶段 2.5 定稿：批量与逐块编辑严格分治，见 §4.4）**：批量替换整体回滚走项目快照，不走撤销栈；逐块精细撤销继续由既有"每页独立、切页即清"的文档撤销栈负责。施加器写入后清空涉及文档的撤销栈——遗留零散步会在回滚后与文档状态错位；已知代价：同块在替换前的手动输入不可再经文档栈回溯，其余块不受影响。`format_changes` 传入的 `FontFormat` 须在施加器入口深拷贝、写回 `blk.fontformat` 时亦深拷贝——否则与 blk 共享对象被外部原地改写（如重建时排版回写）会串改替换目标值。

放弃撤销栈交错路径的原因（2026-08-29 实机复盘，两轮修复后被快照方案整体取代）：构造期 `doc_replace` 先经同步链传播改写 item 文档、随后的 `doc_replace_no_shift` 在其上再套用一次 span（双重替换）；命令与自动压栈的 `TextEditCommand` 对同一文档步双重记账，撤销时互相吞步（表现为替换后 Ctrl+Z 无响应）；`availableUndoSteps` 在 `contentsChanged` 信号时刻尚未计入当前编辑块（滞后一步），推栈时机不可靠；栈中残留命令在场景重建后引用已删 widget，Qt 虚函数内未捕获异常/悬空引用直接原生段错误（闪退）。即便全快照命令语义收敛后，实机仍复现"命令弹出但落点静默失配"（含仅替换当前页的情形），故最终裁决：批量操作不再进入任何撤销栈，其撤销语义整体移交快照回滚（§4.4）。

**撤销通知（阶段 2 附加，阶段 2.5 扩展）**：`ui/mainwindow.py::on_undo` / `ui/mainwindow.py::on_redo` 在历史位置实际变化时经通知中心 `ui/custom_widget/notification.py::toast`（anchor=bottom-left，key 去重）弹出"已撤销/已重做"，连续撤销刷新同一条通知；历史位置未变（无可撤销内容）且本会话存在可用批量快照时，提示可到查找替换面板整体回滚——批量操作撤不动的原因在见底第一时间被解释。

### 4.4 批量快照回滚（阶段 2.5 定稿并实施）

**语义：批量操作只有一把总闸——要么整批退回快照，要么不退。** 批量替换不进页栈、不与逐块编辑撤销混排（混排的推演缺陷：批量后若干手工编辑再想回快照，逐个撤销全是无用功——快照恢复本就连带丢弃其后全部编辑；且跨页批量命令压在单页栈里，恢复范围远超用户眼前所见）。

- **单槽快照**：`utils/proj_imgtrans.py::write_batch_backup` 把当前已落盘的项目 JSON 整体快照到项目目录旁的 `*.batch_backup.json`（原子写入，覆盖旧槽），并记录快照时刻的脏页清单（含当前页）。不做多版本时间戳——回滚只服务"后悔上一批量"。
- **会话内有效**：`utils/proj_imgtrans.py::has_batch_backup` 要求本会话写入过；磁盘残留的跨会话文件不提示恢复。切换/加载项目即失效；`utils/proj_imgtrans.py::clear_batch_backup` 供空替换等路径显式清槽。
- **回滚**：`utils/proj_imgtrans.py::restore_batch_backup` 用快照整体换回各页数据与 base_styles，按快照重标脏页（其中已被重渲过的页结果图此刻必然过期），保持用户当前页不跳转，成功后消费快照。入口两处共用：① 查找替换面板回滚条（替换完成后出现"已替换 N 块 across M 页 ｜ 撤销本次替换"，下一次替换或回滚后消失，经 `ui/global_search_widget.py::batch_rollback_requested` 发往 `ui/mainwindow.py::on_batch_rollback`）；② 见底 toast 提示指引到面板。回滚后清空画布撤销栈、重建当前页场景、重新落盘并走 `_ask_rerender_dirty_pages` 固定询问。回滚确认对话框讲清"将丢弃批量替换之后的全部修改（含其后手动编辑）"。
- **顺带简化**：`ui/mainwindow.py::_rerender_dirty_pages` 删除 `clear_stack` 参数与 `_batch_rerendering` 守卫（保栈只为命令重绑定服务，命令栈路径移除后无所保）。

## 5. 样式管理器 UI 重构

### 5.1 设计三原则

1. **差异优先**：变体只展示 override 字段，其余折叠为"与基准一致"；改动字段高亮。
2. **预览即数据**：预览卡是参数的第一显示层，取代大部分文字摘要行。
3. **编辑器复用**：右栏分组控件 = 查找替换格式条件编辑器的控件来源。

### 5.2 右栏：预览卡 + 差异优先分组（✅ 已落地，2026-08-30）

```text
┌────────────────────────────────────────┐
│  思源黑体-正文         竖排 · 34 块    │
│ ┌────────────────────────────────────┐ │
│ │      漫画预览 Aa 123               │ │ ← 真实字体实时渲染预览卡
│ └────────────────────────────────────┘ │
│ [思源黑体] [24px] [B] [■#FFF] [描2px]  │ ← 关键参数 chip 行（只读，点击滚动定位）
│────────────────────────────────────────│
│ ▾ 文本                ● 2 项与基准不同 │ ← 四组折叠区，组头状态徽标
│ ▸ 颜色与描边           与基准一致      │
│ ▸ 排版                 与基准一致      │
│ ▸ 效果                 阴影·渐变·变换  │
│────────────────────────────────────────│
│            [ 应用修改 ]                │
│ 使用此样式：页1(3) 页2(5) … 点击跳转   │
└────────────────────────────────────────┘
```

落地结构（`ui/fontstyle_manager.py::StyleDetail` 重写）：

- **预览卡** `ui/fontstyle_manager.py::StylePreviewCard`：QTextDocument 近似渲染（字体/字号/颜色/粗斜下划/行距；竖排逐字堆叠近似），编辑字段实时刷新。
- **chip 行** `ui/fontstyle_manager.py::_ChipBar`（手工 resizeEvent 换行布局——PyQt6 下 Python 自定义 QLayout 子类在布局激活时原生段错误，勿走 QLayout）；点击 chip 滚动定位到对应分组。
- **四组折叠区** `ui/style_format_editor.py::FormatGroupCard`（组头状态徽标"与基准一致 / ● n 已修改"，改动组自动展开、字段高亮）+ `ui/style_format_editor.py::FormatEditorPanel`（字段清单来自 `utils/style_query.py::FIELD_GROUPS`；变更收集 `FormatEditorPanel.changed_values` 量化 diff 语义与旧 `_collect_changed` 一致，基线为 None 且编辑值是中性默认时不算变更）。原"13 行只读属性行 + 平铺编辑控件"双视图已删除。
- **效果组只读摘要**（2026-08-30 实机验收反馈调整）：阴影/渐变/变换/斜切不提供编辑控件——详细配置占空间且交互效率低，组头徽标笼统标记 `ui/style_format_editor.py::effects_tokens`（激活语义与预览 chips 一致）；保存/应用样式时效果字段原样透传，`changed_values`/`current_values`/`sync_into` 均不含效果字段（§7 效果栈迁移时整组替换为效果卡片栈）。
- **折叠组标题修复 + bold 弃用**（2026-08-30 二轮验收反馈）：`FormatGroupCard` 组头此前漏 `setText` 导致只显状态徽标无组名——补 `self._toggle.setText(self.title())`；`bold` 弃用（字重全走 `font_weight`）——从 `utils/style_query.py::FIELD_GROUPS`、`utils/base_styles.py` 的 `_SIGNATURE_FIELDS`/`DIFF_FIELDS`/`_BOOL_TOKENS`、编辑器字段清单与树摘要/预览 chips 全部移除，`utils/fontformat.py::FontFormat` 数据字段仅为旧项目兼容保留（`ui/text_panel.py`/`ui/textitem.py` 镜像写入不动）。
- **变体模式**：`FormatEditorPanel.set_format(only_fields=...)` 只渲染 override 字段，无字段的组隐藏；"重置为基准"动作 = `ui/fontstyle_manager.py::_reset_variant_to_base`（把基准值写回变体块，重发现后变体溶解）。
- **动作区**：未分组 → 提升为大样式（`_promote_to_base`）；大样式 → 存预设 / 删除；应用按钮统一为一个（`_apply_all`）。
- **块分布**：`页1(3) 页2(5)…` 页 chip（tooltip 列块号，点击跳该页首个块），复用 `navigate_to_block` 信号；原 `StyleBlockList` 树已删。

### 5.3 字段 → 分组映射（v1，本地 FontFormat 字段）

| 分组 | 字段（`utils/fontformat.py::FontFormat`） |

## 6. 查找替换 UI（格式条件）（✅ 已落地，2026-08-30；同日实测「太挤」改浮层展开）

`ui/global_search_widget.py::GlobalSearchWidget` 新增（第三行工具条 + 按钮锚定下拉浮层）：

- **查找侧"格式条件"入口** 与 **替换侧"替换格式"入口**：两个互斥的 checkable 按钮（`QToolButton#FormatToggleBtn`，QSS checked 态走强调色），点击展开 `ui/custom_widget/float_drop_panel.py::FloatDropPanel` 浮层（交互对齐侧栏 RailDockPanel：**左缘钉在搜索栏右缘、向画布方向展开**——搜索栏保持完全可见可交互；Esc/×/再点按钮关闭，无 pcfg 开合记忆），浮层内是 `QStackedWidget` 承载的两个 `ui/style_format_editor.py::FormatEditorPanel` 页（阶段 3 的四组折叠控件直接复用，效果组仍为只读摘要徽标、不出编辑控件）。**不用内嵌布局的原因**：FormatEditorPanel 的字段行（字体下拉等）最小宽 ~390px，内嵌会把整栏最小宽撑到 ~470px，与 300px 动画列宽冲突导致子控件超界裁切、边框圆角被截；浮层不参与布局无此压力。宿主在**首次打开时惰性解析**为 `window.centralWidget()`（构造期控件树尚未挂进主窗口，`window()` 不可靠）。默认尺寸 420×480（MIN 常量），面板本体继承 `Widget` 基类带 `WA_StyledBackground`，QSS 圆角边框才真正生效。动过的字段数以 `(n)` 追加在按钮文案与浮层标题，查找页头右侧"清空"复位基线；替换页头为「模式下拉 + 清空」，样式下拉仅大样式模式显示在页体顶部。
- **替换模式**：`ui/global_search_widget.py::_replace_format_payload` 按模式下拉二选一——按字段 patch（默认，只动替换格式面板中动过的字段）或整块应用大样式（样式下拉取自 `proj.base_styles`，选中即深拷贝完整 FontFormat）；模式/样式下拉仅在替换格式入口开启时可见。
- **查询即预览**：查找格式条件以 `ui/global_search_widget.py::_find_format_conditions` 读面板实时 diff（相对 `FontFormat()` 默认基线），生成 `utils/style_query.py::FormatCondition`（eq，量化比较）组合为 `utils/style_query.py::FormatPredicate`；条件变更后 Enter 重新搜索。
- **搜索语义**：格式条件激活时，范围下拉的原文/译文维度仅作用于文本谓词（格式是块级）；命中 = 文本谓词 AND 格式谓词。无文本条件时**格式-only 命中以块级条目展示**（无高亮 span，点击照常跳块）。
- **替换语义**：`ui/global_search_widget.py::_collect_replace_targets` 按同一查询门控收集——文本路径沿用现行"当前页 live widget 暂存 / 非当前页直写 + 标脏"；格式 patch **收集期不写数据**，统一暂存为 `format_changes`（old/new_ffmt 均深拷贝，契约 = `utils/style_query.build_query_changes`），由 `ui/textedit_commands.py::GlobalReplaceApplier` 在施加期一次性落点（当前页 live item + 数据层兜底、非当前页直写标脏）；回滚条计数按 (页, 块) 去重（`ui/global_search_widget.py::_show_rollback_strip`）。
- 快照回滚、脏页询问、溢出裁剪链路均不经由本节改动（§4.2/§4.3/§4.4 语义不变）。

## 7. 上游适配评估（v1.5.12 后未发版重构）

上游 dev（09a7aad..8108436，2026-08-21 后）有两组直接相关的底层重构，**均未发版**：

### 7.1 文字效果域重构（影响：效果组，留缝）

- 新增不可变类型化效果栈 `ballontranslator/utils/text_effects.py`（TextEffectStack：solid/渐变 paint、blend 模式、filters（bloom/blur/glitch/grain/noise）、alpha mask、阴影类型、描边位置），`ui/text_engine/effects/` 全新包（renderer/panel/cards 等）。
- 上游 `FontFormat` 的 `text_effects` 字段成为描边/阴影/渐变/不透明度的**唯一权威所有者**；旧扁平字段（`shadow_*`、`gradient_*`、`opacity`、`stroke_width`、`srgb`）降级为 legacy view——经属性钩子兼容读写，旧项目自动迁移。

**判定：本方案数据层设计不变，留三道缝。** ① §3 已约束谓词只走 FontFormat 公开属性——上游迁移后 legacy view 仍兼容读，谓词定义零改动；② §5.3 "效果"组边界恰好对齐上游 effects 迁移边界，移植时该组内部实现整体替换为效果卡片栈，不波及其余三组与整体布局；③ §3 归一化注册制使 `text_effects` 整栈未来可作为单个字段注册（序列化元组归一化）参与 diff/谓词。**不为未发版内容提前重构数据层。**

### 7.2 字体注册表与字重选择器（影响：文本组控件级，跟随移植）

- 新增 `ballontranslator/utils/font_registry.py`（字体 name 表解析、weight 映射、持久化、`resources/font_registry_overrides.json`）+ 字重选择器 rework（仅显示有效字重、bold 回退）。

**判定：不影响布局与数据层，属"文本"组内控件级替换**（字体族/字重下拉的取值来源改为 font_registry），跟随上游移植顺带完成。

### 7.3 移植顺序建议

本重构四阶段不依赖上游未发版内容；§7.1 效果组替换、§7.2 控件替换在上游发版后的移植批次中执行。若移植先于本重构阶段 3，则效果组控件直接按效果卡片栈实现，跳过扁平字段版。
