# 快捷菜单竖排样式（List） 设计与交接文档

> 状态：已实现并通过离线验证（2026-08-12）。
> 面向读者：① 后续接手此功能的开发者；② 未来承担**视觉修缮**的多模态 AI。记录设计思路、数据模型、竖排视觉常量位置、交互定位/钳制、已知 Qt 坑、待修缮/扩展清单。环形样式仍见 `多菜单环形菜单_设计与交接.md`。
> 改动未提交，git 规则见文末。

## 一、一句话现状

快捷菜单（原「环形菜单」设置页，2026-08-12 更名）的每个菜单新增 **Ring / List 两种样式**：环形保持 Blender 式扇区，**竖排（List）把命令卡片垂直堆叠成一列**，弹出在光标的左侧或右侧（`direction` 可配，默认右侧），垂直居中于光标。卡片视觉与环形完全一致（圆角卡片 + 悬停 accent 高亮 + 禁用降透明度），只是没有扇区号。触发/状态机零改动（长按释放提交、短按 PIN、Esc/右键/点击外部取消）。

**用户拍板的设计哲学：竖排列表没有分隔线。分组靠"一个菜单 = 一个功能组"，想分割不同功能就拆成新菜单。** 因此命令池里没有"分隔线"伪条目，列表是纯命令卡片列。

- 配置页：设置 → 快捷菜单 → 选一个菜单 → **样式** 下拉切「竖排」→ 预览立刻变成垂直卡片列 → **方向** 下拉在 左/右 间切换 → 从下方命令池拖命令进列表（按 y 位置插入）、列表内拖动排序、右键/拖回池移除。

## 三、设计思路（为什么这样做）

核心决策链（均经用户逐点确认）：

1. **竖排无分隔线**（2026-08-12 用户否决"分隔线方案"）。用户原话：沿用现有环形菜单的卡片样式，**同类功能卡片合并为一个小菜单；想要分割时直接把不同功能拆分为新的小菜单**。→ 数据模型保持扁平、命令池不加伪条目、编辑器不加分隔 UI，全部简化。
2. **样式切换复用 `layout` 扩展位**。`normalize_pie_menu` 原来就把 `layout` 透传（默认 "ring"），本次只加合法值校验 `("ring","list")`。环形路径（渲染/命中/拖放）**零改动**，竖排是并行的第二套几何，靠 `PieMenu._is_list()` 分支。MainWindow 触发流与布局无关（`set_menu_config` + `start_hold`），**一行不用改**。
3. **状态机/信号复用**。holding/pin/release-commit、窗口 flag（Tool/frameless/stay-on-top/不抢焦点）、`command_triggered`/`canceled` 全部共用；竖排只新增两个 preview 信号（`list_command_dropped`、`list_item_remove_requested`），编辑器按当前 layout 解释 mime。
4. **竖排定位 = 光标旁列 + 垂直居中 + 屏幕钳制**。方向 `right`：列左缘 = 光标 x + `LIST_EDGE_OFFSET`；`left`：列右缘 = 光标 x - `LIST_EDGE_OFFSET`。y = 光标 y - 列高/2（垂直居中，与环形"光标居中"哲学一致）。最后用 `screenAt` 的 `availableGeometry` 钳制，保证列不超出屏幕（列表比屏幕还高时保顶可见）。
5. **命中必须落在卡片上**（无环形那种"整扇区热区"方向回退）。光标按住时停在列外 16px 处 = 无悬停 = 松开即取消，天然防误触；要提交必须把光标移上卡片。
6. **双向样式转换保命令不丢**（容量内）：ring→list 用 `slots_to_items` 扇区主序展平；list→ring 用 `items_to_slots` 顺序分发回扇区（每扇区≤3）。容量不对称（环形 8×3=24 vs 竖排 `LIST_MAX_ITEMS`=24）刻意对齐，故正常转换无损。

## 四、数据模型与转换

`pcfg.pie_menus[*]` 新增/校准字段（`ui/pie_menu.py::normalize_pie_menu` 恒输出全部字段）：

```python
{
    "id": ..., "name": ..., "trigger": ...,
    "layout": "ring" | "list",      # 合法值校验，非法回退 "ring"
    "sectors": 8,                    # ring 用（恒归一化保留）
    "slots": [ [...], ... ],         # ring 用（恒归一化保留）
    "direction": "right" | "left",   # list 用，默认 right，非法回退 right
    "items": [cmd_id, ...],          # list 用：扁平命令 id 列，上限 LIST_MAX_ITEMS，过滤非 str 与 SEPARATOR_SENTINEL
}
```

- **双表示并存**：无论当前 layout 是什么，`slots` 与 `items` 都归一化保留，样式切换时按需重算对方，运行时只读当前 layout 对应的那份。
- 转换函数（导出供编辑器与测试复用）：`slots_to_items(slots)` 扇区主序展平；`items_to_slots(items, sectors)` 顺序填扇区（每扇区 `SECTOR_MAX_CARDS`）。
- 迁移/默认菜单不动（`DEFAULT_PIE_MENUS` 全是 ring）；旧配置无 `direction`/`items` 时 normalize 自动补默认。
- 配置页实时保存模式不变（改 `pcfg.pie_menus` + `save_config()`），下次按触发键即生效。

## 五、代码结构与实现索引（接手必读）

| 文件 | 职责 |
|------|------|
| `ui/pie_menu.py` | 竖排几何/命中/绘制/拖放 + 定位钳制；`normalize_pie_menu` 扩展 + 转换函数；新常量 |
| `ui/pie_menu_editor.py` | 属性行二段式重构（Row1 名称/触发键/冲突 pill，Row2 样式/扇区数/方向）；`_on_style_changed`/`_on_direction_changed`；动态提示文案 |
| `translate/zh_CN.ts` | `PieMenuEditor` context 新增 7 条（样式/环形/竖排/方向/左/右/竖排拖拽提示）；新建菜单上限文案改 "quick menus" |
| `scripts/pie_menu_test.py` | 竖排章节 38 项断言 |

**竖排内部方法**（`PieMenu`）：

| 方法/字段 | 作用 |
|------|------|
| `_is_list()` | layout 分支开关（渲染/命中/拖放/提交全走它） |
| `_list_logical_size()` | 逻辑尺寸：宽 = max(最短 `LIST_MIN_W`, 最宽 label+2×`LIST_PAD_X`) 截 `LIST_MAX_W`；高 = 标题行 + n 卡片 + 间隙 + 上下 padding |
| `_list_item_rect(i)` | 第 i 张卡片矩形（命中与绘制共用，单一事实来源） |
| `_hit_test_list(pos)` / `_list_insert_index(pos)` | 卡片命中（仅卡片矩形）；插入下标 = 第一个中心在光标下方的卡片前 |
| `_move_list_at(global_pos)` | 方向锚定 + 垂直居中 + `availableGeometry` 钳制（含"列高于屏保顶可见"的 `max()` 技巧） |
| `_paint_list` / `_paint_list_drop_line` | 标题行（`pie_menu_display_name`，右截断）+ 卡片列（复用 `_card_palette` 配色）+ 拖放插入线 |
| `set_list_drop_target(idx, rejected)` | 编辑器拖放插入线高亮（满 `LIST_MAX_ITEMS` 红色） |

**新增 preview 信号**（编辑器 `_connect_signals` 全接）：

| 信号 | 含义 |
|------|------|
| `list_command_dropped(idx, cmd_id, src_idx)` | 竖排拖放落地（src_idx=-1 为池新增） |
| `list_item_remove_requested(idx)` | 竖排右键卡片 |

**mime 复用**：竖排卡片拖出 `x-pie-src = "0,{idx}"`（sector 固定 0），拖回命令池由 `CommandPalette.dropEvent` 解析为 `remove_requested(0, idx)` → 编辑器 `_on_card_remove` 按当前 layout 解释（list 时弹 `items[idx]`）。预览当前 layout 决定解释方式，无歧义。

**编辑器 UI**：样式下拉（Ring/List）恒显；**扇区数** 仅在 ring 可见；**方向** 仅在 list 可见（`_load_current_props` 里 `setVisible`）。提示文案随样式切换（`_refresh_hint`）。`_on_new_menu` 默认仍 ring。

## 六、视觉常量与配色位置（视觉修缮必读）

竖排常量在 `ui/pie_menu.py` 顶部（环形常量之后，独立成段注释）：

```python
LIST_TITLE_H = 30.0           # 标题行高（菜单显示名，比卡片略暗）
LIST_ITEM_H = 34.0            # 卡片高
LIST_GAP = 6.0                # 卡片垂直间距
LIST_PAD_X = 12.0             # 卡片内左右 padding
LIST_PAD_Y = 10.0             # 列顶/底 padding
LIST_EDGE_OFFSET = 16.0       # 光标与列的水平间隙
LIST_MIN_W = 140.0            # 列宽下限
LIST_MAX_W = 260.0            # 列宽上限（label 截断？否——宽由最宽 label 决定，超上限封顶）
LIST_MAX_ITEMS = 24           # 卡片上限（对齐环形 8×3 总容量）
```

- 卡片配色/描边/悬停/禁用降透明度与环形**完全同一套**：`_card_palette(dark)`（深 `QColor(35,37,46,200)` / 浅 `QColor(255,255,255,220)`，accent `@accentPrimary` 描边 alpha 160，悬停 accent 填充 + `HOVER_TEXT_COLOR` 白字，禁用 `@textColor` alpha 110）。改环形卡片样式会自动同步竖排——**有意为之**，别给竖排另设一套卡片色。
- 卡片圆角复用 `CARD_CORNER_RADIUS = 5.0`。
- 竖排独有视觉：标题行（`@textColor` alpha 170，右截断 elide）、拖放插入线（accent alpha 220 的 2px 横线，位于目标卡片上缘/末卡片下缘 + `LIST_GAP`；满员红色 `QColor(220,60,60,200)`，仅编辑态可见）。

**预览缩放**：竖排尺寸随内容变（`set_menu_config` 按 `_preview_scale` 重设 `setFixedSize`），painter scale 统一缩放逻辑坐标——与环形同机制，只改了"尺寸来源"。

## 七、已知 Qt 坑（改渲染/交互时必须知道）

1. 环形章节 §七 的全部坑依然适用（`QPen` 无 `setAlpha`、`QDrag` 在 `qtpy.QtGui`、`QTabBar` 无 `clear()`、`%1` 用 `.replace`、离屏字体等）。
2. **`i18n_check` 隐式拼接盲区**：`self.tr("a" "b")` 跨行拼接扫描不到 → ts 恒报 orphan。本次把 `_refresh_hint` 两条提示与新建菜单上限文案**统一改成单行字面量**（`tr(` 后换行、字符串一整行），消除这三条孤儿。命令 label/分类名（`tr(variable)`）仍属既定 orphan 惯例。
3. **竖排定位依赖 `QApplication.screenAt(global_pos)`**：多显示器时钳制用光标所在屏的 `availableGeometry`；`screenAt` 返回 None 时回退 `primaryScreen`。钳制公式里 `min(max(x, L), max(L, R-w))` 的 `max(L, ...)` 是防"列高于屏"时 x 被推到屏幕外的小技巧。
4. **短按 PIN 判定依赖 `_press_timer`**：测试里若先跑过长按用例（monkeypatch `_press_timer.elapsed`），后续短按用例需换新 `QElapsedTimer`（`scripts/pie_menu_test.py` 竖排章节开头有注释）。
5. **样式切换的数据方向**：`_on_style_changed` 只在 layout 真正变化时转换（相同 index 直接 return），避免 `_load_current_props` 的 `blockSignals` 回环。

## 八、待修缮 / 扩展清单

**视觉/体验（可交给多模态 AI）：**

- 竖排弹出动画（淡入 + 轻微位移动画，~80ms）——环形同样未做
- 标题行视觉（当前是单行暗色文本，可考虑加底色条/图标）
- 插入线的视觉细节（当前 2px 横线，可做渐变/箭头）
- 卡片 hover 过渡（环形待修缮项，竖排共用卡片样式会同步受益）
- 配置页预览区容器观感（与环形同题）

**功能/架构扩展位（数据模型已留）：**

- `layout` 将来可加更多形态（如横向条），每个形态 = normalize 合法值 + `_is_list` 式分支 + 一套几何/命中/绘制
- 竖排滚动（超过一屏时）——目前靠 `LIST_MAX_ITEMS=24` 上限兜底，无滚动
- 嵌套分组/子菜单展开——用户明确否决（用多菜单分割），但 `items` 是扁平列表，将来若做分组需改模型
- 命令池继续扩：任何带 `run_fn` + `category` 的命令自动进池，环形/竖排通用

**已知开放行为：**

- 竖排列表允许命令重复出现（与环形一致，不去重）
- 样式切换 ring→list→ring 会丢失环形扇区内的位置分组（展平后无法还原扇区归属）——符合预期，用户需重新编排
- 竖排菜单无命令时只显示标题行（空列表，编辑器可继续拖入）
