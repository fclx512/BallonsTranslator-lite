# 添加新的 UI 翻译

## 架构概览

`self.tr("Text")` → `translate/xx.ts` (XML) → `translate/xx.qm` (二进制, 运行时)

相关脚本：`scripts/qm_compile.py` (自定义 .ts→.qm 编译器)、`scripts/i18n_check.py` (覆盖率审计)、`scripts/ts_auto_fill.py` (同步 .ts ↔ 源码)

- **源字符串**：所有 UI 可见文本均在 Python 代码中使用 `self.tr("English")` 包裹
- **扫描范围**：`ui/`、`modules/`、`utils/`
- **格式字符串**：`self.tr()` 参数包含 `{` 的调用自动跳过（无需添加 .ts 条目）
- **参数描述**：模块参数 `description` 字段是纯数据，由 AST 规则自动提取（见下文 ParamWidget 节）
- **语言注册表**：`utils/shared.py::DISPLAY_LANGUAGE_MAP`（当前只有 `"English"` 和 `"简体中文"`）
- **运行时加载**：`launch.py` 的 `main()` 内 `app.installTranslator` 加载匹配的 `.qm` 文件

## 添加新语言

### 推荐：AI 辅助

1. 确保 `zh_CN.ts` 基线完整：`python scripts/i18n_check.py`（输出 `[PASS]`）
2. 将以下提示连同 `translate/zh_CN.ts` 发给 AI：

   > 请根据 `translate/zh_CN.ts` 创建日语翻译文件 `translate/ja_JP.ts`。要求：保持 `<source>` 不变，删除 `<location>` 行（可选），将所有 `<translation>` 翻译成日语（术语如 OCR/LLM/API 不译），根 `<TS>` 的 `language` 属性改为 `"ja_JP"`，跳过 `type="obsolete"` 条目，保持 XML 格式。

   CJK 捷径：对于 ja_JP/ko_KR 等，约 60% 含汉字的条目可直接复用。提示 AI "对于仍可理解的汉字翻译保持原样，其余翻译成对应语言"。

3. 编译：`python scripts/qm_compile.py translate/ja_JP.ts translate/ja_JP.qm`
4. 注册：在 `utils/shared.py::DISPLAY_LANGUAGE_MAP` 添加条目（键为原生语言名，值为语言代码）
5. 验证：`python scripts/i18n_check.py` + 启动应用切换到新语言测试

### 手动（直接编辑 XML / Qt Linguist）

`.ts` 是纯 XML，可在文本编辑器里编辑：

```xml
<message>
    <source>Delete</source>
    <translation>Supprimer</translation>
</message>
```

- `<location>` 可删，不影响运行时
- `type="obsolete"` 的条目运行时静默忽略
- 空 `<translation/>` 运行时回退到源文本

如有 Qt 开发环境，也可用 `linguist translate/fr_FR.ts` GUI 逐条翻译。编辑后按 AI 辅助流程的步骤 3-5（编译、注册、验证）完成。

## 为开发者：添加新的 tr() 调用

### 自动化（推荐）

```bash
python scripts/ts_auto_fill.py --fill-missing   # 填充缺失条目（标记 type="unfinished"）
# 编辑 zh_CN.ts 填写翻译
python scripts/qm_compile.py translate/zh_CN.ts translate/zh_CN.qm
python scripts/i18n_check.py
```

`ts_auto_fill.py` 扫描 `ui/`、`modules/`、`utils/` 中的 `self.tr()` 调用，与 .ts 比对，缺失条目插入为 `<translation type="unfinished">`。

### 手动

在 `zh_CN.ts` 的正确 `<context>`（与 Python 类名匹配）下插入：

```xml
<message>
    <source>Your New String</source>
    <translation>你的翻译</translation>
</message>
```

然后重新编译并验证。

## 模块参数 hover 备注（ParamWidget）

模块 `params` 字典中的 `"description"` 显示为配置面板中的 tooltip。`ParamWidget`（定义在 `ui/module_parse_widgets.py::ParamWidget`）通过 `self.tr(params["description"])`（变量形式）加载翻译，运行时按值查表、上下文固定为 `<name>ParamWidget</name>`。

**自 2026-08-29 起无需手工同步 ts**：`scripts/i18n_common.py::extract_param_descriptions` 以 AST 规则从 dict 字面量提取 description，`ts_auto_fill.py` / `i18n_check.py` 均可自动管理：

- `modules/` 下（`agent/` 包除外）含字符串 `description` 键的 dict 全部提取
- 其它目录（`ui/`、`utils/`）仅提取同时含 `value` 键的 dict —— 用于排除 LLM 工具 schema 数据
- **排除项（刻意不入 ts）**：`modules/translators/agent/tools.py` 与 `utils/ai_tools.py` 的 description 是 LLM 提示词，保持原样

### 添加步骤

1. 在模块 `params` 字典中添加 `"description": "English"` 字段
2. `python scripts/ts_auto_fill.py --fill-missing --apply` 自动补条目（unfinished），填写中文翻译
3. `python scripts/qm_compile.py translate/zh_CN.ts translate/zh_CN.qm` 编译并 `python scripts/i18n_check.py` 验证

## 显式上下文模式（模块级翻译表）

凡字符串存进表/数据结构、渲染时才 `tr(variable)` 查表的写法（快捷键名、命令标签、分组标题等）检查器都看不见，曾导致整批漏翻译。规范做法：**在字面量定义处**用 `QCoreApplication.translate("上下文", "...")` 标注，变量拿到的是已翻译文本，下游直接使用（tr 对非匹配串原样返回，无需二次翻译）。

已转换的站点：

| 站点 | 上下文 |
|------|--------|
| `ui/configpanel.py::_ACTION_NAMES`、`_SHORTCUT_GROUPS` | `_ShortcutRow` / `ShortcutEditor` |
| `ui/context_menu_config.py` 命令注册表（CmdDef 标签） | `Canvas` |
| `ui/pie_menu_editor.py::_CATEGORY_LABELS`、`_TOGGLE_LABEL` | `PieMenuEditor` |
| `ui/quick_symbol_dialog.py::_GROUPS` | `QuickSymbolDialog` |
| `ui/point_align_dialog.py::_AXIS_LABELS`、`_MODE_LABELS` | `PointAlignDialog` |
| `ui/model_check_dialog.py::_TYPE_LABEL` | `ModelCheckPanel` |
| `ui/io_thread.py::_thread_error_msg` | 各线程子类名 |

特例：饼菜单默认名（`utils/config.py::DEFAULT_PIE_MENUS` 的 `name`）因 config.py 导入早于翻译器安装、不能就地翻译，在 `ui/pie_menu.py::_DEFAULT_MENU_NAME_TR` 留有显式字面量锚点供工具链提取，**勿删**。

孤儿白名单 `scripts/i18n_common.py::KNOWN_ORPHAN_CONTEXTS` 已清空：`i18n_check.py --ci` 报孤儿/缺失即真实问题，须修复。

## 快捷键面板的显式上下文翻译（_ShortcutRow / ShortcutEditor）

快捷键面板中动作名和分组名定义在 `ui/configpanel.py` 的模块级表 `_ACTION_NAMES` / `_SHORTCUT_GROUPS` 中，值直接内联 `QCoreApplication.translate("上下文", "字面量")`（显式上下文 = ts 里的 `<name>`）：

- `_ShortcutRow`（`ui/configpanel.py::_ACTION_NAMES`）：动作名（"Page Up"、"Zoom In"等）
- `ShortcutEditor`（`ui/configpanel.py::_SHORTCUT_GROUPS`）：分组名（"Navigation"、"View"等）

`i18n_check.py` / `ts_auto_fill.py` 通过 `scripts/i18n_common.py::extract_tr_calls` 识别该模式，这些条目**走正常管理流程**：新增/删除快捷键动作时改表即可，ts 条目由 `ts_auto_fill.py --fill-missing` 自动补，`--prune` 也能正常清理。

注意：表在模块导入时求值，依赖 launch.py 先装翻译器再导入 `ui.mainwindow` 的顺序；测试环境无翻译器时返回英文原文。

## 常见问题

**Q: 切换语言后某些文本没有变化？**
A: 运行 `i18n_check.py` 检查是否有对应 .ts 条目。如有但仍无效，重启应用——`QTranslator` 不会刷新 `installTranslator` 之前创建的 widget。

**Q: 编译没有输出或生成了空 .qm？**
A: .ts 可能全部标记为 `type="obsolete"`，`qm_compile.py` 会跳过这些条目。

**Q: 包含 `\n` 的字符串显示为英文？**
A: `.ts` 是 XML 格式，`\n` 在 XML 中是**字面反斜杠+字母 n**，不是换行符。但 `self.tr("...\n...")` 中 `\n` 是 Python 转义得到的真正换行符（0x0A）。两边字符串不同 → Qt 的 ELF hash 不匹配 → 翻译查找失败 → 回退英文。

**修复：** 将 `.ts` 中对应的 `<source>` 和 `<translation>` 的 `\n` 替换为**真正的换行符**（XML 中直接换行或用 `&#10;`）。重新编译 qm 后生效。

```xml
<!-- 错误：XML 中 \n 是字面反斜杠+n -->
<source>Glossary saved to:\n{}\n\nSet as active?</source>

<!-- 正确：使用真正的换行符 -->
<source>Glossary saved to:
{}

Set as active?</source>
```

**Q: 包含 `{` 或 `%` 的字符串？**
A: `i18n_check.py` 自动跳过含 `{` 的 `self.tr()` 调用（视为格式字符串）。如需翻译，手动添加 .ts 条目。

**Q: 语言代码有限制？**
A: 任意非空字符串均可。`qm_compile.py` 对所有字段使用 UTF-8。

**Q: 运行时某些翻译显示为 `?` 字符？**
A: 旧版 `qm_compile.py` 用 `latin-1` 编码，`—`/`→`/`⚠`/`✓` 等非 Latin-1 字符被静默替换为 `?`，也导致 Qt 哈希查找失效。用当前版本（UTF-8）重新编译即可：`python scripts/qm_compile.py translate/zh_CN.ts translate/zh_CN.qm`
