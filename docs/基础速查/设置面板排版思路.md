# 设置面板排版思路

> 给未来维护 AI 的参考：本项目设置面板从“堆叠卡片”改为“两列表单”后的布局约定。
> 形成于 2026-08-13 对项目 / 界面 / 模型 / 嵌字 / 应用 5 个设置页的统一重构。
>
> 逐页功能项清单（每项 → 分节 / 控件 / 配置字段）见 `docs/基础速查/设置面板_功能项清单.md`；分节标题与侧边导航的样式候选也在那份文档的第 2、3 节，本文只讲表单行排版约定。

---

## 1. 核心原则：把设置页当成表单，而不是卡片堆

旧模式的问题：

- 每个选项用一个 `ConfigSubBlock(name=..., widget)` 垂直堆叠，标签在控件上方。
- 结果是空白大、控件左边缘不齐、复选框像“标题 + 选项”两段文字。
- 不同控件（下拉框、输入框、复选框）各自为政，视觉上松散。

新模式的核心：

- **左列标签，右列控件**，所有控件从同一条竖线开始。
- **标签固定宽度**（默认 110px），右对齐，带 `?` 帮助按钮时仍对齐。
- **章节头只负责分组**，不再承载说明；说明放到 `?` 气泡里。
- **垂直间距压紧**，但保留可读性。

## 2. 使用 `ConfigFormRow` 和 `_section_body`

在 `ui/configpanel.py` 中已经封装好两个辅助：

### 2.1 `ConfigFormRow`

```python
ConfigFormRow(
    label: str,          # 左列标签；不需要标签时传 ""
    widget: QWidget,     # 右列控件
    note: str = None,    # 可选帮助说明（会渲染为右侧 ? 按钮）
    label_width: int = 110,
)
```

约定：

| 场景 | 写法 |
|------|------|
| 下拉框/输入框/按钮 | `ConfigFormRow(self.tr("标签"), 控件, note=...)` |
| 单个复选框（本身就是完整描述） | `ConfigFormRow("", 复选框, note=...)` |
| 子选项需要缩进 | 用空标签 + 外部 wrapper 设置左外边距 |

示例：

```python
# 下拉框
self.rst_imgformat_combobox = ConfigComboBox(scrollWidget=self)
self.rst_imgformat_combobox.addItems(["PNG", "JPG", "WEBP", "JXL"])
project_layout.addWidget(
    ConfigFormRow(
        self.tr("Result image format"),
        self.rst_imgformat_combobox,
        note=self.tr("<p>输出格式说明...</p>"),
    )
)

# 复选框
self.seq_badge_checker = ConfigCheckBox(self.tr("Show sequence number on text blocks"))
interface_layout.addWidget(
    ConfigFormRow(
        "",
        self.seq_badge_checker,
        note=self.tr("<p>序号徽标说明...</p>"),
    )
)
```

### 2.2 `_section_body`（页面内分节 = 一张卡）

```python
project_root = project_layout                     # 页面自己的布局，之后不再变
project_layout = _section_body(project_root, self.tr("Output"))
project_layout.addWidget(ConfigFormRow(...))      # → 落进「输出」这张卡
project_layout = _section_body(project_root, self.tr("Backup"))
```

- 一个分节 = 一张 `PanelGroupBox`（`compact` 标题）卡，行物理上在卡里 → 节边界一眼可见（2026-09-20 之前只有一行粗体标题，卡片化前的样子见 git 历史）。
- **卡的工厂函数在 `ui/custom_widget/view_panel.py::add_section_card`**（`ui/configpanel.py::_section_body` 是它的薄封装，只为保住文档里的老名字）：管线阶段面板也要建卡，又不能反向 import `ui/configpanel.py`。
- **返回的是"当前分节的行容器"**，所以行语句照写；**下一节必须再用 root 布局开**——拿当前变量去开会在上一张卡里套娃。
- 卡片主体横向内边距为 0 是有意的：行的 16px 内边距仍在行自己身上，一行的绝对 x 不因卡片化而移动。子选项的 24px 缩进 wrapper 照旧。
- 页面布局的 `setSpacing` 用 10（卡片之间露出的凹陷底色就是分隔），不要再往卡里塞分隔线。
- 浮起的观感来自三层色调（面板/页面底凹陷、卡片浮起 + 1px 描边），**不要给卡片加 `QGraphicsEffect` 投影**——理由与实测坑见 `docs/技术实现/设置面板概述.md` 的「分节卡与凹陷工作面」。
- **卡里除了卡片自己，谁都不许画底色**：描边画在卡片矩形上，子控件却后画、又不随父级圆角裁剪，一层不透明的容器就能把描边整段盖掉（同色时看不出来），卡片之间也会被同色填充连成一片。页内排版容器一律用 `ui/configpanel.py::ConfigFlatContainer`（**不画底色**），别用裸 `QWidget`；`ConfigSubBlock` / `ConfigFormRow` 已派生自它，标签与复选框的兜底底色由 QSS 的 `#ConfigPanel QLabel, #ConfigPanel QCheckBox` 关掉。症状、选择器语义与排查手法见 `docs/基础速查/经验教训.md` §3.6。
- 仅用于页面内分节，不要把说明文字写进卡的标题。

## 3. 页面容器约定

每个设置页用一个**页内排版容器**（`ConfigFlatContainer`，不画底色——页面底由 `_wrap_page` 涂成凹陷色）+ `QVBoxLayout`：

```python
page_widget = ConfigFlatContainer()
page_layout = QVBoxLayout(page_widget)
page_layout.setContentsMargins(0, 0, 0, 0)
page_layout.setSpacing(10)      # 卡片间距
page_root = page_layout         # 分节从 root 开（见 _section_body）
```

`ConfigFormRow` 与分节卡自身已经带了合适的内边距，页面容器不要再额外加间距。页面底由 `_wrap_page` 涂成凹陷色（`Widget#ConfigPageBody`），别在页面里再套一层背景；页内**任何**中间容器（分组、缩进 wrapper、状态条）都别用裸 `QWidget`——它会拿到全局 `QWidget` 底色、与卡片同色，盖掉卡片描边（见 §2.2 末条与 `docs/基础速查/经验教训.md` §3.6）。

## 4. 控件宽度约定

按输入类型固定宽度，避免无意义拉伸：

| 控件类型 | 推荐宽度常量 | 例子 |
|----------|-------------|------|
| 短数字 / 百分比 / 复选框 | `CONFIG_COMBOBOX_SHORT` | 质量、不透明度预设 |
| 中等枚举下拉框 | `CONFIG_COMBOBOX_MIDEAN` | 动画 FPS、预设值输入框 |
| 长文本下拉框 | `CONFIG_COMBOBOX_LONG` | 标点位置、竖排拉丁长度 |
| 按钮 | 不固定，按内容自适应 | 导出配置、卸载模型 |

按钮统一用 `QPushButton#ConfigButton`（`config/stylesheet.css`），已有 `padding: 0 12px` 水平内边距，文本不会紧贴按钮边缘；长按钮（如 "Add Legacy Fonts to Hidden List"）靠 `max-width: 460px` 放行完整文本。

如果控件是 `QLineEdit` 等会拉伸的，手动 `setFixedWidth(...)`，不要依赖 `addStretch()` 推过去。

## 5. 子选项缩进

子选项（如“同样应用于横排文本”“切换页面时也缩放”）需要与父选项的控件列对齐，同时自带宽一级的层级缩进。

`ConfigFormRow` 内部结构：

```
| 16px 左 margin | 110px label | 8px 间距 | 控件 | ... |
```

控件左边缘距行外边缘 `16 + 110 + 8 = 134px`。子选项统一走**同一个写法**——`ConfigFormRow("", 控件)` 套一个 24px 缩进的 wrapper，总缩进 `134 + 24 = 158px`：

```python
self._halfwidth_horizontal_sublock = ConfigFormRow("", self.halfwidth_horizontal_checker)
# 24px 缩进必须加在 wrapper 的 layout 上：加在 widget 上会在 layout 建立前丢失
halfwidth_horizontal_wrapper = QWidget()
hw_layout = QVBoxLayout(halfwidth_horizontal_wrapper)
hw_layout.setContentsMargins(24, 0, 0, 0)
hw_layout.addWidget(self._halfwidth_horizontal_sublock)
self._halfwidth_horizontal_sublock_wrapper = halfwidth_horizontal_wrapper
ts_layout.addWidget(halfwidth_horizontal_wrapper)
```

**不要**手写 `QHBoxLayout` + `setContentsMargins(158, 0, 0, 4)` 的老写法（Typesetting 与 App 页曾各有一处）：那样绕过了 `ConfigFormRow`，禁用态变灰、标签列对齐这些机制都吃不到，而且 158 这个数写死后改 `label_width` 就悄悄错位。使用 `ConfigFormRow("", …)` 时 134 由容器自己算，只有 24px 层级缩进需要写。

切换可见性时**两个都要切**（sublock 与 wrapper），只切一个会留下占位的空 wrapper：

```python
self._halfwidth_horizontal_sublock.setVisible(state)
self._halfwidth_horizontal_sublock_wrapper.setVisible(state)
```

## 6. 特殊：网格布局仍可用

当一组相关控件数量多、按两列排布更节省空间时（如“默认字体格式”的 5 个下拉框），可以保留 `QGridLayout`：

- 外层容器用 `ConfigSubBlock(..., content_margins=(16, 4, 16, 4))` 保持与 `ConfigFormRow` 对齐。
- 网格内部的水平/垂直间距设为 8~16px，不要太散。
- 不要把章节标题已有的说明再重复写成一段 label。

## 7. i18n 注意事项

- 所有 UI 文字必须包在 `self.tr(...)` 里。
- **`self.tr()` 参数必须是单个字符串字面量**，不要跨多行做隐式拼接（如 `"part1 " "part2"`）。`scripts/i18n_check.py` 识别不了这种拼接，会报缺失或孤儿。
- 长说明可以换行，但必须是**一个完整字符串字面量**：

```python
# 正确
note=self.tr(
    "<p>这是一段很长的说明，可以换行写，但仍然是一个字符串。</p>"
),

# 错误
note=self.tr(
    "<p>这是第一段 "
    "这是第二段</p>"
),
```

- 新增/修改字符串后执行：

```bash
python scripts/qm_compile.py translate/zh_CN.ts translate/zh_CN.qm
python scripts/i18n_check.py
```

## 8. 反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|----------|
| `ConfigSubBlock(checkbox, name="标题")` | 标签和复选框文字分离，像两段说明 | `ConfigFormRow("", checkbox, note=...)` |
| `ConfigSubBlock(widget, name="标签")` + `vertical_layout=True` | 标签在上、控件在下，空隙大 | `ConfigFormRow("标签", widget, note=...)` |
| 输入框 `addStretch()` 撑满 | 长输入框不整齐 | 给输入框固定宽度 |
| 卡里再塞说明文字 | 视觉噪音 | 说明放到 `?` 气泡 |
| 每个选项一张分节卡 | 卡片过多、留白过多 | 相关选项归到同一 `_section_body` 卡 |
| 拿"当前分节"变量去开下一节 | 新卡套进上一张卡里 | 每节都用页面的 root 布局开 |
| 卡片上挂 `QGraphicsEffect` 投影 | 有硬崩/渲染两处实测坑 | 靠凹陷底色 + 描边造浮起 |
| 卡内/页内放裸 `QWidget` 容器、状态条自带底色 | 拿到全局 `QWidget` 底色（与卡片同色）→ 盖掉卡片描边、卡片之间连成一片 | 用 `ConfigFlatContainer`；状态条只留顶边分隔线 |

## 9. 快速修改清单

向设置面板新增一项时：

1. 找到目标分节卡，没有就 `_section_body(<页面 root 布局>, 标题)` 新建一张。
2. 用 `ConfigFormRow` 包裹控件；复选框用空标签。
3. 需要说明时传 `note=`，不要写死 label 描述。
4. 给输入类控件设固定宽度。
5. 要加分组/缩进 wrapper 时用 `ui/configpanel.py::ConfigFlatContainer`，**不要**用裸 `QWidget`（会盖掉卡片描边，见经验教训 §3.6）。
6. 在 `translate/zh_CN.ts` 的 `ConfigPanel` context 添加对应条目。
7. 编译 qm 并跑 `i18n_check.py`；改了版式/配色跑 `scripts/settings_render.py` 看一眼（怀疑"底是谁画的"就加 `--diag`）。

## 10. 卡片式页面：LLM Profile（2026-09-09）

LLM Profile 页不走「一个页面一张长表单」，而是**卡片列表 + 折叠详情**（`ui/llm_profile_cards.py`，形态对齐上游 `ballontranslator/ui/llm_profile_widgets.py`）：

- 折叠态只显示摘要：名字 + 能力徽章（文本 / 视觉 OCR / 图像修复）+ host + key 状态图标；
- 摘要行下面常驻**模型下拉**（`ui/llm_profile_cards.py::_ModelSelector`）：文本模型一行，图像模型一行（仅 `image_support` 开启时显示），旁边 `+` 手填、`−` 删当前——切模型不用展开卡片；
- 点卡片头部的编辑按钮才展开详情；详情里通用参数在前，之后是三个能力分节；
- 视觉 / 图像分节由对应徽章门控（`ui/llm_profile_cards.py::LLMProfileBadge` 点击翻转 `vision_support` / `image_support`）——**新增一种能力等于多一个徽章 + 一个默认折叠的分节，页面不会变长**。

模型清单的持久语义：

- 每个 profile 带 `model_options` / `image_model_options` 两份清单（`ui/llm_profile_cards.py::MODEL_OPTION_FIELDS` 映射字段 → 清单），**不预置任何供应商模型表**：只由 Fetch Models 多选或 `+` 手填产生；
- 加载时 `utils/profile_manager.py::normalize_model_options` 规整清单并保证当前值一定在列；`utils/profile_manager.py::remember_model_option` 负责去重追加；
- Fetch Models 走 `utils/profile_manager.py::FilterableListDialog` 的 `multi_select=True`，选中项全部入清单、首个设为当前模型，并立即落盘（`ui/llm_profile_cards.py::_pick_model`）。

排版约定：

- 详情分节由 `ui/llm_profile_cards.py::PROFILE_COMMON_PARAM_DEFS` / `PROFILE_SECTION_PARAM_DEFS` 声明式驱动，每节渲染一个 `ui/module_parse_widgets.py::ParamWidget`；`model` / `image_model` 不在详情里（由摘要行下拉负责）；
- 模型下拉**按内容自适应宽度**（`ConfigComboBox(fix_size=False)` + `AdjustToContents`，不再横向拉伸撑满整行），`+` / `−` 紧跟其右；
- **连接信息块**（`ui/llm_profile_cards.py::_ConnectionBlock`）独立于杂项参数：`api_host` / `api_key` / `image_base_url` 三个字段用「标签在上 + 整行加高输入框」承载（最要紧且需要长输入框的配置），容器带强调左边条；图像端口随 `image_support` 显隐，所以这三个字段也不在参数定义里；
- `ParamWidget` **没有字段级刷新 API**，还会原地改写传入的 params dict，所以每节传副本；
- 字段写回的类型转换在 `ui/llm_profile_cards.py::PROFILE_FIELD_TYPES`（数值/布尔），标签与说明在 `PROFILE_PARAM_LABELS` / `PROFILE_PARAM_DESCRIPTIONS`，模块级翻译表用 `QCoreApplication.translate("LLMProfileCardWidget", ...)` 在字面量处标注上下文。

跨页写入：画布「AI 修图」面板的模型栏（`ui/drawingpanel.py::AIConfigPanel`）会写同一个 profile 的 `image_model`，因此本页 `showEvent` 在 `pcfg.module.model_profiles` 与上次落盘值不一致时重载列表——否则页面持有的旧副本会在 `hideEvent` 落盘时覆盖画布改的模型。

## 11. 画布修复面板（`ui/drawingpanel.py`）

右栏固定 360px（减去工具窄栏后约 326px 可用），面板排版受此硬约束：

- **标签列**统一 `TOOL_LABEL_WIDTH`（110px），所有控件左对齐；
- **滑条 + 精确数值框**（`ui/drawingpanel.py::_create_thickness_control`）：数值框放在标签列右端（标签可省略），滑条独占其余宽度——把数值框放在滑条右侧会把滑条挤短；数值框**不带单位后缀**（右栏里 `"20 px"` 会被裁成 `"20 p"`），行内间距不自设、沿用父布局的 14px，否则滑条起点会比同栏下拉框左移几像素；
- 面板里的下拉框一律经 `ui/drawingpanel.py::_shrinkable_combo` 处理：`QComboBox` 默认把**最长条目的宽度**算进 `minimumSizeHint`，长 profile / 模型名会把整块面板顶宽而被横向裁掉（改按最小内容长度取尺寸后最小宽只剩箭头区，实际宽度仍由布局拉伸决定）；该函数同时把高度锁到 `utils/shared.py::CONFIG_COMBOBOX_HEIGHT`，否则默认高度（29）比同栏其它下拉框（26）高一截（修复工具下拉框属于设置页，在 `ui/drawingpanel.py::DrawingPanel` 构造时补锁一次）；
- **内嵌体布局 margins 一律 0**（画笔体 / 框选体 / `ui/drawingpanel.py::CropControls`）：嵌套 `QWidget` 的默认布局边距会让这一组比上方字段整体右移 9px；
- **按钮内边距**来自 stylesheet 的 `DrawingPanel QPushButton` 规则（`padding: 0 12px`）——全局 `QPushButton` 无内边距，中文两字按钮的 sizeHint 就等于文字宽，字会紧贴边框；
- AI 修图页的比例支持提示用紧凑表格（`InpaintAspectTable*` 的 QSS）而非整句说明；比例单元格 `setWordWrap(True)`，窄栏里换行而不是撑宽面板。

## 12. 合并的管线页：页内标签（2026-09-10）

四个管线页合并成 Modules 组下的一个「Pipeline」页，页内用 `QTabBar` + `QStackedWidget` 切阶段（构建见 `ui/configpanel.py::_build_pipeline_page`）：

- **标签栏钉在页顶**：合并页整体不套 `_wrap_page`（否则标签栏会跟着内容滚走），而是直接 `pageStack.addWidget`；每个标签内容各自 `_wrap_page(panel, margins=(0, 12, 0, 24))`，左右留白交给外层页面边距，避免叠加成双份 24px。
- **页内分节与别的页同一套卡（2026-09-21 补上）**：外层页面与标签页体都走凹陷面（`objectName="ConfigPageBody"` + `_wrap_page(recessed=True)`），阶段面板里的分节用 `ui/custom_widget/view_panel.py::add_section_card` 建卡——「参数」一张，翻译器再一张「API Profile」且排在参数卡**之前**（先选账号、再看这个账号下的参数）。`ui/configpanel.py::_section_body` 只是 `add_section_card` 的薄封装。
- **阶段面板（`ui/module_parse_widgets.py::ModuleConfigParseWidget`）必须保持裸 `QWidget`**：面板自己不画底色，凹陷面才透得上来。换成 `ui/custom_widget/widget.py::Widget` 会刷满全局 `QWidget` 底色、填平卡片之间的凹陷槽；`tests/test_config_card_painting.py::test_pipeline_stage_panel_paints_no_background` 钉着这条。面板内部行自带 16px 横向内边距（与 `ConfigFormRow` 同口径）。
- **卡标题用显式上下文翻译**：`QCoreApplication.translate("ModuleConfigParseWidget", "Parameters")`——`self.tr` 在子类实例上按**子类名**查表（`TextDetectConfigPanel`…），ts 里的 `ModuleConfigParseWidget` 条目永远命中不了，「参数」会显示成英文原文。
- **阶段顶栏 = `[模块名][引擎下拉][?][…]`**：引擎下拉就是面板自带的 `module_combobox`，在标签里直接切换即真正换引擎（`ui/module_manager.py` 的 `set*` 槽把变更镜像回底部栏）。备注按钮用 `p_layout.indexOf(module_combobox) + 1` 定位插入——**不要用固定下标**，阶段面板子类会往同一行插自己的控件。
- **`module_combobox` 是被多方共享的真值源**：底部栏、`ui/module_manager.py`、设置页选择行都读写它。曾把它换成只读引擎名（2026-09-10），次日回退为下拉可切换——只读标签省下的宽度不值得多一次「开设置→切底部栏」的绕路。
- **画布侧用镜像下拉，不共享控件**：`ui/drawingpanel.py::InpaintPanel` / `ui/drawingpanel.py::RectPanel` 经 `ui/module_parse_widgets.py::create_mirror_selector` 各持一个独立镜像（真值源仍是 `module_combobox`，show 时 `sync_items` 重建条目、`activated` 回流触发正常切换链）。禁止把真值源 `addWidget` 借走——那会让设置页的修复标签开天窗，且「切工具时新面板 show 先于旧面板 hide」的时序坑已踩过一轮。
- **搬出来的杂项按语义落位，不设暂存页**：从管线页挪走的 Photoshop 路径与工作台确认最终并入 **App 页**（「应用级、配置一次后不常改」的项归它）。曾有过的 `Misc` 暂存页已解散——`Misc` 这种名字会自己招来下一条无家可归的选项，别再新开。

## 13. 运行窗口（Run）：阶段网格与折叠选项区（2026-09-10）

`ui/run_pipeline_dialog.py::RunPipelineDialog` 承载运行对话框：上半是「启用模块」阶段网格（每阶段 = 图标开关 + 模块下拉），下半是各阶段的折叠选项区（`ui/custom_widget/push_button.py::ExpandingToolButton` 折叠头 + 隐藏体）。

- **模块下拉写回底部栏**（`ui/module_tool_button.py::setSelectedValue` 传 `block_signals=False`），底部栏是唯一真值源，不新增 `ModuleManager` 接口。
- **阶段强调色走主题**：`@accentDetect` / `@accentOCR` / `@accentInpaint` / `@accentTranslate`，图标由 `ui/icon_rendering.py::render_svg_pixmap` 的 `override_fill` 着色（与 LLM Profile 徽章同一套做法），不移植上游硬编码调色板。
- **页码区改用上游控件**：`ui/custom_widget/page_range_progress.py::PageRangeProgressWidget`（复刻上游 `ballontranslator/ui/page_range_progress.py`）——起止页码框（右端 chevron 步进）+ 一条带完成度的区间轨。原来的 `RangeSlider` + 起止 `NoArrowsSpinBox` + All Pages 复选框已拆除：**满区间就是全部页面**，「全部页面」开关与滑条同时在场（勾上就禁用滑条）反而制造了「到底哪个说了算」的困扰。完成度取 `utils/proj_imgtrans.py::ProjImgTrans` 的 `get_page_progress`（页级 `finish_code` 位与），由 `ui/mainwindow.py` 开窗时算好传进对话框。
- **对话框是固定尺寸的**：展开/折叠会改变高度，`RunPipelineDialog._resize_to_fit` 每次重新 `adjustSize` 后按内容锁尺寸（并封顶到屏幕可用高度的 90%）。调用它的时机必须在对话框已 show 之后——首次 `exec()` 前布局尚未激活，此时 `adjustSize` 拿不到真实高度。
- **选项控件直接读写 `pcfg`**（`keep_exist_textlines` / `check_need_inpaint` / `translate_source` / `translate_target` / `single_blk_translate_mode`），与设置页原来的接线一致。
- 阶段下拉用 `ConfigComboBox`（吃到 `ConfigComboBox` 类名选择器的输入样式）；`ConfigComboBox` 的 `scrollWidget=` 形参实际会落到 QComboBox 的 `parent`，需要父级时不要去传它，交给布局的 `addWidget` 即可。
- **折叠区内字号一律 12px**：折叠头、`QLabel#RunPipelineSettingLabel` / `QLabel#RunPipelineSubsectionHeader` 本来就在 QSS 里钉了 12px，区内的下拉/复选框/数值框靠 `config/stylesheet.css` 的 `QWidget#RunPipelineSettingsSection` 一组规则补齐（对齐上游同名规则）。漏掉这组时，区内的 `ConfigComboBox` 会落到全局 `QComboBox` 的 14px，比同一行 12px 的标签大一圈；下拉同时收到 20px 高。验证办法：离屏建好对话框后读 `widget.font().pixelSize()`。
