### 1.1 QM 编码 Bug（2026 年 6 月，已修复）

**问题：** `scripts/qm_compile.py` 曾用 `latin-1` 编码 + `errors="replace"` 处理字符串字段，`—`（em dash, U+2014）、`→`、`⚠`、`✓` 等非 Latin-1 字符被静默替换为 `?`，导致 Qt `QTranslator` 哈希查找失败，对应字符串运行时显示英文。

**修复：** 改为 `s.encode("utf-8")`（`_iso8859_str` 函数语义重命名）。症状与处置见 i18n.md 常见问题「运行时某些翻译显示为 `?` 字符」。

### 1.2 类重命名时，需更新 .ts 上下文

如果 `class OldName` → `class NewName`，则 .ts 中所有位于 `<name>OldName</name>` 下的消息必须移至 `<name>NewName</name>`。Qt 通过类名查找翻译。

历史波及：`ShortcutEditor` → `_ShortcutRow`（27 条消息）、`AiChatPanel` → `ChangeReviewWindow`、`FontFormatPanel` → `ConfigPanel`、`TranslateThread` → `ImgtransThread`、`ProgressMessageBox` → `ImgtransProgressMessageBox`。

### 1.3 .ts 中的重复上下文块

`_normalize_ts()` 函数合并具有相同 `<name>` 的重复 `<context>` 块。`MainWindow` 曾有两个独立块（61 + 11 条消息），第一个块中的条目在实现合并前被静默丢弃。

## 2. 代码清理陷阱

### 2.1 自动清理误删 Re-export（2026 年 5 月）

**问题：** 自动代码检查工具删除了文件中"未使用的 import"，但这些实际上是 **re-export**——在一个文件中导入并通过另一个模块的 `from .base import *` 重新导出的名字。被删除的文件编译正常，但所有依赖方立刻崩溃。

**波及范围：**

| 文件 | 被删的 re-export | 依赖方 |
|------|-----------------|--------|
| `utils/structures.py` | `List, Dict, Union, Tuple, field` | `fontformat.py`, `config.py`, `textblock.py`, `misc.py` |
| `modules/ocr/base.py` | `DEFAULT_DEVICE, DEVICE_SELECTOR` | `ocr/__init__.py`, `ocr_mit.py` |
| `modules/textdetector/base.py` | `DEFAULT_DEVICE, DEVICE_SELECTOR` | `textdetector/__init__.py` |
| `modules/translators/base.py` | `DEVICE_SELECTOR` | `translators/__init__.py` |

**教训：** 删除 import 前必须 grep 全库确认没有其他模块从当前位置导入该名字。仅 `ruff check .` 通过不代表能启动。

**预防：**
- 优先显式列出导出名，避免 `__init__.py` 中的 `from .base import *`
- 批量 import 清理后，至少运行：
  ```python
  python -c "from modules.base import init_module_registries; init_module_registries()"
  ```

## 3. UI 渲染

### 3.1 OverlaySlider 合成渲染伪影修复

**问题：** 多个左侧覆盖面板同时动画时（如 GlobalSearch 关闭 + AI Chat 滑入），在之前打开的面板右边缘出现 75px 宽的纯白竖条。纯白 `#FFFFFF`，与任何主题色不匹配。

**根因：** `OverlaySlider.show()` 使用复杂的合成渲染流程：
1. 将真实控件移至屏幕外，`grab()` 抓取为 QPixmap
2. `hide()` 真实控件，将像素图合成到 `_SharedOverlay`
3. 驱动合成层动画
4. 完成后：销毁合成层，`show()` 真实控件
5. 从合成层切换到真实控件的时间窗口渲染了不完整像素

**修复：** 放弃合成方式。`show()` 现在：
1. 将真实控件置于起始位置
2. 立即 `widget.show()` + `widget.raise_()`
3. 每帧通过 `widget.move()` 驱动位置
4. 通过每帧 `raise_()` 维持 Z 序

真实控件全程保持可见——无需抓图、隐藏、合成、重建循环。

**文件：**
- `ui/overlay_slide.py` — `show()` 走直接动画路径，`_update_animation()` 兜底加 `raise_()`
- `ui/ai_chat_panel.py` — QScrollArea viewport `setAutoFillBackground(True)`（⚠️ 该文件已于 2026-07 删除，但渲染伪影的修复逻辑仍保留在 overlay_slide.py 中）
- `config/stylesheet.css` — `#AIChatArea > QWidget { background-color... }`（⚠️ 该样式规则对应文件已删除）

**注意：** `hide()` 动画仍使用 `_SharedOverlay` 合成（隐藏中的控件无需在动画期间保持交互）。

### 3.2 页面列表信号重入：点脏页跳转错乱（2026-08-28 修复）

**问题：** 样式管理器批量改样式后，点击斜体脏页随机跳转。根因：`ui/mainwindow.py::pageListCurrentItemChanged` 的脏页分支同步调 `ui/mainwindow.py::updatePageList()`，重建列表的 `clear`/`addItem`/`setCurrentItem` 会再触发 `currentItemChanged`，处理器在首次调用返回前被重入，对非点击项重复执行完整切页。

**修复与硬约束：** 重入防护 = 仅在脏页分支内用 `blockSignals(True)` 包住那一次 `updatePageList()`（try/finally 还原）。**禁止把屏蔽挪进 `ui/mainwindow.py::updatePageList` 内部或扩大到其他调用点**——`ui/mainwindow.py::openDir` 的首屏渲染依赖「重建 → `setCurrentItem` → `currentItemChanged` → `pageListCurrentItemChanged` → `updateCanvas()`」这条隐式链路，全局屏蔽会破坏首屏。行为由 `tests/test_page_list_dirty_click.py` 锁定。

### 3.3 PyQt6 所有权陷阱：无父 QCheckBox 传入 setCheckBox 后被 GC（2026-09-06 修复）

**问题：** 撤销确认弹窗（`ui/canvas.py::_confirm_group_undo`）点击「撤销」后界面卡死随即无声退出，无任何 traceback。AV 时机不定：有时看似崩在 `box.exec()` 内部（模态循环里对话框重绘读复选框状态），有时崩在 exec 返回后的 `box.checkBox()`。

**根因：** `box.setCheckBox(QCheckBox(text))`——复选框无父构造后立即传参，中间不留 Python 引用。PyQt6 在此路径上未把所有权转移给 C++（Qt 6.11 实测），临时对象随后被 Python GC 回收 → `QMessageBox` 内部的复选框指针悬空。**AV 位置随 GC 时机漂移**，faulthandler 指向的行号（exec / checkBox）全是下游受害者，极富误导性。最小复现里 `cb = QCheckBox(...)` 恰好赋值给了变量保住引用，所以「最小却不复现」——这是本陷阱最阴险之处。

**修复：** 构造期挂父：`QCheckBox(text, box)`（C++ 端即拥有，PyQt 不回收）。

**通用纪律：** 任何「创建后立即传给 setter、不留 Python 引用」的无父 QWidget/QObject 都是同款雷；传参前先挂父或保引用。排查此类无声 AV 用 `faulthandler.enable()` + `qtpy.sip.isdeleted(obj)` 逐步探测对象存活，不要相信崩溃栈指的行号。演练台已常驻化：`scripts/mw_repro.py`（拉真实 MainWindow 跑场景/驱动交互，见 scripts/README.md）；竞态类崩溃须每配置 ≥4 轮对比崩溃率，单轮结论不可信（本次「面板触发」「复选框触发」「父对象触发」三个假根因均被多轮重测推翻）。

### 3.4 可见控件 `setParent(None)` 会变成顶层原生窗口（2026-09-08 修复）

**问题：** 文本框带特效时，画布左键拖拽框选扫过它，会不断闪出秒关闭的 Win 原生小窗；这些窗口不出现在任务栏（`Qt::Tool`/`Qt::Popup` 族语义），形态像设置面板。删掉特效即不再出现。

**根因：** 框选每一步都会触发 `selectionChanged` → 右栏重建效果卡整组，而 `ui/text_engine/effects/panel.py::TextEffectPanel._clear_effect_cards` 对**处于显示状态**的卡片直接 `setParent(None)`。Qt 对「可见控件解除父级」的语义不是隐藏，而是**变成顶层窗口并 show 出来**，直到随后的 `deleteLater()` 才销毁——于是每一步都闪出一排原生小窗。

**判据：** 看 `isVisible()`，不是 `isHidden()`。父容器隐藏时 `isHidden()` 已是 False 但 `isVisible()` 为 False，此时 `setParent(None)` 不会闪——`ui/text_engine/transforms/panel.py::TextTransformPanel._clear_transform_panels` 的同款代码长期未暴露，正是因为浮层通常关着。修法统一为：先 `hide()`，再摘父级，再 `deleteLater()`。

**通用纪律：** 任何「清空重建」容器（`layout.removeWidget` + `setParent(None)` + `deleteLater`）都要先 `hide()`。排查短命原生窗口：任务栏无图标即 Qt Tool/Popup 族；用系统级 `EnumWindows` 轮询即可抓到这类朝生暮死的窗口（本机实测系统级 `SetWinEventHook` 会让进程直接退出，别用）；要定位「谁把它变成顶层窗口」，给 `QWidget.setVisible` 打桩——PyQt 里它是虚函数，改类属性可截获 C++ 内部调用。行为由 `tests/test_text_effects_cards.py::test_clear_effect_cards_hides_before_detaching` 锁定（打桩 `setParent`，断言摘父级时已隐藏）。

### 3.5 框选拖拽期间暂停右栏面板同步（2026-09-08 修复）

**问题：** 带样式的块参与框选时明显掉帧；纯无特效的块一次选几十个也不卡。用户实机对比结论准确指向「样式」而非「数量」。

**根因：** `ui/canvas.py::Canvas.apply_box_selection` 每个 mouseMove 都 `clearSelection()` + 逐块 `setSelected(True)`，一步产生 2–4 次 `selectionChanged`；每次都走到 `ui/text_panel.py::FontFormatPanel.set_textblk_item` → `ui/text_engine/effects/panel.py::TextEffectPanel._rebuild_effect_cards` 把效果卡整组推倒重建（5 张卡约 30 个控件，含按钮菜单与渐变编辑器）。真实工程 40 步扫掠实测：无特效 10.5 → 4.9 ms/步，带特效 22.9 → 5.4 ms/步；带特效块的 `paint` 只多约 0.4 ms/步——瓶颈在面板重建，不在渲染。

**修复：** 新增 `ui/canvas.py::Canvas._box_select_panel_sync_paused`，拖拽期间在 `ui/canvas.py::Canvas.on_selection_changed` 压住 `incanvas_selection_changed`，松手在 `ui/canvas.py::Canvas.hide_rubber_band` 补发一次，`ui/canvas.py::Canvas.updateCanvas` 复位防卡死；单击选中仍即时同步。代价是拖拽过程中右栏短暂显示旧选中集，松手即纠正（有意取舍）。行为由 `tests/test_box_select.py` 两条用例锁定。

**遗留可挖点：** 每步约 4.9 ms 的基线来自 `clearSelection` + 全量重选引起的整屏重绘；改成只切换差集更快，但会改变「活动块」判定顺序，动前先确认。

**排查方法：** 除 cProfile 外，对**运行时才查找**的方法打桩计时——Qt 信号持有连接时的绑定方法，事后 monkeypatch 类方法拦不住已连接的槽（`Canvas.on_selection_changed` 即此类），必须包住调用点动态查找的方法（如 `set_textblk_item`、`_rebuild_effect_cards`）才能拿到耗时。

## 7. 字体与文本渲染

### 7.1 字重真值化：styleName 精确匹配压过字重（2026-09-04 修复）

问题：字重编辑有时不生效（脏页提示出现、JSON 已落盘，渲染不变）。根因经 qtbase 源码阅读 + 本机 PyQt6 实证：

- `QFont.styleName` 非空且与某 face 的 styleName **精确相等（区分大小写）**时直接命中，**weight 完全被忽略**；未命中才回退 weight/italic 距离匹配。历史写入的脏 face 名（deepcopy 残留、旧版 pin 补丁）因此毒化渲染。Windows DirectWrite 下命中 face 低于请求 weight≥600 时叠加合成假粗体（`DWRITE_FONT_SIMULATIONS_BOLD`）——"改字重看似偶尔生效"的表象来源。
- `QFont.setBold(False)` 无条件把字重重置为 Normal(400)，与原值无关；`bold()` 定义为 weight>Medium。bold 镜像写入全部撤除，`FontFormat.__post_init__` 做 bold=True→700 的字段级折算。
- `QFontDatabase.weight(family, style)` 返回 -1 的坑：查询 API 不走字体别名（渲染路径走别名，割裂根源）；"Semilight" 类样式名被 Qt 的 style 名解析器误解析。**禁用 `QFontDatabase.font()` 取值**——它会制造带 styleName 的 QFont，正是污染源。
- 清 styleName 残留须 `QFont.setStyleName("")` / `QTextCharFormat.setFontStyleName("")`，且 **defaultFont 与字符格式两处同一次清/写、weight 与派生 face 同一次 merge**，杜绝中间态。

修复后的架构：`font_weight` 为唯一真值，`_style_name` 降级为派生显示缓存——`utils/face_resolver.py::resolve_face` / `sync_face`（缓存失效挂 `utils/shared.py::init_font_list`）；所有写入点的重算先于撤销快照构建。完整决策与实现偏差记录随计划文档完结清理，见 daily_log 2026-09-04 条目与 git 历史。

遗留注意：

- `utils/proj_compact.py` 有独立硬编码的 FontFormat 默认值副本，改默认值语义时是漏网同步点。

### 7.2 文本面板选中态语义（同批定稿）

闲置态显示"新块默认格式"并跟随最近编辑（单选编辑也写入默认，配标题区 Reset 重置入口）；多选显示最后选中块 + 混合字段 "—"、触碰字段广播（PS/Figma 语义）。多选态用镜像副本 `active_format`，不再与 global_format 双写。

## 附录：故障快速排查

| 症状 | 可能原因 | 检查方法 |
|------|---------|---------|
| 翻译显示为英文 | QM 损坏或 ts 条目缺失 | 按 [`docs/基础速查/i18n.md`](i18n.md) 常见问题逐条排查 |
| 中文显示为 `?` | 旧版 qm_compile.py | 用当前脚本重新编译 |
| 启动报 ImportError | Re-export 被删 | 检查 `__init__.py` 和 `from .base import *` |
| 滑入时出现 75px 白条 | 合成渲染竞争 | 使用 `OverlaySlider` 直接动画路径 |
| 框选时闪出一排秒关的小窗 | 可见控件 `setParent(None)` 变顶层窗口 | 先 `hide()` 再摘父级（见 3.4） |
| 带样式的块框选掉帧 | 每步重建效果卡整组 | 拖拽期间暂停面板同步（见 3.5） |
| `.jxl` 文件导致闪退 | ultralytics monkey-patch | 使用 `_pil_image_open` 保存的引用 |
