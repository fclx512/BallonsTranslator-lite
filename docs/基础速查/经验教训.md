## 1. 国际化与翻译系统

### 1.1 QM 编码 Bug（2026 年 6 月）

**问题：** `scripts/qm_compile.py` 使用 `latin-1` 编码加 `errors="replace"` 处理字符串字段。`—`（em dash, U+2014）、`→`、`⚠`、`✓` 等非 Latin-1 字符被静默替换为 `?`，导致：
- Qt `QTranslator` 哈希查找失败 → 运行时的字符串找不到翻译
- 所有含这些字符的字符串显示为英文

**修复：** 改为 `s.encode("utf-8")`。哈希计算和字符串存储统一使用 UTF-8。

**文件：** `scripts/qm_compile.py`（`_iso8859_str` 函数 → 语义重命名）

**检测：**

```bash
python -c "
import struct
data = open('translate/zh_CN.qm', 'rb').read()
pos = 16
while pos < len(data):
    t, l = data[pos], struct.unpack('>I', data[pos+1:pos+5])[0]
    if t == 0x69:  # SECTION_MESSAGES
        raw = data[pos+5:pos+5+l]
        for keyword in [b'? recommended', b'? from', b'? Model']:
            if keyword in raw:
                print('QM 已损坏 — 请重新编译！')
                break
    pos += 5 + l
"
```

### 1.2 i18n 检查器 — 多行正则遗漏

**问题：** `scripts/i18n_check.py` 使用 `self\.tr\("((?:[^"\\]|\\.)*)"\)`（仅单行）扫描。多行 `tr()` 调用和隐式字符串拼接对扫描器不可见：

```python
self.tr("line1\nline2")                    # 跨 2 行
self.tr("part1 " "part2")                  # 隐式拼接
self.tr("Enable this for models..."
        "Vision-capable...")               # 换行拼接
```

**修复：** 正则改用 `re.DOTALL` 模式，允许 `tr()` 参数内换行：

```python
r'self\.tr\(\s*("(?:[^"\\]|\\.)*")\s*\)', re.DOTALL
```

**文件：** `scripts/i18n_check.py`

### 1.3 `type="obsolete"` 检测修复

**问题：** 过时条目检测原在 `<translation>` 上查 `type="obsolete"`，但标准将该属性放在 `<message>` 上。检测实际上一直无效。

**修复：** 同时检查 `<message type="obsolete">` 和 `<translation type="obsolete">`。

**文件：** `scripts/i18n_check.py`

### 1.4 Self-tr() 字符串拼接规则

`self.tr()` 参数必须为单个字符串字面量。**严禁使用 Python 隐式拼接：**

```python
# ✅ 正确 — 单个字符串
self.tr("A long sentence that spans lines.")

# ❌ 错误 — 检查器正则检测不到
self.tr("part one "
        "part two")
```

若字符串太长，在 `tr(` 后换行即可（多行正则会处理）：

```python
self.tr("A long sentence the checker will find across lines.")
```

### 1.5 37 个"孤立条目"均为误报

`i18n_check.py --ci` 退出码为 4（孤立条目位）— 这是正常现象。所有 37 个报告出的孤立条目来自两类误报：

**基于变量的 tr() — 27 个条目：**
- `ThreadBase`：`self.tr(self._thread_error_msg)` — 子类中赋值的类变量
- `_ShortcutRow`：`self.tr(_ACTION_NAMES.get(action_id, action_id))` — 字典查找

两者均在运行时通过 Qt 的 `.qm` 查找正确解析。**切勿清除。**

**多行 tr() — 9 个条目：**（见 1.2 — 现已修复，但旧文件可能仍有检查器最初找不到的条目）

### 1.6 类重命名时，需更新 .ts 上下文

如果 `class OldName` → `class NewName`，则 .ts 中所有位于 `<name>OldName</name>` 下的消息必须移至 `<name>NewName</name>`。Qt 通过类名查找翻译。

波及范围：
- `ShortcutEditor` → `_ShortcutRow`（27 条消息）
- `AiChatPanel` → `ChangeReviewWindow`（2 条消息）
- `FontFormatPanel` → `ConfigPanel`（"Effect"）
- `TranslateThread` → `ImgtransThread`
- `ProgressMessageBox` → `ImgtransProgressMessageBox`

### 1.7 .ts 中的重复上下文块

`_normalize_ts()` 函数合并具有相同 `<name>` 的重复 `<context>` 块。`MainWindow` 曾有两个独立块（61 + 11 条消息），第一个块中的条目在实现合并前被静默丢弃。

### 1.8 模块参数描述

含有 `description` 字段的模块参数在运行时使用 `self.tr(variable_name)`。i18n 正则检测不到它们。它们在 .ts 中位于 `<context>ParamWidget</context>` 下，并明确排除在孤立条目检测之外。

## 2. 代码清理陷阱

### 2.1 自动清理误删 Re-export（2026 年 5 月）

**问题：** 自动代码检查工具删除了文件中"未使用的 import"，但这些实际上是 **re-export**——在一个文件中导入并通过另一个模块的 `from .base import *` 重新导出的名字。被删除的文件编译正常，但所有依赖方立刻崩溃。

**波及范围：**

| 文件 | 被删的 re-export | 依赖方 |
|------|-----------------|--------|
| `utils/structures.py` | `List, Dict, Union, Tuple, field` | `fontformat.py`, `config.py`, `textblock.py`, `misc.py` |
| `modules/ocr/base.py` | `DEFAULT_DEVICE, DEVICE_SELECTOR` | `ocr/__init__.py`, `ocr_mit.py` |
| `modules/textdetector/base.py` | `DEFAULT_DEVICE, DEVICE_SELECTOR` | `textdetector/__init__.py` |
| `modules/translators/base.py` | `DEVICE_SELECTOR` | `translators/__init__.py` |

**教训：** 删除 import 前必须 grep 全库确认没有其他模块从当前位置导入该名字。仅 `ruff check .` 通过不代表能启动。

**预防：**
- 优先显式列出导出名，避免 `__init__.py` 中的 `from .base import *`
- 批量 import 清理后，至少运行：
  ```python
  python -c "from modules.base import init_module_registries; init_module_registries()"
  ```

## 3. UI 渲染

### 3.1 OverlaySlider 合成渲染伪影修复

**问题：** 多个左侧覆盖面板同时动画时（如 GlobalSearch 关闭 + AI Chat 滑入），在之前打开的面板右边缘出现 75px 宽的纯白竖条。纯白 `#FFFFFF`，与任何主题色不匹配。

**根因：** `OverlaySlider.show()` 使用复杂的合成渲染流程：
1. 将真实控件移至屏幕外，`grab()` 抓取为 QPixmap
2. `hide()` 真实控件，将像素图合成到 `_SharedOverlay`
3. 驱动合成层动画
4. 完成后：销毁合成层，`show()` 真实控件
5. 从合成层切换到真实控件的时间窗口渲染了不完整像素

**修复：** 放弃合成方式。`show()` 现在：
1. 将真实控件置于起始位置
2. 立即 `widget.show()` + `widget.raise_()`
3. 每帧通过 `widget.move()` 驱动位置
4. 通过每帧 `raise_()` 维持 Z 序

真实控件全程保持可见——无需抓图、隐藏、合成、重建循环。

**文件：**
- `ui/overlay_slide.py` — `show()` 走直接动画路径，`_update_animation()` 兜底加 `raise_()`
- `ui/ai_chat_panel.py` — QScrollArea viewport `setAutoFillBackground(True)`（⚠️ 该文件已于 2026-07 删除，但渲染伪影的修复逻辑仍保留在 overlay_slide.py 中）
- `config/stylesheet.css` — `#AIChatArea > QWidget { background-color... }`（⚠️ 该样式规则对应文件已删除）

**注意：** `hide()` 动画仍使用 `_SharedOverlay` 合成（隐藏中的控件无需在动画期间保持交互）。

### 3.2 页面列表信号重入：点脏页跳转错乱（2026-08-28 修复）

**问题：** 样式管理器批量改样式后，点击斜体脏页随机跳转。根因：`ui/mainwindow.py::pageListCurrentItemChanged` 的脏页分支同步调 `ui/mainwindow.py::updatePageList()`，重建列表的 `clear`/`addItem`/`setCurrentItem` 会再触发 `currentItemChanged`，处理器在首次调用返回前被重入，对非点击项重复执行完整切页。

**修复与硬约束：** 重入防护 = 仅在脏页分支内用 `blockSignals(True)` 包住那一次 `updatePageList()`（try/finally 还原）。**禁止把屏蔽挪进 `ui/mainwindow.py::updatePageList` 内部或扩大到其他调用点**——`ui/mainwindow.py::openDir` 的首屏渲染依赖「重建 → `setCurrentItem` → `currentItemChanged` → `pageListCurrentItemChanged` → `updateCanvas()`」这条隐式链路，全局屏蔽会破坏首屏。行为由 `tests/test_page_list_dirty_click.py` 锁定。

## 4. 图像格式兼容性

### 4.1 JXL (JPEG XL) — ✅ 已重新激活

JXL 格式曾因 `pillow-jxl-plugin` 与 Pillow 11+ 不兼容而封存。已通过将 Pillow 锁在 `<11` 版本解决。

历史问题及修复状态：

**4.1.1 Ultralytics 劫持 PIL.Image.open** — ✅ 已修复

`ultralytics.utils.patches` 用包装器 monkey-patch `Image.open`，捕获所有异常后尝试 `pip install pi-heif`。对 `.jxl` 文件：
- 吞掉真实 PIL 异常
- pip 安装失败（嵌入式 Python 无 pip）
- 抛出 `ModuleNotFoundError: No module named 'pi_heif'` → 闪退

**修复：** 绕过 ultralytics 补丁，使用保存的原始引用：
```python
from ultralytics.utils.patches import _image_open as _pil_image_open
```

**4.1.2 `.jxl` 文件无意义重试** — ✅ 已修复

JXL codec 已注册但无法解码时，重试 5 次纯属浪费。`.jxl` 单独处理——PIL 试一次，失败立刻走 cv2 兜底。

**4.1.3 cv2.imread 被 Ultralytics 劫持** — ✅ 已修复

Ultralytics 将 `cv2.imread` 替换为 `np.fromfile` + `cv2.imdecode`。空文件时，`cv2.imdecode(空buffer)` 抛出 `cv2.error` 断言而非返回 None。cv2 兜底路径已包 `try/except cv2.error`。

**4.1.4 `imwrite` JXL 编码缺 try/except** — ✅ 已修复

JXL 保存路径现包裹 try/except，编码失败时自动回退到 PNG。

**封存的根本原因与最终解决：**

`pillow-jxl-plugin` 与 Pillow >=11 不兼容。最终决定将 Pillow 版本锁定为 `>=10.0,<11`（回退到经测试可工作的版本范围），而非寻找替代 JXL 编解码方案。这保证了所有现有 Pillow API 调用无需修改。

详见 [`utils/io_utils.py`](utils/io_utils.py) 的 `imread()`/`imwrite()`。

**文件：**
- `utils/io_utils.py` — `imread()`, `imwrite()`, `_imread_jxl_fallback()`
- `utils/config.py` — `intermediate_imgsave_ext` 配置字段
- `ui/configpanel.py` — JXL 选项已在格式选择器中恢复

## 6. 反向移植（fork → 上游）

> 首次移植字体排除功能（2026-08-08）的记录。规范见 `docs/技术实现/反向移植_规范.md`。

### 6.1 两仓库环境差异

- **git 身份**：上游克隆是只读 clone，没有 `user.name`/`user.email`。提交前需在 clone 内配置 repo-local 身份（与 fork 一致）。
- **`site-packages/tests` 抢占**：上游 `ballontrans_pylibs_win` 里 ultralytics 自带 `tests` 包（regular package），本地 `tests/` 无 `__init__.py`（namespace package）→ `python -m unittest tests.xxx` 会导入错包、触发 torch 加载失败。用 `python -m unittest discover -s tests -p "<file>"` 绕过。
- **无 lrelease/lupdate**：上游 scripts/update_translation.py 依赖外部 lupdate 命令，环境里没有可执行文件 → 用 fork 的 `scripts/qm_compile.py` 直接编译上游 ts（工具跨仓库复用可行，utf-8 安全）。
- **offscreen 测试坑**：`QMessageBox.information` 是模态阻塞的，offscreen 下挂起 → 测试时 monkeypatch。offscreen 下 `QFontDatabase.families()` 返回空 → 注入假字体列表验证对话框交互逻辑。

### 6.2 上游 UI 布局习惯（作者反馈）

上游设置项的 ConfigSubBlock 习惯是「标题一行 + 控件一行」的两行结构，**不写介绍文本**（description 通常作为 tooltip 而非显示文字）。首次移植把描述文字渲染成第三行且换行错位，被上游作者否决。最终结构：`addBlockWidget(button, name=...)` 直接包按钮，标题和按钮各一行。

### 6.3 移植要点复述

- 手工移植 + 逐处适配 import（`ballontranslator.` 前缀）；`pcfg` 新字段给默认值保 JSON 兼容；UI 字符串 `self.tr()` 英文源 + en_US/zh_CN ts + 编译 qm。
- 上游只有一个字体列表消费点（`mainwindow.on_show_only_custom_font`），fork 的三处消费点因 text_panel/fontstyle_manager 不存在而收敛为一处。
- 启动时无条件走 `on_show_only_custom_font(flag)` 统一应用过滤（否则重启后隐藏字体重现）。

## 7. 字体与文本渲染

### 7.1 字重真值化：styleName 精确匹配压过字重（2026-09-04 修复）

问题：字重编辑有时不生效（脏页提示出现、JSON 已落盘，渲染不变）。根因经 qtbase 源码阅读 + 本机 PyQt6 实证：

- `QFont.styleName` 非空且与某 face 的 styleName **精确相等（区分大小写）**时直接命中，**weight 完全被忽略**；未命中才回退 weight/italic 距离匹配。历史写入的脏 face 名（deepcopy 残留、旧版 pin 补丁）因此毒化渲染。Windows DirectWrite 下命中 face 低于请求 weight≥600 时叠加合成假粗体（`DWRITE_FONT_SIMULATIONS_BOLD`）——"改字重看似偶尔生效"的表象来源。
- `QFont.setBold(False)` 无条件把字重重置为 Normal(400)，与原值无关；`bold()` 定义为 weight>Medium。bold 镜像写入全部撤除，`FontFormat.__post_init__` 做 bold=True→700 的字段级折算。
- `QFontDatabase.weight(family, style)` 返回 -1 的坑：查询 API 不走字体别名（渲染路径走别名，割裂根源）；"Semilight" 类样式名被 Qt 的 style 名解析器误解析。**禁用 `QFontDatabase.font()` 取值**——它会制造带 styleName 的 QFont，正是污染源。
- 清 styleName 残留须 `QFont.setStyleName("")` / `QTextCharFormat.setFontStyleName("")`，且 **defaultFont 与字符格式两处同一次清/写、weight 与派生 face 同一次 merge**，杜绝中间态。

修复后的架构：`font_weight` 为唯一真值，`_style_name` 降级为派生显示缓存——`utils/face_resolver.py::resolve_face` / `sync_face`（缓存失效挂 `utils/shared.py::init_font_list`）；所有写入点的重算先于撤销快照构建。完整决策与实现偏差记录随计划文档完结清理，见 daily_log 2026-09-04 条目与 git 历史。

遗留注意：

- `utils/proj_compact.py` 有独立硬编码的 FontFormat 默认值副本，改默认值语义时是漏网同步点。

### 7.2 文本面板选中态语义（同批定稿）

闲置态显示"新块默认格式"并跟随最近编辑（单选编辑也写入默认，配标题区 Reset 重置入口）；多选显示最后选中块 + 混合字段 "—"、触碰字段广播（PS/Figma 语义）。多选态用镜像副本 `active_format`，不再与 global_format 双写。
