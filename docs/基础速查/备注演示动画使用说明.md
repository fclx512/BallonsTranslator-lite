# 备注演示动画使用说明

设置页问号备注弹层（`ui/configpanel.py::ConfigNotePopup`）支持在文字上方播放一段**代码生成的演示动画**，用于纯文字讲不清的操作类说明（如下拉切换后的视觉效果变化）。首个实例是「标点位置」备注（`anim="punctuation_position"`）。本文是该流程的参考，新增功能动画照此走。

## 适用判断

不是所有备注都值得配动画，按信息形态选载体：

- **纯文本够用**：概念解释、行为在页面上就有即时反馈的选项——保持现状，不加动画。
- **需要动画**：效果有"过程"（移动、展开、飞入）或操作有"步骤"（打开下拉 → 选择 → 生效），或开关改变渲染行为、需要前后对比才直观——按下方管线做。
- **外观展示类开关**（开/关只是"显示/不显示"某个装饰，无布局行为差异，如序号/标签徽标）：可以配动画展示徽标出现的过程，但文案走**单条常显说明**（见「文案方案」），不用改前/改后双条。

动画是烘焙像素，**内嵌文字不走 i18n**，统一直书中文（本 fork 的主要受众）。

## 双轨产物：仓库默认 + 本机覆盖层

产物分两层，展示时本机覆盖层优先：

- **仓库默认**：`config/help_anims/<key>.webp`，git 跟踪、随仓库分发（575×328 = 460×262 × 1.25 DPR）。开发者用 `--all`（默认输出目录）重出后提交——**默认输出目录自动钉定 DPR 1.25 渲染**，跨工作机重出逐字节一致，产物尺寸永不漂移。
- **本机覆盖层**：`config/help_anims_local/<key>.webp`，已 gitignore。设置页「重新生成」按钮的产物落这里（文件名同 key），`ui/configpanel.py::_help_anim_path` 先查它、命中即用，未命中回落仓库默认。
- **清除回退**：设置页「Restore default animations」按钮删除本机覆盖层里全部 webp，即回退仓库默认；覆盖层为空时该按钮置灰。
- 路径在**点击问号时**才解析，所以重生成后新开的弹层立即用新动画，无需重建设置页。

## 一个动画 = 三件套

1. **场景**：在 `scripts/gen_help_anim.py::SCENES` 里注册一条 `scripts/gen_help_anim.py::SceneMetadata`（`scene_class` 指向一个 `scripts/anim_kit.py::AnimScene` 子类，另带 `kind`/`title`/`description` 元数据），负责画整段演示。
2. **产物**：`config/help_anims/<key>.webp`（仓库默认）或 `config/help_anims_local/<key>.webp`（本机覆盖层），无损动画 WebP。
3. **挂载**：对应设置项的 `ConfigSubBlock`/`ConfigFormRow` 加 `anim="<key>"`，问号弹层自动在文字上方播放。

## 制作管线（scripts/gen_help_anim.py + scripts/anim_kit.py）

机制与版式分两层：**机制**（确定性时间轴原语、节奏档位 `scripts/anim_kit.py::RhythmProfile`、光标编排 `scripts/anim_kit.py::CursorPlan`、场景基类 `scripts/anim_kit.py::AnimScene`、文案组件、渲染/编码）在 `scripts/anim_kit.py`，对画布尺寸/文案位置/叙事节奏**零假设**；**弹层版式**（460×262 常量、设置行 + 预览卡 + 文案位）与 7 个场景在 `scripts/gen_help_anim.py`。

**场景形态先选对，别硬套预设**：

- **复选框单点叙事**（光标入场 → 点击 → 过渡 → 文案明暗互换）：继承 `scripts/gen_help_anim.py::CheckboxDemoScene` 预设，填 `CHECK_TEXT`/`CAPTIONS`、覆写 `_paint_content` 与 `_advance` 即可（6 个场景走它）。
- **叙事不匹配**（下拉选择、多拍节奏、拖拽跟随……）：直接继承 `scripts/anim_kit.py::AnimScene` 自行组装，样本是 `scripts/gen_help_anim.py::PunctuationScene`；硬套预设就是"观感莫名其妙"的来源。光标行程用 `scripts/anim_kit.py::CursorPlan` 编排（`go`/`press`/`fade`，帧语义见其 docstring；落点支持 callable，可跟随移动中的目标）。

运行：

```bash
./ballontrans_pylibs_win/python.exe scripts/gen_help_anim.py --scene <key> [--dump-frames DIR]
./ballontrans_pylibs_win/python.exe scripts/gen_help_anim.py --all   # 依次生成 SCENES 全部场景，写仓库默认目录
./ballontrans_pylibs_win/python.exe scripts/gen_help_anim.py --all --out-dir config/help_anims_local   # 写本机覆盖层（设置页按钮即此路径）
```

编写新场景的规则：

- **帧号确定性步进**：所有动画状态（光标位置、下拉展开度、标点位移……）在 `set_state(帧号)` 里按帧号推算，不依赖真实时钟——产物可复现，界面改版后重跑脚本即再生成。过渡进度用 `scripts/anim_kit.py::move_progress`，缓动用模块内的 `out_cubic`。
- **每场景自己的画布与时长**：画布尺寸 = 场景类属性 `SIZE`、帧数 = `N_FRAMES`（`--scene` 的 choices 取 `SCENES` 的键），只动本场景。
- **时间轴用节奏档位，别逐场景手填**：复选框叙事的时间轴改由档位算出——`scripts/gen_help_anim.py::CheckboxDemoScene` 的子类声明 `RHYTHM` 类属性（`scripts/anim_kit.py::RHYTHM_STANDARD` / `scripts/anim_kit.py::RHYTHM_FAST` / 三拍叙事的 `scripts/anim_kit.py::RHYTHM_THREE_BEAT`，或自定 `scripts/anim_kit.py::RhythmProfile`）。档位字段是**时长**（入场/按下/过渡/静止/淡出），帧号由累加得出，不匹配时优先调档位参数或另立档位。`RHYTHM = None`（默认）保留手填常量，向后兼容。多拍叙事同样走档位——三拍把 `hold_after` 拉长容纳后两拍，拍内特有常量（`F_GROW_END`/`F_SHRINK_END`/`F_HANDLE_*`/`F_DRAG_*`）仍手填，见 `scripts/gen_help_anim.py::ClipTextScene`。**解析口径唯一**：`scripts/anim_kit.py::resolve_timeline`（本类手写 F_* 优先 → 档位算出 → 继承值）是「本类手写常量优先、档位补继承值」这一语义的**唯一实现**，渲染侧 `scripts/anim_kit.py::apply_timeline` 与校验侧 `scripts/check_anim_rhythm.py` 都调它——历史上校验只读类属性，会把 `RHYTHM` 场景校验到继承的旧时间轴（假绿灯：`ClipTextScene` 的 `N_FRAMES`/`F_FADE` 校验的是基类的 20/15 而非实例的 36/31）。
- **文案方案分两类**：**行为对比类**（开关改变渲染行为：标点布局/引号宽度/tcy/裁剪/块自动放大等）用改前/改后两条文案**从头到尾同时显示**（改前在上、改后在下，都在预览卡右侧），前缀加粗「改前：」「改后：」；**强调靠明暗**——未激活一条降到约 35% 不透明度、激活的全亮，点击复选框/下拉项后两条用 `out_cubic` 约 5 帧交叉淡化互换强调状态、与预览过渡同步。**外观展示类**（开/关只是显示/不显示某个装饰：序号徽标/标签徽标）改**单条常显说明**——直接描述该功能呈现什么，无改前改后前缀、无明暗互换（如「开启后：序号按阅读顺序贴在每块左上角」）。都只用 `QLabel.setStyleSheet` 调 rgba 前景色 alpha 实现，**禁止 `QGraphicsOpacityEffect`、没有高亮边框**。双条公共实现在 `scripts/anim_kit.py::make_caption_labels` / `scripts/anim_kit.py::set_caption_emphasis`，单条在 `scripts/anim_kit.py::make_single_caption`（几何由调用方传，弹层常量 `CAPTION_*` 在 gen_help_anim）。**不设**「过程说明」第三段文案（只讲操作过程、没有信息量；clip_text 的第三拍拖手柄属于过程，行为自明、不配文案）。
- **产物分辨率 = 460×262 × 渲染 DPR，DPR 双轨**：**仓库默认目录**（`config/help_anims/`）自动**钉定 DPR 1.25**（`QT_ENABLE_HIGHDPI_SCALING=0` + `QT_SCALE_FACTOR=1.25`，先于 QApplication 设置，任何屏幕缩放设置的机器都得到同一 DPR）——入库产物跨工作机尺寸/内容逐字节一致；**其余输出**（本机覆盖层 `config/help_anims_local/`、显式 `--out`/`--out-dir`）按**本机屏幕真实 DPR**——覆盖层的意义就是本机适配（windows 平台下 `grab()` 天然返回 DPR 缩放后的物理像素）。`--dpr NATIVE|数值` 显式覆盖双轨默认。显示侧取屏幕 DPR，每帧 pixmap `setDevicePixelRatio(dpr)`、label 钉 物理/DPR 的逻辑尺寸（`ui/configpanel.py::ConfigNotePopup`），生成 DPR = 显示 DPR 时 1 图像像素 = 1 设备像素、不插值。**别用 `QMovie.setScaledSize`**——那会走插值缩放，白丢分辨率。钉定产物换机器显示时逻辑尺寸会偏大/偏小（依然逐像素清晰），用设置页「应用 → Note Animations → 重新生成演示动画」按钮重出本机适配版。README 大画幅流程不受钉定约束（见下方规划节）。
- **字体**：预览字符与 UI 标签统一**显式家族 "Microsoft YaHei UI"**（GUI 的真实默认；offscreen 平台的"系统默认"会落到 Arial——中文走错回退链且只有灰度 AA，是早期产物发虚的根因），预览字符另设 `QFont.Weight.DemiBold` 提字重——默认字重的黑体在小字号下渲染发虚；字幕/徽标用默认字重即可。家族缺失时 Qt 自动回退，无需额外处理。
- **样式复用真实实现**：主进程里 `app.setStyleSheet(ui/misc.py::parse_stylesheet(...))` + 用户主题，组合框等直接用 `ui/custom_widget` 封装控件，保证与设置页观感一致；取主题色用 `ui/misc.py::get_theme_color`（`AnimScene` 基类已统一取好 fg/accent/border/card）。
- **置顶覆盖层**：光标/下拉列表等要盖在真实子控件上的元素，画在一个透明覆盖子 widget 上，`scripts/anim_kit.py::AnimScene` 基类统一创建并在 `set_state` **每帧 `raise_()`**；场景的置顶内容（如 `PunctuationScene` 的下拉列表）画进 `scripts/anim_kit.py::_paint_overlay_content` 钩子，涟漪与光标由基类在其后统一绘制。覆盖层必须显式 `background: transparent`——裸 `QWidget` 会被全局 QSS 的 `QWidget { background-color }` 规则填实，把下面的控件全盖住（基类已处理）。**两条实测坑**：① 覆盖层建好后仍有子控件压在它上面——徽标场景的单条文案是在 `super().__init__()` 之后才建的，天然排在覆盖层之上、把光标盖住，靠每帧 `raise_()` 修掉；② 置顶内容与光标共用同一 painter，手绘下拉的 `setClipRect`（裁列表项）与 `setOpacity`（展开动画）会**残留**到随后画的涟漪/光标上，把光标裁进下拉矩形或调暗——基类用 `p.save()`/`p.restore()` 隔离置顶内容修掉。两条都有回归：`scripts/check_anim_cursor.py::verify_overlay_stack` / `verify_cursor_paint`（在「还原旧写法」的对照组上验证检查器确实报错，见 `tests/test_anim_checks.py`）。
- **竖排/标点类场景**：标点两种摆放的权威规则在 `ui/text_engine/vertical_layout.py::updateDrawOffsets`（居中 = 字符框正中；靠边 = 墨迹贴字符框右上角、顶格顶；`！？：；` 两种模式都居中），照它画，不要凭感觉。**两把尺子别混用**：格高/进给用 `QFontMetricsF.tightBoundingRect`（引擎 `ui/text_engine/layout.py::get_punc_rect` 用的就是它），墨迹摆位用字形真实轮廓（`QPainterPath.addText`，引擎画的是向量轮廓）——同一字形两者能差 ~1px。改完这类场景必须过真机引擎探针（见「验收」）。
- **文字逐字定位**：`QFontMetricsF.tightBoundingRect` 取墨迹框，`drawText` 的参数是**基线坐标**（目标墨迹左上角减去墨迹偏移，**只减一次**——重复减会导致整列字下坠错位，首个场景踩过）。
- **offscreen 字体坑**：offscreen 平台（现已非默认，仅 `--platform offscreen` 调试用）不读系统字体注册表，必须同时设 `QT_QPA_FONTDIR=C:/Windows/Fonts`，否则中文全是豆腐块（脚本已内置；且 offscreen 默认字体落 Arial、只有灰度 AA，产物会与 windows 原生渲染不一致）。
- **编码参数**：Pillow `save(..., lossless=True, method=6, loop=0, exact=True)`。纯色 UI 内容下无损 WebP 连 GIF/MP4 都小（实测 33 帧 460×262 ≈ 40 KB，调研数据见 `scripts/README.md` 该脚本的登记行）；有损 WebP 在平坦色块上反而是负优化，不用。

## 接入（ui/configpanel.py）

- 动画落盘路径由 `ui/configpanel.py::_help_anim_path` 解析（本机覆盖层 `config/help_anims_local/<key>.webp` 优先，回落仓库默认 `config/help_anims/<key>.webp`），文件两处都缺失时弹层静默跳过动画，不影响纯文本。
- 数据流：`ConfigSubBlock(note=..., anim=...)` / `ConfigFormRow(note=..., anim=...)` → `ui/configpanel.py::_make_note_btn`（点击时才解析路径）→ `ConfigNotePopup(anchor, text, anim_path)`。已挂动画（＝ `scripts/gen_help_anim.py::SCENES` 的键）：`punctuation_position`（标点位置）、`punct_spacing`（紧凑标点间距）、`bracket_halfwidth`（竖排括号半角，演示固定「紧凑标点间距」关闭——那个开关开着时括号本来就被压到半字高，半角开关只剩 11.5→8 的细差）、`tcy`（自动直排内横排）、`block_index`（序号徽标，外观类单条文案）、`tag_badge`（标签徽标，外观类单条文案）、`clip_text`（溢出裁剪，三拍：关闭态块自动放大放字 → 点开开关后裁切+黄框 → 拖手柄放大后黄框消失）；其余备注保持纯文本。
- 重生成：设置页「应用 → Note Animations」有「Regenerate demo animations」按钮（`ui/configpanel.py::on_regen_help_anim`）——确认窗告知后 QProcess 子进程跑 `--all --out-dir config/help_anims_local`（产物写本机覆盖层），状态文字按 stdout 的 `TOTAL n` 行定总数、按 `OK <key>` 行报 n/总数；旁边「Restore default animations」按钮（`ui/configpanel.py::on_restore_help_anim`）删除覆盖层全部 webp 回退仓库默认，删除前同样确认窗告知。空闲时状态条显示当前态（「本机适配 n/总数」/「仓库默认」，`ui/configpanel.py::_refresh_help_anim_status`）。生成脚本写文件走 `<key>.webp.tmp` + `os.replace`（失败重试一次）。**新增弹层场景时无需改任何计数**：`TOTAL` 行、状态条与确认窗文案的场景数都来自 `scripts/gen_help_anim.py::get_scene_count`（`ui/configpanel.py::_get_help_anim_scene_count` 延迟导入调用），确认窗文案是带 `{count}` 占位符的 i18n 字面量，数量变化不影响 .ts 命中。
- 播放行为：无限循环（loop 写在 webp 元数据里）；弹层关闭即停（`ConfigNotePopup.hideEvent`）；全局动画关闭（`pcfg.animation_fps < 0`）时只显示静态首帧。**QMovie 从内存缓冲播放**：文件字节读进 `QBuffer`、`QMovie.setDevice`，全程不持文件句柄——此前 QMovie(路径) 在弹层开着期间一直握着 webp 句柄，重生成的 `os.replace` 目标被占即 WinError 5（真机 7 场景 6 FAIL 的根因），改后生成脚本侧的 tmp+replace+重试只是保险。
- 弹层样式：`ConfigNotePopup` 是无父的顶层 Popup、不是主窗口后代，主窗口那份 QSS 到不了它——它自己 `parse_stylesheet()` 挂一份（否则落回 Qt 默认调色板＝白底直角框）。**底色不走 QSS**：原生透明窗口（`WA_TranslucentBackground`）上 QSS 底在真机合成路径下不画（实测除子控件外全透明），改由 `paintEvent` 自绘圆角矩形（`ui/misc.py::get_theme_color` 取底色与描边），QSS 只管子控件前景色。淡入用原生 `setWindowOpacity`（窗口级不透明度），不用 `QGraphicsOpacityEffect`。

## README 大画幅流程（scripts/gen_readme_anim.py，已落地）

为 README 制作的功能演示走**另一套流程约束**，与弹层流程共用 `scripts/anim_kit.py` 机制但独立成脚本 `scripts/gen_readme_anim.py`（首个场景 `format_tour`：主页面右侧格式面板基础排版巡礼，选中块 → 颜色/字体 → 对齐/斜体 → 竖排 → 行距拖拽，一镜到底）：

- **独立注册表**：场景注册在 `scripts/gen_readme_anim.py::SCENES`，与弹层 `SCENES` 分离，不进设置页「重新生成」流程。
- **画幅逐场景声明**：场景自声明虚拟画布 `SIZE` 与固定输出视口（`VIEW_W`/`VIEW_H`）；**镜头跟随光标**——`camera_rect(f)` 每帧声明视口矩形（光标位置指数趋近 + 首尾全景过渡），交 `scripts/anim_kit.py::iter_frames` 的 camera 参数逐帧裁切。**相机目标必须钳在虚拟画布内**（含全景目标），否则边界裁切让帧尺寸漂移、WebP 编码报 Invalid frame dimensions。镜头/字幕的共用骨架收在 `scripts/anim_kit.py::CameraScene`（DPR 量化取整口径、`_panorama_target` 钳位、`_advance_camera` 指数趋近、`camera_rect`）；各场景只需在 `_build` 末尾调 `_init_camera()`、在 `_update` 里调 `_advance_camera(f)` 并覆写 `_cam_target(f)`（跟随/全景节奏逐场景不同）。字幕不透明度用 `scripts/anim_kit.py::caption_alpha`（beat 起点淡入、下一拍前淡出，只传淡入/淡出帧数）。
- **真机引擎渲染画布块**：文本块直接用 `ui/textitem.py::TextBlkItem` + `QGraphicsScene`（与产品同渲染路径），换字体/颜色/对齐/斜体/竖排/行距全走引擎 setter——竖排几何天然正确，**不需要弹层场景的手绘探针验收**；`setLineSpacing` 的"拖拽中静默刷新显示、松手才重排"产品语义也已逐帧钉实。
- **流式编码**：大画幅帧数 × 全幅内存不可行，`iter_frames` 生成器逐帧产出、`scripts/anim_kit.py::save_webp` 接受可迭代流式消费，内存至多持有当前一帧。
- **编码**：纯色 UI 内容下**无损仍是最优**（README 场景有损实测反而更大），默认无损即可；`save_webp` 留有损参数备用。
- **DPR**：默认 `--dpr 2.0`（钉定，跨机重出尺寸不漂；README 不受弹层 1.25 钉定约束）。
- **光标落点一律由几何推导，禁止手填像素坐标**：落点必须等于「控件/弹层实际画在哪」，两者共用同一份几何，否则出"鼠标与按钮错位"。统一入口在 `scripts/anim_kit.py`：`scripts/anim_kit.py::activate_layout_tree`（递归激活含容器控件自己的 layout）、`scripts/anim_kit.py::widget_scene_center`、`scripts/anim_kit.py::graphics_item_scene_rect`（画布 `QGraphicsItem` → 视口 → 控件坐标，折入 `view.pos()`）；手绘色板/下拉收成**几何与绘制同体**的对象 `scripts/anim_kit.py::PopupPalette` / `scripts/anim_kit.py::PopupDropdown`（`pick_point`/`row_point` 出落点、`cell_rect`/`card_rect`/`paint` 出绘制，同一对象两种用法，两个 README 场景各自只声明参数）。
- **共享点击/移动时序**：每拍「按下后静止 N 帧再启程、移动在目标按下帧前一帧到位」由 `scripts/anim_kit.py::CursorPlan.move_after_press` 表达（常量收在 `scripts/anim_kit.py::PRESS_SETTLE` / `scripts/anim_kit.py::MOVE_LEAD`），不再逐点手算 `start=prev+2` / `arrive=x-1`；两个 README 场景的每拍移动都用它。
- **制作坑（首个场景实测）**：① 光标航点取子控件几何前必须先激活布局树（`scripts/anim_kit.py::activate_layout_tree`）——只 `layout().activate()` 不够：QVBoxLayout 惰性激活，容器控件（`ui/text_panel.py::AlignmentBtnGroup` 等 QFrame）自己的 layout 要等 resize 才解析，此前其子控件几何停在 (0,0)，落点会偏一整个控件宽；② 真实弹层（下拉列表/色板对话框）是顶层窗口，`grab()` 抓不到，展开态必须画进场景覆盖层（同弹层 `PunctuationScene` 做法，属通用规律）；③ 画布 `QGraphicsItem` 坐标不是控件坐标，须经 `scripts/anim_kit.py::graphics_item_scene_rect` 转换（视图有 `view.pos()` 偏移）；④ 建了却不加入布局的子控件会停在 (0,0)，出"幽灵图标"；⑤ `SizeControlLabel` 的 SVG 图标按相对路径加载，**必须从仓库根目录运行**。
- **真机查看**：临时接线可用 `scripts/mw_repro.py` 加临时场景在真实主窗口上方模态播放（本次用后已拆除，下次照做）。

## 验收

自动化（`scripts/verify.py` 每步一行，改动画/面板几何文件自动触发）：

- `scripts/check_anim_rhythm.py` —— 弹层全部场景的**有效时间轴**（`scripts/anim_kit.py::resolve_timeline`，渲染侧同源）不变量：顺序、`N_FRAMES` 下限/大于 `F_FADE`、`EMPH_SEG` 合法性；标点场景与 README 大画幅场景由 `scripts/check_anim_rhythm.py::verify_timeline` / `scripts/check_anim_rhythm.py::verify_plan` 两条线覆盖（后者校验 `CursorPlan` 的按下/航点/淡出帧序）。
- `scripts/check_anim_cursor.py` —— README 场景的落点=实际几何、覆盖层置顶、光标不被手绘弹层裁剪/调暗（真实构造场景后核对）。
- `tests/test_anim_checks.py` —— 上面两个检查器的**负向回归**：在「还原旧写法」的对照组上断言检查器确实报错（防止检查器本身静默失效）。

人工：

1. `--dump-frames` 导出逐帧 PNG，重点核对：文字无豆腐块、动效起止状态正确（如居中帧 vs 靠边帧）、改前/改后两条文案都在且亮的那条始终是当前状态、无控件重叠裁剪、光标轨迹自然。
2. **动 `anim_kit.py`/场景组装方式（不改观感）的改动，过逐帧像素回归**（硬性，确定性步进使它可行）：改前 `--all --dump-frames build/anim_regress/old` 留基线，改后同导 new，逐帧逐像素比对，**门 = 7 场景全帧 0 差异**；比对脚本一次性、用完删（比对时**先解帧再逐一比较**，别拿着多帧 Image 对象边 `seek` 边比——PIL 的时序会产出伪差）。写默认输出目录的运行走钉定 DPR，重写产物与仓库逐字节一致、git 无变化，可放心 dump。README 场景基线同样可 dump；层级修复（覆盖层隔离、每帧重顶）会带来**预期内的差异**——只有那几帧、只影响光标/涟漪/置顶内容。
3. **竖排几何过真机探针**（硬性，手绘几何最容易错）：写一个一次性脚本把同样的竖排文本喂给真机引擎（`ui/textitem.py::TextBlkItem` + `ui/text_engine/vertical_layout.py::VerticalTextDocumentLayout`，与产品同一条渲染路径），两种状态各渲一张图，逐字比对**格框**（引擎取 `line_spaces_lst` 的格顶/格高 + `line_width`）与**墨迹**（渲染图暗像素包围盒），把「引擎 vs 场景」四象限对比图落到 `build/anim_check/`。偏差应 <1px（同口径同缩放下 0.5px 就是像素量化底噪），对不上的以引擎为准修场景。用完删除该脚本。
4. 真机点问号确认弹层内播放、关闭即停。
5. `scripts/verify.py` 全绿（改 `ui/configpanel.py` 会自动触发启动冒烟）。
