# 添加新的 UI 翻译

## 架构概览

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│ self.tr("Text") │ ──→ │  translate/xx.ts │ ──→ │  translate/xx.qm │
│  Python 源码     │     │  (XML, 可编辑)    │     │  (二进制, 运行时) │
└─────────────────┘     └──────────────────┘     └─────────────────┘
                               │
                               ▼
                        scripts/qm_compile.py     (自定义编译器，零依赖)
                        scripts/i18n_check.py     (覆盖率审计)
                        scripts/ts_auto_fill.py   (同步 .ts ↔ 源码)
```text

- **源字符串**：所有 UI 可见文本均在 Python 代码中使用 `self.tr("English")` 包裹
- **扫描范围**：`ui/`、`modules/`、`utils/` —— 三个目录均被扫描以查找 `self.tr()` 调用
- **格式字符串**：参数包含 `{` 的 `self.tr()` 调用会被自动跳过（无需添加 `.ts` 条目）
- **参数描述**：模块参数 `description` 字段使用 `self.tr(variable)`，存储在 `<context>ParamWidget</context>` 下
- **翻译文件**：Qt `.ts`（XML）文件位于 `translate/` 目录
- **运行时加载**：`launch.py` 加载与 `config.display_lang` 匹配的 `.qm` 文件
- **语言注册表**：`utils/shared.py` 中的 `DISPLAY_LANGUAGE_MAP` 字典控制菜单中可用的语言

## 添加新语言（AI 辅助，推荐）

### 第一步：验证覆盖率

运行审计脚本，确保参考翻译是完整的：

```bash
python scripts/i18n_check.py
```

如果输出 `[PASS]`，则 `zh_CN.ts` 基线已完全覆盖。否则，先修复报告中的缺失再继续。

### 第二步：让 AI 进行翻译

将以下提示连同 `translate/zh_CN.ts` 文件一起发送给 AI（Claude、ChatGPT 等）：

> 请根据 `translate/zh_CN.ts` 创建日语翻译文件 `translate/ja_JP.ts`。
>
> 要求：
>
> 1. 保持所有 `<source>` 字符串不变
> 2. 删除 `<location>` 行是可选的
> 3. 将所有 `<translation>` 内容翻译成日语（类名和技术术语如 OCR/LLM/API 保持不译）
> 4. 将根 `<TS>` 元素的 `language` 属性改为 `"ja_JP"`
> 5. 跳过 `type="obsolete"` 或 `type="unfinished"` 的条目（直接翻译其内容）
> 6. 保持与输入相同的 XML 格式

将 AI 输出保存为 `translate/ja_JP.ts`。

#### CJK 捷径

对于日语（ja_JP）、韩语（ko_KR）等 CJK 语言，zh_CN 翻译中大约 60%（使用共享汉字的那些）可以直接复用。使用以下提示：

> 根据 `translate/zh_CN.ts`，创建韩语翻译文件 `translate/ko_KR.ts`。对于在韩语中仍然可理解的包含汉字的翻译，保持原样。其余部分翻译成韩语。

### 第三步：编译 .qm 文件

```bash
python scripts/qm_compile.py translate/ja_JP.ts translate/ja_JP.qm
```

预期输出：

```text
Compiled 677 translations: translate/ja_JP.ts -> translate/ja_JP.qm
```

### 第四步：注册新语言

在 `utils/shared.py` 的 `DISPLAY_LANGUAGE_MAP` 中添加条目：

```python
DISPLAY_LANGUAGE_MAP = {
    "English": "English",
    "简体中文": "zh_CN",
    "日本語": "ja_JP",      # ← 新增
}
```

- **键**：菜单中显示的语言名称（使用该语言的原生名称）
- **值**：必须与 `.ts` 文件根 `<TS>` 元素中的 `language` 属性匹配

### 第五步：验证

```bash
python scripts/i18n_check.py
```

确保验证通过。然后启动应用，通过 `视图 → 显示语言` 切换到新语言，以验证应用内渲染效果。

## 添加新语言（手动）

### 使用 Qt Linguist（GUI）

如果您安装了 Qt 开发环境：

```bash
# 1. 提取 tr() 调用，生成 .ts 骨架
pylupdate5 ui/*.py -ts translate/fr_FR.ts

# 2. 在 Qt Linguist 中打开并逐条翻译
linguist translate/fr_FR.ts

# 3. 编译
python scripts/qm_compile.py translate/fr_FR.ts translate/fr_FR.qm
```

### 直接编辑 XML

`.ts` 文件是纯 XML —— 可以在任何文本编辑器中编辑：

```xml
<?xml version="1.0" encoding="utf-8"?>
<!DOCTYPE TS>
<TS version="2.1" language="fr_FR" sourcelanguage="en">
<context>
    <name>Canvas</name>
    <message>
        <location filename="../ui/canvas.py" line="769"/>
        <source>Delete</source>
        <translation>Supprimer</translation>    <!-- ← 只编辑此处 -->
    </message>
</context>
</TS>
```

- `<source>` 是代码中的英文字符串 —— **不要修改**
- `<translation>` 是填写翻译文本的地方
- `<location>` 可以删除 —— 对运行时行为没有影响
- `type="obsolete"` 的条目在运行时会静默忽略
- 空的 `<translation></translation>` 在运行时会回退到源文本

### 翻译之后

按照上述 AI 辅助工作流的第三步到第五步执行（编译、注册、验证）。

## 添加新的 tr() 调用（针对开发者）

当您在代码中添加 `self.tr("...")` 时，`.ts` 文件也必须同步更新。

### 自动化（推荐）

```bash
# 1. 自动填充缺失条目（标记为 type="unfinished"）
python scripts/ts_auto_fill.py --fill-missing

# 2. 编辑 zh_CN.ts —— 为 type="unfinished" 的条目填写翻译

# 3. 编译并验证
python scripts/qm_compile.py translate/zh_CN.ts translate/zh_CN.qm
python scripts/i18n_check.py
```

`ts_auto_fill.py` 脚本扫描 `ui/`、`modules/` 和 `utils/` 中的 `self.tr()` 调用，
与 `.ts` 文件进行比对，并将缺失的条目作为 `<translation type="unfinished">` 插入
—— 这是一个占位符，在翻译完成前会导致运行时回退到源文本。

### 手动

在 `zh_CN.ts` 的正确 `<context>`（与 Python 类名匹配）下插入新块：

```xml
<message>
    <source>Your New String</source>
    <translation>你的翻译</translation>
</message>
```

然后重新编译并验证。

## 清理过时条目

当 `self.tr()` 调用被删除或重命名时，`.ts` 文件中会留下孤立条目。

```bash
# 试运行：查看将被删除的内容
python scripts/ts_auto_fill.py --prune

# 执行删除（使用与 i18n_check.py 相同的保守过滤器）
python scripts/ts_auto_fill.py --prune --apply
```

清理器会跳过：
- 源文本包含 `{` 的条目（格式字符串）
- `<context>ParamWidget</context>` 下的条目（模块参数描述）
- 其余所有没有匹配 `self.tr()` 调用的条目均被删除。

清理后，重新编译并重新验证：
```bash
python scripts/qm_compile.py translate/zh_CN.ts translate/zh_CN.qm
python scripts/i18n_check.py
```

## 常见问题

**问：切换语言后某些文本没有变化？**
答：运行 `i18n_check.py` 检查该 widget 的 `self.tr()` 调用是否有对应的 `.ts` 条目。如果有但仍不起作用，请尝试重启应用——Qt 的 `QTranslator` 可能不会刷新在 `installTranslator` 调用之前创建的 widget 上的文本。

**问：编译没有输出或生成了空的 .qm？**
答：确保您的 `.ts` 文件包含有效条目（并非全部标记为 `type="obsolete"`）。`qm_compile.py` 脚本会跳过过时条目——如果没有任何有效条目，`.qm` 将是空的。

**问：包含 `{` 或 `%` 的字符串怎么办？**
答：`i18n_check.py` 会自动跳过参数包含 `{` 的 `self.tr()` 调用（视为不需要翻译的 Python 格式字符串）。如果某个格式字符串确实需要翻译，请手动将该条目添加到 `.ts` 文件中。

**问：我可以添加使用非拉丁语系语言代码的语言吗？**
答：语言代码可以是任何非空字符串。`qm_compile.py` 对所有字段（source、context、translation、language code）均使用 UTF-8 编码，无 Latin-1 限制。

**问：运行时某些翻译显示为 `?` 字符，是什么原因？**
答：`.qm` 文件可能是用旧版 `scripts/qm_compile.py` 编译的，该版本使用 `latin-1` 编码。`—`（em dash）、`→`、`⚠`、`✓` 等非 Latin-1 字符被静默替换为 `?`，同时也导致 Qt 基于哈希的字符串查找失效。**使用当前版本的 `qm_compile.py`（UTF-8）重新编译**即可修复。验证方法：

```bash
python -c "
import struct
data = open('translate/zh_CN.qm', 'rb').read()
pos = 16
while pos < len(data):
    t, l = data[pos], struct.unpack('>I', data[pos+1:pos+5])[0]
    if t == 0x69:  # SECTION_MESSAGES
        raw = data[pos+5:pos+5+l]
        for keyword in [b'? recommended', b'? from', b'? Model']:
            if keyword in raw:
                print('QM 已损坏 — 请重新编译！')
                break
    pos += 5 + l
"
```
