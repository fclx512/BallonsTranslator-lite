## 一、PR 概述

该 PR 为 Advanced Text Format 流程添加了四个独立的文字变换维度：

| 变换 | 范围 | 说明 |
|------|------|------|
| **Horizontal Scale** | 10%–400% | 水平独立缩放 |
| **Vertical Scale** | 10%–400% | 垂直独立缩放 |
| **Box Slant** | -85°–85° | 整个文本框剪切（含选择框和手柄跟随） |
| **Glyph Slant** | -45°–45° | 仅字形轮廓倾斜，不改变行布局/换行 |

中性值 `100% / 100% / 0° / 0°` 保持现有渲染路径不变。旧项目加载时自动回退为中性值。

**改动规模**：15 个文件，新增 2 个文件（~1200 行），净改动 ~5800 行。

**4 个 commits：**
1. `5fcbcd55` — feat(text): add independent scale and slant transforms
2. `a62964b1` — refactor(text): simplify transform implementation
3. `139881c6` — refactor(text): deduplicate transform state handling
4. `8cefa80b` — refactor(text): simplify transform controls and move snapshots

## 二、文件级分析

### 新增文件

#### 1. `text_glyph_renderer.py`（+1026 行）

独立字形倾斜渲染引擎。最核心的新文件。

**设计原则**：
- **只读架构**：读取 QTextLayout 已排好的 glyph runs，不修改文档内容
- **路径优先**：优先用 `QRawFont.pathForGlyph()` 获取矢量字形路径施加剪切变换
- **栅格回退**：对无路径/彩色字体（emoji、COLR/CBDT/sbix/SVG 表）降级为 QImage 栅格化后仿射变换合成
- **格式合并**：`resolve_paint_spans()` 合并 fragment/additional/selection 格式，支持富文本多格式段落逐段渲染

**关键函数**：
- `draw_slanted_line()` — 带字形倾斜地绘制一行文字（含背景、下划线、装饰）
- `draw_slanted_glyph_mask()` — 绘制字形倾斜遮罩（用于阴影/笔触效果）
- `slanted_line_ink_bounds()` — 计算倾斜后的 ink bounds
- `glyph_geometry()` — 构建矢量/降级 glyph 几何体
- `glyph_slant_transform()` — 构建 `x' = x - tan(angle) * (y - baseline_y)` 仿射变换

**安全护栏**：
- `FALLBACK_RASTER_MAX_SCALE = 8.0`
- 最大像素 `4_194_304`、最大维度 `8192`、最大字节 `32MB`
- LRU 彩色字体缓存（128 上限）

#### 2. `text_transform.py`（+184 行）

纯辅助模块，不含 Glyph Slant（Glyph Slant 在渲染器中处理）。

**核心函数**：
- `text_transform_matrix(hs, vs, slant, pivot)` — 构建 box-only 仿射矩阵
- `compensated_text_transform_matrix(hs, vs, slant, box_pivot, rotation_angle, rotation_pivot)` — **关键创新**：解决 Qt `QGraphicsItem` 旋转先于 `setTransform()` 的问题。安装 `C = R⁻¹ × S × R` 作为基础变换，使最终组合为 `R × C == S × R`（先 Box 变换后旋转）
- `rect_polygon()` — QRectF → 四顶点 QPolygonF（供 shape control 使用）

## 三、架构亮点（可学习点）

### 1. 分层清晰

```
FontFormat（数据层：存储 → JSON 持久化）
  ↑
TextTransform（纯数值四元组 + 标准化）
  ↑
text_transform.py（仿射矩阵计算：Box 变换 + 旋转补偿）
  ↑
text_glyph_renderer.py（Glyph Slant 渲染引擎：路径级 + 栅格回退）
  ↑
textitem.py（整合：变换安装 + 效果缓存 + 预览系统）
  ↑
text_advanced_format.py（UI 控件层）
```

### 2. 旋转补偿矩阵

Qt 的 `QGraphicsItem.rotation()` 总是先于 `setTransform()` 应用。作者用 `C = R⁻¹ × S × R` 作为基础变换，使 `R × C == S × R`（先缩放/剪切再旋转），让已有旋转的文字项也能使用四个新变换。

### 3. 预览系统

拖拽滑块时实时预览（`_text_transform_preview`），不写入 undo stack。鼠标释放才 commit 生成一个原子 undo 命令。避免拖拽过程产生海量 undo 记录。

### 4. 批量更新合并

`_text_transform_update_depth` 计数器 + `_flush_text_transform_update()` 合并嵌套调用为一次重绘。

### 5. 多边形 shape control

将 shape control 从矩形模型升级为通用多边形模型，使 Box Slant 后的平行四边形选择和缩放手柄仍能正确贴边。

### 6. 字形倾斜与文档隔离

Glyph Slant 完全是渲染层变换，不改变 QTextDocument 的布局计算，因此不影响文本编辑（IME 输入、方向切换、undo/redo）的逻辑。

### 7. 回退方案完善

对彩色字体（emoji 等无法提取矢量路径的字形），用 QImage 栅格化 + 仿射变换再合成，而非直接放弃。

### 8. 项目加载的版本迁移

`TEXT_TRANSFORM_SCHEMA_VERSION` + `migrate_text_transform_payload()` 确保旧项目无缝升级，新字段不存在时自动回退中性值。

## 五、需要注意的地方

1. **代码量大**（~5800 行净改动），实装前应增量进行，分阶段验证
2. **上游的 text_advanced_format.py** 控件体系与我们的打包控件不同，UI 部分应直接重写而非搬运
3. **shape control** 我们当前实现和上游差异大，多边形化是最复杂的环节，需要先深入理解现有代码
4. **效果缓存系统**（shadow/stroke）的 transform 边界预留需要仔细处理
5. **旋转补偿矩阵**的数学推导要验证正确性，避免因 Qt 版本差异导致矩阵计算错误
