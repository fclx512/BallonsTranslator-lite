## 快速入门

### 安装与启动

1. 下载软件压缩包并解压到任意目录
2. 双击 `launch.bat` 启动程序
3. 首次启动会自动检查依赖并下载模型文件
4. 看到主界面即代表启动成功

**推荐配置**：
- Windows 10/11 64 位
- 8GB 以上内存
- NVIDIA 显卡（可选，加速处理）

### 打开项目

点击顶部菜单 **文件 → 打开文件夹**，选择包含图片的目录。支持格式：

| 格式 | 说明 | 备注 |
|------|------|------|
| PNG | 无损格式 | 推荐 |
| JPG/JPEG | 有损压缩 | 文件较小 |
| WebP | 现代格式 | 浏览器兼容 |
| BMP | 未压缩 | 不推荐 |

### 运行翻译管线

配置好各阶段模块后，点击底栏的 **▶ 运行** 按钮即可执行完整管线：

```text
文字检测 → OCR 识别 → 翻译 → 图像修复 → 文字渲染
```

管线执行过程中可在底栏查看进度。

## 文字检测

文字检测是管线的第一步，负责定位图片中的文字区域。

### CTD 检测器

ComicTextDetector（CTD）是针对漫画优化的检测器。

#### 检测尺寸

参数 `detect_size` 控制输入图片的缩放尺寸：

- 范围：896~1280
- 推荐：1024（平衡速度和精度）
- 较大值提高小文字检测率，但降低速度

#### 字体大小

字体相关参数控制检测到的文字块大小：

- `font_size_min`：最小字号过滤
- `font_size_max`：最大字号过滤
- `font_size_multiplier`：大小调整系数

#### 遮罩膨胀

`mask_dilate_size` 控制检测遮罩的膨胀程度：

- 较大的值会扩大遮罩区域，修复时覆盖更多区域
- 过大会覆盖相邻文字，导致文字丢失
- 建议值：5~15

### PaddleOCR 检测器

PaddleOCR v6 ONNX 检测器支持通用场景文字检测。

#### 阈值设置

- `det_db_thresh` (默认 0.2)：检测阈值，越低越敏感
- `det_db_box_thresh` (默认 0.45)：边框阈值
- `det_db_unclip_ratio` (默认 1.4)：边框扩展系数
- `max_candidates` (默认 3000)：最大候选框数

### YSG 检测器

基于 YOLO 的检测器，支持标注类型筛选：

- `balloon`：气泡文字
- `qipao`：气泡
- `shuqing`：竖排文字
- `free`：自由文字

## OCR 识别

OCR 阶段将检测到的文字区域识别为可编辑文本。

### MIT48px OCR

基于 manga-image-translator 的 48px CTC 模型：

- `chunk_size`：批处理大小（8/16/24/32）
- 适合日文漫画文字识别
- 需要 PyTorch 支持

### PaddleOCR ONNX

基于 ONNX 运行时的 OCR 引擎：

- 支持多种语言
- 速度较快
- 适合通用场景

### LLM API OCR

使用大语言模型进行 OCR 识别：

- 通过视觉模型识别文字
- 支持自定义提示词
- 需要 API 访问权限

```python
# OCR 配置示例
config = {
    "ocr_module": "mit48px_ctc",
    "params": {
        "chunk_size": 16,
        "device": "cuda"
    }
}
```

## 翻译模块

翻译模块将 OCR 识别的文字翻译为目标语言。

### LLM API 翻译

#### API 配置

在 **设置 → LLM 配置文件** 中管理 API 配置：

- **API Host**：服务地址
- **API Key**：认证密钥
- **Model**：模型名称
- **Temperature**：生成温度（0~2）
- **Max Tokens**：最大生成长度

#### 提示词模板

翻译提示词模板支持变量替换：

```
{source_language} → 源语言
{target_language} → 目标语言
{text} → 待翻译文本
{context} → 上下文信息
```

### Sakura 翻译器

SakuraLLM 翻译器是专用漫画翻译工具：

- 支持低显存模式
- 可自定义 API 地址
- 支持外部词典

## 图像修复

图像修复阶段移除原文并填充背景。

### AOT 修复器

AOT（Attention-based Outpainting Transformer）修复器：

- `inpaint_size`：修复尺寸（1024/2048）
- 适合大面积背景修复
- 需要 PyTorch 和 GPU

### LaMa 修复器

LaMa 修复器使用大型遮罩修复网络：

- `inpaint_size`：512~2048
- `precision`：fp32/bf16
- 精度较高，适合复杂纹理

### FFC 修复器

FFC（Fourier-Frequency-Customized）修复器：

- 基于频率域的修复方法
- 对重复纹理效果好
- 速度较快

| 修复器 | 速度 | 质量 | 适用场景 |
|--------|------|------|----------|
| AOT | ★★★ | ★★★★ | 大面积背景 |
| LaMa | ★★★ | ★★★★★ | 复杂纹理 |
| FFC | ★★★★ | ★★★ | 重复纹理 |

## 设置面板

### 模块设置

在设置面板中可配置各模块行为。

#### 模块 Actions

- **Load Module**：加载选中的模块
- **Unload Module**：卸载并释放内存
- **Clear Cache**：清空缓存数据

#### 网络设置

- **镜像源**：pip/ HuggingFace 镜像地址
- **代理**：HTTP/HTTPS 代理配置

### 排版设置

排版设置控制文字渲染效果：

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| 字号委派 | 自动/手动控制字号 | 自动 |
| 字体颜色 | 前景色/背景色 | 程序决定 |
| 标点位置 | 传统/简体排版 | 传统 |
| 縦中横阈值 | 数字横排阈值 | 3 |
| 自动布局 | 自动排列文字块 | 开启 |

### 性能设置

- **动画帧率**：0=自动，30/60=固定，-1=关闭
- **文字渲染**：清晰/平滑
- **拖拽时显示装饰**：开启/关闭

## 常见问题

### 翻译质量不佳

可能的原因和解决方案：

1. **提示词不恰当** → 调整 prompt_template
2. **模型能力不足** → 换用更强模型
3. **源语言检测错误** → 手动指定源语言
4. **缺乏上下文** → 启用上下文批量翻译

### 检测不到文字

1. 检查检测模块是否正确加载
2. 降低 `det_db_thresh` 阈值
3. 增大 `detect_size`
4. 尝试不同的检测器

### 修复效果差

1. 增大 `mask_dilate_size` 扩大遮罩
2. 使用更高精度的修复模型
3. 尝试不同的修复器
4. 手动调整遮罩区域
