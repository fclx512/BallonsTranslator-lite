# Adding a New UI Translation

## Architecture Overview

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│ self.tr("Text") │ ──→ │  translate/xx.ts │ ──→ │  translate/xx.qm │
│  Python source   │     │  (XML, editable)  │     │  (binary, runtime)│
└─────────────────┘     └──────────────────┘     └─────────────────┘
                               │
                               ▼
                        scripts/qm_compile.py
                        (custom compiler, zero deps)
```text

- **Source strings**: all UI-visible text is wrapped in `self.tr("English")` in Python code
- **Translation files**: Qt `.ts` (XML) files under `translate/`
- **Runtime loading**: `launch.py` loads the `.qm` file matching `config.display_lang`
- **Language registry**: the `DISPLAY_LANGUAGE_MAP` dict in `utils/shared.py` controls the available languages in the menu

## Adding a New Language (AI-assisted, recommended)

### Step 1: verify coverage

Run the audit script to make sure the reference translation is complete:

```bash
python scripts/i18n_check.py
```

If it prints `[PASS]`, the `zh_CN.ts` baseline is fully covered. Otherwise, fix the reported gaps before proceeding.

### Step 2: ask AI to translate

Send the following prompt to an AI (Claude, ChatGPT, etc.) along with the `translate/zh_CN.ts` file:

> Please create a Japanese translation file `translate/ja_JP.ts` based on `translate/zh_CN.ts`.
>
> Requirements:
>
> 1. Keep all `<source>` strings unchanged
> 2. Removing `<location>` lines is optional
> 3. Translate all `<translation>` content to Japanese (keep class names and technical terms like OCR/LLM/API untranslated)
> 4. Change the root `<TS>` element's `language` attribute to `"ja_JP"`
> 5. Skip entries with `type="obsolete"` or `type="unfinished"` (translate their content directly)
> 6. Keep the same XML format as the input

Save the AI output as `translate/ja_JP.ts`.

#### CJK shortcut

For Japanese (ja_JP), Korean (ko_KR) and other CJK languages, roughly 60% of the zh_CN translations (those using shared Chinese characters) can be reused directly. Use this prompt instead:

> Based on `translate/zh_CN.ts`, create a Korean translation file `translate/ko_KR.ts`. For translations that contain Chinese characters still understandable in Korean, keep them as-is. Translate the rest to Korean.

### Step 3: compile the .qm file

```bash
python scripts/qm_compile.py translate/ja_JP.ts translate/ja_JP.qm
```

Expected output:

```text
Compiled 677 translations: translate/ja_JP.ts -> translate/ja_JP.qm
```

### Step 4: register the new language

Add an entry to `DISPLAY_LANGUAGE_MAP` in `utils/shared.py`:

```python
DISPLAY_LANGUAGE_MAP = {
    "English": "English",
    "简体中文": "zh_CN",
    "日本語": "ja_JP",      # ← new
}
```

- **Key**: the language name shown in the menu (use the language's native name)
- **Value**: must match the `language` attribute in the `.ts` file's root `<TS>` element

### Step 5: validate

```bash
python scripts/i18n_check.py
```

Make sure it passes. Then launch the app and switch to the new language via `View → Display Language` to verify in-app rendering.

## Adding a New Language (manual)

### Using Qt Linguist (GUI)

If you have a Qt development environment installed:

```bash
# 1. Extract tr() calls, generate the .ts skeleton
pylupdate5 ui/*.py -ts translate/fr_FR.ts

# 2. Open in Qt Linguist and translate each entry
linguist translate/fr_FR.ts

# 3. Compile
python scripts/qm_compile.py translate/fr_FR.ts translate/fr_FR.qm
```

### Editing the XML directly

The `.ts` file is plain XML — you can edit it in any text editor:

```xml
<?xml version="1.0" encoding="utf-8"?>
<!DOCTYPE TS>
<TS version="2.1" language="fr_FR" sourcelanguage="en">
<context>
    <name>Canvas</name>
    <message>
        <location filename="../ui/canvas.py" line="769"/>
        <source>Delete</source>
        <translation>Supprimer</translation>    <!-- ← only edit this -->
    </message>
</context>
</TS>
```

- `<source>` is the English string from the code — **do not modify**
- `<translation>` is where you write the translated text
- `<location>` can be deleted — it has no effect on runtime behavior
- Entries with `type="obsolete"` are silently ignored at runtime
- An empty `<translation></translation>` falls back to the source text at runtime

### After translating

Follow Steps 3–5 (compile, register, validate) from the AI-assisted workflow above.

## Adding new tr() calls (for developers)

When you add `self.tr("...")` in the code, the `.ts` files must be updated too.

### AI-assisted (recommended)

1. Run `python scripts/i18n_check.py`
2. Send the `[MISSING .ts ENTRIES]` output to an AI:
   > These are newly added self.tr() calls. Please generate the Chinese translations: ...(paste output)
3. Add the returned `<message>` blocks to the matching `<context>` in `zh_CN.ts`
4. Recompile: `python scripts/qm_compile.py translate/zh_CN.ts translate/zh_CN.qm`
5. Run `i18n_check.py` again to confirm `[PASS]`

### Manual

Insert a new block under the correct `<context>` (matching the Python class name) in `zh_CN.ts`:

```xml
<message>
    <source>Your New String</source>
    <translation>你的翻译</translation>
</message>
```

Then recompile and validate.

## Cleaning up stale entries

When `self.tr()` calls are removed or renamed, orphan entries remain in the `.ts` file.

```bash
python scripts/i18n_check.py
```

The `[ORPHAN .ts ENTRIES]` section lists them. Delete those `<message>` blocks manually.

## FAQ

**Q: Some text doesn't change after switching languages?**
A: Run `i18n_check.py` to check whether the `self.tr()` calls for that widget have corresponding `.ts` entries. If they do and it still doesn't work, try restarting the app — Qt's `QTranslator` may not refresh text on widgets created before `installTranslator` was called.

**Q: Compilation produces no output or an empty .qm?**
A: Make sure your `.ts` file has active entries (not all marked `type="obsolete"`). The `qm_compile.py` script skips obsolete entries — if none remain, the `.qm` will be empty.

**Q: What about strings containing `{` or `%`?**
A: `i18n_check.py` automatically skips `self.tr()` calls whose argument contains `{` (treated as Python format strings that don't need translation). If a format string genuinely needs a translation, add the entry to the `.ts` file manually.

**Q: Can I add a language with a non-Latin language code?**
A: Language codes can be any non-empty string. However, `qm_compile.py` encodes `<source>` and `<context>` fields in Latin-1 — if the language code itself contains characters outside Latin-1 (e.g. emoji), compilation will fail. Translation content (`<translation>`) uses UTF-8 and has no such restriction.
