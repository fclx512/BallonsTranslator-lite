三种重组方案对比

约束：左侧导航 ≤ 4 项；Qt 可实现；不为"无家可归"项创建空组

A

合并弱组 · 四变三

Startup 并入 Save 改称"Project"；Misc 改为"Interface"收容动画+快捷键+预设；Typesetting 不变

B

策略/行为分离 · 四变四

Typesetting 拆为"Font Policy"（4×2 委托网格）和"Typography"（其余排版行为）；Save+Startup 合并；Misc 保留

C

推荐：三组 + 紧凑控件

Project / Typesetting / Interface 三组。Typesetting 内用紧凑开关替 4×2 下拉网格，预设区移入 Interface

方案 A — 合并弱组，控件不变

最大优点：改动最小。但 Typesetting 仍然拥挤。

优点

  • 改动最小，代码量最少
  • "Miscellaneous"有了体面的名字
  • 左侧仍为 3 项（更少）

缺点

  • Typesetting 拥挤问题未解决
  • 4×2 下拉网格视觉疲劳依旧

优点

  • 每组内容聚焦，语义清晰
  • Typesetting 一拆为二，不再拥挤

缺点

  • 左侧导航多 1 项（4 项→5 项），用户担心数量过多
  • "Font Policy"这个名字对普通用户不够直观

方案 C — 推荐：三组 + 紧凑控件

优点

  • 左侧仅 3 项，最简洁
  • Typesetting 用紧凑面板包装委托网格，视觉压力减半
  • "Project"语义涵盖启动+保存，"Interface"涵盖动画+快捷键+预设

缺点

  • Typesetting 仍相对较重（但比现状好很多）
  • "Interface"组稍显杂（但比 "Miscellaneous" 语义明确）
